배열과 연결리스트

메모리 구조 비교 · 2차원 배열 주소계산 · 삽입/삭제 · PART 04. 자료구조론

핵심 요약

배열은 연속된 메모리에 데이터를 놓고 인덱스로 직접 접근한다. 연결리스트는 흩어진 메모리를 포인터로 연결하고, 원하는 노드까지 순차적으로 따라가야 한다.

🎯이 단원을 왜 배우나

"바로 찾기"와 "쉽게 끼워넣기"는 동시에 가질 수 없다

데이터를 한 줄로 저장하는 방법은 크게 둘뿐이다. 배열은 좌석번호가 붙은 극장처럼 자리를 미리 연속으로 예약해두는 방식이고, 연결리스트는 보물찾기 쪽지처럼 "다음은 어디"라는 메모만 들고 흩어져 있는 방식이다.

이 차이가 성능을 정반대로 갈라놓는다. 배열은 좌석번호만 알면 계산 한 번으로 바로 그 자리에 갈 수 있어 접근이 O(1)이지만, 중간에 한 명을 끼워넣으려면 뒤쪽 사람을 전부 한 칸씩 밀어야 해서 삽입이 O(n)이다. 연결리스트는 반대로 쪽지 두 장만 고쳐 쓰면 끼워넣기가 끝나 삽입이 O(1)이지만, k번째를 찾으려면 처음부터 쪽지를 따라가야 해서 접근이 O(n)이다.

그래서 시험은 늘 이 트레이드오프를 찌른다 — "정렬된 데이터를 빠르게 탐색하려면?"(→ 배열 + 이진탐색), "삽입·삭제가 잦으면?"(→ 연결리스트). 그리고 배열에서는 주소 계산 문제, 연결리스트에서는 포인터 조작 순서와 탐색 비교 횟수가 단골로 나온다.

2차원 배열 주소 계산 (행우선 vs 열우선) 📖 기출문제집 p.435~437

행우선(row-major): 주소 = 시작주소 + ((행-a)×열의개수 + (열-b)) × 원소크기
열우선(column-major): 주소 = 시작주소 + ((열-b)×행의개수 + (행-a)) × 원소크기

계산 예제: a[5][6] 배열이 열우선으로 저장, a[0][0]=1000번지, 정수 4byte일 때 a[2][3]의 주소는?

  1. 열우선 공식 적용: 주소 = 시작주소 + (열번호 × 전체 행 수 + 행번호) × 원소크기
  2. a[2][3]에서 행번호=2, 열번호=3, 전체 행 수=5, 원소크기=4
  3. = 1000 + (3 × 5 + 2) × 4
  4. = 1000 + (15 + 2) × 4 = 1000 + 17 × 4 = 1000 + 68
  5. = 1068번지

공식을 외우지 말고 "앞에 몇 칸이 있나"를 세라

주소 공식은 결국 "시작주소 + (내 앞에 놓인 원소 개수) × (원소 하나의 크기)" 이 한 줄이다. 헷갈리는 건 "내 앞에 몇 개가 있나"인데, 이건 저장 순서를 따라 채워나가는 그림을 떠올리면 자동으로 나온다.

  • 행우선은 한 행을 다 채우고 다음 행으로 간다 → A[i][j] 앞에는 완성된 행 i개(= i × 열의 개수)와 현재 행에서 j개가 있다 → (i × 열개수 + j)
  • 열우선은 한 열을 다 채우고 다음 열로 간다 → 앞에 완성된 열 j개(= j × 행의 개수)와 현재 열에서 i개가 있다 → (j × 행개수 + i)

기억할 한 줄: "행우선이면 열의 개수를 곱하고, 열우선이면 행의 개수를 곱한다." (자기 이름과 반대쪽 개수를 곱한다고 외우면 절대 안 틀린다.)

주의: 문제에서 원소 크기가 1byte면 곱셈이 생략된 것처럼 보이고, 16진수로 주소를 주면 변위를 10진수로 계산한 뒤 16진수로 바꿔서 더해야 한다.

연결리스트의 구조와 종류

연결리스트의 노드(Node)는 데이터 필드 + 링크(포인터) 필드로 구성된다. C에서는 자기참조 구조체(자기 자신과 같은 타입을 가리키는 포인터를 담은 구조체)로 구현한다.

종류구조특징
단순 연결리스트한 방향(next)만 연결마지막 노드의 link는 NULL
이중 연결리스트양방향(prev, next) 연결왼쪽↔오른쪽 노드가 서로를 가리킴, 역방향 탐색 가능
원형 연결리스트마지막 노드가 첫 노드를 가리킴마지막 노드 link는 NULL이 아니라 첫 노드 주소 — 끝에 삽입이 O(1)로 효율적
함정 주의: "원형 연결리스트의 마지막 노드는 NULL을 가리킨다" → ❌ 틀림. 첫 노드의 주소를 가리켜야 원형이 된다.

연결리스트 탐색 — 인덱스를 따라가며 세는 문제 📖 기출문제집 p.440

계산 방법: 연결리스트는 배열처럼 "몇 번째"로 바로 못 간다. HEADER가 가리키는 인덱스부터 시작해서, 각 노드의 Pointer(다음 인덱스)를 따라 한 칸씩 이동하며 비교해야 한다.

노드 삽입 — 포인터만 두 줄 바꾸면 끝 📖 기출문제집 p.441~442

계산 방법: preNode와 nextNode 사이에 newNode를 끼워 넣을 때는 순서가 중요하다 — newNode가 먼저 nextNode를 가리키게 한 다음에, preNode가 newNode를 가리키게 해야 한다 (순서를 바꾸면 원래 연결이 끊어져 버린다).

  1. newNode.link = preNode.link; — newNode가 원래 다음 노드(nextNode)를 가리키게 먼저 연결
  2. preNode.link = newNode; — preNode가 newNode를 가리키도록 변경 (이제 원래 연결은 완전히 끊김)

노드 삭제 — 실제 메모리 주소로 따라가기 📖 기출문제집 p.442

계산 방법: A(2000번지)→B(2020번지)→C(2010번지)→D(2030번지) 순으로 연결된 리스트에서 B를 삭제하면, B의 이전 노드인 A가 B를 건너뛰고 B가 가리키던 곳(C, 2010번지)을 직접 가리키게 바뀐다.

  1. 삭제 전: A(2000)의 link=2020(B) → B(2020)의 link=2010(C) → C(2010)의 link=2030(D)
  2. B를 삭제하려면 A가 B를 건너뛰어야 함
  3. A(2000)의 link를 2020(B)에서 2010(C)으로 변경 → A→C로 바로 연결
  4. B(2020) 노드는 이제 아무도 가리키지 않으므로 메모리에서 회수 가능
주의: 이 문제의 함정은 "C의 link가 바뀐다"고 착각하는 것 — 실제로 바뀌는 건 B의 이전 노드(A)의 link다. C는 원래대로 D(2030)를 계속 가리킨다.

📌시험 빈출 포인트

  • 배열=직접접근(O(1))·연결리스트=순차접근(O(n)) — 임의 위치 접근 속도 비교
  • 2차원 배열 주소 계산: 행우선/열우선 공식에 정확히 대입해서 계산하는 문제 매년 출제
  • 희소행렬(0이 많은 행렬)은 연결리스트로 표현하는 게 배열보다 효율적
  • 원형 연결리스트의 마지막 노드는 첫 노드 주소를 가리킴 (NULL 아님)
  • 노드 삽입 시 newNode.link 먼저, preNode.link 나중 — 순서를 바꾸면 리스트가 끊어짐
  • 노드 삭제 시 실제로 바뀌는 건 삭제할 노드의 이전 노드의 link
  • 연결리스트가 배열보다 메모리 사용량이 더 크다 (포인터 저장 공간 때문)

문제 12016 계리직 · 기출문제집 p.436

char A[20][30]; 으로 선언된 배열 A의 원소 A[8][7]의 주소를 행 우선 순서와 열 우선 순서로 각각 바르게 계산한 것은? (단, A[0][0]의 주소는 1,000이고 하나의 원소는 1 byte)

  1. 행 우선 1,167 / 열 우선 1,148
  2. 행 우선 1,167 / 열 우선 1,218
  3. 행 우선 1,247 / 열 우선 1,148
  4. 행 우선 1,247 / 열 우선 1,218
해설 보기

정답 ③ 행 우선 1,247 / 열 우선 1,148

배열은 20행 30열, 원소 크기 1byte, 시작주소 1000이다. 행우선은 열의 개수(30)를, 열우선은 행의 개수(20)를 곱한다.

  1. 행우선: 1000 + (8 × 30 + 7) × 1 = 1000 + (240 + 7) = 1247
  2. 열우선: 1000 + (7 × 20 + 8) × 1 = 1000 + (140 + 8) = 1148

함정: ②·④번의 1218은 열우선인데 실수로 열의 개수 30을 곱한(7×30+8=218) 값이다. 행/열 어느 쪽 개수를 곱하는지가 이 문제의 전부이니, "자기 이름과 반대쪽 개수를 곱한다"를 반드시 확인하고 계산할 것.

문제 22018 국회 · 기출문제집 p.437

배열 int array[10][200]을 행우선순서로 저장하는 경우 원소 array[7][12]의 시작주소는? (단, 배열의 시작주소는 10840h, int는 4바이트, 첨자는 0부터 시작, h는 16진수 표기)

  1. 10804h
  2. 11E50h
  3. 16488h
  4. 108BFh
해설 보기

정답 ② 11E50h

16진수가 섞여 혼란스럽지만, 변위(떨어진 거리)는 10진수로 계산하고 마지막에만 16진수로 바꿔 더하면 된다.

  1. 행우선이므로 앞에 놓인 원소 개수 = 7 × 200(열의 개수) + 12 = 1400 + 12 = 1412개
  2. 변위(byte) = 1412 × 4 = 5648 (10진수)
  3. 5648을 16진수로 변환: 5648 ÷ 16 = 353…0, 353 ÷ 16 = 22…1, 22 ÷ 16 = 1…6 → 1610h
  4. 주소 = 10840h + 1610h = 11E50h (840 + 610 = E50, 자리올림 없음)

함정: 10진수 변위 5648을 그대로 16진수 주소에 더해버리면(10840h + 5648) 완전히 다른 값이 나온다. 진법을 반드시 통일한 뒤 더할 것.

문제 32013 국가직 7급 · 기출문제집 p.437

개수가 정해진 자연수를 크기순으로 저장하고 탐색하기에 가장 적절한 자료구조와 탐색방법으로 옳게 짝지어진 것은?

  1. 배열 - 순차탐색
  2. 배열 - 이진탐색
  3. 단순 연결리스트 - 순차탐색
  4. 단순 연결리스트 - 이진탐색
해설 보기

정답 ② 배열 - 이진탐색

  1. "개수가 정해진" → 크기가 고정이어도 되므로 배열이 적합 (연결리스트의 장점인 가변 크기가 필요 없다)
  2. "크기순으로 저장" → 정렬된 상태 → 이진탐색의 전제조건을 만족
  3. 배열은 인덱스로 중간 원소에 O(1)로 바로 접근할 수 있으므로 이진탐색이 가능하고, 탐색 시간은 O(log n)

왜 ④번은 안 되나: 이진탐색은 "가운데 원소를 즉시 꺼내는" 동작이 핵심인데, 연결리스트는 가운데로 가려면 처음부터 포인터를 따라가야 한다(O(n)). 그래서 연결리스트에 이진탐색을 붙이면 장점이 사라진다. "정렬 + 이진탐색 = 배열"로 묶어서 기억할 것.

문제 42011 국가직 7급 · 기출문제집 p.438

연결 리스트(linked list)에 대한 설명으로 옳지 않은 것은? (단, 연결 리스트의 크기는 N이다)

  1. 다음(next) 원소의 장소나 주소를 저장하기 위한 기억공간이 추가로 필요하다.
  2. 자료가 연결된 순서대로 기억공간에 저장된다.
  3. 특정 자료를 검색하는 데 걸리는 시간은 O(N)이다.
  4. 삭제할 노드의 이전 노드 위치를 알 경우 삭제 시간은 O(1)이다.
해설 보기

정답 ② 자료가 연결된 순서대로 기억공간에 저장된다 (틀린 설명)

연결리스트의 존재 이유 자체가 "연속된 메모리를 쓰지 않아도 되게 하는 것"이다. 각 노드는 메모리 여기저기 흩어져 있고, 포인터로만 논리적 순서를 만든다. 물리적으로 연속 저장되는 것은 배열이다.

나머지는 모두 옳다 — ① 포인터 필드만큼 추가 메모리가 든다(연결리스트의 단점), ③ 임의 노드 검색은 처음부터 따라가야 하므로 O(N), ④ 선행 노드를 이미 알고 있으면 포인터 한 줄만 고치면 되므로 O(1).

주의: ④번이 헷갈리기 쉽다. 삭제 자체는 O(1)이지만 선행 노드를 찾는 과정까지 포함하면 O(N)이다. 문제에 "이전 노드 위치를 알 경우"라는 단서가 붙어 있는지 꼭 확인하라.

문제 52025 국가직 · 기출문제집 p.439

원형 연결 리스트에 대한 설명으로 옳은 것은?

  1. 하나의 노드에서 모든 노드로의 접근이 가능하다.
  2. 하나의 노드에서 링크를 계속 따라가면 모든 노드를 거쳐도 자기 자신으로 되돌아올 수 없다.
  3. 마지막 노드의 링크 필드 값은 NULL이다.
  4. 리스트의 끝에 노드를 삽입하는 연산이 단순 연결 리스트보다 비효율적이다.

정답 ① 하나의 노드에서 모든 노드로의 접근이 가능하다

원형 연결 리스트는 마지막 노드의 링크가 NULL이 아니라 첫 노드를 가리킨다. 이 한 가지 차이에서 나머지 성질이 전부 파생된다.

  1. 고리가 닫혀 있으므로 어느 노드에서 출발해도 계속 따라가면 전부 방문하고 자기 자신으로 돌아온다 → ① 옳음, ② 틀림
  2. NULL이 없다 → ③ 틀림
  3. 마지막 노드가 곧 첫 노드의 바로 앞 노드이므로, 끝에 삽입하는 연산이 O(1)이다. 단순 연결 리스트는 끝까지 걸어가야 해서 O(n) → 원형이 더 효율적이므로 ④ 틀림

세 종류 비교: 단순(마지막 → NULL) / 원형(마지막 → 첫 노드) / 이중(각 노드가 앞·뒤 양쪽 포인터를 가짐, 역방향 이동 가능).

문제 62018 계리직 · 기출문제집 p.439

배열(Array)과 연결리스트(Linked List)에 대한 설명으로 옳지 않은 것은?

  1. 연결리스트는 배열에 비하여 희소행렬을 표현하는 데 비효율적이다.
  2. 연결리스트에 비하여 배열은 원소를 임의의 위치에 삽입하는 비용이 크다.
  3. 연결리스트에 비하여 배열은 임의의 위치에 있는 원소를 접근할 때 효율적이다.
  4. n개의 원소를 관리할 때, 연결리스트가 n 크기의 배열보다 메모리 사용량이 더 크다.

정답 ① 희소행렬 표현에 연결리스트가 비효율적이다 (틀린 설명 — 오히려 효율적이다)

희소행렬은 대부분의 값이 0인 행렬이다. 예를 들어 1000×1000 행렬에 0이 아닌 값이 10개뿐이라면, 배열로 만들면 100만 칸을 잡아놓고 99만 9990칸을 0으로 낭비한다.

연결리스트로 0이 아닌 값만 (행, 열, 값) 노드로 연결하면 10개 노드만 있으면 된다 → 연결리스트가 압도적으로 효율적이다.

나머지는 모두 옳다 — ② 배열은 삽입 시 뒤 원소를 전부 밀어야 함(O(n)), ③ 배열은 인덱스 계산으로 즉시 접근(O(1)), ④ 연결리스트는 포인터 필드만큼 추가 메모리를 쓴다.

문제 72015 국가직 · 기출문제집 p.441

연결리스트의 preNode 노드와 그 다음 노드 사이에 새로운 newNode를 삽입하려 한다. 빈칸 ⓐ에 들어갈 명령문으로 옳은 것은?

Node *newNode = (Node*)malloc(sizeof(Node));
ⓐ
preNode->link = newNode;
  1. newNode->link = preNode;
  2. newNode->link = preNode->link;
  3. newNode->link->link = preNode;
  4. newNode = preNode->link;
해설 보기

정답 ② newNode->link = preNode->link;

삽입의 순서가 이 문제의 전부다. 원래 연결은 preNode → (다음 노드) 인데, 이것을 preNode → newNode → (다음 노드)로 바꿔야 한다.

  1. 먼저 newNode가 "다음 노드"를 가리키게 한다 → newNode->link = preNode->link; (이때 preNode->link에는 아직 원래 다음 노드의 주소가 남아 있다)
  2. 그 다음 preNode가 newNode를 가리키게 한다 → preNode->link = newNode;

순서를 바꾸면 왜 안 되나: preNode->link = newNode를 먼저 해버리면, 원래 다음 노드의 주소가 덮어써져 영영 사라진다(리스트의 뒷부분 전체를 잃는다). 그래서 삽입은 항상 "새 노드의 연결을 먼저, 기존 노드의 연결을 나중에"가 철칙이다.

정답 ③ 6번

연결리스트 탐색은 헤더가 가리키는 노드부터 시작해 포인터를 따라가며 하나씩 비교한다. 인덱스 순서가 아니라 포인터가 이어주는 순서로 움직이는 것이 핵심이다.

  1. 인덱스 3 → CHOI (1번째 비교, 아님) → 포인터 4로 이동
  2. 인덱스 4 → BAEK (2번째 비교, 아님) → 포인터 2로 이동
  3. 인덱스 2 → PARK (3번째 비교, 아님) → 포인터 1로 이동
  4. 인덱스 1 → KIM (4번째 비교, 아님) → 포인터 6으로 이동
  5. 인덱스 6 → MIN (5번째 비교, 아님) → 포인터 5로 이동
  6. 인덱스 5 → LEE (6번째 비교, 찾음!)

전체 논리적 순서는 CHOI → BAEK → PARK → KIM → MIN → LEE → ANN → JUNG 이다.

함정: 표의 Index 번호 순서(1,2,3…)로 따라가면 완전히 다른 답이 나온다. 연결리스트에서 인덱스는 단지 "저장된 칸 번호"일 뿐 순서와 무관하다는 점이 이 문제의 출제 의도다.
