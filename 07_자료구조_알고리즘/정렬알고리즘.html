정렬 알고리즘

버블·선택·삽입·퀵·합병·기수 정렬 단계별 풀이, 시간복잡도 비교 · PART 04. 자료구조론

핵심 요약

시험에 나오는 정렬 문제는 대부분 "이 배열이 몇 단계 만에 이렇게 바뀌었다, 무슨 정렬이냐" 또는 "n회전 후 배열 상태는?"를 묻는다. 그러니 각 정렬이 한 단계에서 뭘 하는지(비교? 교환? 어디를 건드리는지)를 손으로 직접 따라갈 수 있어야 한다.

🎯이 단원을 왜 배우나

정렬은 "답을 외우는 단원"이 아니라 "손으로 굴리는 단원"이다

정렬 알고리즘은 컴퓨터가 가장 많이 하는 일 중 하나다. 검색을 빠르게 하려면(이진탐색) 먼저 정렬돼 있어야 하고, 중복 제거·순위 매기기·그룹 묶기 전부 정렬이 깔려 있어야 편하다. 그래서 정렬은 다른 알고리즘의 전처리 단계로 끝없이 등장한다.

그런데 시험 관점에서 더 중요한 건 따로 있다. 정렬 문제는 "규칙만 알면 반드시 맞힐 수 있는 계산 문제"라는 점이다. 개념을 헷갈려서 틀리는 게 아니라, 한 회전이 어디서 끝나는지를 잘못 세서 틀린다. 그러니 각 정렬의 "1회전"이 정확히 무슨 작업인지만 확실히 구분하면 된다.

세 가지 O(n²) 정렬의 1회전 구분법

  • 버블: 왼쪽부터 인접한 두 칸을 계속 비교·교환 → 1회전 끝나면 가장 큰 값이 맨 오른쪽에 확정
  • 선택: 남은 범위에서 최솟값을 찾아 현재 맨 앞과 딱 한 번 교환 → 1회전 끝나면 가장 작은 값이 맨 왼쪽에 확정
  • 삽입: 정렬된 부분 바로 다음 값 하나를 꺼내 알맞은 자리에 밀어 넣기 → 1회전 끝나면 앞쪽 2개가 정렬됨

단계별 배열 변화만 보고 정렬 종류를 맞히는 문제는 이 세 특징으로 전부 구분된다. 인접한 것끼리만 바뀌면 버블, 멀리 있는 최솟값이 앞으로 튀어오면 선택, 앞쪽만 조금씩 정리되며 커지면 삽입이다.

왜 "비교 정렬의 한계는 O(n log n)"인가

두 값을 비교하면 얻는 정보는 "크다/작다" 두 가지뿐이다. n개의 데이터가 배열될 수 있는 경우의 수는 n!가지인데, 한 번 비교할 때마다 후보가 절반씩 줄어든다고 보면 필요한 비교 횟수는 최소 log₂(n!) ≈ n log₂n번이다. 그래서 값을 비교해서 정렬하는 한 O(n log n)보다 빨라질 수 없다.

기수 정렬만 O(n)이 가능한 이유는 값을 비교하지 않기 때문이다. "이 수의 일의 자리가 7이니까 7번 바구니에 넣어라"처럼 자릿수를 보고 바로 자리를 정하므로 비교 정렬의 한계에 걸리지 않는다. 대신 자릿수(d)만큼 반복해야 하고 바구니용 추가 공간이 필요하다.

시험 포인트: "비교 기반 정렬 중 가장 빠른 시간복잡도는?" → O(n log₂n)(퀵·합병·힙). "비교가 아닌 분배에 의한 정렬은?" → 기수 정렬.

안정 정렬(Stable Sort)이란

값이 같은 원소들의 원래 순서가 정렬 후에도 유지되면 "안정 정렬"이다. 예를 들어 [3A, 1, 3B]를 정렬했을 때 [1, 3A, 3B]가 나오면 안정, [1, 3B, 3A]가 나오면 불안정이다.

왜 중요한가? "성적순으로 정렬한 뒤 학년순으로 다시 정렬"처럼 두 번 정렬해서 다중 기준을 만들 때, 두 번째 정렬이 안정적이어야 첫 번째 정렬 결과가 보존된다.

안정: 버블 · 삽입 · 합병 · 기수 / 불안정: 선택 · 퀵 · 힙 · 셸
암기법: "멀리 있는 값을 확 바꿔치기하는 정렬(선택·퀵·힙)"은 같은 값의 순서를 흐트러뜨리므로 불안정하다고 기억하면 된다.

🫧버블 정렬 — 실제 기출 예제로 손으로 따라가기 📖 기출문제집 p.498

배열 [5, 2, 3, 8, 1]을 오름차순 정렬. 버블 정렬은 왼쪽부터 인접한 두 칸씩 비교하며 왼쪽이 크면 교환 — 이걸 배열 끝까지 반복하는 게 "한 패스(pass)"다.

패턴을 눈치챘는가? 버블 정렬은 한 패스마다 뒤에서부터 하나씩 제자리를 찾아간다 (초록색 칸이 오른쪽에서부터 채워짐). 그래서 n개짜리 배열은 최대 n−1번의 패스면 항상 끝난다.

코드로 보는 버블 정렬 📖 기출문제집 p.501

기출에 C 코드 빈칸 채우기로도 나온다. 구조를 한 번 뜯어보면 조건식을 외울 필요가 없어진다.

for (x = 0; x < size; x++)  ← x는 회전(pass) 번호. 한 회전마다 값 하나의 자리가 확정된다.
  for (y = 0; y < size - x - 1; y++)  ← y는 비교 위치. 뒤쪽 x개는 이미 확정됐으니 -x-1만큼 덜 본다.
    if (value[y] > value[y+1]) { 교환 }  ← 오름차순: 왼쪽이 크면 교환
    if (value[y] < value[y+1]) { 교환 }  ← 내림차순: 왼쪽이 작으면 교환

핵심은 비교 대상이 항상 value[y]와 value[y+1](인접한 두 칸)이라는 것 — value[x]가 들어간 선택지는 버블 정렬이 아니므로 바로 걸러낼 수 있다.

최솟값 선택 vs 최댓값 선택 — 둘 다 선택 정렬이다

위 예제는 "최솟값을 찾아 맨 왼쪽과 교환"하는 방식이다. 그런데 기출에는 "최댓값을 찾아 맨 오른쪽과 교환"하는 버전도 나온다. 방향만 반대일 뿐 둘 다 선택 정렬이다.

예: [6, 5, 8, 9, 4, 2]에서 최댓값 선택 방식 → 최댓값 9와 맨 오른쪽 2를 교환하면 6 5 8 2 4 9. 이렇게 멀리 떨어진 두 값이 한 번에 자리를 맞바꾸는 모습이 보이면 선택 정렬을 의심해야 한다 (버블은 인접한 것끼리만 바뀐다).

📥삽입 정렬 — 실제 기출 예제 📖 기출문제집 p.503

배열 [69, 30, 10, 2, 16, 8, 31, 22]. 삽입 정렬은 배열을 "정렬된 부분"과 "안 정렬된 부분"으로 나누고, 안 정렬된 부분의 맨 앞 값을 정렬된 부분의 알맞은 자리에 밀어 넣는다.

회전정렬된 부분안 정렬된 부분
초기693010216 8 31 22
1회전3069102168 31 22
2회전103069216831 22
3회전21030691683122
4회전21016306983122
  1. 초기: 첫 원소 69는 "정렬된 부분"이 1개짜리라고 취급하고 시작
  2. 1회전: 30을 꺼내 정렬된 부분[69]과 비교 → 30<69이므로 69 앞으로 삽입 → [30,69]
  3. 2회전: 10을 꺼내 [30,69]와 비교 → 10이 제일 작으므로 맨 앞 삽입 → [10,30,69]
  4. 3회전: 2를 꺼내 [10,30,69]와 비교 → 2가 제일 작으므로 맨 앞 삽입 → [2,10,30,69]
  5. 4회전: 16을 꺼내 [2,10,30,69]와 뒤에서부터 비교 → 69>16(밀림), 30>16(밀림), 10<16(멈춤) → 10 뒤에 삽입 → [2,10,16,30,69]
정답 확인: 4회전 후 전체 배열 = 2, 10, 16, 30, 69, 8, 31, 22 (정렬된 부분 5개 + 아직 안 건드린 나머지 8,31,22 그대로)
삽입 정렬 문제의 최대 함정: 삽입 정렬은 언제나 앞쪽(정렬된 부분)만 정돈되어 있고 뒤쪽은 원본 그대로다. 그래서 "정렬 과정에서 나올 수 없는 배열"을 묻는 문제는 앞부분이 정렬돼 있지 않은 선택지를 고르면 된다. 예를 들어 3 1 5 2 4 9는 맨 앞 두 개(3, 1)부터 순서가 어긋나 있으므로 삽입 정렬 도중에 절대 나올 수 없다.

⚡퀵 정렬 — 피벗으로 갈라치기 📖 기출문제집 p.505~506

퀵 정렬은 분할 정복(divide and conquer) 방식이다. 피벗(pivot, 제어키)을 하나 정하고, 피벗보다 작은 값은 왼쪽으로 / 큰 값은 오른쪽으로 몰아넣은 뒤(분할), 양쪽을 각각 같은 방법으로 다시 정렬한다(재귀).

기출 예제: (5, 2, 6, 4, 7, 3, 8, 1), 피벗은 5. 첫 분할이 끝난 직후 상태를 구해보자.

분할 결과 검산법: 피벗 왼쪽 그룹의 모든 값이 피벗보다 작기만 하면 정답이다 — 그룹 안에서 정렬돼 있을 필요는 없다. 그래서 (3 2 1 4)처럼 뒤죽박죽인 채로 답이 된다. 선택지 중 "(1 2 3 4), (6 7 8)"처럼 이미 완전히 정렬된 것은 1회 분할 직후 결과로는 오히려 틀린 답인 경우가 많다.

퀵 정렬의 최악의 경우가 "이미 정렬된 배열"인 이유

퀵 정렬이 빠른 건 피벗이 데이터를 절반씩 갈라줄 때다(그래야 log n 깊이). 그런데 이미 정렬된 배열에서 첫 원소를 피벗으로 잡으면, 피벗보다 작은 값이 하나도 없어서 한쪽은 0개, 다른 쪽은 n−1개로 갈린다. 이게 매번 반복되면 깊이가 n이 되어 O(n²)로 떨어진다.

그래서 "정렬된 입력에 가장 불리한 정렬은?" → 퀵 정렬, "정렬된 입력에 가장 유리한 정렬은?" → 삽입 정렬(비교만 하고 이동이 없어 O(n))이라는 정반대 결론이 나온다. 이 대비가 시험에 그대로 출제된다.

🔗합병 정렬 — 쪼갰다가 합치며 정렬 📖 기출문제집 p.506~507

합병(merge) 정렬은 배열을 더 이상 쪼갤 수 없을 때까지 반으로 나눈 뒤, 둘씩 정렬하면서 합쳐 올라온다. 아래는 기출 예제 [8, 9, 4, 3, 7, 1, 5, 2]의 합치는 과정이다.

합병 정렬의 식별 포인트: 단계별 배열을 봤을 때 2개씩 → 4개씩 → 8개씩 구간별로 정렬되어 있으면 합병 정렬이다. 또 합칠 때 임시 배열이 필요하므로, "정렬 대상 크기만큼 추가 메모리가 필요한 정렬"의 정답은 언제나 합병 정렬이다.

🪣기수 정렬 — 비교하지 않고 바구니에 분배 📖 기출문제집 p.507~508

기수(radix) 정렬은 값을 비교하지 않는다. 대신 자릿수를 보고 0~9번 바구니에 나눠 담았다가 순서대로 꺼내기를 낮은 자리(일의 자리)부터 반복한다. 기출 예제 [534, 821, 436, 773, 348, 512]로 확인해보자.

기수 정렬 식별법: ① 데이터가 6개인데 단계가 3개뿐이다(비교 정렬이라면 5회전 필요). ② 중간 단계를 보면 크기 순서가 뒤죽박죽인데도 최종적으로 정렬된다. 이 두 가지가 보이면 기수 정렬이다. 단계 수는 데이터 개수가 아니라 자릿수로 결정된다.

왜 반드시 "낮은 자리부터(LSD)" 해야 하는가

낮은 자리부터 정렬하면, 높은 자리로 넘어갈 때 이전 단계의 순서가 보존되면서(안정 정렬이라 가능) 자연스럽게 세부 순서가 유지된다. 예를 들어 3단계에서 512와 534가 둘 다 [5]번 바구니에 들어가는데, 2단계에서 이미 512가 534보다 앞이었기 때문에 그 순서 그대로 담겨 정답이 된다.

만약 높은 자리부터 했다면, 아래 자리를 정렬할 때 위 자리 순서가 망가져 버린다. 그래서 기수 정렬은 LSD(Least Significant Digit) 방식이 기본이다.

📌시험 빈출 포인트

  • 주어진 "단계별 배열 변화"만 보고 어떤 정렬인지 맞추는 문제 — 인접한 것끼리만 바뀌면 버블, 멀리 있는 최솟값이 앞으로 튀면 선택, 앞쪽만 정돈되며 커지면 삽입, 2·4·8개 구간별로 정렬되면 합병
  • "n회전 후 배열" 문제는 반드시 표를 그려 한 회전씩 적어라 — 암산하면 반드시 틀린다
  • 선택 정렬은 이미 제자리인 값이면 교환 없이 넘어갈 수 있다 (교환 없다고 정렬 안 한 게 아님)
  • 삽입 정렬 도중 "나올 수 없는 배열" = 앞쪽(정렬된 부분)이 정렬돼 있지 않은 것
  • 퀵 정렬 분할 직후 그룹은 정렬돼 있지 않아도 된다 (피벗보다 작기만 하면 됨)
  • 퀵 정렬 최악 O(n²), 평균 O(n log₂n) — "평균이 O(log n)"은 오답 함정
  • 합병 정렬만 유일하게 추가 메모리(임시 배열)가 필요한 정렬
  • 기수 정렬은 비교가 아닌 분배 정렬이라 O(n), 단계 수 = 자릿수
  • 최악에도 O(n log₂n)을 보장하는 정렬 = 힙 정렬, 2-way 합병 정렬 (퀵은 아님!)
  • 안정 정렬: 버블·삽입·합병·기수 / 불안정: 선택·퀵·힙·셸
  • 이미 정렬된 데이터에 가장 빠른 정렬 = 삽입 정렬 (O(n)), 가장 불리한 정렬 = 퀵 정렬

  4. 1 2 3 4 5 9

  3. 삽입 정렬에서는 첫 회전만 지나도 앞쪽 2개가 정렬되므로, 앞이 정렬 안 된 상태는 어느 시점에도 존재할 수 없다
  4. 게다가 뒤쪽 5가 원래 자리(맨 끝)에서 사라져 3번째로 이동했는데, 삽입 정렬은 아직 처리하지 않은 뒤쪽 원소를 건드리지 않는다

  3. 계속 진행: L은 4를 지나 7에서 멈추고, H는 8을 지나 3에서 멈춤 → 교환 → 5 2 1 4 3 7 8 6
  4. H가 L보다 왼쪽으로 가면 종료 → 마지막으로 피벗 5와 H가 가리키는 3을 교환 → 3 2 1 4 5 7 8 6
  5. 피벗 5를 기준으로 왼쪽 (3 2 1 4), 오른쪽 (7 8 6)

함정: ⑤번 같은 "(1 2 3 4), (6 7 8)"류 선택지는 양쪽이 이미 완전히 정렬되어 있는데, 1회 분할로는 그렇게 되지 않는다. 분할의 목표는 "피벗보다 작은 것들 / 큰 것들"로 가르기만 하는 것이다. ②③은 값 배치가 실제 교환 과정과 맞지 않는다.

문제 112022 국가직 · 기출문제집 p.511

정렬 알고리즘 중 최악의 경우를 가정할 때 시간복잡도가 다른 것은?

  1. 삽입 정렬(Insertion sort)
  2. 쉘 정렬(Shell sort)
  3. 버블 정렬(Bubble sort)
  4. 힙 정렬(Heap sort)
해설 보기

정답 ④ 힙 정렬 — 혼자만 O(n log₂n)

  1. 삽입·쉘·버블 정렬의 최악 시간복잡도는 모두 O(n²)
  2. 힙 정렬은 최악에도 O(n log₂n)을 보장한다 (힙 재구성이 항상 log n 깊이)

반드시 같이 외울 것 — 최악의 경우 기준 분류:

O(n²) 그룹 (최악)O(n log₂n) 그룹 (최악)
버블, 선택, 삽입, 쉘, 퀵힙, 2-way 합병

최대 함정은 퀵 정렬이다 — 평균은 O(n log n)이라 빠른 정렬로 알려져 있지만 최악은 O(n²)이다. "최악에도 O(n log n)을 보장하는 정렬"을 물으면 힙과 합병만 정답이다.
