자료구조와 알고리즘 개요

선형/비선형 분류 · 알고리즘의 조건 · 시간복잡도 · 순환(재귀) · PART 04. 자료구조론

핵심 요약

자료구조는 데이터 사이의 관계가 1:1이면 선형(배열·리스트·스택·큐), 1:n 또는 n:m이면 비선형(트리·그래프)이다.

알고리즘의 성능은 시간복잡도(Big-O)로 표현하고, 순환(재귀)은 결국 스택에 함수 호출을 쌓았다 꺼내는 것이다.

🎯이 단원을 왜 배우나

"데이터를 어떻게 담아두느냐"가 프로그램의 속도를 결정한다

같은 데이터 1만 개라도 어떤 그릇에 담느냐에 따라 "특정 값 찾기"가 1번 만에 끝날 수도, 1만 번을 뒤져야 할 수도 있다. 전화번호부가 가나다순으로 정렬돼 있으면 몇 번 펼쳐서 찾지만, 순서 없이 쌓여 있으면 처음부터 다 읽어야 하는 것과 같다. 자료구조 = 데이터를 담는 그릇의 설계, 알고리즘 = 그 그릇에서 일을 처리하는 절차다.

그런데 "빠르다/느리다"를 초 단위로 말하면 컴퓨터 성능마다 달라져 비교가 안 된다. 그래서 입력이 n개일 때 연산을 몇 번 하는가로 표현하기로 약속한 것이 시간복잡도(Big-O)다. 기계가 아니라 알고리즘 자체의 성질을 재는 자라서, 어떤 컴퓨터에서 돌리든 결론이 같다.

시험은 이 단원에서 딱 세 가지를 묻는다 — ① 이 자료구조가 선형인가 비선형인가, ② 이 코드의 시간복잡도가 무엇인가(반복문 중첩 세기), ③ 이 재귀 함수의 호출 횟수·결과값이 얼마인가(손으로 펼쳐 세기). 전부 손으로 직접 세어보는 연습이 답이다.

💡주요 개념 — 자료구조의 분류

선형 구조 vs 비선형 구조 📖 기출문제집 p.431

구분관계정의예시
선형(Linear)1 : 1데이터 항목 사이의 선후 관계가 하나의 "선"으로 명확하게 이어짐배열, 연결리스트, 스택, 큐
비선형(Non-linear)1:n 또는 n:m하나의 항목이 여러 항목과 관계를 가짐 (그래프적 구조)트리, 그래프
함정 주의: "이진 트리(Binary Tree)"는 이름에 "트리"가 들어가니 당연히 비선형이다 — "선형 자료구조가 아닌 것은?" 문제의 단골 정답.
비유: 선형 구조 = 기차처럼 한 줄로 서서 앞뒤만 아는 관계, 비선형 구조 = 가족 족보처럼 한 사람 밑에 여러 자식이 뻗어나가는 관계

알고리즘의 조건 📖 기출문제집 p.432

조건의미
입력 (Input)외부에서 제공되는 자료가 0개 이상 있을 수 있다
출력 (Output)반드시 1개 이상의 결과를 생성해야 한다
명확성 (Definiteness)각 명령은 모호하지 않고 명확해야 한다
유한성 (Finiteness)한정된 수의 단계 뒤에는 반드시 종료해야 한다
실제성 (Effectiveness)모든 명령은 실제로 실행 가능한 연산이어야 한다
유효성 (Feasibility)원칙적으로 모든 명령은 종이와 연필만으로도 수행 가능해야 한다
함정 주의: "알고리즘 단계들에는 순서가 정해져 있지 않다" → ❌ 틀림. 알고리즘은 정해진 순서대로 진행되어야 한다.

컴퓨팅 사고(Computational Thinking)의 4요소

  • 분해(Decomposition): 복잡한 문제를 작은 문제 여러 개로 쪼갬
  • 패턴 인식(Pattern Recognition): 작은 문제들 사이의 반복되는 패턴을 찾음
  • 추상화(Abstraction): 불필요한 부분을 제거하고 핵심 요소만 남김
  • 알고리즘(Algorithm): 문제 해결을 위한 절차를 정함

📈시간복잡도 (Big-O 표기법)

알고리즘이 "얼마나 빠른가"를 입력 크기 n이 커질 때 연산 횟수가 어떤 속도로 늘어나는지로 표현한 것이다. 여러 항이 섞여 있으면 차수가 가장 높은 항 하나만 남기고 나머지는 버린다 (예: 3nlogn+100 → O(nlogn)).

시간복잡도 크기 순서 (작은 것 → 큰 것):
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!) < O(nⁿ)

코드를 보고 시간복잡도 알아내는 3단계 — 이것만 하면 다 맞는다

  • 1단계. 반복문의 반복 횟수를 n으로 표현한다. for(i=0; i<n; i++) → n번, for(i=0; i<500; i++) → 500번 = 상수 = O(1) (n과 무관하면 아무리 큰 수라도 상수다!), while(n > 1) n = n/2; → 절반씩 줄어드니 log n번
  • 2단계. 중첩되어 있으면 곱한다. 바깥 n번 × 안쪽 n번 = n². 바깥 n번 × 안쪽 500번 = 500n = O(n)
  • 3단계. 나란히 있으면 더한 뒤 가장 큰 항만 남긴다. n² + n + 100 → O(n²). 계수(3n → n)와 상수(+100)는 전부 버린다.

왜 계수와 낮은 항을 버리나? n이 100만이 되면 n²은 1조인데 거기에 붙은 +100이나 ×3은 비율로 보면 무의미하다. Big-O는 "n이 아주 커질 때의 추세"만 보는 도구이기 때문이다.

연습: 아래 코드의 시간복잡도는? 📖 기출문제집 p.433

for (i = 0; i < n; i++)
  for (j = 0; j < 500; j++)
    printf("...");
  1. 바깥 for문: i가 0부터 n-1까지 → n번 반복 → O(n)
  2. 안쪽 for문: j가 0부터 499까지 → n과 무관하게 항상 500번 → O(1)
  3. 중첩이므로 곱한다: n × 500 = 500n
  4. 계수 500을 버리면 → O(n) (이중 for문이라고 무조건 O(n²)이 아니다!)

🔁순환 (재귀, Recursion) 📖 기출문제집 p.433~435

재귀함수는 자기 자신을 다시 호출하는 함수다. 컴퓨터 내부적으로는 함수를 호출할 때마다 그 상태(지역변수, 복귀주소)를 스택에 쌓고, 종료 조건(base case)에 도달하면 쌓인 순서의 반대로 하나씩 꺼내며(pop) 계산을 완성한다. 그래서 재귀는 "스택"과 뗄 수 없다.

계산 방법: factorial(4)를 재귀로 계산하는 과정

  1. factorial(4)를 호출 → 아직 답을 모르니 factorial(3)을 먼저 호출해야 함 → 스택에 factorial(4) 쌓임
  2. factorial(3) → factorial(2)를 호출해야 함 → 스택에 factorial(3) 쌓임
  3. factorial(2) → factorial(1)을 호출해야 함 → 스택에 factorial(2) 쌓임
  4. factorial(1) → factorial(0)을 호출해야 함 → 스택에 factorial(1) 쌓임
  5. factorial(0) = 1 (종료조건 도달) → 이제부터 스택에서 꺼내며(pop) 역순으로 계산 시작
  6. factorial(1) = 1 × factorial(0) = 1 × 1 = 1 → pop
  7. factorial(2) = 2 × factorial(1) = 2 × 1 = 2 → pop
  8. factorial(3) = 3 × factorial(2) = 3 × 2 = 6 → pop
  9. factorial(4) = 4 × factorial(3) = 4 × 6 = 24 → pop, 최종 답

계산 방법: fib(5) 호출 횟수와 결과값 구하기 📖 기출문제집 p.433

fib(n) = fib(n-1) + fib(n-2), fib(0)=0, fib(1)=1 일 때
  1. fib(5) = fib(4) + fib(3)
  2. fib(4) = fib(3) + fib(2), fib(3) = fib(2) + fib(1)
  3. 계속 쪼개면 fib(1)과 fib(0)이 나올 때까지 호출이 가지치기 됨
  4. 모든 호출을 다 세면 fib(5) 자신을 포함해 총 15번 호출됨
  5. 최종 결과값 fib(5) = 5

재귀 호출 횟수를 실수 없이 세는 법 — 아래에서부터 쌓아 올려라

fib(5)를 트리로 그려서 세면 가지가 15개나 되어 반드시 실수한다. 작은 것부터 표로 쌓아 올리면 절대 틀리지 않는다.

호출 횟수를 C(n)이라 하자. fib(n)은 자기 자신 1번 + fib(n-1)의 호출들 + fib(n-2)의 호출들이므로 C(n) = 1 + C(n-1) + C(n-2)이고, 종료조건인 C(0) = C(1) = 1이다.

n012345
호출 횟수 C(n)111+1+1=31+3+1=51+5+3=91+9+5=15
결과값 fib(n)011235

덤으로 알 수 있는 것: n이 1 늘 때마다 호출 횟수가 거의 1.6배씩 불어난다 → 이 단순 재귀 피보나치의 시간복잡도가 O(2ⁿ)급으로 끔찍한 이유이고, 그래서 실무에서는 표에 저장해두고 재활용하는 방식(동적 계획법)을 쓴다.

재귀 → 반복문 변환 팁: 재귀함수가 종료되는 조건(base case, 예: n==0)이 반복문에서는 루프를 멈추는 조건의 반대가 된다. factorial 재귀의 종료조건이 n==0이면, 반복문의 while 조건은 n>0이어야 한다.

📌시험 빈출 포인트

  • 선형(배열·리스트·스택·큐) vs 비선형(트리·그래프) 구분 — 이진 트리는 비선형
  • 알고리즘의 6가지 조건: 입력·출력·명확성·유한성·실제성·유효성 (순서가 없다는 표현은 오답)
  • 시간복잡도 여러 항이 섞이면 차수가 가장 높은 항만 남기고 표기
  • 이중 for문(중첩 반복문) → O(n²), 단일 for문 → O(n), 절반씩 줄여나가면 → O(log n)
  • 재귀 함수의 총 호출 횟수·최종 반환값을 손으로 직접 트리처럼 펼쳐서 계산하는 문제 (fib류)
  • 재귀함수를 반복문(while/for)으로 바꾸는 문제 — 종료조건의 반대가 반복 조건이 됨

문제 12022 지방직 · 기출문제집 p.432

컴퓨터 알고리즘의 조건에 대한 설명으로 옳지 않은 것은?

  1. 각 명령어의 의미는 모호하지 않고 명확해야 한다.
  2. 알고리즘 단계들에는 순서가 정해져 있지 않다.
  3. 한정된 수의 단계 후에는 반드시 종료되어야 한다.
  4. 각 명령어들은 실행 가능한 연산이어야 한다.
해설 보기

정답 ② 알고리즘 단계들에는 순서가 정해져 있지 않다 (틀린 설명)

알고리즘은 정해진 순서대로 수행되는 절차다. 순서가 없으면 같은 입력에 대해 결과가 달라질 수 있어 애초에 알고리즘이 아니다.

나머지 선택지는 각각 명확성(①)·유한성(③)·실제성(④)으로, 모두 알고리즘의 정당한 조건이다.

암기: 입력 · 출력 · 명확성 · 유한성 · 실제성 · 유효성 — 이 중 "출력은 1개 이상 반드시 있어야 하지만 입력은 0개여도 된다"는 점이 따로 출제되니 함께 기억할 것.

문제 22007 국가직 7급 · 기출문제집 p.432

입력 데이터의 개수 n에 대한 시간 복잡도가 가장 큰 것은?

  1. O(10(n + log n))
  2. O(n² + 1)
  3. O(3n log n + 100)
  4. O(n² log n)
해설 보기

정답 ④ O(n² log n)

각 선택지를 먼저 간단히 정리(계수·상수·낮은 항 제거)한 뒤 크기를 비교한다.

  1. ① O(10(n + log n)) → 계수 10 제거, n과 log n 중 큰 항만 → O(n)
  2. ② O(n² + 1) → 상수 제거 → O(n²)
  3. ③ O(3n log n + 100) → 계수·상수 제거 → O(n log n)
  4. ④ O(n² log n) → 더 줄일 항이 없음 → O(n² log n)
  5. 크기 순서 O(n) < O(n log n) < O(n²) < O(n² log n) 이므로 가장 큰 것은 ④

함정: ②번 O(n²)와 ④번 O(n² log n)을 헷갈리기 쉽다. 같은 n²이라도 log n이 더 곱해져 있으면 더 크다. 계수 10이 붙은 ①번을 크다고 착각하는 것도 흔한 실수 — 계수는 크기 판단에 아무 영향이 없다.

문제 32024 지방직 · 기출문제집 p.433

다음 C 언어 코드의 시간 복잡도는? (단, n은 임의의 양의 정수)

for (i = 0; i < n; i++)
  for (j = 0; j < 500; j++)
    printf("i * j = %d\n", i * j);
  1. O(n)
  2. O(n²)
  3. O(log n)
  4. O(n log n)
해설 보기

정답 ① O(n)

  1. 바깥 for문은 n번 반복 → O(n)
  2. 안쪽 for문은 n과 무관하게 항상 500번 반복 → 상수 → O(1)
  3. 전체 실행 횟수 = n × 500 = 500n → 계수를 버리면 O(n)

함정: ②번 O(n²)을 고르기 쉽다. "for문이 2개 중첩 = O(n²)"이 아니다. 안쪽 반복 횟수가 n에 연동되어야 n²이 된다. 안쪽이 고정 횟수(500, 1000, 10만이어도)면 그냥 상수배일 뿐이다.

문제 42020 국회 · 기출문제집 p.433

다음 C 언어 프로그램에서 calc 함수의 실행 시간을 점근 표기법으로 표시한 것은?

int calc(int n) {
  int i, ret = 0;
  if (n <= 0) return 0;
  for (i = 1; i <= n; i++)
    ret += 1;
  return ret + calc(n - 1);
}
  1. O(log₂n)
  2. O(n log₂n)
  3. O(n)
  4. O(n²)
해설 보기

정답 ④ O(n²)

재귀 + 반복문이 섞인 유형이다. "몇 번 호출되는가 × 한 번 호출될 때 하는 일"로 분리해서 생각한다.

  1. 호출 횟수: calc(n) → calc(n-1) → calc(n-2) → … → calc(0). n이 1씩 줄며 한 줄로 내려가므로 총 n번 호출 → O(n)
  2. 한 번 호출될 때의 일: 내부 for문이 1부터 n까지 도므로 약 n번 반복 → O(n)
  3. 둘을 곱하면 n × n = O(n²)

함정: ③번 O(n)은 재귀 깊이만 세고 내부 for문을 놓친 경우다. 반대로 반복문만 보고 O(n)이라 답해도 똑같이 틀린다. 재귀 문제는 항상 "깊이 × 각 단계 비용" 두 가지를 다 확인해야 한다.

참고로 앞 문제(문제 3)와 비교하면 차이가 선명하다 — 거기서는 안쪽이 고정 500회라 O(n)이었지만, 여기서는 안쪽이 n에 연동되므로 O(n²)이 된다.

재귀는 종료조건부터 거꾸로 올라오며 계산하는 것이 가장 빠르고 안전하다.

해설 보기

정답 ③ ⓐ n > 0, ⓑ f = f * n--;

이 재귀 함수는 팩토리얼(n!)이다. n × (n-1) × … × 1을 계산한다.

  1. ⓐ 반복 조건: 재귀의 종료조건이 n == 0이므로, 반복문은 그 반대인 n > 0 동안 계속 돌아야 한다. ①·②번의 n < 0은 애초에 한 번도 실행되지 않는다.
  2. ⓑ 본체: f에 현재 n을 곱한 뒤 n을 1씩 감소시켜야 n, n-1, n-2 … 순으로 곱해진다 → f = f * n--
  3. ④번처럼 n++이면 n이 계속 커져 무한 루프에 빠진다.

변환 공식: 재귀 → 반복으로 바꿀 때 "종료조건의 부정 = 루프 조건", "재귀 호출 인자의 변화 = 루프 안의 증감" 두 가지만 맞추면 된다.
