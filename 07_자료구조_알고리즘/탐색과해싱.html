탐색과 해싱

순차·이진·보간 탐색, 해시 함수와 충돌 해결 · PART 04. 자료구조론

핵심 요약

순차탐색은 처음부터 하나씩(O(n)), 이진탐색은 정렬된 데이터에서 절반씩 잘라가며 찾는다(O(log n)).

해싱은 계산으로 바로 위치를 찾아가는 방식(이상적으로 O(1))이지만, 서로 다른 값이 같은 위치로 몰리는 충돌(Collision)이 생기면 느려진다.

🎯이 단원을 왜 배우나

"찾기"를 얼마나 빨리 하느냐가 프로그램 속도를 결정한다

데이터를 저장하는 이유는 결국 나중에 찾아 쓰기 위해서다. 그래서 자료구조 공부의 최종 목적지는 "얼마나 빨리 찾을 수 있는가"다. 100만 개 데이터에서 하나를 찾을 때, 순차탐색은 최대 100만 번 비교하지만 이진탐색은 20번, 해싱은 이상적이면 1번이면 끝난다. 이 차이가 곧 서비스의 응답 속도 차이다.

세 방법은 "공짜가 없다"는 점에서 서로 다른 대가를 치른다.

  • 순차탐색: 아무 조건 없이 쓸 수 있다. 대신 느리다(O(n)).
  • 이진탐색: 아주 빠르다(O(log n)). 대신 반드시 정렬되어 있어야 한다. 정렬 비용(O(n log n))을 미리 지불하는 셈이다.
  • 해싱: 가장 빠르다(O(1)). 대신 여분의 저장 공간이 필요하고, 충돌이라는 골칫거리를 떠안아야 한다.

시험에서는 ①이진탐색의 비교 횟수 세기와 ②해시 주소 계산 + 충돌 처리가 거의 매년 나온다. 둘 다 손으로 표를 그려 한 칸씩 채우면 반드시 맞는 계산 문제이므로, 규칙만 정확히 알면 확보 가능한 점수다.

이진탐색 실제로 손으로 풀어보기 📖 기출문제집 p.514

정렬된 배열 [4, 6, 11, 12, 15, 17, 18, 20, 21] (인덱스 1~9)에서 21을 찾는다고 하자. 중간 인덱스는 (low+high)÷2를 내림(floor)해서 구한다.

각 원소를 찾는 데 필요한 비교 횟수 (같은 배열)

이진탐색은 어떤 값을 찾느냐에 따라 비교 횟수가 다르다. 위 배열의 모든 원소에 대해 세어 보면 규칙이 보인다.

인덱스123456789
값4611121517182021
비교 횟수323413234
규칙: 맨 처음 mid가 되는 값(여기선 15)이 비교 1회로 가장 빠르고, 탐색 트리의 가장 깊은 곳에 있는 값(12, 21)이 4회로 가장 느리다. "비교 횟수가 가장 많은 데이터는?"이라는 문제는 mid를 계속 계산해 내려가며 가장 늦게 도달하는 값을 찾으면 된다.

비교 횟수를 빨리 세는 요령 — 머릿속에 트리를 그린다

이진탐색은 사실 이진 탐색 트리를 타고 내려가는 것과 같다. 첫 mid가 루트, 왼쪽 절반의 mid가 왼쪽 자식, 오른쪽 절반의 mid가 오른쪽 자식… 이렇게 보면 비교 횟수 = 그 값의 트리 깊이다.

위 예제라면 루트는 15(깊이1), 그 자식은 6과 18(깊이2), 그 다음이 4·11·17·20(깊이3), 가장 아래가 12·21(깊이4)이다. 표의 숫자와 정확히 일치한다. 이렇게 트리 모양으로 한 번 그려두면 아홉 개 값의 비교 횟수를 한꺼번에 알 수 있다.

함정 주의: "순차탐색이 이진탐색보다 평균적으로 빠르다" → ❌ 틀림. 이진탐색은 O(log n), 순차탐색은 O(n)이라 데이터가 많을수록 이진탐색이 압도적으로 빠르다. (단, 순차탐색은 정렬이 필요 없다는 장점은 있음)

🗂️주요 개념 — 해싱(Hashing) 📖 기출문제집 p.518~522

해싱의 아이디어: "찾지 말고 계산해라"

순차탐색도 이진탐색도 결국 "어디 있나 찾아 헤매는" 방식이다. 해싱은 발상을 뒤집는다 — 저장할 때부터 "이 값은 여기에 둔다"는 규칙(해시 함수)을 정해두면, 찾을 때도 같은 계산 한 번으로 바로 그 자리에 갈 수 있다.

예: 100칸 사물함에 학번으로 물건을 넣는데 "학번 % 100번 칸에 넣는다"고 정해두면, 나중에 찾을 때도 계산 한 번이면 끝이다. 뒤질 필요가 없으니 O(1)이다.

문제는 학번 12345와 67845가 둘 다 45번 칸으로 간다는 것 — 이게 충돌(collision)이다. 가능한 키의 종류는 어마어마한데 칸 수는 유한하므로 충돌은 피할 수 없고, 반드시 처리 방법을 마련해야 한다. 해싱 공부의 절반이 충돌 처리인 이유다.

해시 함수의 종류

함수방법
제산법 (Division)키를 테이블 크기로 나눈 나머지를 주소로 사용 — h(k) = k mod m. 가장 많이 출제됨
폴딩법 (Folding)키를 여러 부분으로 나눠 더하거나 XOR한 결과를 주소로 사용
중간제곱법 (Mid-square)키를 제곱한 뒤 가운데 몇 자리를 뽑아 주소로 사용
숫자분석법 (Digit analysis)키의 자릿수 중 고르게 분포된 자리만 골라 사용

실제 기출 예제: 제산법으로 충돌 찾기

11칸짜리 배열에 데이터 111, 112, 113, 220, 221, 222를 키 % 11로 저장한다면?

키계산해시주소
111111 % 111
112112 % 112
113113 % 113
220220 % 110
221221 % 111
222222 % 112
결과: 111과 221이 둘 다 해시주소 1 → 충돌. 112와 222가 둘 다 해시주소 2 → 충돌. 나머지(113→3, 220→0)는 겹치지 않아 충돌 없음.

충돌(오버플로) 해결 방법 2가지

방식원리세부 기법
폐쇄 주소법 (Closed Addressing)처음 계산된 해시주소는 그대로 두고, 그 자리에 연결리스트(체인)로 계속 이어붙임체이닝 (Chaining)
개방 주소법 (Open Addressing)충돌 나면 다른 빈 자리를 찾아 해시주소를 다시 계산해서 옮김선형조사법, 이차조사법, 이중해싱, 재해싱
비유: 체이닝 = 같은 우편함에 편지가 여러 통 오면 묶어서 꽂아두는 것. 개방주소법(선형조사) = 내 우편함이 찼으면 바로 옆 빈 우편함을 찾아 넣는 것.

같은 데이터를 두 방식으로 저장하면 결과가 어떻게 다른지 그림으로 비교해보자. h(k) = k mod 7, 입력 순서는 3, 10, 5, 9, 12이다. (3과 10이 주소 3에서, 5와 12가 주소 5에서 충돌한다)

선형 조사법 계산 연습 📖 기출문제집 p.522

위 그림의 과정을 한 줄씩 적으면 이렇다. h(k) = k mod 7, 충돌 시 주소 +1씩 옮긴다.

  1. 3: 3 % 7 = 3 → [3] 비어 있음 → [3]에 저장
  2. 10: 10 % 7 = 3 → [3]에 3이 있음 충돌! → 3+1 = [4] 비어 있음 → [4]에 저장
  3. 5: 5 % 7 = 5 → [5] 비어 있음 → [5]에 저장
  4. 9: 9 % 7 = 2 → [2] 비어 있음 → [2]에 저장
  5. 12: 12 % 7 = 5 → [5]에 5가 있음 충돌! → 5+1 = [6] 비어 있음 → [6]에 저장
이차 조사법(Quadratic Probing)과의 차이: 선형 조사는 +1, +2, +3…으로 한 칸씩 옮기지만, 이차 조사는 +1², +2², +3² = +1, +4, +9…로 점점 멀리 뛴다. 그리고 새로 계산한 주소도 테이블 크기로 다시 나눠야 한다 — 예를 들어 테이블 크기 7에서 6+1=7이면 7 mod 7 = [0]번으로 돌아간다. 이 "다시 mod 하기"를 빠뜨리는 게 가장 흔한 실수다.

왜 선형조사법이 이차조사법보다 불리한가 — 군집화(clustering)

선형조사는 충돌하면 바로 옆 칸을 쓰므로, 한 지역에 값이 몰리기 시작하면 그 덩어리가 점점 커진다(1차 군집화). 덩어리가 커질수록 그 근처에 해시된 새 값은 덩어리 끝까지 밀려가야 해서 점점 느려진다.

이차조사법은 +1, +4, +9처럼 멀리 흩뿌리므로 이 문제가 완화된다. 더 나아가 이중 해싱은 "얼마나 건너뛸지"를 두 번째 해시 함수로 정해 키마다 다른 간격을 쓴다.

적재율(Load Factor)과 성능

적재율 α = 저장된 데이터 수 ÷ 전체 버킷 수. 테이블이 얼마나 찼는지를 나타내는 값이다.

  • α가 작으면(테이블이 헐렁하면) 충돌이 드물어 O(1)에 가까운 성능
  • α가 1에 가까워지면 충돌이 폭증해 성능이 급격히 나빠진다
  • 개방주소법은 α가 1을 넘을 수 없다(칸보다 데이터가 많을 수 없음). 체이닝은 1을 넘을 수 있다(계속 매달면 되므로)
  • α가 일정 수준(보통 0.7~0.75)을 넘으면 재해싱(rehashing) — 테이블을 더 크게 만들어 전부 다시 저장한다

해싱 성능 요약

  • 충돌이 전혀 없으면 탐색 시간복잡도는 O(1) — 계산 한 번으로 바로 찾음
  • 충돌이 발생한 최악의 경우 시간복잡도는 O(n) — 이때는 이진탐색(O(log n))보다 오히려 느리다
  • 해시 함수 종류: 제산법(나머지), 폴딩법(부분을 나눠 더하거나 XOR), 중간제곱법, 숫자분석법
  • 키 공간(가능한 키의 수)이 저장 공간보다 훨씬 크므로 충돌은 필연적으로 발생한다
  • 삽입·삭제가 빈번해도 유리하다 (위치를 계산으로 알아내므로 데이터를 밀거나 당길 필요가 없음)

📌시험 빈출 포인트

  • 이진탐색은 정렬된 데이터에서만 가능 — "정렬 안 된 데이터"라고 하면 순차탐색만 가능
  • 이진탐색 비교 횟수 계산: n개 데이터면 최대 ⌈log₂n⌉번, 값마다 횟수가 다름(첫 mid가 1회로 가장 빠름)
  • mid 계산 시 내림(floor) 여부를 문제에서 반드시 확인
  • 제산법 해시 충돌 찾기: 두 키를 배열크기로 나눈 나머지가 같으면 충돌
  • 체이닝=연결리스트(폐쇄주소법), 선형조사법=배열 안에서 빈칸 탐색(개방주소법) — 절대 뒤바꾸지 말 것
  • 이차조사법은 +1², +2², +3²로 이동하고 매번 테이블 크기로 다시 mod 해야 함
  • 충돌 없을 때 O(1), 충돌(최악) 있을 때 O(n) — 최악이면 이진탐색보다 느리다
  • 충돌 해결 기법 개수를 세는 문제: 체이닝·선형조사·이차조사·이중해싱·재해싱·오픈어드레싱 모두 해당

문제 12025 법원직 · 기출문제집 p.514

리스트 {10, 11, 15, 23, 30, 58, 70}에서 이진탐색과 순차탐색을 수행하려 한다. 가장 옳은 설명은?

  1. 평균적으로 시간복잡도는 순차탐색이 이진탐색보다 더 작다.
  2. 10을 검색할 때 비교 횟수는 이진탐색 2번, 순차탐색 1번이다.
  3. 정렬이 안 된 리스트에서 순차탐색은 사용 가능하지만, 이진탐색은 사용할 수 없다.
  4. 정렬된 리스트에서 임의의 값을 검색할 때 순차탐색의 평균 시간복잡도는 O(1)이다.

  2. ② 틀림: 10은 맨 앞이므로 순차탐색은 1번이 맞지만, 이진탐색은 mid=23(4번째) → 15(2번째) → 10 순으로 3번 비교해야 한다
  3. ③ 맞음: 이진탐색은 "중간값보다 크면 오른쪽"이라는 판단이 정렬을 전제로 하므로 정렬 안 된 데이터엔 쓸 수 없다. 순차탐색은 조건이 없다
  4. ④ 틀림: 순차탐색은 정렬 여부와 무관하게 평균 O(n)이다 (평균 n/2번 비교)

정리: 이진탐색의 유일한 약점이자 순차탐색의 유일한 강점이 "정렬 필요 여부"다. 이 대비가 문제의 핵심이다.

  4. 12

선택지 각각을 찾아가며 비교 횟수를 세어 보자. 인덱스는 1~9, mid = ⌊(low+high)/2⌋.

문제 42010 계리직 · 기출문제집 p.518

  1. 111, 112
  2. 112, 222
  3. 113, 221
  4. 220, 222
해설 보기

정답 ② 112, 222

제산법이므로 각 키를 11로 나눈 나머지를 구한다. (11 × 10 = 110, 11 × 20 = 220을 기준으로 잡으면 암산이 쉽다)

  1. 111 % 11 = 111 − 110 = 1
  2. 112 % 11 = 112 − 110 = 2
  3. 113 % 11 = 113 − 110 = 3
  4. 220 % 11 = 0 (220 = 11 × 20)
  5. 221 % 11 = 221 − 220 = 1 → 111과 같음 충돌
  6. 222 % 11 = 222 − 220 = 2 → 112와 같음 충돌

충돌 쌍은 (111, 221)과 (112, 222) 두 가지인데, 선택지에 있는 것은 ②뿐이다.

함정: ①(111,112)은 주소가 1과 2로 다르다. 숫자가 비슷하다고 충돌하는 게 아니라 나머지가 같아야 충돌이다.

해설 보기

정답: [0]=6, [1]=20, [2]=9, [3]=16, [6]=2

이차 조사법은 충돌하면 h(k)+1², h(k)+2², h(k)+3² …로 이동하고, 계산한 주소가 테이블 크기를 넘으면 다시 mod 7을 해야 한다.

  1. 9: 9 % 7 = 2 → [2] 비어 있음 → [2] = 9
  2. 16: 16 % 7 = 2 → 충돌 → 2+1²=3 → [3] 비어 있음 → [3] = 16
  3. 2: 2 % 7 = 2 → 충돌 → 2+1²=3 도 충돌(16) → 2+2²=6 → [6] 비어 있음 → [6] = 2
  4. 6: 6 % 7 = 6 → 충돌(2) → 6+1²=7 → 7 mod 7 = 0 → [0] 비어 있음 → [0] = 6
  5. 20: 20 % 7 = 6 → 충돌(2) → 6+1=7→[0] 충돌(6) → 6+4=10 → 10 mod 7 = 3 → 충돌(16) → 6+9=15 → 15 mod 7 = 1 → [1] 비어 있음 → [1] = 20

최대 함정: ④번 단계처럼 7을 넘어가면 mod를 한 번 더 해서 [0]으로 돌아가야 한다. 이걸 놓치고 "자리가 없다"고 판단하면 완전히 다른 답이 나온다. 이차조사법 문제는 매 시도마다 mod를 붙이는 습관이 필요하다.

문제 92018 국가직 · 기출문제집 p.520

해싱(Hashing)에 대한 설명으로 옳지 않은 것은?

  2. 충돌이 발생하지 않는 해시 함수를 사용한다면 해싱의 탐색 시간 복잡도는 O(1)이다.
  3. 선형 조사법(Linear Probing)은 연결리스트(Linked List)를 사용하여 오버플로우 문제를 해결한다.
  4. 폴딩함수는 탐색키를 여러 부분으로 나누어 이들을 더하거나 배타적 논리합을 하여 해시 주소를 얻는다.
해설 보기

정답 ③ — 연결리스트를 쓰는 건 체이닝이다

  1. ③이 틀린 이유: 연결리스트를 사용하는 것은 체이닝(폐쇄 주소법)이다. 선형 조사법은 개방 주소법으로, 배열 안에서 다음 빈 칸을 찾아 옮긴다
  2. ① 맞음: 이것이 바로 충돌의 정의다
  3. ② 맞음: 충돌이 없으면 계산 한 번에 도달하므로 O(1)
  4. ④ 맞음: 폴딩법의 정확한 정의 (부분으로 나눠 합하거나 XOR)

이 함정은 매년 형태만 바꿔 나온다. 정리 한 줄: "체인(사슬)이라는 이름 자체가 연결리스트", 선형·이차·이중해싱은 전부 주소를 다시 계산하는 개방주소법이다.

문제 102021 국가직 · 기출문제집 p.521

해시(Hash)에 대한 설명으로 옳지 않은 것은?

  1. 연결리스트는 체이닝(Chaining) 구현에 적합하다.
  2. 충돌이 전혀 없다면 해시 탐색의 시간 복잡도는 O(1)이다.
  3. 최악의 경우에도 이진 탐색보다 빠른 성능을 보인다.
  4. 해시 함수는 임의의 길이의 데이터를 입력받을 수 있다.

  1. 해싱의 최악은 모든 키가 한 주소로 몰린 경우다. 이때는 그 체인(또는 조사 순서)을 전부 훑어야 하므로 O(n)
  2. 반면 이진탐색은 최악에도 O(log₂n)을 보장한다
  3. O(n) > O(log n)이므로 최악의 경우엔 해싱이 더 느리다 → ③은 틀린 설명
