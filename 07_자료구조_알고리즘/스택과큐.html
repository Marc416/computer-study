스택과 큐

LIFO vs FIFO · 원형 큐 · PART 04. 자료구조론

핵심 요약

스택(Stack) = 후입선출(LIFO) — 넣은 것과 같은 쪽에서 꺼낸다.

큐(Queue) = 선입선출(FIFO) — 넣는 곳(rear)과 꺼내는 곳(front)이 서로 다른 쪽이다.

🎯이 단원을 왜 배우나

"일부러 불편하게 만든" 자료구조가 왜 필요한가

스택과 큐는 배열이나 리스트보다 기능이 적다. 아무 위치나 건드릴 수 있는 배열과 달리, 스택은 맨 위만, 큐는 양 끝만 만질 수 있다. 그런데 이 제약이 곧 장점이다. 접근 지점이 하나로 고정되니 삽입·삭제가 항상 O(1)로 끝나고, 무엇보다 "나중에 한 일을 먼저 되돌린다"(스택), "먼저 온 것을 먼저 처리한다"(큐)는 현실의 규칙을 그대로 표현할 수 있다.

실제로 컴퓨터 안에서 이 둘은 도처에 쓰인다. 함수를 호출하면 복귀 주소가 스택에 쌓이고(그래서 나중에 호출한 함수가 먼저 끝난다), 프린터 대기열과 CPU 스케줄링 대기열은 큐다. Ctrl+Z(실행 취소)는 스택, 웹 서버의 요청 처리 순서는 큐다.

시험에서 이 단원의 최대 배점은 후위표기법(postfix)이다. 우리가 쓰는 2+3*4 같은 수식은 사람에게는 자연스럽지만 컴퓨터에게는 괄호와 우선순위를 계속 따져야 해서 불편하다. 그래서 컴파일러는 이것을 괄호도 우선순위도 필요 없는 후위표기(234*+)로 바꾼 뒤 스택 하나만으로 계산한다. 변환 문제와 계산 문제가 거의 매년 나오므로, 아래 요령을 손으로 익혀두면 확실한 득점원이 된다.

💡주요 개념

스택 (Stack) — LIFO 📖 기출문제집 p.445

스택은 한쪽 끝(top)에서만 삽입(push)과 삭제(pop)가 모두 일어나는 제한된 선형 자료구조다. 마지막에 넣은 것이 가장 먼저 나온다.

비유: 접시를 쌓아놓은 더미. 맨 위 접시부터 집어 쓰고, 새 접시도 맨 위에 올린다 — 바닥 접시는 다 치울 때까지 못 건드린다.

스택의 활용: 함수 호출 시 복귀주소 저장, 재귀(순환) 호출, 인터럽트 복귀주소 관리, 수식 계산(후위표기법), 괄호 짝 검사, 이진트리 순회·깊이우선탐색(DFS)

큐 (Queue) — FIFO 📖 기출문제집 p.467

큐는 삽입은 rear(뒤)에서, 삭제는 front(앞)에서 일어나는 자료구조다. 먼저 줄 선 사람이 먼저 나간다.

비유: 편의점 계산 줄. 뒤로 가서 줄을 서고(rear), 맨 앞사람부터 계산하고 나간다(front).

큐의 활용: 운영체제의 프로세스 스케줄링(대기열), 스풀링(인쇄 대기열), 너비우선탐색(BFS)

원형 큐 (Circular Queue)

배열로 큐를 구현하면 front가 계속 앞으로 이동하면서 배열 앞쪽에 빈 칸이 낭비되는 문제가 생긴다. 원형 큐는 배열의 끝과 처음을 이어붙여(모듈로 연산) 이 낭비를 없앤다.

가득 참 vs 비어있음 구분 함정: 단순 큐에서는 front==rear일 때 "비었다"와 "가득 찼다"를 구분 못 하는 문제가 생긴다. 그래서 원형 큐는 보통 자리 하나를 비워두고 "rear+1 == front(mod n)"이면 가득 찬 것으로 판단한다.

데크 (Deque, Double-Ended Queue)

양쪽 끝에서 삽입과 삭제가 모두 가능한 자료구조다. 스택으로도, 큐로도 쓸 수 있는 만능 형태라고 생각하면 된다.

자료구조삽입 위치삭제 위치한 줄 정리
스택한쪽 끝(top)같은 쪽 끝(top)한쪽에서만 넣고 뺀다 (LIFO)
큐rear (뒤)front (앞)넣는 곳과 빼는 곳이 반대 (FIFO)
데크양쪽 끝 모두양쪽 끝 모두양쪽 어디서든 넣고 뺀다
함정 주의: "데크는 삽입과 삭제를 한쪽 끝에서만 수행한다" → ❌ 틀림(그건 스택). 데크(Double-Ended Queue)는 이름 그대로 양쪽 끝(double-ended)을 다 쓴다. 📖 기출문제집 p.467

🧮후위표기법 (Postfix) — 이 단원 최대 배점

수식을 쓰는 방법은 연산자를 어디에 두느냐에 따라 세 가지다. 피연산자(A, B)의 순서는 세 방식 모두 똑같고, 연산자 위치만 움직인다는 점이 모든 변환 문제의 열쇠다.

표기법연산자 위치A+B의 표현특징
전위(Prefix)피연산자 앞+AB연산자-피연산자-피연산자
중위(Infix)피연산자 사이A+B사람이 쓰는 방식, 괄호·우선순위 필요
후위(Postfix)피연산자 뒤AB+괄호 불필요, 컴퓨터가 스택으로 바로 계산

중위 → 후위 변환: "괄호 치고 연산자를 오른쪽으로 밀어내기"

가장 실수 없는 방법은 ①연산 순서대로 괄호를 전부 친 다음 ②각 괄호의 연산자를 그 괄호의 닫는 쪽으로 옮기고 ③괄호를 지우는 3단계다.

예: A + B * C → ① 우선순위대로 괄호: (A + (B * C)) → ② 연산자를 각 괄호 끝으로: (A (B C *) +) → ③ 괄호 제거: ABC*+

핵심 원칙 두 가지 — ① 피연산자 순서는 절대 안 바뀐다(A B C 그대로), ② 연산자는 계산되는 순서대로 등장한다(먼저 계산할 *가 앞, 나중에 계산할 +가 뒤).

이 두 가지만 알면 선택지를 보고 빠르게 소거할 수 있다. 피연산자 순서가 원본과 다른 선택지는 즉시 탈락이고, 남은 것 중 연산자 순서가 우선순위와 맞는 것을 고르면 된다.

변환 예제: (8 − 2*3) / 2 + 6*3 / 2 를 후위표기로 📖 기출문제집 p.455

  1. 괄호 안의 2*3을 먼저 변환 → 23*
  2. 괄호 안의 8 − (23*) 변환 → 823*−
  3. 그것을 /2 → 823*−2/
  4. 오른쪽 항의 6*3 변환 → 63*
  5. 그것을 /2 → 63*2/
  6. 마지막으로 두 덩어리를 +로 묶기 → 823*−2/63*2/+

후위 → 전위 변환: 연산자를 왼쪽으로 옮기기만 하면 된다

후위식 ABC*D/+E−를 전위로 바꾸려면, 안쪽부터 "피연산자-피연산자-연산자" 묶음을 찾아 연산자를 앞으로 빼내고, 그 묶음을 하나의 피연산자로 취급하며 반복한다.

  1. BC* 발견 → *BC (이제 이 덩어리를 ⓧ라 하자)
  2. ⓧD/ → /ⓧD = /*BCD (덩어리 ⓨ)
  3. Aⓨ+ → +Aⓨ = +A/*BCD (덩어리 ⓩ)
  4. ⓩE− → −ⓩE = −+A/*BCDE

여기서도 피연산자 순서 A B C D E는 끝까지 그대로다. 전위·후위 변환 문제에서 선택지의 알파벳 순서가 뒤바뀐 것들은 전부 오답이다.

후위식 계산: 스택으로 기계처럼 처리하기 📖 기출문제집 p.458

규칙은 딱 두 줄이다 — 숫자를 만나면 스택에 push, 연산자를 만나면 스택에서 2개를 pop해 계산하고 결과를 다시 push. (뺄셈·나눗셈은 먼저 꺼낸 값이 뒤쪽 피연산자라는 점에 주의!)

뺄셈·나눗셈 순서 함정: 9 6 − 에서 pop하면 6이 먼저 나오고 9가 나중에 나온다. 하지만 계산은 나중에 꺼낸 것 − 먼저 꺼낸 것 = 9 − 6 = 3이다. 순서를 뒤집어 6−9=−3으로 계산하는 것이 가장 흔한 실수다.

📌시험 빈출 포인트

  • 스택 = 같은 쪽에서 삽입·삭제(LIFO), 큐 = 다른 쪽에서 삽입·삭제(FIFO)
  • 스택의 대표 활용: 함수 호출 복귀주소, 재귀, DFS — 큐의 대표 활용: 스케줄링, 스풀링, BFS
  • 스택·큐 모두 배열/연결리스트로 둘 다 구현 가능, 삽입·삭제의 시간복잡도는 O(1)
  • 원형 큐를 쓰는 이유: 배열 기반 큐에서 앞쪽 빈 공간 낭비를 없애기 위해
  • 0-주소 명령어(스택 계산) 문제는 CPU와 명령어처리 문서에 계산 예제 있음
  • 중위 → 후위 변환은 거의 매년 출제 — 피연산자 순서는 그대로, 연산자는 계산 순서대로 뒤에 붙는다
  • 후위식 계산은 스택으로: 숫자는 push, 연산자는 2개 pop 후 계산해 다시 push
  • 뺄셈·나눗셈에서 나중에 꺼낸 값이 앞(9 6 − 는 9−6) — 순서 뒤집는 실수 주의
  • 데크(Deque)는 양쪽 끝 모두 삽입·삭제 가능 ("한쪽 끝만"은 스택)
  • "스택으로 구현 불가능한 것" → 은행 대기열·BFS(둘 다 큐)

문제 12017 국회 · 기출문제집 p.455

중위 표기법으로 된 다음 식의 후위 표기법으로 옳은 것은?
(8 − 2*3) / 2 + 6*3 / 2

  1. 823*−2/63*2/+
  2. 23*8−2/63*2/+
  3. 82−3*2/6+3*2/
  4. 823*−2/63*2+/
해설 보기

정답 ① 823*−2/63*2/+

먼저 소거법: 피연산자 순서는 원본과 같아야 한다. 원본 숫자 순서는 8, 2, 3, 2, 6, 3, 2이다. ②번은 23*8로 시작해 순서가 바뀌었으므로 즉시 탈락.

  1. 괄호 안 2*3 → 23*
  2. 8 − (23*) → 823*−
  3. … / 2 → 823*−2/
  4. 6*3 → 63*, 이어서 /2 → 63*2/
  5. 두 덩어리를 +로 결합 → 823*−2/63*2/+

함정: ④번은 마지막 두 연산자가 2+/로 뒤바뀌어 있다. 오른쪽 항은 "(6*3)을 2로 나눈 뒤" 더하는 것이므로 /가 +보다 먼저 와야 한다. 연산자 등장 순서 = 실제 계산 순서임을 이용해 마지막 글자부터 확인하면 빠르다(가장 마지막에 계산되는 연산자가 맨 끝에 온다).

문제 22020 국회 · 기출문제집 p.456

다음 중위 표기법 식의 후위 표기법으로 옳은 것은?
( 7 + 6 / 2 ) / 2 + 9 * 4 / 3

  1. 6/2+7/29*4/3+
  2. 62/7+2/943*/+
  3. 76/2+2/94*3/+
  4. 762/+2/94*3/+
해설 보기

정답 ④ 762/+2/94*3/+

  1. 괄호 안에서 6/2가 먼저 → 62/
  2. 괄호 안 7 + (62/) → 762/+
  3. 괄호 전체를 /2 → 762/+2/
  4. 오른쪽 9*4 → 94*, 이어서 /3 → 94*3/
  5. +로 결합 → 762/+2/94*3/+

함정: ③번(76/2+…)은 괄호 안에서 7과 6을 먼저 묶어버린 오답이다. 괄호 안이라도 *, / 가 +, − 보다 우선이므로 6/2를 먼저 처리해야 한다. 괄호가 있다고 무조건 왼쪽부터 묶으면 안 된다.

문제 32018 서울시 · 기출문제집 p.457

중위 표기법으로 표현된 다음 수식을 후위 표기법으로 옳게 표현한 것은?
a + (b*c − d)*(e − f*g) − h

  1. ab*cd+efg*−*−h
  2. abc*d+ef*g−*−h
  3. abcd+−efg*+*−h−
  4. abc*d−efg*−*+h−
해설 보기

정답 ④ abc*d−efg*−*+h−

괄호가 둘 있으니 각 괄호를 따로 변환한 뒤 조립하는 것이 정석이다.

  1. 첫 괄호 (b*c − d) → bc* 후 −d → bc*d−
  2. 둘째 괄호 (e − f*g) → fg* 후 e− → efg*−
  3. 두 괄호를 *로 곱함 → bc*d− efg*− *
  4. a + 결합 → a bc*d−efg*−* + = abc*d−efg*−*+
  5. 마지막 − h → abc*d−efg*−*+h−

함정: ②번은 첫 괄호를 abc*d+로 써서 −를 +로 잘못 옮겼고, 둘째 괄호도 ef*g−로 곱셈 대상이 뒤바뀌어 있다(f*g를 먼저 묶어야 하는데 e*f를 묶음). 괄호 내부를 하나씩 따로 완성한 뒤 조립하면 이런 실수를 피할 수 있다.

문제 42017 하반기 국가직 · 기출문제집 p.457

다음 후위(postfix) 표기식을 전위(prefix) 표기식으로 바꾼 것은? (단, +, −, *, /는 연산자이고 A, B, C, D, E는 피연산자)
ABC*D/+E−

  1. −+A*/BCDE
  2. −/*+ABCDE
  3. +/*−ABCDE
  4. −+A/*BCDE
해설 보기

정답 ④ −+A/*BCDE

후위식을 안쪽부터 "피연산자-피연산자-연산자" 묶음으로 찾아 연산자를 앞으로 빼내며 진행한다.

  1. BC* → *BC
  2. (*BC) D / → /*BCD
  3. A (/*BCD) + → +A/*BCD
  4. (+A/*BCD) E − → −+A/*BCDE

빠른 확인법: 네 선택지 모두 피연산자 순서가 ABCDE로 같으므로 연산자 배열만 비교하면 된다. 정답의 연산자 순서는 − + A / * — 가장 나중에 계산되는 −가 맨 앞에 오는 것이 전위표기의 특징이다(후위와 정확히 반대).

함정: ①번(−+A*/BCDE)은 *와 /의 순서만 살짝 바뀐 오답이다. BC를 먼저 곱하므로 *가 BC 바로 앞에 붙어야 한다.

문제 52010 계리직 · 기출문제집 p.458

후위 형식으로 표기된 다음 수식을 스택으로 처리할 때, 스택의 탑(TOP) 원소의 값을 올바르게 나열한 것은?
4 5 + 2 3 * −

  1. 4, 5, 2, 3, 6, −1, 3
  2. 4, 5, 9, 2, 3, 6, −3
  3. 4, 5, 9, 2, 18, 3, 16
  4. 4, 5, 9, 2, 3, 6, 3
해설 보기

정답 ④ 4, 5, 9, 2, 3, 6, 3

토큰을 하나씩 처리할 때마다 맨 위 값이 무엇인지 적어나가면 된다.

  1. 4 push → 스택 [4], top = 4
  2. 5 push → [4,5], top = 5
  3. + → 5와 4를 꺼내 4+5=9 push → [9], top = 9
  4. 2 push → [9,2], top = 2
  5. 3 push → [9,2,3], top = 3
  6. * → 3과 2를 꺼내 2*3=6 push → [9,6], top = 6
  7. − → 6과 9를 꺼내 9−6=3 push → [3], top = 3

함정: ②번의 마지막 값 −3은 뺄셈 순서를 뒤집어 6−9로 계산한 오답이다. pop은 6이 먼저 나오지만, 계산은 나중에 꺼낸 9가 앞에 온다. 뺄셈·나눗셈에서 이 순서를 놓치면 부호나 값이 완전히 달라진다.

문제 62019 국가직 · 기출문제집 p.459

다음 전위(prefix) 표기식의 계산 결과는?
+ − 5 4 × 4 7

  1. −19
  2. 7
  3. 28
  4. 29
해설 보기

정답 ④ 29

전위식은 "연산자-피연산자-피연산자" 묶음을 찾아 계산하고, 그 결과를 다시 하나의 피연산자로 취급한다. 오른쪽 끝에서부터 보는 것이 편하다.

  1. 오른쪽 끝의 묶음 × 4 7 → 4 × 7 = 28
  2. 그 앞 묶음 − 5 4 → 5 − 4 = 1
  3. 남은 것은 + (1) (28) → 1 + 28 = 29

함정: ③번 28은 마지막 덧셈을 빠뜨린 값, ②번 7은 −5 4와 ×4 7의 숫자를 잘못 짝지은 경우다. 전위식은 연산자가 앞에 몰려 있어 어느 숫자 둘이 짝인지 헷갈리기 쉬우니, 반드시 오른쪽부터 "연산자+숫자2개" 덩어리를 찾아 지워나가며 풀어라.

문제 72025 국가직 · 기출문제집 p.445

스택을 이용하여 구현할 수 있는 것이 아닌 것은?

  1. 괄호 매칭
  2. 진법 변환
  3. 후위표현 연산
  4. 은행 대기열
해설 보기

정답 ④ 은행 대기열

은행 대기열은 먼저 온 사람이 먼저 처리되는 FIFO이므로 큐(Queue)로 구현한다. 스택으로 만들면 나중에 온 사람이 먼저 처리되는 불합리가 생긴다.

나머지는 모두 "가장 최근 것을 먼저 되돌려야 하는" LIFO 성질을 쓴다:

  • 괄호 매칭: 여는 괄호를 쌓아두고, 닫는 괄호가 나오면 가장 최근에 열린 괄호와 짝을 맞춰야 한다
  • 진법 변환: 나눗셈의 나머지가 나온 순서의 반대로 읽혀야 하므로 스택에 쌓았다 꺼낸다
  • 후위표현 연산: 피연산자를 쌓아두고 연산자를 만나면 맨 위 2개를 꺼내 계산한다

유사 기출: "스택을 사용하는 예로 옳지 않은 것은?" → 정답은 트리의 너비 우선 탐색(BFS). BFS는 큐, DFS는 스택이라는 짝을 반드시 기억할 것.

문제 82018 국가직 · 기출문제집 p.467

자료구조에 대한 설명으로 옳지 않은 것은?

  1. 데크는 삽입과 삭제를 한쪽 끝에서만 수행한다.
  2. 연결리스트로 구현된 스택은 그 크기가 가변적이다.
  3. 배열로 구현된 스택은 구현이 간단하지만 그 크기가 고정적이다.
  4. 원형연결리스트는 한 노드에서 다른 모든 노드로 접근이 가능하다.
해설 보기

정답 ① 데크는 삽입과 삭제를 한쪽 끝에서만 수행한다 (틀린 설명)

데크(Deque = Double-Ended Queue)는 이름 그대로 양쪽 끝 모두에서 삽입·삭제가 가능하다. "한쪽 끝에서만"은 스택의 설명이다.

나머지는 모두 옳다 — ② 연결리스트 기반 스택은 노드를 계속 붙일 수 있어 크기 제한이 없고, ③ 배열 기반 스택은 선언한 크기를 넘을 수 없으며(오버플로 발생), ④ 원형연결리스트는 고리가 닫혀 있어 어디서든 전체 순회가 가능하다.

세 줄 정리: 스택 = 한쪽만 / 큐 = 양쪽인데 넣는 곳·빼는 곳이 각각 고정 / 데크 = 양쪽 모두 자유.
