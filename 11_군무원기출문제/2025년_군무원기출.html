📊2025년 출제 경향

영역별 출제 분포 (총 25문항)

  • 데이터베이스·자료구조 6문항 — 가장 비중이 큰 영역. 특히 자료구조에서 Splay Tree·레드블랙 트리처럼 학부 수준을 넘는 고급 트리가 2문항이나 나왔다.
  • 네트워크·정보보안 5문항 — 게이트웨이, OSI 계층, TCP/IP 계층 같은 기본 암기형이 대부분이라 점수 따기 쉬운 구간.
  • 컴퓨터구조 4문항 — 유니코드, 시스템SW 분류, 인터럽트 우선순위, 부울식 간소화.
  • 운영체제 4문항 — 교착상태 4조건, 디스크 스케줄링, 단편화 등 빈출 주제 그대로.
  • 소프트웨어공학 3문항 — 유지보수 유형, 애자일, 응집도/결합도.
  • 프로그래밍 2문항 — 파이썬 반복문 추적, C 포인터. 코드를 손으로 따라가야 풀린다.
  • 신기술 1문항 — 음성인식 화자 종속/독립.

난이도 특징: 단순 암기보다 "설명이 서로 뒤바뀐 선택지"를 골라내는 유형이 압도적으로 많다(Q16 디스크 스케줄링, Q17 유지보수, Q19 비식별화가 전형적). 개념 이름과 설명을 짝지어 외우는 연습이 그대로 점수가 된다.

💻컴퓨터구조

문제 12025 군무원 · 기출문제집 p.813

유니코드(Unicode)의 설명으로 가장 적절한 것은?

  1. 문자의 저장 공간을 줄이기 위해 8비트 구조로 설계되었으며 저장 효율이 가장 큰 문자 인코딩 방식이다.
  2. 국가별로 독립적인 문자 코드체계를 유지하는 것이 목표이며 코드 충돌을 방지하기 위해 코드페이지를 지역마다 다르게 관리한다.
  3. 미국에서만 사용되는 특수 문자 처리를 위한 방식이며 멀티바이트 언어 표현에는 적합하지 않다.
  4. 아스키 코드의 한계를 극복하기 위해 16비트 이상을 사용해 전 세계 대부분의 문자를 통합적으로 표현하는 통합 문자 체계이다.
해설 보기

정답 ④

유니코드는 언어와 상관없이 모든 문자를 16비트(2바이트) 이상으로 표현하는 통합 코드체계다.

오답 정리

  • ① 8비트로는 256자밖에 못 담는다 → 그건 확장 아스키 얘기. 유니코드는 저장 효율이 좋은 게 아니라 오히려 용량을 더 쓰는 대신 전 세계 문자를 담는 방식이다.
  • ② "국가별 독립 코드체계 + 코드페이지"는 EUC-KR, Shift-JIS 같은 지역 코드의 특징이다. 유니코드는 정확히 그 반대 — 하나의 코드표로 통합하는 게 목적.
  • ③ "미국 전용, 멀티바이트 부적합"은 아스키(ASCII) 설명이다.

문제 52025 군무원 · 기출문제집 p.815

시스템 소프트웨어로 가장 적절하지 않은 것은?

  1. 운영체제(Operating System)
  2. 워드 프로세서(Word Processor)
  3. 부트 로더(Boot Loader)
  4. 장치 드라이버(Device Driver)
해설 보기

정답 ② 워드 프로세서

워드 프로세서는 사용자가 직접 목적을 가지고 쓰는 응용 소프트웨어다.

구분 기준 한 줄: "컴퓨터 자체를 돌아가게 하는가(시스템)" vs "사용자의 일을 처리하는가(응용)". 운영체제·부트로더·장치드라이버는 전부 컴퓨터를 돌아가게 하는 쪽이다. 컴파일러·링커·로더도 시스템 소프트웨어에 포함된다는 점을 함께 기억해 둘 것.

📚 01_컴퓨터구조 · 소프트웨어와 컴퓨터 분류

문제 142025 군무원 · 기출문제집 p.819

인터럽트에 대한 설명으로 가장 적절한 것은?

  1. 여러 장치에서 인터럽트가 발생하는 경우 발생 순서에 따라 처리한다.
  2. 일반적으로 하드웨어 인터럽트보다 소프트웨어 인터럽트의 우선순위가 높다.
  3. 일반적으로 내부 인터럽트보다 외부 인터럽트의 우선순위가 높다.
  4. Daisy Chain 방식은 우선순위 판별을 위한 소프트웨어 방법이다.
해설 보기

정답 ③

오답 정리 — 세 개 모두 "반대로 서술"한 전형적 함정

  • ① 발생 순서가 아니라 우선순위가 높은 것부터 처리한다. (인터럽트는 FIFO가 아니다)
  • ② 거꾸로다. 하드웨어 인터럽트 > 소프트웨어 인터럽트. 전원 이상·기계 고장처럼 급한 건 전부 하드웨어 쪽이기 때문이다.
  • ④ Daisy Chain은 장치를 직렬로 연결해 우선순위를 가리는 하드웨어 방식이다. 소프트웨어 방식은 폴링(polling).

암기: 우선순위는 대체로 "기계가 급한 것 > 사람이 시킨 것" 순 — 전원이상 > 기계착오 > 외부신호 > 입출력 > 명령어오류 > SVC(프로그램 호출).

📚 01_컴퓨터구조 · 명령어와 인터럽트

문제 152025 군무원 · 기출문제집 p.819

부울식 xy + xy' + x'z + x'z' 를 최소화한 결과로 가장 적절한 것은?

  1. x
  2. y
  3. 0
  4. 1
해설 보기

정답 ④ 1

  1. 앞 두 항에서 x를 묶는다: xy + xy' = x(y + y')
  2. 뒤 두 항에서 x'를 묶는다: x'z + x'z' = x'(z + z')
  3. 보원 법칙 A + A' = 1 적용: y + y' = 1, z + z' = 1
  4. 남는 식: x·1 + x'·1 = x + x'
  5. 다시 보원 법칙: x + x' = 1

패턴 인식: 같은 변수로 묶었을 때 (A + A') 꼴이 두 군데서 동시에 보이면 답은 거의 항상 1이다. 카르노맵으로 그리면 모든 칸이 1로 채워지는 상황.

🖥️운영체제

문제 72025 군무원 · 기출문제집 p.815

운영체제의 역할에 대한 설명으로 가장 적절하지 않은 것은?

  1. CPU, 메모리, 입출력 장치 등 하드웨어 자원을 효율적으로 할당하고 배분한다.
  2. 사용자에게 컴퓨터 프로그램을 효율적으로 실행할 수 있는 환경을 제공한다.
  3. 사용자가 작성한 원시 프로그램을 번역하여 시스템에서 실행할 수 있게 한다.
  4. 시스템 오류를 감지하고 처리하여 시스템이 정상적으로 작동하도록 유지한다.
해설 보기

정답 ③

원시 프로그램(소스코드)을 기계어로 번역하는 것은 컴파일러·인터프리터 같은 언어 번역 프로그램의 역할이지 운영체제의 기능이 아니다.

둘 다 "시스템 소프트웨어"라는 큰 우산 안에 있어서 헷갈리기 쉽다. 운영체제는 자원을 나눠주고 관리하는 쪽, 번역기는 코드를 바꿔주는 쪽으로 역할이 완전히 분리되어 있다.

교착 상태가 발생하기 위한 네 가지 필요조건을 나열한 것으로 가장 적절한 것은?

  1. 상호 배제, 비선점, 우선순위 무시, 순환 요청
  2. 상호 배제, 점유와 대기, 비선점, 환형 대기
  3. 점유와 대기, 자원 분할, 우선순위 할당, 순환 대기
  4. 공유 자원, 동시 접근, 비선점, 병렬 대기
해설 보기

정답 ② 상호 배제, 점유와 대기, 비선점, 환형 대기

교착상태 4대 필요조건은 고정된 세트라 통째로 외워야 한다. 네 개가 전부 성립할 때만 교착상태가 생기므로, 반대로 하나만 깨면 예방된다.

조건뜻
상호 배제 (Mutual Exclusion)한 자원은 한 번에 한 프로세스만
점유와 대기 (Hold & Wait)자원을 쥔 채로 다른 자원을 기다림
비선점 (No Preemption)남이 쥔 자원을 강제로 뺏을 수 없음
환형 대기 (Circular Wait)대기 관계가 원형으로 이어짐

함정: "우선순위 무시", "자원 분할", "동시 접근" 같이 그럴듯하지만 목록에 없는 단어가 하나라도 섞여 있으면 그 선택지는 오답이다. ①③④ 모두 그 방식으로 걸러진다.

📚 02_운영체제 · 임계영역과 교착상태

문제 162025 군무원 · 기출문제집 p.819

디스크 스케줄링 기법에 대한 설명으로 가장 적절한 것은?

  1. FCFS 스케줄링은 탐색 시간을 최소화하기 위해 항상 현재 헤드 위치에서 가장 가까운 요청을 먼저 처리하는 방식으로 응답 시간의 편차를 줄이기 위한 목적에 최적화되어 있다.
  2. SSTF 스케줄링은 디스크 헤드를 일정 방향으로 왕복시키며 모든 요청을 순차적으로 처리하는 방식이며 헤드가 끝에 도달하면 반대 방향으로 전환한다.
  3. SCAN 스케줄링은 응답 시간의 공정성을 보장하지 않으며 서비스 요청의 우선순위와 무관하게 헤드가 도착한 순서에 따라 FIFO로 처리한다.
  4. N-단계 SCAN 스케줄링은 요청 큐를 일정 단위로 나누어 처리하므로 과도한 요청이 발생하더라도 각 단계별로 제한된 요청만 처리함으로써 응답 지연을 완화하고 스케줄링의 예측 가능성을 향상시킨다.
해설 보기

정답 ④

①②③이 서로 설명을 바꿔 쓴 것임을 알아채는 게 핵심이다. 원래 짝은 이렇다:

기법진짜 설명
FCFS요청이 도착한 순서대로 FIFO 처리 (→ ③번이 서술한 내용)
SSTF현재 헤드에서 가장 가까운 요청 우선. 빠르지만 응답시간 편차가 크고 기아 발생 (→ ①번이 서술한 내용, 단 "편차를 줄인다"는 부분은 거짓)
SCAN헤드를 한 방향으로 훑고 끝에서 반대로 전환 (엘리베이터 방식) (→ ②번이 서술한 내용)
N-단계 SCAN큐를 N개 단위로 끊어 그 안의 요청만 처리 → 늦게 온 요청이 새치기 못 하므로 예측 가능성↑

풀이 요령: 이런 "설명 뒤섞기" 문제는 선택지마다 기법 이름을 지우고 설명만 읽은 뒤 어느 기법인지 스스로 이름 붙여보면 빠르게 걸러진다.

📚 02_운영체제 · 디스크 스케줄링과 할당기법

문제 252025 군무원 · 기출문제집 p.823

운영체제의 단편화(Fragmentation) 문제에 대한 설명으로 가장 적절한 것은?

  1. 단편화는 문맥 교환 속도를 높이기 위해 의도적으로 발생시키는 메모리 최적화 전략이며 이를 방지하기 위해 페이지 크기를 줄이는 것이 효과적이다.
  2. 내부 단편화는 주기억장치 전체가 비어 있음에도 불구하고 외부 단편화가 해결되지 않아 프로세스가 적재되지 못하는 현상을 의미한다.
  3. 단편화는 주기억장치에서 사용되지 않는 비연속적인 작은 조각들이 생기는 현상이며, 인접한 자유 공간을 하나로 합치는 통합(Coalescing) 기법이나 데이터를 재배치해 연속 공간을 확보하는 압축(Compaction) 기법으로 해결한다.
  4. 단편화를 해결하기 위해 가장 일반적으로 사용하는 방법은 고정된 위치에만 프로세스를 할당하여 주소 공간의 이동을 최소화하는 방식이며 이는 동적 메모리 할당보다 유연성이 높다.
해설 보기

정답 ③

오답 정리

  • ① 단편화는 의도적 전략이 아니라 할당·해제가 반복되며 자연히 생기는 부작용이다.
  • ② 설명 자체는 외부 단편화 이야기인데 이름만 "내부 단편화"로 바꿔놓은 함정. 내부 단편화 = 고정 크기 블록에 프로세스를 넣고 남는 자투리, 외부 단편화 = 빈 공간은 충분한데 흩어져 있어 못 쓰는 상태.
  • ④ 고정 할당은 오히려 내부 단편화를 키우고 유연성도 낮다. 일반적 해법은 동적 할당이다.

문제 42025 군무원 · 기출문제집 p.814

프로토콜 구조가 다른 네트워크 환경들을 연결할 수 있는 기능을 제공하고 여러 계층의 프로토콜 변환 기능을 수행하는 장비로 가장 적절한 것은?

정답 ② 가짜 튜플(Spurious Tuple)

릴레이션을 잘못 분해한 뒤 자연 조인으로 복원하면, 원본에 없던 엉뚱한 행이 생겨난다. 이것이 가짜 튜플이다.

기출문제집의 예를 보면, 학번 2021이 IT31·IT32를, 학점 B+·A0을 각각 갖고 있을 때 조인하면 (2021, IT31, B+), (2021, IT31, A0), (2021, IT32, B+), (2021, IT32, A0) 네 행이 생긴다 — 실제로는 없던 조합 2개가 끼어든 것이다.

함정: ①③④는 전부 정규화를 안 했을 때(분해 전에) 생기는 이상현상이다. 이 문제는 "분해 후 다시 조인했을 때"를 묻고 있으므로 성격이 다르다.

레드-블랙 트리도 결국 이진 탐색 트리다. BST에서는 "루트에서 시작해 키가 작으면 왼쪽, 크면 오른쪽"이라는 규칙 때문에 어떤 키에 대해서든 탐색 경로가 단 하나로 정해진다. 따라서 "여러 경로로 삽입·삭제 가능"은 성립할 수 없다.

  • ④ 레드-블랙 트리는 2-3-4 트리와 일대일 대응된다(빨간 노드 = 부모와 같은 묶음에 속한 키). 이것이 레드-블랙 트리 설계의 출발점이다.

소프트웨어 구현 시 응집도(Cohesion)와 결합도(Coupling)의 설명으로 가장 적절한 것은?

  1. 모듈 내의 응집도는 최대화되어야 하며 모듈 간의 결합도는 최소화되어야 한다.
  2. 모듈 내의 응집도는 최대화되어야 하며 모듈 간의 결합도 또한 최대화되어야 한다.
  3. 모듈 내의 응집도는 최소화되어야 하며 모듈 간의 결합도는 최대화되어야 한다.
  4. 모듈 내의 응집도는 최소화되어야 하며 모듈 간의 결합도 또한 최소화되어야 한다.
해설 보기

정답 ① 응집도 ↑, 결합도 ↓

좋은 모듈 설계의 제1원칙이다. 이유를 알면 절대 헷갈리지 않는다.

  • 응집도(모듈 안쪽)는 "한 모듈이 한 가지 일에만 집중하는 정도" → 높을수록 모듈이 명확해지니 최대화.
  • 결합도(모듈 사이)는 "다른 모듈에 얼마나 얽매여 있는가" → 낮을수록 하나를 고쳐도 남에게 영향이 없으니 최소화.

한 문장 암기: "안은 끈끈하게(응집도↑), 밖은 느슨하게(결합도↓)"

다음 파이썬 프로그램의 실행 결과로 가장 적절한 것은?

a = 0
b = 0
c = 0

for a in range(1, 20, 3):
    b += a
    c += b
    if b > 15:
        break
print("Result: ", c)
  1. Result: 40
  2. Result: 51
  3. Result: 70
  4. Result: 75
해설 보기

정답 ① Result: 40

range(1, 20, 3) → 1부터 20 미만까지 3씩 증가: 1, 4, 7, 10, 13, 16, 19. 표를 그려 한 회차씩 추적하면 실수하지 않는다.

회차ab (누적합)c (b의 누적)b > 15 ?
1111아니오
2456아니오
371218아니오
4102240예 → break
  1. c에 더하는 것은 a가 아니라 b(누적합)라는 점에 주의
  2. break는 c += b 다음에 실행되므로, 4회차의 c=40까지는 반영된다
  3. 따라서 출력은 40

함정: break를 "조건을 만족한 회차는 빼고" 빠져나가는 것으로 착각하면 18(3회차까지)이 나온다. break 문이 코드의 몇 번째 줄에 있는지를 반드시 확인할 것.

문제 212025 군무원 · 기출문제집 p.822

다음 C 프로그램의 실행 결과로 가장 적절한 것은?

#include <stdio.h>
int main()
{
    int *ptr, x = 9;
    ptr = &x;
    *ptr += 1;
    printf("%d, %d\n", *ptr, x);
}
  1. 9, 9
  2. 9, 10
  3. 10, 9
  4. 10, 10
해설 보기

정답 ④ 10, 10

  1. ptr = &x; → ptr에 x의 주소를 저장. 이제 ptr은 x를 가리킨다.
  2. *ptr += 1; → *ptr은 "ptr이 가리키는 곳의 값" = x 그 자체. 따라서 x가 9 → 10이 된다.
  3. *ptr과 x는 같은 메모리 한 칸을 서로 다른 이름으로 읽는 것이므로 둘 다 10.

핵심: 포인터를 통해 값을 바꾸면 원본 변수가 실제로 바뀐다. 이것이 C에서 함수가 호출자의 변수를 수정할 수 있는 원리(참조에 의한 전달 흉내)이기도 하다.

함정: ③(10, 9)은 "*ptr만 바뀌고 x는 그대로"라고 착각한 경우다. 둘은 복사본이 아니라 같은 실체다.
