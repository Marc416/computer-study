💻컴퓨터구조

문제 62023 군무원 · 기출문제집 p.836

다음 부울 함수를 간소화한 결과로 옳은 것은?

f(x, y, z) = xyz + xy'z + x'yz + x'yz'
  1. xy + yz
  2. xz + y'z
  3. xy + y'z
  4. x'y + xz
해설 보기

정답 ④ x'y + xz

공통 인수로 묶어 A + A' = 1을 만드는 것이 핵심이다. 어떻게 묶을지는 앞의 두 항, 뒤의 두 항을 각각 살펴보면 보인다.

  1. 앞 두 항 xyz + xy'z — 공통으로 xz가 들어 있다 → xz(y + y')
  2. 뒤 두 항 x'yz + x'yz' — 공통으로 x'y가 들어 있다 → x'y(z + z')
  3. 보원 법칙 적용: y + y' = 1, z + z' = 1
  4. 결과: xz·1 + x'y·1 = xz + x'y → 선택지 ④와 같다

검산법: 자신 없으면 x, y, z에 값을 몇 개 넣어 원식과 답이 같은지 확인한다.
예: x=1, y=0, z=1 → 원식 = 1·0·1 + 1·1·1 + 0·0·1 + 0·0·0 = 1, 답 xz + x'y = 1·1 + 0·0 = 1 ✓
예: x=0, y=1, z=0 → 원식 = 0 + 0 + 0 + 1·1·1 = 1, 답 = 0 + 1·1 = 1 ✓

묶는 요령: 항이 4개면 대개 2개씩 짝을 지어 묶인다. 서로 한 변수만 다른(나머지는 같은) 항을 찾아 짝지으면 그 변수가 소거된다.

문제 72023 군무원 · 기출문제집 p.837

레지스터에 대한 설명으로 옳지 않은 것은?

  1. MBR(Memory Buffer Register)은 메모리의 내용을 임시로 기억한다.
  2. Index Register는 명령어 실행 중 절대 주소를 결정한다.
  3. MAR(Memory Address Register)은 메모리의 주소를 임시로 기억한다.
  4. PC(Program Counter)는 다음에 실행될 명령어의 주소를 기억한다.
해설 보기

정답 ②

인덱스 레지스터가 담는 것은 절대 주소가 아니라 "기준 주소로부터 얼마나 떨어져 있는가"(변위, offset)다.

왜 이런 게 필요한가: 배열 arr[0], arr[1], arr[2]...를 차례로 접근한다고 하자. 매번 명령어를 새로 만들 수는 없으니, 기준 주소(배열 시작점)는 고정해두고 인덱스 레지스터 값만 0, 1, 2로 바꿔가며 같은 명령어를 반복 실행한다. 반복문이 배열을 훑는 원리가 바로 이것이다.

유효주소 = 기준 주소 + 인덱스 레지스터 값 — 즉 인덱스 레지스터는 절대 주소를 "결정"하는 게 아니라 계산에 쓰이는 한 조각일 뿐이다.

나머지가 참인 이유: ① MBR은 메모리와 주고받는 데이터를 임시 보관 ✓ ③ MAR은 접근할 주소를 보관 ✓ ④ PC는 다음 명령어 주소를 보관 ✓

📚 01_컴퓨터구조 · 컴퓨터 시스템 개요

문제 132023 군무원 · 기출문제집 p.839

펌웨어(firmware)에 대한 설명으로 가장 적절하지 않은 것은?

  1. 전형적인 처리 루틴 등에 많이 사용된다.
  2. 시스템의 효율을 높이기 위해 RAM에 저장되어 관리된다.
  3. Basic Input/Output System이 펌웨어의 일종이다.
  4. 소프트웨어를 하드웨어화한 것으로 소프트웨어와 하드웨어의 중간에 해당한다.
해설 보기

정답 ② (RAM이 아니라 ROM에 저장된다)

펌웨어는 ROM에 저장되는 하드웨어 제어용 마이크로프로그램이다. RAM은 전원이 꺼지면 날아가므로(휘발성), 전원을 켜자마자 실행되어야 하는 펌웨어를 담을 수 없다.

BIOS가 왜 대표적 펌웨어인가: 컴퓨터 전원을 켜면 아직 운영체제가 메모리에 올라오기 전이다. 이때 하드웨어를 점검하고(POST) OS를 불러올 프로그램이 필요한데, 그게 BIOS다. 전원이 꺼져도 살아 있어야 하므로 반드시 ROM(비휘발성)에 있어야 한다.

펌웨어의 정체성: "소프트웨어인데 하드웨어에 심어져 있는 것" — 그래서 소프트웨어와 하드웨어의 중간(middleware)이라고도 부른다 (④가 참인 이유).

주의: 부팅 과정에서 "BIOS 정보를 RAM에 복사한다(섀도잉)"는 단계가 있긴 하다. 하지만 펌웨어가 원래 저장되어 있는 곳을 묻는다면 답은 ROM이다.

📚 01_컴퓨터구조 · 마이크로오퍼레이션과 기억장치

문제 202023 군무원 · 기출문제집 p.844

DRAM과 SRAM에 대한 설명 중 가장 적절하지 않은 것은?

  1. DRAM은 주기억장치로, SRAM은 캐시메모리로 각각 사용된다.
  2. 동일한 크기인 경우 DRAM이 SRAM에 비해 비싸다.
  3. 메모리 읽기/쓰기 속도가 DRAM이 SRAM에 비해 느리다.
  4. 단위면적당 기억소자 집적도가 DRAM이 SRAM에 비해 매우 높다.
해설 보기

정답 ② (DRAM이 아니라 SRAM이 비싸다)

모든 차이가 "저장 소자"에서 갈린다. 이 하나만 기억하면 나머지는 전부 유도된다.

  • SRAM = 플립플롭(트랜지스터 6개쯤)으로 1비트 저장 → 부품이 많이 드니 비싸고(②), 집적도 낮고(④), 대신 빠르다(③)
  • DRAM = 커패시터(축전기) 1개로 1비트 저장 → 부품이 적으니 싸고 빽빽하게 넣을 수 있지만, 전하가 새기 때문에 주기적으로 재충전(refresh)해야 해서 느리다

따라서 비싸고 빠른 SRAM은 작게 쓰는 캐시에, 싸고 느린 DRAM은 크게 써야 하는 주기억장치에 배치한다(①이 참인 이유).

공통점(자주 나오는 함정): SRAM도 DRAM도 둘 다 휘발성이다. "SRAM은 재충전이 필요 없으니 비휘발성"이라는 선택지가 자주 나오는데 틀렸다 — 전원이 끊기면 둘 다 날아간다.

📚 01_컴퓨터구조 · 캐시 기억장치

🖥️운영체제

문제 142023 군무원 · 기출문제집 p.839

가상기억장치(virtual memory)의 특징으로 가장 적절하지 않은 것은?

  1. 가상기억장치의 목적은 처리 속도의 향상에 있다.
  2. 가상기억장치로 사용하는 보조기억장치는 보통 디스크를 사용한다.
  3. 주소 매핑은 가상 주소를 실기억 주소로 조정하여 변환하는 것이다.
  4. 가상기억장치 관리 기법으로 페이징 기법과 세그먼트 기법이 있다.
해설 보기

정답 ①

가상기억장치의 목적은 속도가 아니라 "공간"이다 — 실제 RAM보다 큰 프로그램도 실행할 수 있게 하고, 더 많은 프로그램을 동시에 올려 다중 프로그래밍 정도를 높이는 것이 목적이다.

오히려 속도는 느려진다. 필요한 페이지가 RAM에 없으면(페이지 부재) 디스크까지 가서 가져와야 하는데, 디스크는 RAM보다 수만 배 느리다. 즉 가상메모리는 "속도를 조금 희생해서 공간을 크게 얻는" 거래다.

시험에서의 정확한 표현: "프로세서 이용률과 처리율(throughput)은 향상되지만, 응답시간·반환시간은 향상되지 않는다." 이 문장을 그대로 외워두면 관련 문제를 전부 처리할 수 있다.

극단적 사례: 페이지 교체가 너무 잦아져 CPU가 일은 안 하고 디스크 입출력만 계속하는 상태를 스래싱(thrashing)이라 한다. 가상메모리가 속도를 올려준다면 존재할 수 없는 현상이다.

"핵심(kernel = 알맹이)" + "메모리에 상주" + "자원 관리" 세 키워드가 전부 커널을 가리킨다.

문제 32023 군무원 · 기출문제집 p.835

OSI 참조 모델의 각 계층과 이에 해당하는 프로토콜의 연결이 옳지 않은 것은?

  1. 네트워크 계층 — IP
  2. 데이터 링크 계층 — UDP
  3. 전송 계층 — TCP
  4. 응용 계층 — FTP
해설 보기

정답 ② (UDP는 데이터 링크 계층이 아니라 전송 계층)

  2. 브리지(Bridge)
  3. 라우터(Router)
  4. 더미허브(Dummy Hub)
해설 보기

정답 ② 브리지(Bridge)

핵심 단서는 "차단하여 효율을 높인다"(필터링)이다. 브리지는 MAC 주소를 보고 "이 프레임은 같은 쪽에 있는 컴퓨터끼리 주고받는 거네" 하고 판단해서 반대편으로 넘기지 않는다. 덕분에 불필요한 트래픽이 줄고 충돌 도메인이 분리된다.

오답 정리

  • ① 리피터(1계층)는 신호를 증폭만 한다. 내용을 볼 줄 모르니 필터링 불가.
  • ④ 더미허브(1계층)는 들어온 신호를 모든 포트로 그냥 뿌린다(브로드캐스트). 오히려 트래픽이 늘어난다.

판별 요령: "MAC 주소·LAN 연결·필터링" → 브리지/스위치(2계층), "IP 주소·경로 선택·다른 네트워크" → 라우터(3계층), "신호 증폭" → 리피터(1계층).

(1) 점 대 점(Point-to-Point) 간 신뢰 통신을 보장하는 프로토콜 계층과, (2) 종단(End-to-End) 간 신뢰 통신을 보장하는 프로토콜 계층으로 가장 적절한 것은?

  1. (1) 물리 계층  /  (2) 링크 계층
  2. (1) 링크 계층  /  (2) 전송 계층
  3. (1) 네트워크 계층  /  (2) 전송 계층
  4. (1) 응용 계층  /  (2) 링크 계층
해설 보기

정답 ② (1) 데이터링크 계층 / (2) 전송 계층

"점 대 점"과 "종단 간"이 무엇을 뜻하는지가 문제의 전부다.

  • Point-to-Point(점 대 점) = 바로 옆에 붙어 있는 두 장비 사이 한 구간. 내 PC ↔ 공유기, 공유기 ↔ 통신사 라우터 같은 한 홉(hop)씩을 말한다. 이 구간의 오류 검출·재전송을 책임지는 것이 데이터링크 계층이다.
  • End-to-End(종단 간) = 최초 출발지 ↔ 최종 목적지 전체. 중간에 라우터가 몇 개를 거치든 상관없이 "내 PC에서 보낸 데이터가 저쪽 서버에 온전히 도착했는가"를 책임지는 것이 전송 계층(TCP)이다.

비유: 택배가 물류센터에서 물류센터로 넘어갈 때마다 파손 여부를 확인하는 것이 데이터링크(점 대 점), 보낸 사람과 받는 사람이 최종적으로 물건이 다 왔는지 확인하는 것이 전송 계층(종단 간)이다.

이렇게 이해하면 ①④처럼 물리 계층이나 응용 계층이 답이 될 수 없는 이유도 자연스럽게 정리된다.

단계정렬된 부분정렬 안 된 부분한 일
초기76 3 9 4첫 원소는 그 자체로 정렬된 것으로 본다

문제 152023 군무원 · 기출문제집 p.840 · 난이도 상

다음 Java 프로그램의 실행 결과로 옳은 것은?

int[] arr1 = new int[6];
int[] arr2 = new int[6];
int var1 = 1, var2 = 1;

for (int i = 0; i < arr1.length; i++) { arr1[i] = var1; var1 *= 2; }
for (int i = 0; i < arr2.length; i++) { arr2[i] = var2; var2 *= 4; }

// list1 ← arr1, list2 ← arr2 로 변환
list3.addAll(list1);
list3.addAll(list2);
Collections.sort(list3);

// list4 : list3에서 중복을 제거한 리스트
for (Integer num : list3) {
    if (!list4.contains(num)) { list4.add(num); }
}

System.out.print("Result1: " + (list3.size() + list4.size()) +
                 ", Result2: " + (list4.get(2) + list4.get(4)));
  1. Result1: 20, Result2: 24
  2. Result1: 21, Result2: 20
  3. Result1: 21, Result2: 24
  4. Result1: 20, Result2: 20
해설 보기

정답 ② Result1: 21, Result2: 20

코드가 길어 보이지만 배열 두 개를 만들고, 합치고, 중복 제거하는 것이 전부다. 순서대로 값을 적어나가면 된다.

  1. arr1 만들기 — 1에서 시작해 2배씩, 6개: 1, 2, 4, 8, 16, 32
  2. arr2 만들기 — 1에서 시작해 4배씩, 6개: 1, 4, 16, 64, 256, 1024
  3. list3 = 둘을 합쳐 정렬 (12개, 중복 포함):
    1, 1, 2, 4, 4, 8, 16, 16, 32, 64, 256, 1024
    → list3.size() = 12
  4. list4 = 중복 제거 (1, 4, 16이 각각 두 번씩 있었으므로 3개 감소):
    1, 2, 4, 8, 16, 32, 64, 256, 1024
    → list4.size() = 9
  5. Result1 = 12 + 9 = 21
  6. Result2 = list4.get(2) + list4.get(4) — 인덱스는 0부터이므로 get(2)는 세 번째 원소 = 4, get(4)는 다섯 번째 원소 = 16 → 4 + 16 = 20

index 0-based 함정: 오답 ①③의 Result2 = 24는 get(2)=8, get(4)=32로 인덱스를 1부터 센 경우다(세 번째를 8로, 다섯 번째를 32로 착각). 자바·C·파이썬 모두 인덱스는 0부터라는 것을 손으로 번호를 매겨가며 확인해야 한다.

인덱스012345678
list412481632642561024

겹치는 값 찾기 요령: 2의 거듭제곱(1,2,4,8,16,32)과 4의 거듭제곱(1,4,16,64,…)은 4의 거듭제곱이 곧 2의 짝수 제곱이므로 1, 4, 16이 공통이다. 32 이하에서만 겹친다는 점을 알면 빠르게 셀 수 있다.

문제 162023 군무원 · 기출문제집 p.841~842 · 난이도 상

다음 C 프로그램의 실행 결과를 올바른 순서대로 나타낸 것은?

#include <string.h>
#include <stdio.h>

int main() {
    char list[] = "22QPP1";
    const char *pa, *pb;
    char *pc, *pd;

    pa = &list[1];
    list[2] = 'K';
    pb = &list[3];
    pc = list;

    pd = strstr(pa, pb);
    printf("pd : %s\n", pd);

    if (pd != 0) {
        strncpy(pd, "77", 3);
        printf("pc : %s\n", pc);
    }
    printf("pb : %s\n", pb);
}
  1. pd : 2K  /  pc : 22K771  /  pb : 771
  2. pd : 2K  /  pc : 22K77  /  pb : 77
  3. pd : PP1  /  pc : 22K77  /  pb : 77
  4. pd : PP1  /  pc : 22K771  /  pb : 771
해설 보기

정답 ③ pd : PP1 / pc : 22K77 / pb : 77

배열 칸에 번호를 붙여 그림을 그려가며 따라가는 것이 유일한 정공법이다.

  1. 초기 상태 — char list[] = "22QPP1";
    인덱스0123456
    값22QPP1\0
  2. pa = &list[1]; → pa는 인덱스 1을 가리킴 → 문자열로 읽으면 "2QPP1"
  3. list[2] = 'K'; → 배열이 "22KPP1"로 바뀜. (pa가 가리키는 내용도 자동으로 "2KPP1"로 바뀐다 — 같은 배열을 보고 있으므로)
  4. pb = &list[3]; → 인덱스 3부터 → "PP1"
    pc = list; → 인덱스 0부터 → "22KPP1"
  5. pd = strstr(pa, pb) — pa("2KPP1") 안에서 pb("PP1")를 찾는다. 찾으면 그 위치의 포인터를 반환 → 인덱스 3 위치 → pd = &list[3]
    👉 첫 출력: pd : PP1 (①② 탈락)
  6. strncpy(pd, "77", 3) — pd 위치부터 3바이트를 복사한다. "77"은 '7','7','\0' 세 글자이므로 인덱스 3,4,5가 각각 7, 7, \0으로 덮인다
    인덱스0123456
    값22K77\0\0
  7. pc 출력 — 인덱스 0부터 \0을 만날 때까지 읽으면 2, 2, K, 7, 7 → pc : 22K77 (④ 탈락)
  8. pb 출력 — 인덱스 3부터 \0까지 → 7, 7 → pb : 77

이 문제의 두 가지 핵심

  • 포인터는 값을 복사하지 않고 "같은 배열의 어느 칸"을 가리킬 뿐이다. 그래서 배열을 한 번 고치면 그 칸을 보던 모든 포인터의 출력이 함께 바뀐다.
  • C 문자열은 \0(널 문자)을 만나면 끝난다. strncpy가 3바이트를 복사하며 \0까지 같이 써버렸기 때문에, 뒤에 남아 있던 '1'은 지워진 게 아니라 널 문자에 가려 보이지 않게 된 것이다. 이 차이를 아는지가 ③과 ④를 가른다.
