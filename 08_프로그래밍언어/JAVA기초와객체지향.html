JAVA 기초와 객체지향

JVM 구조 · 접근제어자 · 오버로딩/오버라이딩 · 예외처리 · PART 07. 프로그래밍언어론

핵심 요약

Java는 JVM(가상머신) 위에서 돌아가기 때문에 OS 종류와 상관없이 같은 파일을 실행할 수 있다 (Write Once, Run Anywhere).

오버로딩=같은 이름, 다른 매개변수(한 클래스 안). 오버라이딩=상속 관계에서 부모 메소드를 자식이 재정의.

💡주요 개념

JVM(Java Virtual Machine)은 왜 필요한가 📖 기출문제집 p.674

C언어는 컴파일하면 그 OS 전용 기계어(.exe 등)가 나와서 다른 OS에서는 못 돌린다. Java는 이 문제를 "한 단계 우회"해서 해결한다 — OS가 아니라 가상의 컴퓨터(JVM)를 대상으로 컴파일하는 것이다.

함정 주의: "Java는 컴파일 과정 없이 바로 실행된다" → ❌ 틀림. 컴파일(javac)로 바이트코드를 만든 뒤, JVM이 이를 인터프리터 방식으로 실행한다 — 컴파일+인터프리터가 섞인 하이브리드 구조.

접근 제어자 (Access Modifier) 📖 기출문제집 p.772~773

제어자같은 클래스같은 패키지자식 클래스(다른 패키지)전체
privateOXXX
default (생략)OOXX
protectedOOOX
publicOOOO

예제로 확인하기: A1(x=public, y=private, z=protected) → A2 extends A1(a=protected, b=private) → A3 extends A2(q=private)

  1. A3 자신의 private q는 자기 클래스 안이므로 접근 가능
  2. x(public)는 어디서든 접근 가능 → 접근 가능
  3. z(protected, A1 소유)는 자식 클래스 A3까지 상속되어 접근 가능
  4. a(protected, A2 소유)도 마찬가지로 자식인 A3에서 접근 가능
  5. y(private, A1 소유)는 A1 내부에서만 유효 → A3에서 접근 불가
  6. b(private, A2 소유)도 A2 내부에서만 유효 → A3에서 접근 불가
  7. 결론: A3에서 쓸 수 있는 변수 = x, z, a, q

오버로딩(Overloading) vs 오버라이딩(Overriding) 📖 기출문제집 p.771

구분오버로딩오버라이딩
관계상속 관계 필요 없음 (한 클래스 안)상속 관계 필요 (부모-자식)
메소드 이름같음같음
매개변수달라야 함(개수/타입)같아야 함
목적같은 동작을 여러 자료형으로 제공부모 동작을 자식이 새로 정의
오버로딩 예제: add(int a, int b)와 add(double a, double b)가 한 클래스에 같이 있으면, add(5.7, 9.8) 호출 시 인자가 실수이므로 double 버전이 자동으로 선택된다 — "매개변수의 타입과 개수로 어떤 메소드를 쓸지 컴파일러가 결정"하는 것이 오버로딩의 핵심.

예외 처리 (Exception Handling) 📖 기출문제집 p.787

배열 범위를 벗어나거나 0으로 나누는 등 실행 중 발생하는 오류를 예외(Exception)라 하고, try-catch-finally로 잡아서 처리한다.

블록역할
try예외가 발생할 수 있는 코드를 넣는 곳
catch지정한 종류의 예외가 발생했을 때만 실행
finally예외 발생 여부와 무관하게 항상 실행
계산 예제: a=3, b=0일 때 result = a/b를 try 안에서 실행 → 출력 순서는? 📖 기출문제집 p.787
  1. try 블록 진입, a/b 계산 시도 → 0으로 나누기라서 ArithmeticException 발생
  2. 예외가 발생했으므로 try 블록의 나머지(print("A"))는 실행되지 않고 바로 catch로 이동
  3. catch 블록 실행 → print("B")
  4. finally 블록은 무조건 실행 → print("C")
  5. try-catch-finally 이후 코드 실행 → print("D")
  6. 최종 출력: BCD (A는 출력되지 않음에 주의)

📌시험 빈출 포인트

  • Java는 컴파일(bytecode 생성) + JVM 인터프리터 실행이 결합된 하이브리드 방식
  • 접근제어자 범위: private < default < protected < public
  • protected는 다른 패키지의 자식 클래스에서도 접근 가능하다는 점 (default와 헷갈림 주의)
  • 오버로딩=매개변수로 구분(상속 불필요), 오버라이딩=상속관계에서 시그니처 동일하게 재정의
  • 메소드 오버로딩 시 실제 호출되는 버전은 전달 인자의 타입/개수로 결정
  • try 블록에서 예외 발생 시 그 지점 이후 try 블록 코드는 건너뛰고 catch로 즉시 이동
  • finally는 예외 발생 여부와 무관하게 항상 실행 (return이 있어도 실행됨)
  • 필드 name이 private인데 외부 클래스에서 a.name = "값"처럼 직접 접근하면 컴파일 오류
