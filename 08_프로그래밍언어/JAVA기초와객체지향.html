JAVA 기초와 객체지향

JVM 구조 · 접근제어자 · 오버로딩/오버라이딩 · 동적 바인딩 · 생성자 · 예외처리 · PART 07. 프로그래밍언어론

핵심 요약

Java는 JVM(가상머신) 위에서 돌아가기 때문에 OS 종류와 상관없이 같은 파일을 실행할 수 있다 (Write Once, Run Anywhere).

오버로딩=같은 이름, 다른 매개변수(한 클래스 안). 오버라이딩=상속 관계에서 부모 메소드를 자식이 재정의.

출력 문제의 90%는 "어느 클래스의 것이 실행되는가"를 묻는다 — 메소드는 실제 객체, 필드·static은 참조 타입 기준이다.

🎯이 단원을 왜 배우나

Java 출제는 "코드 읽고 출력 맞히기"가 전부다

이 단원에서 문법을 처음부터 다 배울 필요는 없다. 기출을 보면 거의 모든 문제가 짧은 코드 하나를 주고 "출력 결과는?"이라고 묻는 형태다. 그리고 그 코드들이 노리는 함정은 놀랍게도 대여섯 가지로 정해져 있다.

  • 상속 + 오버라이딩: 부모 타입 변수에 자식 객체를 담았을 때 누구의 메소드가 실행되는가
  • 오버로딩: 이름이 같은 메소드가 여러 개일 때 인자 타입으로 어느 것이 뽑히는가
  • 생성자 호출 순서: 자식 객체를 만들면 부모 생성자가 먼저 실행된다
  • 접근 제어자: private 필드를 밖에서 건드리면 컴파일 오류
  • 예외 처리: 예외가 터진 뒤 어느 줄이 실행되고 어느 줄이 건너뛰어지는가
  • 정수 나눗셈·비트 연산: 5/2는 2.5가 아니라 2

따라서 공부 전략은 명확하다. 이 여섯 함정의 원리를 먼저 이해하고, 코드를 볼 때 "지금 이 문제는 어느 함정을 노렸나"를 먼저 찾는 것이다. 문법을 몰라서 틀리는 게 아니라, 이 규칙 중 하나를 놓쳐서 틀린다.

아래 동적 바인딩 절이 이 중 가장 어렵고 가장 자주 나오는 부분이니, 다른 걸 다 건너뛰더라도 그 표 하나는 반드시 외워야 한다.

💡주요 개념

JVM(Java Virtual Machine)은 왜 필요한가 📖 기출문제집 p.674

C언어는 컴파일하면 그 OS 전용 기계어(.exe 등)가 나와서 다른 OS에서는 못 돌린다. Java는 이 문제를 "한 단계 우회"해서 해결한다 — OS가 아니라 가상의 컴퓨터(JVM)를 대상으로 컴파일하는 것이다.

함정 주의: "Java는 컴파일 과정 없이 바로 실행된다" → ❌ 틀림. 컴파일(javac)로 바이트코드를 만든 뒤, JVM이 이를 인터프리터 방식으로 실행한다 — 컴파일+인터프리터가 섞인 하이브리드 구조.

정수 연산과 비트 시프트 — 계산 문제의 기본기 📖 기출문제집 p.767

반드시 기억할 두 가지

  • int / int = int — 소수점이 버려진다. 5/2는 2.5가 아니라 2, 101/4는 25. (한쪽이라도 실수면 실수 결과)
  • 시프트는 곱하기·나누기 2의 거듭제곱 — x >> n 은 x ÷ 2ⁿ, x << n 은 x × 2ⁿ

예: (101 >> 2) << 3 → 101 ÷ 4 = 25 (소수점 버림) → 25 × 8 = 200. 여기서 "101을 4로 나누면 25.25인데?"라고 생각하면 틀린다. 비트를 오른쪽으로 밀면 밀려난 비트는 그냥 사라지므로 자동으로 버림이 된다.

접근 제어자 (Access Modifier) 📖 기출문제집 p.772~773

제어자같은 클래스같은 패키지자식 클래스(다른 패키지)전체
privateOXXX
default (생략)OOXX
protectedOOOX
publicOOOO

예제로 확인하기: A1(x=public, y=private, z=protected) → A2 extends A1(a=protected, b=private) → A3 extends A2(q=private)

  1. A3 자신의 private q는 자기 클래스 안이므로 접근 가능
  2. x(public)는 어디서든 접근 가능 → 접근 가능
  3. z(protected, A1 소유)는 자식 클래스 A3까지 상속되어 접근 가능
  4. a(protected, A2 소유)도 마찬가지로 자식인 A3에서 접근 가능
  5. y(private, A1 소유)는 A1 내부에서만 유효 → A3에서 접근 불가
  6. b(private, A2 소유)도 A2 내부에서만 유효 → A3에서 접근 불가
  7. 결론: A3에서 쓸 수 있는 변수 = x, z, a, q
핵심 감각: private은 상속되지 않는다고 생각하면 편하다(정확히는 상속되지만 접근이 막힘). "부모의 private 필드를 자식이 쓸 수 있나?" → 없다.

구분오버로딩오버라이딩

메소드 이름같음같음

오버로딩 예제: add(int a, int b)와 add(double a, double b)가 한 클래스에 같이 있으면, add(5.7, 9.8) 호출 시 인자가 실수이므로 double 버전이 자동으로 선택된다 — "매개변수의 타입과 개수로 어떤 메소드를 쓸지 컴파일러가 결정"하는 것이 오버로딩의 핵심.
함정 주의: "오버라이딩은 매개변수 개수와 자료형이 서로 다른 것" → ❌ 그건 오버로딩 설명이다. 오버라이딩은 시그니처(이름+매개변수)를 똑같이 유지하고 내용만 바꾸는 것이다. 둘의 정의를 바꿔치기한 선택지가 단골로 나온다.

⭐ 가장 중요: 동적 바인딩 — "누구의 것이 실행되는가"

부모 타입 변수에 자식 객체를 담으면 생기는 혼란

Foo f = new Bar(); 처럼 참조 변수의 타입(Foo)과 실제 만들어진 객체(Bar)가 다를 수 있다. 이때 f.something()을 부르면 Foo 것이 실행될까, Bar 것이 실행될까? 대상이 무엇이냐에 따라 답이 갈린다 — 이 표가 Java 출력 문제의 절반을 푼다.

대상무엇을 기준으로 결정되나결과
인스턴스 메소드 (일반 메소드)실제 객체의 타입 (Bar)자식이 오버라이딩했으면 자식 것 실행 (동적 바인딩)
static 메소드참조 변수의 타입 (Foo)오버라이딩 대상이 아님 → 부모 것 실행
필드(멤버 변수)참조 변수의 타입 (Foo)자식이 같은 이름 필드를 가져도 부모 것 사용
오버로딩 선택참조 변수 타입에 보이는 메소드 중 인자 타입으로자식에만 있는 오버로딩 버전은 호출 불가

생성자와 호출 순서 📖 기출문제집 p.780~781

자식을 만들면 부모부터 태어난다

자식 객체를 생성하면 자식 생성자의 첫 줄에서 부모 생성자가 먼저 호출된다. 코드에 super();를 안 써도 컴파일러가 자동으로 넣어준다. 집을 지을 때 1층을 먼저 올려야 2층을 얹을 수 있는 것과 같다.

  • super() — 부모 클래스의 생성자 호출
  • this() — 같은 클래스의 다른 생성자 호출

그래서 출력 순서를 물으면 가장 안쪽(조상)부터 바깥으로 나오면서 찍힌다.

예외 처리 (Exception Handling) 📖 기출문제집 p.787~789

배열 범위를 벗어나거나 0으로 나누는 등 실행 중 발생하는 오류를 예외(Exception)라 하고, try-catch-finally로 잡아서 처리한다.

블록역할
try예외가 발생할 수 있는 코드를 넣는 곳
catch지정한 종류의 예외가 발생했을 때만 실행
finally예외 발생 여부와 무관하게 항상 실행
throws이 메소드에서 이런 예외가 날 수 있다고 미리 알림(떠넘기기)
대표 예외언제 발생
ArithmeticException정수를 0으로 나눌 때
ArrayIndexOutOfBoundsException배열 범위를 벗어난 인덱스 접근
NullPointerExceptionnull인 객체의 멤버에 접근
계산 예제: a=3, b=0일 때 result = a/b를 try 안에서 실행 → 출력 순서는? 📖 기출문제집 p.787
  1. try 블록 진입, a/b 계산 시도 → 0으로 나누기라서 ArithmeticException 발생
  2. 예외가 발생했으므로 try 블록의 나머지(print("A"))는 실행되지 않고 바로 catch로 이동
  3. catch 블록 실행 → print("B")
  4. finally 블록은 무조건 실행 → print("C")
  5. try-catch-finally 이후 코드 실행 → print("D")
  6. 최종 출력: BCD (A는 출력되지 않음에 주의)

📌시험 빈출 포인트

  • Java는 컴파일(bytecode 생성) + JVM 인터프리터 실행이 결합된 하이브리드 방식
  • Java는 다중 상속·포인터·구조체·연산자 오버로딩을 지원하지 않는다 (지원한다고 쓰면 오답)
  • int ÷ int는 소수점 버림 — 5/2 = 2, 101/4 = 25
  • 접근제어자 범위: private < default < protected < public
  • protected는 다른 패키지의 자식 클래스에서도 접근 가능 (default와 헷갈림 주의)
  • 부모의 private 필드는 자식에서 접근 불가, 외부에서 private 필드 직접 대입 시 컴파일 오류
  • 오버로딩=매개변수로 구분(상속 불필요, 컴파일 타임), 오버라이딩=상속관계에서 시그니처 동일 재정의(런타임)
  • ⭐ 인스턴스 메소드는 실제 객체 기준, static 메소드와 필드는 참조 변수 타입 기준
  • 자식 객체 생성 시 부모 생성자가 먼저 실행된다 (super() 자동 삽입)
  • 추상 클래스와 인터페이스는 객체를 직접 생성할 수 없다, 인터페이스 구현은 implements
  • try에서 예외 발생 시 그 지점 이후 try 코드는 건너뛰고 catch로 즉시 이동, finally는 항상 실행

✏️연습문제

코드 문제는 변수 값을 종이에 적어가며 손으로 따라가는 게 가장 빠릅니다. 먼저 풀어본 뒤 해설을 펼치세요.

문제 12018 계리직 · 기출문제집 p.767

JAVA 프로그램의 실행 결과로 옳은 것은?

class Test {
    public static void main(String[] args) {
        int a = 101;
        System.out.println((a >> 2) << 3);
    }
}
  1. 0
  2. 200
  3. 404
  4. 600
해설 보기

정답 ② 200

  1. a >> 2 = 오른쪽으로 2비트 시프트 = ÷ 2² = ÷4 → 101 ÷ 4 = 25 (소수점 0.25는 밀려나 사라짐)
  2. 25 << 3 = 왼쪽으로 3비트 시프트 = × 2³ = ×8 → 25 × 8 = 200

확인용 비트 계산: 101 = 1100101 → 오른쪽 2칸 밀면 11001(=25, 끝의 01은 버려짐) → 왼쪽 3칸 밀면 11001000(=200).

함정: 101÷4를 25.25로 계산한 뒤 ×8 해서 202를 만들면 틀린다. 정수 연산은 중간에 무조건 버림이 일어난다.

문제 62009 PL · 기출문제집 p.774

다음 자바 프로그램의 실행 결과는? (출력은 공백으로 구분)

public class Test {
    public static void main(String[] args) {
        int x = 1, y = 2;
        double m = 3.4, n = 5.6;
        int[] p = {10, 20, 30, 40};
        System.out.print(sum(m, n) + " ");
        System.out.print(sum(x, y) + " ");
        System.out.print(sum(p));
    }
    public static int sum(int a, int b) { return a + b; }
    public static double sum(double a, double b) { return a + b; }
    public static int sum(int a[]) {
        int total = 0;
        for (int i = 0; i < a.length; i++) total += a[i];
        return total;
    }
}
  1. 3  9.0  100
  2. 9.0  3  100
  3. 9.0  3  60
  4. 3  9.0  60
해설 보기

정답 ② 9.0  3  100

이름이 같은 sum이 세 개 있다 — 전형적인 오버로딩이다. 인자의 타입과 개수를 보고 컴파일러가 어느 것을 쓸지 고른다.

  3. sum(p) → p가 배열 → sum(int[]) 실행 → 10+20+30+40 = 100

함정 두 개: ⑴ 출력 순서를 코드 순서(m,n 먼저)가 아닌 정의 순서로 착각하면 ①번을 고르게 된다. ⑵ 9.0 vs 9 — double 반환값은 소수점이 붙어 출력된다는 점도 선택지를 가르는 포인트다.

public class ClassA extends ClassP {

메소드ClassA의 정의관계실행되는 것
func1int func1(int, int)오버라이딩 (시그니처 동일)ClassA → 5 % 2 = 1

해설 보기

문제 112010 계리직 · 기출문제집 p.771

다음 Java 프로그램에서 사용되지 않은 기법은?

class Adder {
    public int add(int a, int b) { return a + b; }
    public double add(double a, double b) { return a + b; }
}
class Computer extends Adder {
    private int x;
    public int calc(int a, int b, int c) {
        if (a == 1) return add(b, c);
        else return x;
    }
    Computer() { x = 0; }
}
public class Adder_Main {
    public static void main(String args[]) {
        Computer c = new Computer();
        System.out.println("100+200=" + c.calc(1, 100, 200));
        System.out.println("5.7+9.8=" + c.add(5.7, 9.8));
    }
}
  1. 캡슐화 (Encapsulation)
  2. 상속 (Inheritance)
  3. 오버라이딩 (Overriding)
  4. 오버로딩 (Overloading)
해설 보기

정답 ③ 오버라이딩

코드에서 각 기법을 하나씩 찾아보면 된다.

  • 캡슐화 O — private int x; 처럼 데이터를 클래스 안에 감췄다
  • 상속 O — class Computer extends Adder
  • 오버로딩 O — add(int,int)와 add(double,double)가 한 클래스(Adder) 안에 이름만 같고 매개변수가 다르게 정의됨
  • 오버라이딩 X — 자식 Computer가 부모 Adder의 메소드를 같은 시그니처로 재정의한 곳이 없다. calc()는 부모에 없던 새 메소드일 뿐

구분 요령: 한 클래스 안에 이름 같은 메소드가 여러 개면 오버로딩, 부모-자식 사이에 똑같은 메소드가 겹치면 오버라이딩. 이 코드에는 후자가 없다.
