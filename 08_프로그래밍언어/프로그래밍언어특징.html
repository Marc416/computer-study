프로그래밍 언어의 특징

고급/저급언어, 번역 프로그램, 컴파일 단계, 매개변수 전달, 객체지향 패러다임 · PART 07. 프로그래밍언어론

핵심 요약

컴퓨터는 기계어(0과 1)만 이해한다. 사람이 쓰기 편한 고급언어를 기계어로 바꿔주는 게 번역 프로그램(컴파일러/인터프리터)이다.

실행까지 가는 길은 번역(컴파일) → 링킹 → 로딩 순서다. 객체지향 언어의 4대 특성은 캡슐화·상속·다형성·추상화다.

🎯이 단원을 왜 배우나

"사람의 글"과 "기계의 전기신호" 사이의 번역 문제

CPU가 실제로 이해하는 건 10110000 01100001 같은 기계어 비트열뿐이다. 그런데 사람이 이걸 직접 쓸 수는 없다. 그래서 사람이 읽을 수 있는 고급언어로 쓰고, 이걸 기계어로 바꿔주는 프로그램을 따로 두는 것이다. 이 단원의 거의 모든 내용은 결국 "누가, 언제, 어떤 단위로 번역하는가"라는 한 가지 질문의 변주다.

번역 시점에 따라 성격이 완전히 갈린다. 컴파일러는 "전부 미리 번역해두고 나중에 실행" — 번역 결과물(목적 프로그램)이 파일로 남으니 저장 공간이 더 들지만, 한 번 만들어두면 실행은 빠르다. 인터프리터는 "필요할 때 한 줄씩 그때그때 번역" — 결과물을 안 남기니 가볍지만, 같은 줄을 반복 실행하면 매번 다시 번역해야 해서 느리다. 이 트레이드오프 하나가 시험에 가장 많이 나온다.

그리고 번역만으로는 실행이 안 된다. 여러 조각으로 나눠 짠 코드와 라이브러리를 하나로 합치고(링킹), 그걸 메모리에 올려야(로딩) 비로소 돌아간다. 순서를 묻는 문제가 단골이니 번역 → 링킹 → 로딩은 통째로 외워두면 된다.

함정 주의: 자바·코볼·포트란은 전부 고급언어다. "저급언어를 고르시오" 문제에서 어셈블리어만 저급언어로 분류된다. 또 어셈블리어도 번역이 필요하다(어셈블러가 담당) — "어셈블리어는 번역 없이 바로 실행된다"는 틀린 설명이다.

언어 번역 프로그램 — 누가 기계어로 바꿔주나 📖 기출문제집 p.676~678

종류번역 대상번역 단위
어셈블러어셈블리어 → 기계어-
컴파일러고급언어 → 기계어(목적 프로그램)파일(전체) 단위 한꺼번에 번역
인터프리터고급언어 → 즉시 실행문장(줄) 단위로 번역하며 바로 실행
프리프로세서(전처리기)컴파일 전 원시 프로그램을 가공매크로 치환, include 처리 등
함정 주의: 워드프로세서는 번역 프로그램이 아니다(문서 편집용 응용 소프트웨어). "언어 번역 프로그램에 해당하지 않는 것" 문제의 단골 정답.

컴파일러는 "번역 후 실행"이라 목적 프로그램을 저장할 공간이 더 필요하지만, 한 번 번역해두면 반복 실행이 빠르다. 인터프리터는 저장 공간은 적게 들지만 실행할 때마다 매번 다시 해석하므로 반복문이 많은 프로그램에서는 느리다.

Java는 컴파일러인가 인터프리터인가 — 정답은 "둘 다"(하이브리드)

시험에 자주 나오는 함정이다. Java는 javac로 소스를 바이트코드(.class)까지 컴파일한 다음, 그 바이트코드를 JVM이 인터프리터 방식으로 해석·실행한다. 즉 중간코드 생성까지는 컴파일 기법, 실행은 해석 기법이다.

그래서 "Java 컴파일러는 인터프리터인가?"라고 물으면 아니다(컴파일러는 컴파일러다). 반대로 "JVM은 인터프리터인가?"라고 물으면 그렇다. 같은 언어를 두고 묻는 대상이 달라지니 문장을 끝까지 읽어야 한다.

실행까지 가는 전체 경로 — 번역 → 링킹 → 로딩 📖 기출문제집 p.676, p.680

컴파일이 끝났다고 바로 실행되는 게 아니다. 내가 짠 코드 조각들과 이미 만들어진 라이브러리(예: printf)를 하나로 이어 붙이고(링킹), 완성된 실행 파일을 주기억장치에 올려야(로딩) CPU가 실행할 수 있다.

고급 언어의 컴파일 7단계 📖 기출문제집 p.677

앞의 세 단계가 하는 일 — 문장 하나로 이해하기

int a = b + 1; 이라는 한 줄을 컴파일러가 어떻게 뜯어보는지 따라가 보자.

  • 어휘분석: 글자를 의미 있는 최소 단위(토큰)로 쪼갠다 → int / a / = / b / + / 1 / ;
  • 구문분석: 이 토큰 배열이 문법에 맞는 문장인지 검사하고 구조(트리)를 만든다. int a = = b; 처럼 문법이 깨지면 여기서 잡힌다.
  • 의미분석: 문법은 맞아도 말이 되는지를 본다. b가 선언되지 않았거나, 문자열을 정수에 넣으려 하면 여기서 잡힌다.

암기 포인트: 문법 오류는 구문분석, 타입 오류는 의미분석. 순서는 "단어 → 문장 → 뜻" (어휘 → 구문 → 의미)으로 기억하면 순서를 뒤집은 선택지에 안 걸린다.

매개변수 전달 방식 — 값 호출 vs 참조 호출 📖 기출문제집 p.758

함수를 부를 때 인자를 "복사해서" 넘기느냐(Call by Value), "원본 주소를" 넘기느냐(Call by Reference)의 차이다. 이 차이가 곧 함수 안에서 값을 바꿨을 때 호출한 쪽에 반영되는가를 결정한다.

C언어의 결정적 함정: int score[3] 같은 배열 이름은 그 자체가 시작 주소다. 그래서 get_average(score, 3)처럼 배열을 넘기면 겉보기와 달리 참조에 의한 호출(call by reference)로 처리된다. "배열을 넘겼으니 값 호출"이라고 쓴 선택지는 틀린 설명이다.

정적 타이핑 vs 동적 타이핑

구분정적 타이핑 (Static)동적 타이핑 (Dynamic)
타입 결정 시점컴파일 시점 (미리 선언)실행 시점 (값을 넣는 순간)
변수 선언int a = 10; 처럼 타입 명시a = 10 처럼 타입 없이
대표 언어C, C++, Java, KotlinPython, JavaScript, Ruby
함정 주의: "Python은 정적 타이핑을 지원하는 컴파일러 방식 언어" → ❌ 완전히 반대다. Python은 동적 타이핑 + 인터프리터 방식이다. 이 문장은 거의 매년 오답 선택지로 등장한다.

객체지향 프로그래밍의 4대 특성

특성의미
캡슐화 (Encapsulation)데이터와 메소드를 하나로 묶고, 외부에서 직접 접근 못하게 숨김(정보 은닉)
상속 (Inheritance)기존 클래스의 속성·기능을 물려받아 새 클래스를 만듦 (여러 클래스 조합이 아님)
다형성 (Polymorphism)같은 이름의 메소드가 상황에 따라 다르게 동작 (오버로딩·오버라이딩으로 구현)
추상화 (Abstraction)공통 특징만 뽑아 추상 클래스/인터페이스로 표현, 추상 클래스는 직접 객체 생성 불가
함정 주의: "상속이란 여러 클래스를 조합해 새 클래스를 만드는 것" → ❌ 틀림. 상속은 기존 클래스 하나(또는 그 계층)의 속성을 물려받는 것이다. 또 "객체는 재사용 가능하지만 클래스는 불가능" → ❌ 클래스야말로 재사용을 위한 틀이다. 자세한 오버로딩/오버라이딩 예제는 JAVA 기초와 객체지향 문서 참고.

웹 스크립트 언어 — 서버 측 vs 클라이언트 측 📖 기출문제집 p.674

구분실행 위치대표 언어
서버 측 스크립트웹 서버에서 실행 후 결과(HTML)만 전송ASP, JSP, PHP, CGI
클라이언트 측 스크립트사용자의 웹 브라우저에서 실행JavaScript, VBScript
함정 주의: "CGI 프로그램은 클라이언트에서 실행된다" → ❌ 틀림. CGI·ASP·JSP·PHP는 모두 서버 측에서 실행된다. 암기법: "자바스크립트만 브라우저, 나머지 알파벳 3글자(ASP/JSP/PHP/CGI)는 서버".

📌시험 빈출 포인트

  • 고급언어(자바·코볼·포트란 등) vs 저급언어(기계어·어셈블리어) 구분
  • 컴파일러(파일 단위, 목적 프로그램 생성) vs 인터프리터(문장 단위, 목적 프로그램 미생성) 차이
  • 반복문이 많으면 컴파일러 방식이 더 효율적 (인터프리터는 매번 재해석)
  • 큰 기억장소를 요구하는 쪽은 컴파일러 (목적 프로그램을 저장해야 하므로) — 인터프리터라고 쓰면 오답
  • 실행까지의 순서: 번역 → 링킹 → 로딩 (링킹·로딩 순서 바꾼 선택지 주의)
  • 컴파일 7단계 순서: 어휘분석→구문분석→의미분석→중간코드생성→코드최적화→목적코드생성→링킹
  • Java는 컴파일+인터프리터 하이브리드, Python은 동적 타이핑+인터프리터
  • C에서 배열을 인자로 넘기면 call by reference로 처리된다
  • 객체지향 4대 특성(캡슐화·상속·다형성·추상화) 정의 구분
  • 서버 측 스크립트(ASP/JSP/PHP/CGI) vs 클라이언트 측 스크립트(JavaScript) 구분

정답 ① 어셈블리어

저급언어는 기계어와 어셈블리어 둘뿐이다. 나머지는 전부 고급언어라고 보면 된다.

자바·코볼·포트란은 모두 사람이 읽을 수 있는 문장 형태의 고급언어다. "오래된 언어(코볼·포트란)니까 저급언어 아닐까?"라고 생각하기 쉬운데, 오래됐는지 여부와 고급/저급은 아무 관계가 없다. 기준은 오직 "사람 기준이냐 하드웨어 기준이냐"이다.

정답 ① LISP

LISP은 대표적인 함수형(functional) 언어다. 나머지 Java·Python·C#은 모두 객체지향을 지원한다.

프로그래밍 언어에 대한 설명으로 옳지 않은 것은?

  1. Objective-C, Java, C#은 객체지향 언어이다.
  2. Python은 정적 타이핑을 지원하는 컴파일러 방식의 언어이다.
  3. ASP, JSP, PHP는 서버 측에서 실행되는 스크립트 언어이다.
  4. XML은 전자문서를 표현하는 확장가능한 표준 마크업 언어이다.
해설 보기

정답 ② (Python은 동적 타이핑 + 인터프리터 방식이다)

②번은 두 군데나 틀렸다. Python은 ⑴ 정적 타이핑이 아니라 동적 타이핑(값을 넣는 순간 타입 결정), ⑵ 컴파일러가 아니라 인터프리터 방식이다.

이 문장은 거의 매년 형태만 바꿔 출제되는 1순위 오답 선택지다. "Python + 정적 + 컴파일"이 한 문장에 있으면 무조건 틀렸다고 보면 된다.

소프트웨어 개발 언어에 대한 설명으로 옳지 않은 것은?

  1. C#은 마이크로소프트 닷넷 프레임워크를 지원하는 객체지향 언어이다.
  2. Python은 인터프리터 방식의 객체지향 언어로서 실행시점에 데이터 타입을 결정하는 동적 타이핑 기능을 갖는다.
  3. Kotlin은 그래픽 요소를 강화한 게임 개발 전용 언어이다.
  4. Java는 컴파일된 프로그램이 JVM상에서 인터프리터 방식으로 실행되는 플랫폼 독립적 프로그래밍 언어이다.
해설 보기

정답 ③ (Kotlin은 게임 전용 언어가 아니다)

Kotlin은 안드로이드 스튜디오 개발사인 JetBrains가 2011년 공개한 언어로, JVM 위에서 동작하며 자바와 상호운용이 가능하다. 정적 타입 언어이고 함수형·객체지향을 모두 지원하는 오픈소스다. "게임 개발 전용"이라는 설명은 완전히 지어낸 말이다.

참고로 ②·④번은 앞 문제와 달리 맞는 설명이다. 같은 Python·Java 설명이라도 문장에 따라 정답이 갈리므로, 키워드(동적/정적, 인터프리터/컴파일러)를 하나하나 대조해야 한다.

언어 번역 프로그램에 해당하지 않는 것은?

  1. 어셈블러
  2. 컴파일러
  3. 인터프리터
  4. 워드프로세서
해설 보기

정답 ④ 워드프로세서

워드프로세서는 문서 편집용 응용 소프트웨어일 뿐 번역과 무관하다.

  • 어셈블러: 어셈블리어 → 기계어

문제 62025 소방경채 · 기출문제집 p.676

프로그래밍 언어에 대한 설명으로 옳은 것만을 <보기>에서 모두 고르면?

ㄱ. C, JAVA, PASCAL은 컴파일러 언어이다.

ㄴ. 어셈블리어는 번역 과정 없이 직접 실행이 가능한 언어이다.

ㄷ. 소스 파일을 실행하기 위해서는 번역 - 로딩 - 링킹 순으로 처리해야 한다.

ㄹ. 고급언어는 사람이 이해하기 쉬운 언어이며 저급언어는 컴퓨터가 이해하기 쉬운 언어이다.

해설 보기

정답 ㄱ, ㄹ

  1. ㄱ (O) — C, JAVA, PASCAL은 컴파일 과정을 거치는 언어다. (JAVA는 바이트코드까지 컴파일하는 하이브리드지만, 컴파일러 언어로 분류한다)
  2. ㄴ (X) — 어셈블리어도 어셈블러로 기계어 번역이 필요하다. 번역 없이 직접 실행되는 건 오직 기계어뿐이다.
  3. ㄷ (X) — 순서가 뒤집혔다. 올바른 순서는 번역 - 링킹 - 로딩이다. (합쳐서 완성한 다음에 메모리에 올린다)
  4. ㄹ (O) — 고급/저급언어의 정의 그대로다.

이 문제의 핵심은 ㄷ이다. "로딩-링킹" vs "링킹-로딩"을 바꿔 놓는 함정이 반복 출제된다. 합친 뒤에 올린다고 논리로 기억할 것.

다음은 고급 언어의 컴파일 단계이다. ㉠~㉢에 들어갈 단계를 순서대로 나열한 것은?
원시프로그램 → ( ㉠ ) → ( ㉡ ) → ( ㉢ ) → 코드최적화 → 코드생성 → 링크

  1. 어휘분석 - 의미분석 - 구문분석
  2. 어휘분석 - 구문분석 - 의미분석
  3. 구문분석 - 어휘분석 - 의미분석
  4. 구문분석 - 의미분석 - 어휘분석
해설 보기

정답 ② 어휘분석 → 구문분석 → 의미분석

컴파일러가 소스를 읽는 순서는 사람이 글을 읽는 순서와 똑같다 — 단어 → 문장 → 뜻.

  1. 어휘분석: 소스를 토큰 단위로 쪼갠다 (단어 나누기)
  2. 구문분석: 토큰 배열이 문법에 맞는지 검사하고 구조를 만든다 (문장 만들기)
  3. 의미분석: 문법은 맞아도 의미상 오류(선언 안 된 변수, 타입 불일치 등)가 없는지 본다 (뜻 확인)
  4. 이후 중간코드 생성 → 코드최적화 → 목적코드 생성 → 링크

단어를 나누기도 전에 문법을 볼 수는 없다 — 그래서 어휘가 반드시 맨 앞이라는 것만 알아도 ③·④는 바로 소거된다.

프로그램 구현 기법(컴파일러 / 인터프리터 / 하이브리드)에 대한 설명으로 옳지 않은 것은?

  1. 하이브리드 기법에서는 인터프리터가 중간 언어로 번역된 프로그램을 해석하고 실행한다.
  2. 인터프리터를 이용한 기법에서는 고급 언어 프로그램을 명령문 단위로 하나씩 해석하여 바로 실행한다.
  3. 반복문이 많은 프로그램의 실행에서 컴파일러를 이용한 기법이 인터프리터를 이용한 기법보다 효율적이다.
  4. 인터프리터를 이용한 기법은 번역된 프로그램을 저장하기 위한 큰 기억 장소를 요구하는 단점이 있다.
해설 보기

정답 ④ (큰 기억장소를 요구하는 것은 컴파일러다)

인터프리터는 목적 프로그램을 아예 만들지 않는다. 저장할 결과물이 없으니 큰 기억장소도 필요 없다. 반대로 컴파일러는 번역 결과인 목적 프로그램을 파일로 남겨야 하므로 더 큰 저장 공간이 필요하다.

③번이 맞는 이유도 같은 원리다: 반복문은 같은 줄을 수백 번 실행하는데, 인터프리터는 실행할 때마다 매번 다시 번역하므로 손해가 누적된다. 컴파일러는 이미 번역해둔 기계어를 반복 실행할 뿐이라 빠르다.

한 줄 정리: 인터프리터 = 가볍지만 느림(반복 시), 컴파일러 = 무겁지만 빠름.

인터프리터(Interpreter) 방식의 언어로 옳지 않은 것은?

  1. JavaScript
  2. C
  3. Basic
  4. LISP
해설 보기

정답 ② C

C와 C++는 대표적인 컴파일러 방식 언어다. 반면 JavaScript, JSP, HTML, 액션스크립트, SQL, Python, Ruby, Basic, LISP 등은 인터프리터 방식으로 분류된다.

암기 요령: "실행 파일(.exe)이 만들어지면 컴파일러, 소스 그대로 돌리면 인터프리터." C는 컴파일하면 실행 파일이 나오지만, 파이썬 스크립트는 소스 파일 그대로 실행한다.

문제 102022 국가직 · 기출문제집 p.758

C 프로그램 코드가 다음과 같을 때, 매개변수 전달 방법에 대한 설명으로 옳지 않은 것은?

int get_average(int score[], int n) {
    int i, sum = 0;
    for (i = 0; i < n; i++)
        sum += score[i];
    return sum / n;
}
void main(void) {
    int score[3] = {1, 2, 5};
    printf("%d\n", get_average(score, 3));
}
  1. 전달할 데이터의 양이 많을 경우에는 참조에 의한 호출이 효율적이다.
  2. 값에 의한 호출로 전달된 데이터는 호출된 함수에서 값을 변경하더라도 함수 종료 후 상위 함수에 반영되지 않는다.
  3. 값에 의한 호출은 함수 호출 시 데이터 복사가 발생한다.
  4. 위 프로그램에서 get_average()를 호출하는 데 사용한 매개변수 score는 값에 의한 호출로 처리된다.
해설 보기

정답 ④ (score는 배열이므로 참조에 의한 호출로 처리된다)

  1. C에서 배열 이름은 그 배열의 시작 주소를 의미한다. score는 곧 "첫 번째 원소가 있는 메모리 번지"다.
  2. 따라서 get_average(score, 3)은 배열 전체를 복사해 넘기는 게 아니라 주소를 넘긴다 → call by reference
  3. 반면 두 번째 인자 3은 그냥 값이므로 call by value다. 한 함수 호출 안에서 두 방식이 섞일 수 있다는 점이 포인트.
  4. 판별법: 주소를 넘기면 참조 호출, 값을 넘기면 값 호출.

①·②·③번은 모두 맞는 설명이다. 특히 ①번은 배열을 주소로 넘기는 이유 그 자체다 — 원소가 100만 개라면 전부 복사하는 비용이 엄청나기 때문이다.
