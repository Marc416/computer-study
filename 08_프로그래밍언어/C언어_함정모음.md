# C언어 시험 함정 모음

## 핵심 요약
> C언어 문제는 "코드를 대충 읽으면 틀리게 만드는" 함정이 핵심이다.
> 특히 **대입 vs 비교**, **연산자 우선순위**, **증감 연산자**를 노린다.

---

## 함정 1: 대입 연산자(=) vs 비교 연산자(==)

### 문제 유형 (2020 국가직 기출)

```c
int a, b;
a = b = 1;
if (a = 2)         // ⚠️ 함정! 비교(==)가 아니라 대입(=)
    b = a + 1;
else if (a == 1)
    b = b + 1;
else
    b = 10;
printf("%d, %d\n", a, b);
```

### 풀이 과정

| 단계 | 코드 | a | b | 설명 |
|------|------|---|---|------|
| 1 | `a = b = 1` | 1 | 1 | 초기값 설정 |
| 2 | `if (a = 2)` | **2** | 1 | a에 2를 **대입**, 2≠0이므로 **참** |
| 3 | `b = a + 1` | 2 | **3** | 참이므로 이 줄 실행 |

**결과: `2, 3`** (정답 ①)

### 왜 틀리기 쉬운가?

`if (a = 2)`를 `if (a == 2)`로 착각하면:
- a==2는 거짓(a는 1이니까) → else if로 넘어감
- a==1이 참 → b = b+1 = 2
- 결과: `1, 2` ← **오답 ③에 해당**

### 핵심 규칙

| 코드 | 의미 | if문 안에서 결과 |
|------|------|-----------------|
| `a == 2` | a가 2인지 **비교** | true 또는 false |
| `a = 2` | a에 2를 **대입** | 대입된 값(2) → 참 |
| `a = 0` | a에 0을 **대입** | 대입된 값(0) → **거짓** |

> **한 줄 정리**: `if` 안에 `=`가 하나면 대입! 대입된 값이 0이면 거짓, 아니면 참!

## 함정 2: 증감 연산자 (++, --)

### 전위 vs 후위

```c
int a = 5;
int b = a++;   // b = 5, a = 6  (먼저 대입, 나중에 증가)
int c = ++a;   // c = 7, a = 7  (먼저 증가, 나중에 대입)
```

| 구분 | 코드 | 동작 순서 | 비유 |
|------|------|-----------|------|
| 후위(a++) | `b = a++` | 값 쓰고 → 증가 | "나중에 올릴게" |
| 전위(++a) | `b = ++a` | 증가 → 값 사용 | "먼저 올리고 줄게" |

## 함정 3: 논리 연산자 단축 평가

```c
int a = 0, b = 0;
if (a++ && b++)    // a++은 0(거짓) → b++는 실행 안 됨!
    printf("참");
// 결과: a=1, b=0 (b는 증가 안 됨!)
```

| 연산자 | 단축 평가 규칙 |
|--------|---------------|
| `&&` (AND) | 앞이 거짓이면 → 뒤는 실행 안 함 |
| `\|\|` (OR) | 앞이 참이면 → 뒤는 실행 안 함 |

## 함정 4: switch문 break 누락

```c
int x = 1;
switch(x) {
    case 1: printf("A");     // break 없음! → fall-through
    case 2: printf("B");     // 여기도 실행됨
    case 3: printf("C"); break;
    default: printf("D");
}
// 결과: ABC (break 만날 때까지 계속 실행)
```

---

## 시험 빈출 포인트

1. **`=`와 `==` 구분** → 거의 매년 출제
2. **전위/후위 증감 연산자** → printf 안에서 자주 출제
3. **단축 평가** → &&, || 와 증감 연산자 조합
4. **switch fall-through** → break 빠진 경우
