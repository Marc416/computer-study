# 순차 파일과 인덱스 순차 파일

## 핵심 요약
> 순차 파일 = 데이터를 순서대로 쭉 저장한 파일
> 인덱스 순차 파일 = 순차 파일 + 목차(인덱스)를 붙여서 빠르게 찾을 수 있게 한 파일

## 주요 개념

### 순차 파일 (Sequential File)
- 레코드가 **키 값 기준으로 정렬**되어 순서대로 저장됨
- 비유: 번호순으로 정리된 서류철. 처음부터 순서대로 넘겨봐야 함
- 새 레코드 추가 → **파일 끝에 추가**
- **범위 검색에 강함** (예: "학번 100~200번 모두 찾아줘")
- 특정 한 건만 찾을 때는 처음부터 쭉 훑어야 해서 느림

### 인덱스 순차 파일 (Indexed Sequential File, ISAM)
- 순차 파일에 **인덱스(목차)**를 추가한 구조
- 비유: 목차가 있는 책. 목차에서 페이지 번호 보고 바로 이동
- 인덱스에 기록되는 것: **필드 값 + 위치 값(포인터)**
  - 예: `학번 2024001 → 디스크 5번 블록`
- **소량 레코드 검색에 강함** (예: "학번 150번 찾아줘")
- 오버플로우 영역이 존재 (공간이 넘칠 때 임시 저장 공간)

## 핵심 용어 정리

| 용어 | 쉬운 설명 | 비유 |
|------|-----------|------|
| 오버플로우 블록 | 기본 블록이 꽉 차서 넘친 데이터를 담는 **미리 확보된 예비 공간** | 사물함이 꽉 차서 미리 남겨둔 빈 방(창고)에 넣는 것 |
| 인덱스 대상 필드 값 | 검색 기준이 되는 값 (키 값) | 목차의 제목 |
| 위치 값 (포인터) | 해당 데이터가 저장된 물리적 위치 | 목차의 페이지 번호 |
| 인덱스 갱신 | 데이터 변경 시 목차도 함께 수정하는 것 | 책에 페이지 추가되면 목차도 수정 |
| 다중레벨 인덱스 | 인덱스 위에 또 인덱스를 쌓은 계층 구조 | 1층→분야, 2층→세부주제, 3층→실제 책 |
| 재조직 (Reorganization) | 오버플로우가 쌓여 느려지면 기본 영역에 다시 깔끔하게 정리하는 것 | 보조 창고 물건을 원래 방에 재정리하는 대청소 |

## 시험 빈출 포인트

### 순차 파일 특징
- ✅ 레코드 추가는 **파일 끝**에서 이루어짐
- ✅ **범위 검색**(대량 데이터)에 효과적
- ✅ **오버플로우 블록이 없음** (그건 인덱스 순차 파일 개념)

### 인덱스 순차 파일 특징
- ✅ 인덱스에는 **필드 값 + 위치 값** 쌍으로 기록
- ✅ 레코드 추가/삭제 시 **인덱스 갱신 필요**
- ✅ **소량 레코드 접근**에 순차 파일보다 효과적
- ✅ 오버플로우 영역 존재 (미리 확보된 예비 공간)
- ✅ 오버플로우가 쌓이면 **재조직** 필요

## 헷갈리는 개념 비교

| 구분 | 순차 파일 | 인덱스 순차 파일 |
|------|-----------|------------------|
| 구조 | 데이터만 순서대로 | 데이터 + 인덱스(목차) |
| 검색 방식 | 처음부터 순서대로 탐색 | 인덱스로 위치 찾아 바로 이동 |
| 범위 검색 (대량) | ⭐ 효과적 | 보통 |
| 개별 검색 (소량) | 느림 | ⭐ 효과적 |
| 레코드 추가 | 파일 끝에 추가 | 오버플로우 영역 활용 가능 |
| 오버플로우 블록 | ❌ 없음 | ⭕ 있음 (미리 예비 공간 확보) |
| 인덱스 갱신 | 해당 없음 | 추가/삭제 시 필요 |

### 오버플로우 블록 vs 메모리 페이징 (헷갈리지 말 것!)

| 구분 | 오버플로우 블록 | 메모리 페이징 |
|------|---------------|--------------|
| 어디서? | **디스크** (저장소) | **메모리** (RAM) |
| 언제? | 데이터 **삽입**할 때 | 데이터 **읽어올** 때 |
| 왜? | 디스크 블록에 자리가 없어서 | 프로그램 실행에 필요해서 |
| 관련 과목 | 데이터베이스 (파일 구조) | 운영체제 (가상 메모리) |

## 심화: DB는 디스크에 어떻게 저장되나?

DB도 결국 **디스크에 파일로 저장**됨. 디스크는 **블록(block)** 단위로 읽고 씀.

```
디스크 = 아파트 단지
블록 = 각 호실 (보통 4KB)
레코드 = 호실 안 주민 (한 블록에 여러 레코드)
```

### 오버플로우 블록이 생기는 과정 (ISAM)

ISAM은 파일 생성 시 **오버플로우 영역을 미리 확보**해 둠 (예비 빈 공간)

```
[기본 영역]
  [블록1] 학번: 10, 20, 30  ← 꽉 참!
  [블록2] 학번: 40, 50, 60

[오버플로우 영역]
  [    ] [    ] [    ]  ← 처음엔 텅 비어있음

학번 25를 추가하려면? → 블록1에 자리가 없음!
→ 오버플로우 영역의 빈 블록을 가져다 씀

[기본 영역]
  [블록1] 10, 20, 30 →→→ [오버플로우A: 25]  ← 포인터로 연결
  [블록2] 40, 50, 60

오버플로우가 계속 쌓이면?
  [블록1] 10,20,30 → [오버플로우A: 25] → [오버플로우B: 27]  🐌 점점 느려짐
  → 재조직(Reorganization) 필요! (대청소해서 기본 영역에 다시 정리)
```

순차 파일은 끝에 이어붙이면 되니까 오버플로우 문제가 없음!

### ISAM 저장 구조

```
┌─────────────────────────────────┐
│         마스터 인덱스            │  ← 가장 큰 범위 안내
├─────────────────────────────────┤
│        실린더 인덱스             │  ← 중간 범위 안내
├─────────────────────────────────┤
│        트랙 인덱스               │  ← 세부 안내
├─────────────────────────────────┤
│     기본 영역 (Prime Area)      │  ← 실제 데이터 (정렬됨)
├─────────────────────────────────┤
│   오버플로우 영역 (Overflow)     │  ← 미리 확보된 예비 공간 (넘치면 여기 저장)
└─────────────────────────────────┘
```

**문제:** 옳은 설명의 총 개수는?

| 선지 | O/X | 이유 |
|------|-----|------|
| ㄱ. 순차 파일 레코드 추가는 마지막 위치 | ✅ | 끝에 추가함 |
| ㄴ. 순차 파일은 범위 검색에 효과적 | ✅ | 정렬되어 있어 대량 범위 검색에 좋음 |
| ㄷ. 순차 파일은 오버플로우 블록 안 생김 | ✅ | 오버플로우는 인덱스 순차 파일 개념 |
| ㄹ. 인덱스에 필드 값 + 위치 값 기록 | ✅ | 값과 포인터 쌍으로 저장 |
| ㅁ. 인덱스 갱신 없이 추가/삭제 가능 | ❌ | 인덱스 갱신 반드시 필요 |
| ㅂ. 소량 접근에 순차보다 효과적 | ❌ | (답이 4개이므로) |
| ㅅ. 다중레벨 최하위가 순차 파일 형식 | ❌ | 최하위 레벨도 인덱스 구조임 |

**정답: ③ 4개 (ㄱ, ㄴ, ㄷ, ㄹ)**
