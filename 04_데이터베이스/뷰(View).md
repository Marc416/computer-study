# 뷰 (View)

## 핵심 요약
> 뷰 = **SELECT문을 저장해놓은 가상 테이블**
> 실제 데이터는 없고, 조회할 때마다 원본 테이블에서 가져온다.
> 비유: 뷰는 "창문" — 창문 자체에 풍경이 있는 게 아니라, 창문을 통해 바깥을 보는 것

## 주요 개념

### 뷰란?
- 기본 테이블에서 유도된 **가상 테이블** (논리적으로만 존재)
- 실제 데이터를 저장하지 않음 → 조회할 때마다 SELECT문이 실행됨
- CREATE VIEW로 **정의만** 할 수 있고, ALTER VIEW로 **변경은 불가**

### 뷰 SQL 문법

**뷰 생성:**
```sql
CREATE VIEW 우수학생 AS
SELECT 학번, 이름, 학과
FROM 학생
WHERE 성적 >= 90;
```

**뷰 사용 (일반 테이블처럼 조회):**
```sql
SELECT * FROM 우수학생;
```

**뷰 삭제:**
```sql
DROP VIEW 우수학생;
```

**뷰 수정하고 싶을 때:**
```sql
-- ALTER VIEW는 없다!
-- 삭제 후 다시 생성해야 함
DROP VIEW 우수학생;
CREATE VIEW 우수학생 AS
SELECT 학번, 이름, 학과
FROM 학생
WHERE 성적 >= 95;  -- 조건 변경
```

### "뷰의 정의는 변경할 수 없다"의 의미

| 할 수 있는 것 | 할 수 없는 것 |
|-------------|-------------|
| CREATE VIEW (생성) | ALTER VIEW (변경) |
| DROP VIEW (삭제) | 한번 만든 뷰의 SELECT문 수정 |
| DROP 후 다시 CREATE | - |

> 뷰는 **정의(생성)와 삭제만** 가능하고, 수정은 불가!
> 바꾸고 싶으면 **부수고(DROP) 다시 만들기(CREATE)**

### 뷰의 장점
- **보안성**: 민감한 컬럼을 숨기고 필요한 것만 보여줄 수 있음
- **편의성**: 복잡한 쿼리를 뷰로 만들어두면 간단하게 조회 가능
- **독립성**: 기본 테이블 구조가 바뀌어도 뷰를 통해 동일한 형태로 접근 가능

### 뷰에 대한 뷰 (중첩 뷰)

뷰 위에 또 다른 뷰를 만들 수 있다!

```sql
-- 1단계: 컴공과 학생만 뽑는 뷰
CREATE VIEW 컴공학생 AS
SELECT 학번, 이름, 성적 FROM 학생 WHERE 학과 = '컴공';

-- 2단계: 컴공학생 뷰에서 90점 이상만 뽑는 뷰
CREATE VIEW 컴공우수학생 AS
SELECT 학번, 이름 FROM 컴공학생 WHERE 성적 >= 90;
```

> 주의: **원본 뷰를 DROP하면 그 위에 만든 뷰도 사용 불가!**
> 비유: 1층을 없애면 2층도 무너진다

### 뷰를 통한 데이터 변경 (INSERT/UPDATE/DELETE)

뷰는 가상 테이블이지만, **뷰를 통해 원본 테이블의 데이터를 변경할 수 있다.**
INSERT, UPDATE, DELETE 모두 가능하지만 **조건이 까다롭다.**

뷰를 통해 변경하면 → 실제로는 **원본 테이블의 데이터가 바뀌는 것!**

```sql
-- 우수학생 뷰를 통해 INSERT → 원본 학생 테이블에 삽입됨
INSERT INTO 우수학생 VALUES ('003', '박민수', '컴공');

-- 뷰를 통해 UPDATE → 원본 테이블이 수정됨
UPDATE 우수학생 SET 이름 = '박민호' WHERE 학번 = '003';

-- 뷰를 통해 DELETE → 원본 테이블에서 삭제됨
DELETE FROM 우수학생 WHERE 학번 = '003';
```

**단, 다음의 경우에는 변경 불가:**

| 불가 조건 | 이유 |
|----------|------|
| 집계함수 (SUM, AVG, COUNT 등) | 어떤 행을 바꿔야 할지 알 수 없음 |
| DISTINCT | 중복 제거된 결과라 원본 특정 불가 |
| GROUP BY | 그룹화된 결과라 원본 행 특정 불가 |
| 여러 테이블 JOIN | 어느 테이블을 바꿔야 할지 모호 |
| 기본키가 포함되지 않은 뷰 | 어떤 행인지 식별 불가 |

> 핵심 암기: **단순한 뷰(단일 테이블 + PK 포함 + 집계 없음)만 변경 가능!**
> 복잡한 뷰일수록 변경 불가 확률 높음

## 시험 빈출 포인트

### 자주 나오는 문제 유형
1. "뷰에 대한 설명으로 옳지 않은 것은?"
2. "뷰를 통해 데이터 삽입이 불가능한 경우는?"
3. "뷰의 정의를 변경하려면?"  → DROP 후 재생성

### 함정 보기 패턴
- "뷰는 실제 데이터를 저장한다" → ❌ (가상 테이블)
- "ALTER VIEW로 뷰를 수정할 수 있다" → ❌ (DROP 후 CREATE)
- "뷰를 통해 항상 데이터를 변경할 수 있다" → ❌ (제한적)
- "뷰는 독립적인 인덱스를 가진다" → ❌ (가상이니까)

## 헷갈리는 개념 비교

| 구분 | 뷰 (View) | 테이블 (Table) |
|------|-----------|---------------|
| 데이터 저장 | ❌ 없음 (가상) | ⭕ 실제 저장 |
| CREATE | ⭕ 가능 | ⭕ 가능 |
| ALTER | ❌ 불가 | ⭕ 가능 |
| DROP | ⭕ 가능 | ⭕ 가능 |
| SELECT | ⭕ 가능 | ⭕ 가능 |
| INSERT/UPDATE/DELETE | 제한적 | ⭕ 가능 |
