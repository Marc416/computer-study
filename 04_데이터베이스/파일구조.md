# 파일 구조 (파일 편성)

## 핵심 요약
> 컴퓨터가 데이터를 디스크에 저장할 때 **"어떤 방식으로 정리할까?"**의 문제
> 우리가 물건을 정리하는 방식이 여러 가지인 것처럼, 파일 저장 방식도 여러 가지!

---

## 왜 이런 게 필요해?

집에 물건이 100개 있다고 생각해보자.
- 그냥 아무데나 던져놓을 수도 있고 (히프 파일)
- 번호순으로 정리할 수도 있고 (순차 파일)
- 목차를 만들어서 빨리 찾게 할 수도 있고 (ISAM)
- 더 똑똑한 목차를 쓸 수도 있다 (VSAM)

각 방식마다 장단점이 있어서, 시험에서는 **이 차이를 구분**하는 문제가 나온다!

---

## 주요 개념 (쉬운 비유로 이해하기)

### 1. 순차 파일 (Sequential File) — "번호표 순서대로 앉는 극장"
- 1번, 2번, 3번... **키(번호) 순서대로** 차곡차곡 저장
- 앞에서부터 순서대로 읽으면 빠름
- 하지만 중간에 새 데이터를 끼워넣기가 어려움
- 순서가 엉키면 **재구성(reorganization)**을 해서 다시 정렬 가능

### 2. ISAM (Indexed Sequential Access Method) — "목차 있는 사전 + 임시 창고"
- 한국어: **색인 순차 접근 방식**
- 사전을 떠올려보자. "ㄱ→10페이지, ㄴ→50페이지" 이런 **목차(인덱스)**가 있으면 빨리 찾을 수 있다!

**★ 3가지 영역으로 구성 (시험 핵심!)**

| 영역 | 비유 | 역할 |
|------|------|------|
| 인덱스 영역 | 사전의 목차 | 어디에 뭐가 있는지 안내 |
| 데이터 영역 | 사전의 본문 | 실제 데이터가 저장된 곳 |
| 오버플로우 영역 | 임시 창고 | 본문이 꽉 차면 여기에 저장 |

- 인덱스(목차)는 한 번 만들면 **안 바뀜** (정적 인덱스)
- 임시 창고(오버플로우)가 쌓이면 느려짐 → **주기적으로 재조직** 해줘야 함

### 3. VSAM (Virtual Storage Access Method) — "스스로 정리되는 스마트 책장"
- ISAM의 **업그레이드 버전** (IBM에서 만듦)
- ISAM의 문제점: 임시 창고가 쌓이면 느려진다
- VSAM은 **B+ 트리**라는 똑똑한 구조로 알아서 공간을 재배치!
- 그래서 **별도의 오버플로우 영역이 필요 없음**

쉽게 말하면:
- ISAM = 일반 책장 → 칸이 꽉 차면 바닥에 쌓아둠 → 사람이 정리해야 함
- VSAM = 스마트 책장 → 알아서 공간 만들어줌 → 자동 정리

### 4. 히프 파일 (Heap File) — "순서 없이 던져놓는 창고"
- Heap = 영어로 "무더기"
- 이사할 때 박스를 아무데나 쌓아놓는 것처럼, **들어오는 대로 그냥 저장**
- 넣는 건 빠르지만, 찾으려면 처음부터 끝까지 다 뒤져야 함
- 가장 단순한 파일 구조

### 5. 직접 파일 (Direct/Hash File) — "사물함 번호로 바로 찾기"
- 해싱 함수(계산 공식)로 **저장 위치를 바로 계산**
- 찾는 속도가 매우 빠름
- 단점: 서로 다른 데이터가 같은 위치로 계산되는 **충돌(collision)** 문제 발생 가능

---

## 시험 빈출 포인트 ⭐

1. **ISAM = 인덱스 + 데이터 + 오버플로우** (3개 영역!) ← 가장 많이 출제!
2. **VSAM = B+ 트리** 사용, 오버플로우 영역 없음
3. **히프 파일 = 순서 없이 저장** (가장 단순)
4. ISAM은 오버플로우 쌓이면 → **재조직(reorganization)** 필요
5. ISAM의 인덱스는 삽입/삭제해도 **변경 안 됨** (정적)
6. VSAM의 인덱스는 삽입/삭제하면 **자동 변경** (동적)

## 헷갈리는 개념 비교 (시험 단골!)

### ISAM vs VSAM (바꿔서 출제 많이 함!)

| 구분 | ISAM | VSAM |
|------|------|------|
| 비유 | 목차 있는 사전 + 임시창고 | 스마트 책장 |
| 인덱스 구조 | 정적 (안 바뀜) | B+ 트리 (동적) |
| 오버플로우 영역 | **있음** ← 시험 핵심! | **없음** |
| 재조직 | 사람이 주기적으로 해야 함 | 자동 관리 |

### 전체 파일 구조 비교

| 구분 | 비유 | 저장 순서 | 검색 | 삽입 |
|------|------|-----------|------|------|
| 순차 파일 | 번호표 극장 | 키 순서대로 | 순차 빠름 | 느림 |
| ISAM | 사전+임시창고 | 키 순서+인덱스 | 빠름 | 보통 |
| VSAM | 스마트 책장 | B+트리 | 빠름 | 빠름 |
| 히프 파일 | 물건 던져놓는 창고 | 순서 없음 | 느림 | 빠름 |
| 직접 파일 | 사물함 번호 | 해시 함수 | 매우 빠름 | 빠름 |

> Q: 파일구조에 대한 설명으로 옳지 않은 것은?

| 보기 | 내용 | O/X | 이유 |
|------|------|-----|------|
| ① | VSAM은 B+ 트리 인덱스 구조를 사용 | ✅ | VSAM의 핵심 특징 |
| ② | 히프 파일은 키 순서 관계없이 저장 | ✅ | 히프 = 순서 없이 저장 |
| ③ | ISAM은 오버플로우 영역이 필요 없다 | ❌ | ISAM은 오버플로우 **필요함!** |

**정답: ③** — ISAM은 오버플로우 영역이 반드시 필요하다!
