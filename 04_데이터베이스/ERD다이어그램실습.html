ERD 다이어그램 실습

개체-관계 모델을 실제 도형으로 그리고 테이블로 변환하기 · PART 05. 데이터베이스론

핵심 요약

ERD는 사각형(개체) · 마름모(관계) · 타원(속성) 3가지 도형으로만 그린다. 변환 규칙은 ER다이어그램_관계형변환 문서에 표로 정리되어 있으니, 이 문서는 실제로 그림이 어떻게 생겼는지에 집중한다.

💡주요 개념 — ERD 표기법

3가지 기본 도형

실전 예제 1. 1:N 관계 — 공장이 판매처에 물건을 주문받는 구조 📖 기출문제집 (계리직 기출) 참고

공장(1) : 판매처(N) = 하나의 공장이 여러 판매처로부터 주문을 받는 구조. 기존 문서의 예제를 그림으로 그리면 다음과 같다.

테이블 변환 결과:

판매처 테이블공장 테이블
판매처번호, 담당자, 공장명(FK), 수량공장명, 단가
왜 N쪽에 다 몰아넣나? 판매처 1곳은 공장 1곳으로부터만 주문하므로(N:1 방향), 판매처 레코드 하나에 공장명(FK) 하나만 적으면 관계가 표현된다. 반대로 공장 테이블에 판매처를 넣으려면 공장 하나가 여러 판매처를 가지므로 한 칸에 여러 값이 들어가야 해서 정규화 위반이 된다.

실전 예제 2. M:N 관계 — 학생과 과목의 수강 관계

테이블 변환 결과 (3개 테이블):

학생수강 (관계 테이블)과목
학번, 이름학번(FK)+과목코드(FK) = 복합PK, 성적과목코드, 과목명

📌시험 빈출 포인트

  • 도형 매칭: 사각형=개체, 마름모=관계, 타원=속성 — 반대로 나오면 오답
  • 기본키(PK) 속성은 타원 안 글자에 밑줄로 표시
  • 1:N 관계의 속성은 N쪽 테이블에, M:N 관계는 반드시 별도 테이블 생성
  • M:N 관계 테이블의 기본키는 양쪽 FK를 합친 복합키
