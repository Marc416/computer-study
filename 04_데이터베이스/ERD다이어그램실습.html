ERD 다이어그램 실습

ERD 표기법 · 관계형 스키마 변환 · 키(Key) 결정 · PART 05. 데이터베이스론

핵심 요약

ERD는 사각형(개체) · 마름모(관계) · 타원(속성) 3가지 도형이 기본. 도형 매칭 문제가 그대로 나온다.

변환 규칙의 핵심 두 줄: 1:N이면 1쪽의 키를 N쪽에 외래키로 넣고, M:N이면 반드시 별도 테이블을 만든다.

🎯이 단원을 왜 배우나

"머릿속 구상"을 "실제 테이블"로 옮기는 다리

데이터베이스를 만들 때 바로 테이블부터 그리지 않는다. 먼저 "이 업무에는 어떤 대상들이 있고 서로 무슨 관계인가"를 그림으로 정리하는데, 그게 ERD(개체-관계 다이어그램)다. 이 단계를 개념적 설계라 부르고, 이걸 실제 테이블 구조로 바꾸는 단계를 논리적 설계라 한다.

왜 굳이 그림을 한 번 거치나? 테이블부터 만들면 관계를 표현할 방법을 잘못 골라서 나중에 데이터가 중복되거나 한 칸에 값을 여러 개 넣어야 하는 사태가 벌어지기 때문이다. ERD를 먼저 그리면 "이건 1:N이네, 그럼 외래키를 이쪽에 두면 되겠다"가 기계적으로 결정된다.

시험은 이 "기계적 결정"을 정확히 묻는다. 출제 형태는 딱 두 가지다 — ① 도형·표기법이 무엇을 뜻하는지, ② ERD 그림을 주고 올바른 관계형 스키마(테이블 목록)를 고르게 하기. ②번은 계리직에서 거의 매년 나오는데, 아래 변환 규칙 3줄만 외우면 선택지를 하나씩 소거해 확실히 맞힐 수 있다.

💡주요 개념 — ERD 표기법

3가지 기본 도형 📖 기출문제집 p.541

타원의 변형 — 속성의 종류를 모양으로 구별한다

속성은 전부 타원이지만, 선의 모양으로 종류를 나눈다. 특히 다중값 속성(이중선 타원)은 "이 그림에서 다중값 속성을 찾아라" 형태로 출제된다.

기출 함정(2021 지방직): ER 다이어그램을 주고 "다중값 속성을 가지고 있다"는 선택지를 넣는데, 실제 그림의 속성이 전부 실선 타원(단일값)이면 그 선택지가 오답이다. 그림 문제에서는 선이 한 겹인지 두 겹인지부터 확인해라.

변환 규칙 3줄 — 이것만 알면 변환 문제는 끝

ERD → 관계형 스키마

  1. 개체(사각형) → 각각 하나의 테이블이 된다
  2. 1:N 관계 → 별도 테이블을 만들지 않고, 1쪽의 기본키를 N쪽 테이블에 외래키로 추가한다. 관계에 딸린 속성도 N쪽에 함께 넣는다
  3. M:N 관계 → 양쪽 어디에도 담을 수 없으므로 반드시 별도 테이블을 만들고, 양쪽 기본키를 모두 외래키로 가져와 복합 기본키로 삼는다. 관계 속성도 이 테이블에 넣는다

왜 1:N은 N쪽인가? 판매처 1곳은 공장 1곳에서만 주문하므로 판매처 레코드에 공장명 한 개만 적으면 끝난다. 반대로 공장 테이블에 판매처를 적으려면 공장 하나가 여러 판매처를 가지므로 한 칸에 값 여러 개가 들어가야 해서 원자성(1NF) 위반이 된다. "여러 개를 가진 쪽이 아니라, 하나만 가진 쪽 정보를 상대에게 준다"고 기억하면 방향을 헷갈리지 않는다.

🏭실전 예제 1 — 1:N 관계 변환 📖 기출문제집 p.542

공장(1) : 판매처(N) = 하나의 공장이 여러 판매처로부터 주문을 받는 구조. 2022 계리직에 그대로 출제된 형태다.

  1. 개체가 2개(공장, 판매처)이므로 테이블도 기본 2개
  2. 1:N이므로 관계 "주문"은 별도 테이블이 되지 않는다 → 테이블 총 2개로 확정 (선택지에 테이블 3개짜리가 있으면 소거)
  3. 1쪽(공장)의 기본키 공장명을 N쪽(판매처)에 외래키로 추가
  4. 관계 속성 수량도 N쪽(판매처)에 추가
판매처 테이블공장 테이블
판매처번호, 담당자, 공장명(FK), 수량공장명, 단가
선택지 소거 요령: 이 유형은 ① 테이블이 몇 개인지, ② 외래키가 어느 쪽에 붙었는지 두 가지만 보면 대부분 답이 하나로 좁혀진다. 공장 테이블에 판매처번호가 들어간 선택지는 방향이 반대라 바로 오답이다.

🎓실전 예제 2 — M:N 관계 변환 📖 기출문제집 p.543

학생과 과목은 서로 여러 개를 가질 수 있다(한 학생이 여러 과목, 한 과목에 여러 학생). 2023 계리직 출제 형태다.

  1. 개체 2개(학생, 과목) + M:N 관계 1개 → 테이블은 총 3개
  2. 관계 테이블 "등록"에 학생의 PK(학번)와 과목의 PK(과목번호)를 둘 다 가져온다
  3. 이 둘을 합친 {학번, 과목번호}가 복합 기본키이자, 각각 학생·과목 테이블을 참조하는 외래키가 된다
  4. 관계 속성 성적도 등록 테이블에 추가
학생등록 (관계 테이블)과목
학번, 이름학번(FK) + 과목번호(FK) = 복합PK, 성적과목번호, 과목명
왜 둘 다 필요한가: 등록 테이블에 학번만 있으면 "누가 등록했는지"는 알아도 "무슨 과목인지"를 모른다. 반대도 마찬가지다. 어떤 학생이 어떤 과목에 등록했는지를 정확히 표현하려면 두 키가 모두 있어야 하고, 그래서 복합키가 된다.

🔑주요 개념 — 키(Key)의 종류 📖 기출문제집 p.545~547

ERD를 테이블로 바꿀 때 "무엇을 기본키로 삼을지" 정해야 하므로, 키 개념이 함께 출제된다. 다섯 종류의 관계를 포함 관계로 그려두면 한 번에 정리된다.

키유일성최소성정의
슈퍼키OX튜플을 유일하게 식별하지만, 불필요한 속성이 붙어 있어도 됨
후보키OO유일하게 식별하면서 속성을 하나라도 빼면 식별 불가해지는 최소 집합
기본키OO후보키 중 대표로 선택된 하나 (NULL 불가)
대체키OO후보키 중 기본키로 선택되지 않은 나머지
외래키-다른(또는 자기) 릴레이션의 기본키를 참조하는 속성

유일성과 최소성, 말로 풀면

유일성 = 그 값만 보면 행을 딱 하나로 집어낼 수 있다. 최소성 = 속성을 하나라도 빼면 그 능력이 사라진다(= 군더더기가 없다).

예를 들어 {학번}이 후보키라면, {학번, 이름}도 여전히 유일하게 식별은 된다 → 유일성 O. 하지만 이름을 빼도 학번만으로 식별되므로 최소성 X → 이건 후보키가 아니라 슈퍼키다. "유일성은 만족하지만 최소성은 만족하지 못하는 키"라는 문제 문구가 나오면 무조건 슈퍼키다.

차수 vs 카디널리티 (2024 법원직 함정): 하나의 릴레이션에서 속성(열)의 개수 = 차수(degree), 튜플(행)의 개수 = 카디널리티(cardinality)다. 문제에서 "속성의 전체 개수를 카디널리티라 한다"고 하면 틀린 설명이다.

📌시험 빈출 포인트

  • 도형 매칭: 사각형=개체, 마름모=관계, 타원=속성 — 서로 바꿔 놓으면 오답
  • 다중값 속성 = 이중선 타원, 유도 속성 = 점선 타원, 기본키 = 밑줄
  • 1:N 변환 → 별도 테이블 없음, 1쪽 PK를 N쪽에 FK로 + 관계 속성도 N쪽에
  • M:N 변환 → 반드시 별도 테이블, 양쪽 PK를 모아 복합 기본키
  • 유일성 O + 최소성 X = 슈퍼키 / 둘 다 O = 후보키
  • 기본키로 안 뽑힌 후보키 = 대체키 (외래키가 아님 — 단골 함정)
  • 차수=속성 개수, 카디널리티=튜플 개수
  • 후보키 판정 문제는 주어진 인스턴스(데이터)로 직접 중복 여부를 확인해야 한다

문제 12014 서울시 · 기출문제집 p.541

개체 관계 모델(Entity-Relationship model)을 그래프 방식으로 표현한 E-R 다이어그램에서 마름모 모양으로 표현되는 것은?

  1. 개체 타입(entity type)
  2. 관계 타입(relationship type)
  3. 속성(attribute)
  4. 키 속성(key attribute)
  5. 링크(link)
해설 보기

정답 ② 관계 타입

도형 매칭은 암기 항목이다: 사각형=개체, 마름모=관계, 타원=속성, 선(링크)=연결.

암기 팁: 마름모는 두 사각형 사이에 끼어 둘을 이어주는 모양으로 그려진다. "가운데 껴 있는 도형 = 관계"로 그림의 위치와 함께 외우면 헷갈리지 않는다.

문제 22022 계리직 · 기출문제집 p.542

공장(1) : 판매처(N)의 주문 관계를 나타낸 E-R 다이어그램을 관계형 스키마로 올바르게 변환한 것은?
공장{공장명(PK), 단가}, 판매처{판매처번호(PK), 담당자}, 주문 관계에 "수량" 속성이 달림. 밑줄은 기본키.

  1. 판매처(판매처번호, 담당자) / 공장(공장명, 단가, 판매처번호, 수량)
  2. 판매처(판매처번호, 담당자, 공장명, 수량) / 공장(공장명, 단가)
  3. 판매처(판매처번호, 담당자) / 주문(판매처번호, 수량) / 공장(공장명, 단가)
  4. 판매처(판매처번호, 담당자) / 주문(공장명, 수량) / 공장(공장명, 단가)
해설 보기

정답 ②

  1. 1:N이므로 관계 테이블을 만들지 않는다 → 테이블 3개인 ③·④ 소거
  2. 남은 ①·② 중, 1쪽(공장)의 PK인 공장명이 N쪽(판매처)에 FK로 들어가야 한다 → ①은 반대 방향(공장에 판매처번호)이라 소거
  3. 관계 속성 수량도 N쪽인 판매처에 함께 들어간다 → ②가 정확히 이 형태

왜 ①이 안 되나: 공장 하나가 여러 판매처를 상대하므로, 공장 테이블에 판매처번호를 넣으려면 한 행에 판매처번호를 여러 개 적어야 한다. 이는 원자값 위반이다.

참고: 굳이 주문을 별도 릴레이션으로 만든다면 판매처번호와 공장명을 모두 외래키로 포함하고 기본키는 판매처번호가 되어야 하는데, ③·④는 둘 중 하나만 있어서 어느 쪽이든 틀렸다.

문제 32023 계리직 · 기출문제집 p.543

학생(M) : 과목(N)의 등록 관계(성적 속성 포함)를 나타낸 E-R 다이어그램을 관계형 스키마로 올바르게 변환한 것은?
학생{학번(PK), 이름}, 과목{과목번호(PK), 과목명}. 밑줄은 기본키.

  1. 학생(학번, 이름) / 등록(성적) / 과목(과목번호, 과목명)
  2. 학생(학번, 이름) / 등록(과목번호, 성적) / 과목(과목번호, 과목명, 성적)
  3. 학생(학번, 이름) / 등록(학번, 성적) / 과목(과목번호, 과목명)
  4. 학생(학번, 이름) / 등록(학번, 과목번호, 성적) / 과목(과목번호, 과목명)
해설 보기

정답 ④

  1. M:N이므로 관계 테이블 "등록"이 반드시 필요하다 (네 선택지 모두 만들었으므로 여기선 소거 안 됨)
  2. 등록 테이블은 학번과 과목번호를 둘 다 가져야 "어떤 학생이 어떤 과목에 등록했는지"를 표현할 수 있다 → 학번만 있는 ③, 과목번호만 있는 ②, 아무 키도 없는 ① 전부 소거
  3. {학번, 과목번호}가 복합 기본키이면서 각각 학생·과목에 대한 외래키 역할을 한다
  4. 관계 속성 성적은 등록 테이블에 들어간다 (②처럼 과목 테이블에 넣으면 안 됨 — 성적은 과목의 속성이 아니라 "학생이 그 과목에서 받은" 값이므로)

핵심 판별: M:N 문제는 "관계 테이블에 양쪽 키가 모두 있는가" 한 가지만 보면 대부분 즉시 답이 나온다.

문제 42014 서울시 · 기출문제집 p.545

데이터베이스 키(key)에 대한 다음 설명에 해당하는 키는?
릴레이션에 있는 모든 투플들을 유일하게 식별할 수 있는 애트리뷰트의 부분집합으로 유일성과 최소성을 만족함

  1. 기본키(primary key)
  2. 후보키(candidate key)
  3. 대체키(alternate key)
  4. 슈퍼키(super key)
  5. 외래키(foreign key)
해설 보기

정답 ② 후보키

"유일성 + 최소성"이라는 문구가 곧 후보키의 정의다.

①번을 고르면 안 되는 이유: 기본키도 유일성·최소성을 만족하지만, 기본키는 "후보키 중에서 대표로 뽑힌 것"이라는 선택 과정이 정의에 포함된다. 문제 지문에 "선택된"이라는 말이 없으면 답은 후보키다. 지문에 "후보키 중에서 선택된"이 있으면 기본키, "선택되지 않은 나머지"면 대체키다.

문제 52021 국회 · 기출문제집 p.546

릴레이션을 구성하는 모든 튜플에 대해 유일성은 만족하지만 최소성은 만족하지 못하는 키로 옳은 것은?

  1. 기본키(Primary Key)
  2. 대체키(Alternate Key)
  3. 복합키(Composite Key)
  4. 후보키(Candidate Key)
  5. 슈퍼키(Super Key)
해설 보기

정답 ⑤ 슈퍼키

유일성만 만족하고 최소성은 만족하지 않는 키 = 슈퍼키. 기본키·대체키·후보키는 전부 최소성까지 만족한다.

구체적 예: 학생 테이블에서 {학번}이 후보키라면, {학번, 이름}, {학번, 주소}, {학번, 이름, 나이} … 이 모든 조합이 슈퍼키다. 학번만으로 이미 식별되니 나머지는 군더더기지만, 여전히 유일하게 식별은 되기 때문이다.

함정: ③번 복합키는 "여러 속성을 묶어 만든 키"라는 구성 방식에 대한 말이지, 최소성 여부와는 무관한 개념이다.

속성 A, B, C로 정의된 릴레이션의 인스턴스가 아래와 같을 때, 후보키의 조건을 충족하는 것은?

ABC
1127
20127
1123

126
  1. (A)
  2. (A, C)
  3. (B, C)
  4. (A, B, C)
해설 보기

정답 ② (A, C)

후보키 = 유일성 O + 최소성 O. 각 선택지의 값 조합을 실제로 나열해 중복이 있는지 확인하면 된다.

  1. (A): 1, 20, 1, 1, 1 → 1이 네 번 중복 → 유일성 ✕
  2. (A, C): (1,7), (20,7), (1,3), (1,4), (1,6) → 전부 서로 다름 → 유일성 O. A만·C만으로는 식별 불가하므로 최소성도 O → 후보키
  3. (B, C): (12,7), (12,7), (12,3), (1,4), (2,6) → 1행과 2행이 완전히 같음 → 유일성 ✕
  4. (A, B, C): 유일성은 만족하지만, 이미 (A,C)만으로 식별되므로 B가 군더더기 → 최소성 ✕ (슈퍼키)

풀이 순서: ① 후보 조합별로 값을 실제로 적어본다 → ② 같은 줄이 있으면 즉시 탈락 → ③ 살아남은 것 중 속성을 하나 빼도 여전히 유일한지 확인해 최소성을 검사한다.

문제 72016 계리직 · 기출문제집 p.547

직원 테이블 직원(사번, 이름, 주민등록번호, 주소, 나이, 성별, 부서번호)에서 키와 관련된 설명으로 옳지 않은 것은?
(단, 사번과 주민등록번호는 각각 유일한 값을 갖고, 부서번호는 부서 테이블을 참조하며, 나이가 같은 동명이인이 존재할 수 있다.)

  1. 부서번호는 외래키이다.
  2. 사번은 기본키가 될 수 있다.
  3. (이름, 나이)는 후보키가 될 수 있다.
  4. 주민등록번호는 대체키가 될 수 있다.
해설 보기

정답 ③

문제 단서에 "나이가 같은 동명이인이 존재할 수 있다"가 명시돼 있다. 즉 (이름, 나이)가 같은 행이 둘 이상 나올 수 있으므로 유일성이 깨진다 → 후보키가 될 수 없다.

  1. ① 부서번호는 부서 테이블의 기본키를 참조한다고 했으므로 외래키 → 옳음
  2. ② 사번은 유일하다고 했으므로 기본키 후보 → 옳음
  3. ④ 주민등록번호도 유일하므로 후보키이고, 기본키로 사번을 뽑았다면 나머지 후보키인 주민등록번호는 대체키 → 옳음

출제 포인트: 이런 문제는 괄호 안 단서가 정답을 결정한다. "동명이인이 있을 수 있다", "값이 중복될 수 있다" 같은 조건이 보이면 그것과 연결된 선택지가 정답일 확률이 매우 높다.

문제 82024 법원직 · 기출문제집 p.545

릴레이션에 대한 설명 중 가장 옳지 않은 것은?

  1. 하나의 릴레이션에서 속성의 전체 개수를 카디널리티라 한다.
  2. 릴레이션 스키마는 릴레이션의 이름과 포함된 모든 속성의 이름을 정의하는 논리적 구조를 의미한다.
  3. 릴레이션의 특성 중 튜플의 유일성과 속성의 무순서 특성도 존재한다.
  4. 릴레이션의 특성 중 속성의 원자성은 속성값으로 원자값만을 사용할 수 있다는 의미이다.
해설 보기

정답 ①

속성(열)의 개수는 차수(degree)다. 카디널리티(cardinality)는 튜플(행)의 개수를 뜻한다.

암기법: 카디널리티 = 가로줄(행) 개수, 디그리(차수) = 더 세로줄(열) 개수. 또는 "카드(card)를 몇 장 쌓았나 = 행 수"로 외워도 된다.

나머지는 릴레이션의 기본 특성 그대로다 — 튜플은 모두 상이(유일성), 속성 간 순서 없음, 튜플 간 순서 없음, 속성값은 원자값(더 이상 분해 불가).

문제 9개념 확인 · 응용

"한 명의 교수는 여러 강의를 담당하고, 하나의 강의는 반드시 한 명의 교수만 담당한다"는 구조를 ERD로 그린 뒤 테이블로 변환하면 테이블은 몇 개가 되고, 외래키는 어느 테이블에 들어가는가?

해설 보기

정답: 테이블 2개 / 외래키는 강의 테이블에 교수번호(PK) 추가

  1. 관계 판정: 교수 1명 → 강의 여러 개, 강의 1개 → 교수 1명 = 교수(1) : 강의(N)
  2. 1:N이므로 관계는 별도 테이블이 되지 않는다 → 개체 수 그대로 테이블 2개(교수, 강의)
  3. 1쪽(교수)의 기본키를 N쪽(강의)에 외래키로 넣는다 → 강의(강의코드, 강의명, 교수번호(FK))

확인 논리: 강의 한 행에 교수번호를 하나만 적으면 되는가? → 강의는 교수 1명만 담당하므로 하나면 충분하다 → 방향이 맞다. 반대로 교수 테이블에 강의코드를 넣으면 한 교수가 여러 강의를 하므로 값이 여러 개 필요해져 실패한다.
