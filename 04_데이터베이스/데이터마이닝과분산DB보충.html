데이터마이닝과 분산DB 보충

연관규칙 지지도·신뢰도 계산, 분산DB 단편화 투명성 · PART 05. 데이터베이스론

핵심 요약

데이터마이닝은 대량 데이터에서 패턴을 찾아내는 것 — 그 중 "장바구니 분석(연관규칙)"의 지지도·신뢰도 계산이 최다빈출.

분산DB의 단편화 투명성은 기존 분산 데이터베이스 문서에 없던 내용이라 여기서 보충.

💡주요 개념 — 데이터마이닝

데이터마이닝 5대 규칙 📖 기출문제집 p.603

규칙하는 일
연관 규칙 (Association)여러 트랜잭션에서 동시에 발생하는 항목들의 관계 발견 ("기저귀 사면 맥주도 산다")
연속성 규칙 (Sequence)개인별 이력을 시계열로 분석해 향후 발생 가능성 예측
분류 규칙 (Classification)이미 알려진 그룹의 특징에 맞춰 새 데이터를 분류
군집 규칙 (Clustering)유사한 데이터끼리 그룹화 (정답 그룹이 미리 정해져 있지 않음)
특성화 규칙 (Characterization)특정 클래스·그룹만의 고유한 특징을 도출
함정 주의: "특성화 규칙이 시계열로 트랜잭션 발생 가능성을 예측한다" → ❌ 그건 연속성 규칙(Sequence)의 역할이다. 특성화 규칙은 예측이 아니라 "고유 특징 도출"이 핵심.
구별 팁: 분류(Classification)는 "이미 정해진 그룹 중 어디에 속하나", 군집(Clustering)은 "정해진 그룹이 없는 상태에서 비슷한 것끼리 스스로 묶기" — 학교로 치면 분류는 "반 배정", 군집은 "쉬는 시간에 끼리끼리 모이기".

지지도(Support)와 신뢰도(Confidence) 계산

지지도 = 전체 트랜잭션 중 두 항목이 같이 나온 비율. 신뢰도 = 항목 A가 나온 트랜잭션 중에서 항목 B도 같이 나온 비율(조건부 확률).

지지도(A,B) = (A와 B를 모두 포함한 트랜잭션 수) ÷ (전체 트랜잭션 수)
신뢰도(A→B) = (A와 B를 모두 포함한 트랜잭션 수) ÷ (A를 포함한 트랜잭션 수)

예제. 아래 5개 거래 기록에서 "기저귀 → 맥주" 규칙의 신뢰도는? 📖 기출문제집 p.602

거래번호구매 품목
1맥주, 땅콩, 기저귀
2맥주, 커피, 기저귀
3맥주, 기저귀, 계란
4땅콩, 계란, 우유
5땅콩, 커피, 기저귀, 우유
  1. 규칙이 "기저귀 → 맥주"이므로 분모는 기저귀를 산 거래 수를 센다
  2. 기저귀가 포함된 거래: 1, 2, 3, 5번 → 총 4건
  3. 그 중 맥주도 같이 산 거래: 1, 2, 3번 → 3건 (5번은 기저귀만 있고 맥주 없음)
  4. 신뢰도 = 3 ÷ 4 = 0.75
함정 주의: 분모를 "전체 거래 수(5)"로 착각하면 안 된다 — 신뢰도의 분모는 조건절(기저귀)이 나온 거래 수다. 전체 거래 수로 나누는 것은 지지도 계산법이다.

🌐주요 개념 — 분산DB 단편화 투명성

분산 데이터베이스 문서에는 위치·중복·병행·장애 투명성이 정리되어 있다. 여기서는 그 목록에 없던 단편화(분할) 투명성을 보충한다.

단편화(Fragmentation)의 3가지 방식 📖 기출문제집 p.600

방식쪼개는 기준
수평적 단편화행(row) 기준으로 나눔 — 예: 서울지점 고객 / 부산지점 고객
수직적 단편화열(column) 기준으로 나눔 — 예: 자주 조회하는 컬럼 / 거의 안 쓰는 컬럼
혼합 단편화행과 열 기준을 둘 다 적용
함정 주의: "장애 투명성은 장애가 발생하지 않도록 예방하는 것" → ❌ 틀림. 장애 투명성은 장애가 나도 사용자가 정상적으로 계속 쓸 수 있게 하는 것이지, 장애 자체를 막는 개념이 아니다.

📌시험 빈출 포인트

  • 지지도·신뢰도 계산 문제 — 분모를 무엇으로 하는지가 함정 포인트
  • 데이터마이닝 5대 규칙의 이름과 설명 매칭
  • 단편화 투명성의 3가지 방식(수평/수직/혼합) 구분
  • 장애 투명성 = "장애 예방"이 아니라 "장애 발생해도 정상 이용 가능"
