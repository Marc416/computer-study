데이터마이닝과 분산 데이터베이스

연관규칙 지지도·신뢰도 계산 · 분산 투명성 5종 · 2단계 완료 규약 · PART 05. 데이터베이스론

핵심 요약

데이터마이닝 계산문제는 "분모를 무엇으로 하느냐" 하나로 갈린다 — 지지도는 전체, 신뢰도는 조건절(A).

분산DB는 투명성 5종(위치·단편화·중복·장애·병행)의 정의 매칭이 전부. 특히 장애 투명성 = 장애를 막는 게 아니라, 나도 계속 쓸 수 있게 하는 것.

🎯이 단원을 왜 배우나

"쌓아둔 데이터"에서 돈이 되는 패턴을 캐낸다

DB에 거래 기록이 수백만 건 쌓여도, 그 자체로는 그냥 로그일 뿐이다. 여기서 "기저귀를 사는 사람은 맥주도 같이 산다" 같은 규칙을 찾아내면 매대 배치를 바꿔 매출을 올릴 수 있다. 이렇게 대량 데이터에서 숨은 패턴·규칙을 캐내는(mining) 작업이 데이터마이닝이다.

시험에 나오는 건 딱 두 가지다 — ① 5대 규칙의 이름과 설명 매칭, ② 지지도·신뢰도 계산. ②번은 공식만 알면 20초 안에 풀리는 확정 득점 문제인데, 분모를 잘못 잡아 틀리는 사람이 대부분이다.

데이터베이스가 여러 곳에 흩어져 있다면

본사와 지점이 각자 DB를 갖고 있는데 사용자는 하나의 DB처럼 쓰고 싶다. 이를 가능하게 하는 것이 분산 데이터베이스이고, 핵심 목표는 "흩어져 있다는 사실을 사용자에게 숨기는 것" — 이게 바로 투명성(transparency)이다.

투명성은 다섯 종류인데 출제는 정의를 한 줄씩 바꿔 놓고 틀린 것 찾기가 거의 전부다. 특히 장애 투명성을 "장애가 일어나지 않게 예방하는 것"으로 바꾼 선택지가 단골 정답이니, 다섯 개 정의를 문장째로 익혀두면 된다.

⛏️주요 개념 — 데이터마이닝

데이터마이닝 5대 규칙 📖 기출문제집 p.603

규칙교과서 정의 (시험 문구)한 단어 요약
연관 규칙
(Association)		여러 개의 트랜잭션들 중에서 동시에 발생하는 트랜잭션의 연관관계를 발견같이 산다
연속성 규칙
(Sequence)		개인별 트랜잭션 이력 데이터를 시계열적으로 분석하여 향후 발생 가능성을 예측다음에 산다
분류 규칙
(Classification)		이미 알려진 특정 그룹의 특징을 부여하고 정의된 분류에 맞게 구분정해진 칸에 넣기
군집 규칙
(Clustering)		상호 유사한 특성을 갖는 데이터들을 그룹화하여 패턴 분석비슷한 것끼리
특성화 규칙
(Characterization)		특정 클래스나 그룹의 고유한 특징을 도출이 집단의 특징
최다 함정(2025 소방경채): "특성화 규칙은 트랜잭션 이력을 시계열로 분석해 향후 발생 가능성을 예측한다" → ❌ 그건 연속성 규칙(Sequence)의 정의다. 특성화는 예측이 아니라 "특징 도출"이다. "시계열·예측"이라는 단어가 보이면 무조건 연속성 규칙으로 반응하면 된다.
분류 vs 군집 구별: 분류는 "이미 정해진 그룹 중 어디에 속하나"(정답표가 있음), 군집은 "정해진 그룹 없이 비슷한 것끼리 스스로 묶기"(정답표가 없음). 학교로 치면 분류는 반 배정, 군집은 쉬는 시간에 끼리끼리 모이기.

지지도·신뢰도 — 분모가 전부다

연관 규칙 A → B("A를 사면 B도 산다")의 품질을 재는 두 지표다. 분자는 둘 다 같고 분모만 다르다.

지지도(A, B) = (A와 B를 모두 포함한 트랜잭션 수) ÷ (전체 트랜잭션 수)
신뢰도(A → B) = (A와 B를 모두 포함한 트랜잭션 수) ÷ (A를 포함한 트랜잭션 수)

왜 두 지표가 다 필요한가

신뢰도만 보면 함정에 빠진다. 전체 10,000건 중 A와 B가 함께 나온 게 딱 2건이고 A가 나온 것도 2건이라면 신뢰도는 100%지만, 이건 그냥 우연히 두 번 겹친 것일 뿐 규칙이라 할 수 없다. 이때 지지도는 2/10000 = 0.02%로 매우 낮게 나와 "표본이 너무 적다"는 경고를 준다.

그래서 실무에서는 지지도로 먼저 거르고(충분히 자주 나오는가), 신뢰도로 규칙의 강도를 판단한다. 시험에서는 이 둘을 각각 계산하게 하거나, 어느 쪽 분모인지 헷갈리게 하는 식으로 출제된다.

예제. 아래 5개 거래에서 "기저귀 → 맥주" 규칙의 지지도와 신뢰도는? 📖 기출문제집 p.602

거래번호구매 품목기저귀?맥주?
1맥주, 땅콩, 기저귀OO
2맥주, 커피, 기저귀OO
3맥주, 기저귀, 계란OO
4땅콩, 계란, 우유XX
5땅콩, 커피, 기저귀, 우유OX
  1. 표에 "기저귀?" "맥주?" 열을 직접 추가해 O/X를 적는다 — 이 한 단계가 실수를 없앤다
  2. 둘 다 O인 거래 = 1, 2, 3번 → 3건 (이것이 공통 분자)
  3. 기저귀가 있는 거래 = 1, 2, 3, 5번 → 4건 / 전체 거래 = 5건
  4. 신뢰도(기저귀→맥주) = 3 ÷ 4 = 0.75 (분모 = 기저귀 거래 수)
  5. 지지도(기저귀, 맥주) = 3 ÷ 5 = 0.6 (분모 = 전체 거래 수)
함정: 신뢰도를 구하라고 했는데 분모를 전체 거래 수(5)로 잡으면 0.6이 나온다. 선택지에 0.6과 0.75가 나란히 놓여 있는 이유가 바로 이것이다. "A → B"에서 화살표 왼쪽(A)이 분모라고 기억해라.

🌐주요 개념 — 분산 데이터베이스

분산 DB란 📖 기출문제집 p.600

네트워크로 연결된 여러 사이트에 데이터베이스 자체가 분산되어 있고, DBMS도 각 사이트에서 운영된다. 사용자는 다른 사이트의 데이터에도 접근할 수 있으며, 분산되지 않은 하나의 DB처럼 보이게 만드는 것이 목표다.

장점단점
데이터를 분산해 트랜잭션 처리 성능 향상설계와 관리가 복잡하고 비용이 큼
데이터를 중복 저장해 가용성·신뢰성 향상여러 사이트에 걸친 무결성 유지가 어려움
지역 사이트별 자율성과 점진적 확장 용이네트워크 장애 시 응답 지연 가능
함정(2012 지방직): "지역 사이트에 있는 모든 DBMS가 동일해야 한다" → ❌ 틀림. 서로 다른 DBMS를 써도 ODBC(Open DataBase Connectivity) 같은 표준 인터페이스로 상호 호환이 가능하다. "동일해야 한다·같아야 한다"처럼 강한 제약을 주장하는 선택지는 대체로 오답이다.

분산 투명성 5종 — 정의 그대로 외우기

투명성정의 (시험 문구)
위치 투명성
(Location)		데이터가 어디에 저장되어 있는지 몰라도 논리적 이름만으로 접근 가능
단편화(분할) 투명성
(Fragmentation)		데이터가 여러 조각으로 나뉘어 저장되어도 하나인 것처럼 사용
중복 투명성
(Replication)		데이터가 여러 곳에 중복되어 있어도 동일한 값을 유지·하나처럼 사용
장애 투명성
(Failure)		일부 시스템에 장애가 발생해도 사용자는 정상적으로 사용 가능
병행 투명성
(Concurrency)		여러 사용자가 동시에 접근해도 충돌 없이 일관된 결과 제공
매년 나오는 함정(2025 법원직): "장애 투명성은 장애가 발생하지 않도록 조치하여 DB가 운영되는 것" → ❌ 틀림. 장애 투명성은 장애를 막는 것이 아니라, 장애가 나도 사용자는 모른 채 계속 쓸 수 있게 하는 것이다. 투명성은 전부 "사용자에게 숨긴다"는 뜻이지 "문제를 없앤다"는 뜻이 아니라는 점을 기억해라.

단편화(Fragmentation)의 3가지 방식

방식쪼개는 기준
수평적 단편화행(row) 기준 — 예: 서울지점 고객 / 부산지점 고객
수직적 단편화열(column) 기준 — 예: 자주 조회하는 컬럼 / 거의 안 쓰는 컬럼
혼합 단편화행과 열 기준을 둘 다 적용

2단계 완료 규약(2PC, Two-Phase Commit) 📖 기출문제집 p.601

분산 환경에서는 여러 사이트가 함께 하나의 트랜잭션을 처리한다. 이때 어떤 사이트는 커밋하고 어떤 사이트는 롤백하면 원자성이 깨진다. 그래서 조정자(coordinator)가 전체의 의견을 모아 다 함께 커밋하거나 다 함께 롤백하도록 통제하는데, 이것이 2단계 완료 규약이다.

함정(2007 국가직 7급): "응답이 모두 'Not OK'일 경우에만 rollback으로 결정한다" → ❌ 틀림. 하나라도 Not OK면 rollback이다. 반대로 commit은 모두 OK일 때만 가능하다. "commit은 만장일치, rollback은 한 표면 충분"으로 외워라.

📌시험 빈출 포인트

  • 신뢰도 분모 = A(조건절)를 포함한 거래 수, 지지도 분모 = 전체 거래 수
  • "시계열·향후 예측" → 연속성 규칙 (특성화 규칙과 바꿔치기하는 함정 최다)
  • 분류 = 정해진 그룹에 배정 / 군집 = 정해진 그룹 없이 유사도로 묶기
  • 분산DB에서 모든 사이트의 DBMS가 동일할 필요는 없다 (ODBC로 호환)
  • 장애 투명성 = 장애가 나도 정상 사용 (장애 예방이 아님)
  • 단편화 3종: 수평(행) · 수직(열) · 혼합
  • 2PC: 전원 OK → commit, 하나라도 Not OK → rollback, 목적은 원자성 보장
  • 모바일·임베디드용 경량 DBMS = SQLite (별도 서버 불필요)

문제 12018 국회 · 기출문제집 p.602

다음은 마트의 판매 기록이다. 규칙 "기저귀 → 맥주"의 신뢰도(confidence) 값으로 옳은 것은?

식별자품목
1맥주, 땅콩, 기저귀
2맥주, 커피, 기저귀
3맥주, 기저귀, 계란
4땅콩, 계란, 우유
5땅콩, 커피, 기저귀, 우유
  1. 0.33
  2. 0.5
  3. 0.75
  4. 0.8
  5. 1.00
해설 보기

정답 ③ 0.75

  1. 규칙이 "기저귀 → 맥주"이므로 분모는 기저귀를 산 거래 수
  2. 기저귀 포함 거래: 1, 2, 3, 5번 → 4건
  3. 그 중 맥주도 함께 산 거래: 1, 2, 3번 → 3건 (5번은 기저귀는 있지만 맥주가 없다)
  4. 신뢰도 = 3 ÷ 4 = 0.75

오답이 만들어지는 방식: ④번 0.8은 분자를 4로 잘못 센 경우(5번 거래를 포함시킴), 선택지에 없지만 0.6은 분모를 전체 5건으로 잡은 경우(그건 지지도다). 5번 거래에 맥주가 없다는 것을 놓치지 않는 게 핵심이라, 표에 O/X를 직접 적어가며 세는 습관이 중요하다.

문제 22025 소방경채 · 기출문제집 p.603

데이터마이닝 기법에 대한 설명으로 옳지 않은 것은?

  1. 연관 규칙(Association rules)은 관련성이 강한 데이터의 조합을 통해 패턴을 발견한다.
  2. 군집 규칙(Clustering rules)은 상호 유사한 특성을 지닌 데이터를 그룹화하여 패턴을 분석한다.
  3. 분류 규칙(Classification rules)은 이미 알려진 특정 그룹의 특징을 부여하고 기준에 맞게 분류한다.
  4. 특성화 규칙(Characterization rules)은 트랜잭션 이력 데이터를 시계열로 분석하여 트랜잭션의 향후 발생 가능성을 예측한다.
해설 보기

정답 ④

④번의 설명("시계열로 분석하여 향후 발생 가능성 예측")은 연속성 규칙(Sequence)의 정의다. 특성화 규칙은 특정 클래스나 그룹의 고유한 특징을 도출하는 것으로, 예측과는 무관하다.

이 유형은 5개 중 두 개의 정의를 서로 맞바꾸는 방식으로만 출제되므로, 다섯 키워드만 확실히 외우면 매번 맞힐 수 있다.

문제 32025 법원직 · 기출문제집 p.600

분산 데이터베이스의 분산 투명성에 관한 설명 중 가장 옳지 않은 것은?

  1. 위치 투명성은 데이터의 실제 저장 위치를 알 필요 없이 논리적인 이름만으로 데이터에 접근할 수 있다는 것을 의미한다.
  2. 중복 투명성은 동일한 데이터가 여러 지역에 저장되었더라도 하나의 데이터베이스 시스템에 저장된 것처럼 사용하는 것을 의미한다.
  3. 단편화 투명성에는 수직적 단편화, 수평적 단편화, 혼합 단편화가 있다.
  4. 장애 투명성은 장애가 발생하지 않도록 조치하여 데이터베이스가 운영되는 것을 의미한다.
해설 보기

정답 ④

장애 투명성은 "일부 시스템에 장애가 발생해도 사용자는 정상적으로 사용 가능"하다는 뜻이다. 장애를 예방한다는 말이 아니다.

개념적으로 왜 그런가: 투명성(transparency)이라는 단어 자체가 "사용자에게 보이지 않게 숨긴다"는 의미다. 위치 투명성은 위치를 숨기고, 중복 투명성은 중복을 숨기고, 장애 투명성은 장애를 숨긴다. 어느 것도 "문제 자체를 없앤다"는 뜻이 아니다 — 이 관점 하나면 다섯 개 정의를 전부 일관되게 이해할 수 있다.

문제 42012 지방직 · 기출문제집 p.600

분산 데이터베이스에 대한 설명으로 옳지 않은 것은?

  1. 데이터 분산 기술을 이용하여 트랜잭션 처리성능을 향상시킬 수 있다.
  2. 지역 사이트에 있는 모든 DBMS가 동일해야 한다.
  3. 데이터 중복기술을 이용하여 가용성을 높일 수 있다.
  4. 트랜잭션의 원자성을 보장하기 위해 2단계 완료 규약(2-phase commit protocol)을 사용할 수 있다.
해설 보기

정답 ②

각 지역 사이트가 서로 다른 DBMS를 사용해도 ODBC(Open DataBase Connectivity) 같은 표준 인터페이스를 통해 상호 호환이 가능하다. "모든 DBMS가 동일해야 한다"는 제약은 존재하지 않는다.

선택지 감별법: "반드시·모두·항상·동일해야" 같은 절대적 표현이 들어간 선택지는 오답일 확률이 높다. 반대로 ①③④처럼 "~할 수 있다"는 가능성 표현은 대체로 옳은 진술이다. 물론 내용 확인이 우선이지만, 시간이 부족할 때 유용한 감별 기준이다.

문제 52007 국가직 7급 · 기출문제집 p.601

2단계 완료 규약(two-phase commit protocol)에 관한 설명 중 옳지 않은 것은?

  1. 2단계 완료 규약은 연동된 데이터베이스 시스템에서 트랜잭션의 원자성을 지원하기 위한 방법이다.
  2. 조정자가 존재하여 여러 데이터베이스 시스템들 간의 commit이나 rollback이 일치하도록 보장한다.
  3. 모든 데이터베이스 시스템으로부터 전달된 강제 쓰기(force-write)에 대한 응답이 모두 'Not OK'일 경우에만 조정자는 'rollback'으로 결정한다.
  4. 모든 데이터베이스 시스템으로부터 전달된 강제 쓰기에 대한 응답이 모두 'OK'일 경우에만 조정자는 'commit'으로 결정한다.
해설 보기

정답 ③

하나라도 'Not OK'가 있으면 rollback으로 결정한다. "모두 Not OK일 경우에만"은 조건이 지나치게 까다로워, 한 사이트만 실패해도 나머지는 커밋해버리는 결과가 되어 원자성이 깨진다.

  1. 목적을 먼저 떠올린다 — 2PC의 존재 이유는 "전부 커밋 or 전부 롤백"(원자성)
  2. 따라서 commit은 만장일치 조건(④번이 옳음), rollback은 반대표 1개면 성립
  3. ③번은 rollback 조건을 만장일치로 바꿔 놓았으므로 틀림

비유: 등산 동아리가 "전원이 가겠다고 해야 출발, 한 명이라도 못 간다면 전원 취소"로 정한 것과 같다. 한 명이 못 간다고 나머지만 출발하면 "다 같이 가거나 다 같이 안 간다"는 원칙이 깨진다.

문제 62017 국회 · 기출문제집 p.601

현재 모바일 기기에 탑재되는 임베디드 데이터베이스 엔진의 대표적인 예로서, 서버가 따로 필요하지 않아 널리 활용되는 것은?

  1. SQLite
  2. MySQL
  3. mSQL
  4. Oracle
  5. SQL Server
해설 보기

정답 ① SQLite

SQLite는 구글 안드로이드, 애플 아이폰 등에 기본 탑재된 DBMS로 표준 SQL의 대부분을 지원한다. 별도의 서버 프로세스가 필요 없는 경량 DB라서 앱 안에 파일 하나로 내장된다.

구별 포인트: MySQL·Oracle·SQL Server는 모두 서버-클라이언트 구조로 동작하는 대형 DBMS다. 문제에 "임베디드·모바일·서버 불필요·경량"이라는 키워드가 나오면 답은 SQLite다. 이름 끝의 "Lite"(가벼운)가 그대로 힌트다.

문제 7개념 확인 · 응용

문제 1의 거래 데이터에서 "기저귀와 맥주"의 지지도(support)를 구하고, 신뢰도(0.75)와 값이 다른 이유를 설명하시오.

해설 보기

정답: 지지도 = 3 ÷ 5 = 0.6

  1. 분자는 신뢰도와 동일하다 — 기저귀와 맥주를 모두 산 거래 = 1, 2, 3번 → 3건
  2. 지지도의 분모는 전체 거래 수 = 5건
  3. 지지도 = 3 ÷ 5 = 0.6

값이 다른 이유: 분자는 같지만 분모가 다르기 때문이다. 신뢰도의 분모(기저귀 거래 4건)는 전체(5건)보다 작으므로 신뢰도(0.75) > 지지도(0.6)가 된다. 일반적으로 신뢰도는 지지도보다 크거나 같다(분모가 전체의 부분집합이므로).

해석: 지지도 0.6은 "전체 거래의 60%에서 이 조합이 나타난다"(충분히 흔하다)는 뜻이고, 신뢰도 0.75는 "기저귀를 산 사람의 75%가 맥주도 샀다"(규칙이 꽤 강하다)는 뜻이다.
