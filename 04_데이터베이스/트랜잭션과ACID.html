트랜잭션과 ACID

상태 전이 · ACID · 병행제어(로킹/2PL) · 회복 기법(REDO/UNDO) · PART 05. 데이터베이스론

핵심 요약

트랜잭션 = 데이터베이스의 더 이상 쪼갤 수 없는 작업 단위. "전부 성공 아니면 전부 취소"가 원칙.

ACID를 실제로 지켜내는 두 장치가 병행제어(로킹)와 회복(REDO/UNDO)이고, 시험 계산문제는 거의 전부 이 둘에서 나온다.

🎯이 단원을 왜 배우나

"돈은 빠져나갔는데 안 들어왔다"를 막는 기술

A 계좌에서 B 계좌로 1,000원을 이체한다고 하자. DBMS 입장에서 이건 두 개의 쓰기 연산이다 — A에서 1,000 빼기, B에 1,000 더하기. 그런데 첫 번째 연산을 끝내고 두 번째를 하기 직전에 정전이 났다면? 돈은 공중으로 사라진다. 이 사고를 원천적으로 막기 위해 "이 두 연산은 한 덩어리다, 쪼개서 반영하지 마라"고 DBMS에 선언하는 것이 트랜잭션이다.

문제는 하나 더 있다. 내가 이체하는 동시에 다른 사람도 같은 계좌를 건드리면? 두 작업이 뒤엉켜 잔액이 엉망이 된다. 그래서 DBMS는 두 가지 장치를 둔다.

  • 병행제어(Concurrency Control) — 여러 트랜잭션이 동시에 돌아도 서로 방해하지 않게 잠금(Lock)으로 교통정리
  • 회복(Recovery) — 장애가 나도 로그(log)를 보고 완료된 것은 다시 반영(REDO), 미완료는 되돌리기(UNDO)

시험은 이 구조를 정확히 반영한다. 개념 문제는 ACID 4개 이름 매칭, 계산 문제는 로그를 주고 "어느 트랜잭션을 REDO/UNDO 하는가"를 묻는다. 후자가 매년 나오는데, 아래 판정 규칙 하나만 외우면 전부 풀린다.

💡주요 개념 — 트랜잭션과 ACID

트랜잭션(Transaction)이란? 📖 기출문제집 p.568

데이터베이스에 대한 하나의 논리적 작업 단위. 여러 개의 연산(읽기/쓰기)이 모여 있지만, DBMS 입장에서는 더 쪼갤 수 없는 한 덩어리로 취급된다. 정의를 정확히 말하면 "한꺼번에 모두 수행되어야 할 일련의 데이터베이스 연산들의 모임"이자 병행 제어 및 회복 작업의 논리적 단위다.

비유: 계좌이체 = "A 계좌에서 -1000원" + "B 계좌에 +1000원"이라는 2개의 연산이지만, 사용자에게는 "이체"라는 하나의 행위다. 둘 중 하나만 성공하면 절대 안 된다.

트랜잭션의 생명주기 — 5가지 상태

트랜잭션은 실행되는 동안 아래 5개 상태 중 하나에 반드시 속해 있다. 이 전이도를 알아야 "커밋 전/후" 회복 문제를 정확히 풀 수 있다.

ACID 4대 특성 📖 기출문제집 p.568~571

특성교과서 정의 (시험 문구 그대로)비유
Atomicity
원자성		트랜잭션은 전부(all) 또는 전무(nothing)의 실행만 있지, 일부 실행으로는 기능을 가질 수 없다계좌이체: 보내기+받기 둘 다 되거나 둘 다 안 됨
Consistency
일관성		트랜잭션이 성공적으로 완료하면 언제나 일관된 DB 상태가 된다 (실행으로 일관성이 깨지지 않음)이체 전후 두 계좌 잔액의 합은 항상 동일
Isolation
격리성·고립성		연산의 중간 결과에 다른 트랜잭션이 접근할 수 없다내가 이체 중일 때 남이 내 중간 잔액을 못 봄
Durability
영속성·지속성		일단 성공적으로 끝내면 그 결과는 어떠한 경우에도 보장된다 (장애가 나도 손실 없음)결제 완료 문자를 받았다면 그 기록은 절대 사라지지 않음

용어가 문제마다 다르게 나온다 — 전부 같은 말

  • Isolation = 격리성 = 고립성 = 독립성
  • Durability = 영속성 = 지속성

반대로 ACID가 아닌데 자꾸 선택지로 나오는 가짜들이 있다: 일시성(temporality), 병행성(concurrency), 의존성(dependency), 종속성, 투명성(transparency). "ACID가 아닌 것을 고르시오" 유형은 이 가짜 목록만 외워도 바로 풀린다.

원자성 vs 일관성 구별법: 원자성은 "연산이 몇 개 반영됐나"(전부 or 전무)에 대한 말이고, 일관성은 "DB가 규칙을 지키고 있나"(제약조건 만족)에 대한 말이다. 초점이 다르다.

🔐주요 개념 — 병행제어(Concurrency Control)

병행 수행이 일으키는 3가지 사고 📖 기출문제집 p.577

여러 트랜잭션을 동시에 돌리면 처리량은 올라가지만, 통제하지 않으면 아래 문제가 생긴다. 이름과 현상을 짝짓는 문제가 자주 나오고, 셋을 서로 바꿔 놓은 선택지가 함정이다.

문제무슨 일이 벌어지나
갱신 분실
(Lost Update)		두 트랜잭션이 같은 데이터를 동시에 갱신해서 먼저 한 갱신이 덮어써져 사라짐
모순성
(Inconsistency)		한 트랜잭션이 여러 갱신을 하는 중에, 다른 트랜잭션이 일관성 없는 중간 상태의 데이터를 읽어 모순된 결과를 냄
연쇄 복귀
(Cascading Rollback)		트랜잭션이 rollback되면, 그 트랜잭션이 변경한 데이터를 이미 읽어간 다른 트랜잭션들도 줄줄이 rollback해야 함
함정 주의: "갱신 분실 = 일관성 없는 데이터를 읽어 모순된 결과가 나오는 것" → ❌ 그건 모순성이다. "갱신 분실 = 롤백 시 다른 트랜잭션도 롤백" → ❌ 그건 연쇄 복귀다. 2024 국가직 문제가 정확히 이 셋을 뒤섞어 냈다.

로킹(Locking) — 공유 락 vs 배타 락

로크(lock)는 하나의 트랜잭션이 데이터를 접근하는 동안 다른 트랜잭션이 그 데이터를 접근하지 못하게 막는 장치다. 두 종류가 있다.

구분공유 락 (Shared, S)배타 락 (eXclusive, X)
가능한 연산read만 가능 (write 불가)read·write 모두 가능
다른 트랜잭션과 공존다른 S락과는 동시 보유 가능어떤 락과도 공존 불가 (독점)
비유도서관 책을 여럿이 같이 읽기책을 혼자 빌려 가서 고치기
매년 나오는 함정: "공용(공유) lock을 수행하면 read·write를 모두 할 수 있다" → ❌ read만 가능하다. 쓰려면 배타 락이 필요하다.

2단계 로킹 규약(2PL) — 이름의 뜻과 한계

이름 그대로 트랜잭션의 생애를 두 단계로 나눈다. 확장 단계에서는 락을 얻기만 하고, 축소 단계에서는 락을 풀기만 한다. 한 번 풀기 시작하면 다시는 새 락을 얻을 수 없다는 것이 규칙의 전부다.

가장 많이 틀리는 한 줄 — 2PL은 교착상태를 막지 못한다

2PL이 보장하는 것은 직렬 가능성(serializability)뿐이다. 즉 "동시에 돌렸지만 결과는 하나씩 차례로 돌린 것과 같다"를 보장한다. 그런데 T1은 A락을 쥔 채 B를 기다리고, T2는 B락을 쥔 채 A를 기다리면? 둘 다 영원히 대기 = 교착상태(deadlock)다. 2PL은 이걸 전혀 막지 못한다.

선택지에 "2단계 로킹 규약을 적용하면 교착상태를 예방할 수 있다"가 보이면 거의 무조건 오답이다. 반대로 "직렬 가능성은 보장하지만 교착상태는 발생할 수 있다"가 정답 문장이다. 2018 국가직·2022 계리직·2024 국가직에서 반복 출제됐다.

로킹 단위(granularity)도 자주 나온다. 단위가 작아질수록 → 락 개수가 많아져 관리는 복잡해지지만 병행성(동시성)은 높아진다. 단위가 커질수록 → 관리는 단순하지만 병행성이 떨어진다.

교착상태 예방 — wait-die vs wound-wait 📖 기출문제집 p.578

타임스탬프(먼저 시작한 쪽이 "고참")를 이용해 교착상태를 예방하는 두 기법이다. 요청하는 쪽이 고참이냐 신참이냐에 따라 행동이 갈린다.

기법요청자가 고참(먼저 시작)일 때요청자가 신참일 때
wait-die기다린다 (wait)자신이 죽는다 (die → 나중에 재시작)
wound-wait상대를 죽이고 선점 (wound)기다린다 (wait)
이름으로 외우기: 두 이름 모두 "고참이 하는 행동"이 앞에 온다. wait-die → 고참은 wait. wound-wait → 고참은 wound(상대에게 상처 입혀 쫓아냄). 뒤 단어는 신참의 행동이다.

🔁주요 개념 — 회복(Recovery) 기법

즉시 갱신 vs 지연 갱신 📖 기출문제집 p.572~575

트랜잭션이 바꾼 값을 언제 디스크에 쓰느냐가 두 기법을 가른다. 이 차이가 곧 UNDO가 필요한지 여부를 결정하기 때문에, 문제를 풀 때 제일 먼저 확인해야 할 조건이다.

구분즉시 갱신 (Immediate Update)지연 갱신 (Deferred Update)
디스크 반영 시점커밋 전에도 수시로 씀커밋 이후에만 씀
미완료 트랜잭션의 변경이 디스크에?있을 수 있음 → 지워야 함절대 없음 → 지울 것도 없음
필요한 회복 연산REDO + UNDO 둘 다REDO만 (UNDO 불필요)
한 줄 정리: 지연 갱신에는 UNDO가 없다. 문제에 "지연 갱신"이라 쓰여 있는데 선택지에 "undo한다"가 있으면 그게 바로 정답(틀린 것 고르기) 또는 오답(옳은 것 고르기)이다. 2012 국가직 문제가 정확히 이것을 물었다.

검사점(Checkpoint)과 REDO/UNDO 판정 규칙

검사점은 "여기까지는 디스크에 확실히 반영해뒀다"고 도장을 찍는 지점이다. 덕분에 회복할 때 로그 전체를 뒤질 필요 없이 검사점 이후만 보면 된다. 아래 3분류 규칙이 이 단원 계산문제의 전부다.

  1. 검사점 이전에 commit → 이미 디스크에 안전하게 반영됨 → 제외(아무 작업 없음)
  2. 검사점 이후 ~ 장애 전에 commit → 반영이 안 됐을 수 있음 → REDO(새 값으로 다시 쓰기)
  3. 장애 시점까지 commit 못 함 → 반쪽짜리 변경이 남아 있을 수 있음 → UNDO(옛 값으로 되돌리기)
  4. 단, 지연 갱신이면 3번 대상들도 애초에 디스크에 안 쓰였으므로 UNDO 없이 그냥 무시
Abort된 트랜잭션은? 지연 갱신에서는 커밋 전에 디스크를 건드리지 않았으니 아무 조치도 필요 없다. 즉시 갱신에서는 이미 UNDO가 수행됐거나 수행해야 한다.

📌시험 빈출 포인트

  • ACID가 아닌 가짜 목록: 일시성·병행성·의존성·종속성·투명성 → "아닌 것 고르기"의 단골 정답
  • "전부 또는 전무" = 원자성, "중간 결과 접근 불가" = 격리성, "장애에도 결과 보존" = 영속성
  • commit/rollback으로 전부 반영 or 전부 취소 → 원자성이 담당 (일관성 아님)
  • 2PL은 직렬 가능성 보장 O, 교착상태 예방 X — 최다 함정
  • 공유 락은 read 전용, 배타 락이라야 write 가능
  • 로킹 단위가 작아지면 → 락 수 증가·관리 복잡·병행성 증가
  • 지연 갱신 = UNDO 없음, 즉시 갱신 = REDO + UNDO 둘 다
  • 회복 3분류: 검사점 전 커밋=제외 / 검사점 후 커밋=REDO / 미커밋=UNDO
  • wound-wait: 고참이 요청하면 상대를 죽이고 선점, wait-die: 고참이 요청하면 기다림

✏️연습문제

먼저 스스로 풀어본 뒤 "해설 보기"를 눌러 확인하세요.

문제 12024 계리직 · 기출문제집 p.569

트랜잭션의 특성(ACID)에 대한 설명으로 옳지 않은 것은?

  1. 지속성(durability): 트랜잭션이 실행을 성공적으로 완료하면 결과는 영속적이다.
  2. 일관성(consistency): 트랜잭션이 실행을 성공적으로 완료하면 언제나 일관성 있는 데이터베이스 상태로 변환한다.
  3. 원자성(atomicity): 트랜잭션은 전체 또는 일부 실행만으로도 트랜잭션의 기능을 갖는다.
  4. 고립성(isolation): 트랜잭션 실행 중에 있는 연산의 중간 결과는 다른 트랜잭션이 접근할 수 없다.

정답 ③

원자성은 전부(all) 또는 전무(nothing)만 인정한다. "일부 실행만으로도 기능을 갖는다"는 원자성을 정면으로 부정하는 문장이다.

함정 구조: 이 유형은 ACID 4개 중 딱 하나의 정의만 슬쩍 뒤집어 놓는다. 특히 원자성의 "전부/전무"를 "일부도 가능"으로 바꾸는 패턴이 가장 흔하니, 원자성 선택지부터 확인하는 습관을 들이면 빨리 풀린다.

문제 22014 국가직 · 기출문제집 p.569

데이터베이스에서 트랜잭션(transaction)이 가져야 할 ACID 특성으로 옳지 않은 것은?

  1. 원자성 (atomicity)
  2. 고립성 (isolation)
  3. 지속성 (durability)
  4. 병행성 (concurrency)
해설 보기

정답 ④ 병행성(concurrency)

ACID = Atomicity(원자성) · Consistency(일관성) · Isolation(고립성) · Durability(지속성). 병행성은 여기 없다.

같은 유형 모아보기: 같은 자리에 들어가는 가짜 선택지가 해마다 바뀐다 — 일시성(2011 지방), 병행성(2014 국가직), 종속성(2012 계리직), 의존성(2025 지방직), 투명성(2018 국회). 전부 ACID가 아니다.

문제 32017 국가직 · 기출문제집 p.571

트랜잭션이 정상적으로 완료(commit)되거나, 중단(abort)되었을 때 롤백(rollback)되어야 하는 트랜잭션의 성질은?

  1. 원자성 (atomicity)
  2. 일관성 (consistency)
  3. 격리성 (isolation)
  4. 영속성 (durability)
해설 보기

정답 ① 원자성

"모두 실행되어 commit되거나, 모두 실행되지 않은 상태로 rollback된다" — 이것이 바로 전부 또는 전무, 즉 원자성의 정의다.

함정: ②번 일관성을 고르기 쉽다. 하지만 일관성은 "끝나고 나서 DB가 규칙을 지키는가"에 대한 성질이고, commit/rollback이라는 메커니즘 자체는 원자성을 구현하기 위한 장치다. 문제에 commit·rollback·전부·전무라는 단어가 보이면 원자성을 먼저 의심해라.

문제 42007 국가직 · 기출문제집 p.570

데이터베이스 시스템의 트랜잭션이 가져야 할 속성에 대한 설명으로 옳지 않은 것은?

  1. 트랜잭션에 포함된 연산들이 수행 중에 오류가 발생할 경우에 어떠한 연산도 수행되지 않은 상태로 되돌려져야 한다.
  2. 만약 데이터베이스가 처음에 일관된 상태에 있었다면 트랜잭션이 실행되고 난 후에도 계속 일관된 상태로 유지되어야 한다.
  3. 동시에 수행되는 트랜잭션들은 상호 작용할 수 있다.
  4. 트랜잭션이 성공적으로 수행 완료된 후에 시스템의 오류가 발생한다 하더라도 트랜잭션에 의해 데이터베이스에 변경된 내용은 보존된다.
해설 보기

정답 ③

각 선택지가 어느 특성을 설명하는지 매칭해보면 답이 바로 보인다.

  1. ①번 = 원자성 (오류 시 아무것도 수행 안 한 상태로 복귀) → 옳음
  2. ②번 = 일관성 (실행 전후로 일관된 상태 유지) → 옳음
  3. ③번 = 격리성을 위반하는 문장. 격리성에 의해 동시 수행 트랜잭션은 서로의 중간 결과에 접근할 수 없으므로 상호 작용할 수 없다 → 틀림
  4. ④번 = 영속성 (완료 후 장애가 나도 보존) → 옳음

풀이 요령: 이런 "서술형 4지선다"는 각 문장 옆에 A·C·I·D를 적어보면 하나가 반드시 안 맞는다.

문제 52012 국가직 · 기출문제집 p.572~573

지연 갱신(deferred update) 기반 회복 기법을 사용하는 DBMS에서 다음과 같은 로그 레코드가 생성되었다. 시스템 실패가 발생해 DBMS가 재시작할 때, 데이터베이스에 수행되는 연산으로 옳지 않은 것은?
(단, <Tn, A, old, new>는 트랜잭션 Tn이 데이터 A의 이전값을 이후값으로 갱신했다는 의미)

<T1, Start>
<T1, A, 900, 1000>
<T1, Commit>
<T4, Start>
<T3, Start>
<T2, Start>
< 검사점 연산(Checkpoint) >
<T2, B, 2100, 2200>
<T2, Commit>
<T3, C, 1700, 1800>
<T3, Abort>
<T4, A, 600, 700>
시스템 실패

  1. T1 : no operation
  2. T2 : redo
  3. T3 : no operation
  4. T4 : undo
해설 보기

정답 ④ (T4는 undo가 아니라 no operation)

문제 첫 줄의 "지연 갱신"이 모든 것을 결정한다. 지연 갱신에서는 커밋될 때 비로소 디스크에 쓰므로, 커밋 안 된 트랜잭션의 변경은 애초에 디스크에 없다 → 지울 것이 없다 → UNDO를 하지 않는다.

  1. T1: 검사점 이전에 Commit 완료 → 이미 안전하게 반영됨 → no operation (①번 옳음)
  2. T2: 검사점 이후에 Commit → 반영을 보장하기 위해 REDO (②번 옳음)
  3. T3: Abort됨 → 지연 갱신이라 디스크에 쓴 적 없음 → no operation (③번 옳음)
  4. T4: Commit 못 하고 장애 발생 → 역시 디스크에 쓴 적 없음 → no operation이 맞다. "undo"라고 한 ④번이 틀린 설명

함정: 습관적으로 "미커밋 = UNDO"라고 반사적으로 답하면 바로 틀린다. 기법 이름(지연/즉시)을 먼저 확인하는 것이 이 유형의 유일한 요령이다.

문제 62010 국가직 7급 · 기출문제집 p.573

로그를 이용한 즉시 갱신 회복 기법을 사용하는 DB 시스템이 다운된 후 재기동되었을 때, 로그에 다음 레코드들이 들어 있었다. 복구를 수행한 후 데이터베이스 항목 A, B, C, D의 값으로 옳은 것은?

< 체크포인트 >
[T1, start]
[T1, A, 100, 300]
[T2, start]
[T1, B, 200, 300]
[T3, start]
[T2, C, 700, 400]
[T3, D, 200, 800]
[T2, commit]
[T4, start]
[T4, C, 400, 500]
[T1, commit]
시스템 다운

  1. A:100, B:200, C:700, D:200
  2. A:300, B:300, C:400, D:200
  3. A:100, B:200, C:400, D:800
  4. A:300, B:300, C:400, D:800
해설 보기

정답 ② A:300, B:300, C:400, D:200

즉시 갱신이므로 커밋된 것은 REDO(new값), 커밋 안 된 것은 UNDO(old값). 트랜잭션별로 커밋 여부부터 표시하고 시작하면 실수가 없다.

트랜잭션커밋?처리결과
T1 (A:100→300, B:200→300)✅ commitREDOA=300, B=300
T2 (C:700→400)✅ commitREDOC=400
T3 (D:200→800)❌ 미커밋UNDOD=200 (old값 복원)
T4 (C:400→500)❌ 미커밋UNDOC=400 (old값 복원)

C값이 헷갈리는 이유: C는 T2가 400으로 바꾸고(커밋됨), T4가 다시 500으로 바꿨다(미커밋). T4를 UNDO하면 T4의 old값인 400으로 돌아가는데, 이 값이 마침 T2의 REDO 결과와 같다. 따라서 최종 C = 400.

함정: ④번(D:800)은 T3의 커밋 여부를 확인하지 않고 그냥 new값을 쓴 오답이다. 로그에서 commit 줄이 있는지를 트랜잭션마다 눈으로 찍어가며 확인해라.

문제 72021 계리직 · 기출문제집 p.576

트랜잭션 복구 진행 시 복구대상을 제외 / 재실행(Redo) / 실행취소(Undo)로 구분할 때 옳은 것은?
T1~T6은 각 트랜잭션의 시작·끝 구간, Ts는 검사점 시점, Tf는 장애 발생 시점. T1은 검사점 이전 커밋, T2·T3·T6은 검사점 이후 장애 이전 커밋, T4·T5는 장애 시점까지 미완료.

  1. 제외: T1 / 재실행: T2, T3 / 실행취소: T4, T5, T6
  2. 제외: T1 / 재실행: T2, T3, T6 / 실행취소: T4, T5
  3. 제외: T2, T3 / 재실행: T1, T6 / 실행취소: T4, T5
  4. 제외: T4, T5 / 재실행: T6 / 실행취소: T1, T2, T3
해설 보기

정답 ②

  1. 검사점 이전에 커밋한 T1 → 이미 디스크 반영 보장 → 제외
  2. 검사점과 장애 사이에 커밋한 T2, T3, T6 → REDO
  3. 장애 시점까지 커밋 못 한 T4, T5 → UNDO

그림 문제 푸는 순서: ① 검사점 세로선과 장애 세로선을 긋는다 → ② 각 트랜잭션의 끝점이 어디에 있는지만 본다(시작점은 상관없다) → ③ 끝점이 검사점 왼쪽이면 제외, 검사점과 장애 사이면 REDO, 장애선에 걸쳐 있으면 UNDO.

함정: 시작점 위치에 눈이 가면 헷갈린다. 판정은 오직 커밋(끝) 시점으로만 한다.

문제 82024 국가직 · 기출문제집 p.577

DBMS에서의 병행 수행 및 병행 제어에 대한 설명으로 옳은 것은?

  1. 2단계 로킹 규약을 적용하면 트랜잭션 스케줄의 직렬 가능성을 보장할 수 있으나 교착상태가 발생할 수도 있다.
  2. 트랜잭션이 데이터에 공용 lock 연산을 수행하면 해당 데이터에 read, write 연산을 모두 수행할 수 있다.
  3. 연쇄 복귀는 하나의 트랜잭션이 여러 개의 데이터 변경 연산을 수행할 때 일관성 없는 상태의 데이터베이스에서 데이터를 가져와 연산을 수행함으로써 모순된 결과가 발생하는 것이다.
  4. 갱신 분실은 트랜잭션이 완료되기 전에 장애가 발생하여 rollback 연산을 수행하면, 이 트랜잭션이 장애 발생 전에 변경한 데이터를 가져가 변경 연산을 수행한 또 다른 트랜잭션에도 rollback 연산을 수행하여야 한다는 것이다.
해설 보기

정답 ①

  1. ① 2PL의 정확한 성질이다 — 직렬 가능성은 보장하지만 교착상태는 막지 못한다 → 옳음
  2. ② 공용(공유) 락은 read만 가능하다. write까지 하려면 배타 락이 필요 → 틀림
  3. ③ 이 설명은 모순성(inconsistency)의 정의다 → 이름이 바뀜
  4. ④ 이 설명은 연쇄 복귀(cascading rollback)의 정의다 → 이름이 바뀜

출제 패턴: ③·④처럼 설명은 맞는데 이름표만 바꿔 다는 수법이 병행제어 파트의 주력 함정이다. 갱신분실·모순성·연쇄복귀 셋의 핵심 동사를 기억해라 — 갱신분실은 "덮어써짐", 모순성은 "중간값을 읽음", 연쇄복귀는 "덩달아 롤백".

문제 92025 법원직 · 기출문제집 p.578

교착상태 예방을 위해 wound-wait 기법을 사용한다고 가정한다. 트랜잭션 T1과 T2가 존재하고 T1의 우선순위가 T2보다 높은 경우, T2가 할당받은 자원을 T1이 요청한다면 어떤 결과가 발생하는가?

  1. T1은 T2가 해당 자원을 반납할 때까지 대기 상태에서 기다린다.
  2. T2가 할당받고 있는 자원을 선점(preemption)하여 T1에게 할당한다.
  3. T1의 실행을 취소(abort)하고 이후 재실행(restart)하도록 한다.
  4. T1으로 하여금 busy-waiting하면서 해당 자원의 점유를 시도하게 한다.
해설 보기

정답 ② T2의 자원을 선점하여 T1에게 할당

wound-wait의 앞 단어가 고참(우선순위 높은 쪽)의 행동이다. 고참 T1이 요청하면 신참 T2에게 상처를 입혀(wound) 쫓아내고 자원을 뺏는다.

  1. 요청자 T1 = 우선순위 높음 = 고참
  2. 기법이 wound-wait → 고참의 행동은 wound(선점)
  3. 따라서 T2를 강제로 롤백시키고 자원을 T1에게 넘김 → ②

비교: 만약 wait-die였다면? 고참의 행동은 wait이므로 ①번(기다린다)이 정답이 된다. 같은 상황이라도 기법 이름에 따라 답이 정반대가 되니, 문제에서 기법 이름을 먼저 동그라미 쳐라.

문제 10개념 확인 · 응용

로킹 단위(locking granularity)를 레코드 단위에서 테이블 단위로 크게 바꾸면 어떤 변화가 생기는가? 락의 개수, 관리 복잡도, 병행성 측면에서 설명하시오.

해설 보기

정답: 락 개수 감소 · 관리 단순화 · 병행성(동시성) 저하

  1. 단위가 커지면 한 번에 잠그는 범위가 넓어지므로 필요한 락의 개수는 줄어든다
  2. 관리할 락이 적으니 DBMS의 오버헤드와 관리 복잡도는 낮아진다
  3. 그러나 테이블 하나를 통째로 잠그면 다른 트랜잭션은 그 테이블의 무관한 행조차 건드릴 수 없다 → 병행성 저하

정리: 로킹 단위와 병행성은 반비례, 로킹 단위와 관리 편의성은 비례다. 시험에서는 주로 반대 방향(단위가 작아지면 락 수 증가·관리 복잡·병행성 증가)으로 출제된다.
