# ER 다이어그램 → 관계형 스키마 변환

## 핵심 요약
> E-R 다이어그램의 개체(Entity)와 관계(Relationship)를 테이블로 바꾸는 규칙!
> **관계의 카디널리티(1:1, 1:N, M:N)에 따라 변환 방법이 달라진다.**

## 주요 개념

### 변환 기본 원칙
- **개체(Entity)** → 테이블로 변환
- **속성(Attribute)** → 컬럼(열)으로 변환
- **기본키(PK)** → 밑줄 친 속성이 기본키
- **관계(Relationship)** → 카디널리티에 따라 처리 방식이 다름

### 카디널리티별 변환 규칙 ⭐⭐⭐

#### 1:1 관계
- 어느 쪽이든 상대방의 PK를 FK로 가져옴
- 관계 속성도 FK를 넣은 쪽에 추가
- 비유: "1:1 짝꿍 → 아무나 한쪽이 상대 이름표 가져가기"

#### 1:N 관계 (가장 빈출!)
- **1쪽의 PK**를 **N쪽 테이블에 FK로 추가**
- 관계에 달린 속성도 **N쪽에 추가**
- 별도 테이블 만들 필요 없음!
- 비유: "선생님(1) - 학생(N) → 학생 명부에 담임선생님 이름 적기"

#### M:N 관계
- **반드시 별도의 관계 테이블 생성**
- 관계 테이블에 양쪽 PK를 FK로 포함 → 이 두 FK가 합쳐서 복합 PK
- 관계 속성은 이 관계 테이블에 추가
- 비유: "학생(M) - 과목(N) → 수강신청 테이블 따로 만들기"

## 시험 빈출 포인트

### 자주 나오는 문제 유형
1. **ER 다이어그램 보고 올바른 릴레이션 고르기** (2022 계리직 기출)
2. 1:N에서 FK를 어디에 넣는지 묻는 문제
3. M:N에서 별도 테이블의 PK 구성 묻는 문제

### 실수하기 쉬운 함정
- ❌ 1:N인데 별도 관계 테이블을 만든 보기 → 오답
- ❌ 1쪽 테이블에 N쪽 PK를 넣은 보기 → 오답 (방향이 반대!)
- ❌ 관계 속성(예: 수량)을 엉뚱한 테이블에 넣은 보기 → 오답

## 헷갈리는 개념 비교

| 구분 | 1:1 | 1:N | M:N |
|------|-----|-----|-----|
| 별도 테이블 | 불필요 | 불필요 | **필수** |
| FK 위치 | 아무 쪽 | **N쪽**에 추가 | 관계 테이블 |
| 관계 속성 위치 | FK 넣은 쪽 | **N쪽** | 관계 테이블 |
| 관계 테이블 PK | - | - | 양쪽 PK 합침(복합키) |

## 예제 풀이 (2022 계리직 기출)

```
판매처(N) ---주문--- 공장(1)
  ↓                    ↓
판매처번호(PK)        공장명(PK)
담당자                단가
          수량(관계속성)
```

**변환 결과:**
- 판매처(**판매처번호**, 담당자, 공장명(FK), 수량) ← N쪽에 1쪽PK + 관계속성
- 공장(**공장명**, 단가) ← 그대로

**정답: ②**

## 한 줄 암기
