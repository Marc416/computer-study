# 분산 데이터베이스

## 핵심 요약
> 여러 사이트에 DB를 나눠 저장하되, 사용자에게는 **하나의 DB처럼** 보이게 하는 시스템

## 주요 개념

### 분산 데이터베이스란?
- 네트워크로 연결된 **여러 컴퓨터(사이트)**에 데이터베이스가 분산 저장
- 사용자는 데이터가 어디 있는지 몰라도 됨 → **위치 투명성**
- 데이터가 복사되어 있어도 몰라도 됨 → **중복 투명성**

### 데이터 중복(Replication) 기술
- 같은 데이터를 **여러 사이트에 복사**해두는 것
- Redis의 Replica와 비슷한 개념
- **장점**: 한 서버가 죽어도 다른 서버에서 읽기 가능 → **가용성 향상**
- **단점**: 데이터 수정 시 모든 복사본을 동기화해야 함

### 2단계 완료 규약 (2-Phase Commit Protocol)
- 분산 환경에서 **트랜잭션의 원자성**을 보장하는 프로토콜
- 비유: "다같이 손잡고 뛰어!" → 먼저 "준비됐어?" 확인 → "뛰어!"

| 단계 | 이름 | 동작 |
|------|------|------|
| 1단계 | Prepare(투표) | 조정자가 각 사이트에 "커밋 준비 됐어?" → 각 사이트가 OK/NO 응답 |
| 2단계 | Commit(결정) | 모두 OK → 커밋 / 하나라도 NO → 전체 롤백 |

### 이기종 DBMS 연결
- 각 사이트가 **서로 다른 DBMS**를 써도 됨 (Oracle, MySQL 혼용 가능)
- **ODBC**(Open DataBase Connectivity)로 상호 호환 가능

## 분산 DB의 투명성 (시험 빈출!)

| 투명성 | 의미 |
|--------|------|
| 위치 투명성 | 데이터가 어디 저장되어 있는지 몰라도 됨 |
| 중복 투명성 | 데이터가 복제되어 있어도 몰라도 됨 |
| 병행 투명성 | 여러 사용자가 동시 접근해도 문제없음 |
| 장애 투명성 | 일부 사이트 장애에도 정상 작동 |

## 시험 빈출 포인트
- ❌ "모든 사이트의 DBMS가 동일해야 한다" → **틀림!** (ODBC로 이기종 연결 가능)
- ⭕ 데이터 중복으로 **가용성** 향상 가능
- ⭕ 2단계 완료 규약으로 **원자성** 보장
- ⭕ 사용자에게 **하나의 DB처럼** 보이게 하는 것이 핵심
