# 릴레이션의 특성

## 핵심 요약
> 릴레이션은 수학의 **집합(Set)** 개념이 기반!
> 집합의 성질을 그대로 물려받았기 때문에 여러 제약이 생긴다.

## 주요 개념

### 릴레이션이란?
- 수학적으로 "투플(행)의 집합"
- 집합이니까 → 중복 불가, 순서 없음
- 비유: 릴레이션 = 주머니 속 구슬들. 같은 구슬 두 개 없고, 넣은 순서도 의미 없음

### 릴레이션의 4가지 특성 ⭐⭐⭐

| 특성 | 설명 | 이유 |
|------|------|------|
| **투플의 유일성** | 중복 투플 없음 | 집합은 같은 원소를 가질 수 없으니까 |
| **투플의 무순서** | 행의 순서 의미 없음 | 집합은 {A,B} = {B,A}니까 |
| **속성의 무순서** | 열의 순서 의미 없음 | 속성은 이름으로 구분하니까 |
| **속성의 원자성** | 하나의 속성값은 하나의 값만 | 1정규형(1NF)의 기본 조건 |

### 왜 "모든 릴레이션은 반드시 키를 가지는가"?

1. 릴레이션은 집합 → 모든 투플이 서로 다름
2. 서로 다르다 → 최소한 전체 속성을 합치면 구별 가능 → **슈퍼키 존재**
3. 슈퍼키가 있으면 → 그 안에서 최소성을 만족하는 **후보키** 추출 가능
4. 후보키 중 하나를 선택 → **기본키(PK)**

> 즉, "PK가 있어서 구별되는 게 아니라, 구별되어야 하니까 PK가 반드시 존재하는 것"

### 이론 vs 현실

| 구분 | 릴레이션 (이론) | SQL 테이블 (현실) |
|------|----------------|-------------------|
| 중복 행 | ❌ 불가 | ⭕ 가능 (PK 없으면) |
| 행 순서 | 의미 없음 | ORDER BY로 정렬 가능 |
| NULL | 원칙적으로 없음 | 허용 |
| 기반 | 집합(Set) | 멀티셋(Multiset/Bag) |

> 시험에서는 **이론(릴레이션)** 기준으로 출제된다!

## 시험 빈출 포인트

### 자주 나오는 문제 유형
1. "릴레이션의 특성으로 옳지 않은 것은?" → 투플 순서 있다(❌), 속성값 다중값 가능(❌)
2. "릴레이션에서 반드시 성립하는 것은?" → 투플 유일성(⭕)
3. "모든 릴레이션이 키를 가지는 이유는?" → 집합이므로 투플이 모두 상이

### 함정 보기 패턴
- "투플은 삽입된 순서대로 저장된다" → ❌ (무순서)
- "하나의 속성이 여러 값을 가질 수 있다" → ❌ (원자성 위반)
- "기본키가 없는 릴레이션도 존재한다" → ❌ (반드시 존재)

## 용어 정리

| 릴레이션 용어 | 같은 말 (파일) | 같은 말 (테이블) |
|--------------|---------------|-----------------|
| 릴레이션 | 파일 | 테이블 |
| 투플 | 레코드 | 행(Row) |
| 속성 | 필드 | 열(Column) |
| 카디널리티 | - | 행의 수 |
| 차수(Degree) | - | 열의 수 |
| 도메인 | - | 속성이 가질 수 있는 값의 범위 |

## 헷갈리는 용어 상세 정리 ⭐⭐⭐

### 차수(Degree)와 카디널리티(Cardinality)

예시 테이블:

| 학번 | 이름 | 학과 |
|------|------|------|
| 001 | 김철수 | 컴공 |
| 002 | 이영희 | 경영 |

- **차수 = 3** → 속성(열)의 개수 (학번, 이름, 학과) → **옆으로 세기**
- **카디널리티 = 2** → 투플(행)의 개수 (김철수, 이영희) → **아래로 세기**

> 암기법: **"차 속 카 투"** → 차수는 속성 수, 카디널리티는 투플 수

주의: 차수는 스키마가 바뀌지 않는 한 고정이지만, 카디널리티는 데이터가 추가/삭제되면 변한다.

### 속성의 원자성 (Atomicity)

**원자(Atom)** = 더 이상 쪼갤 수 없는 가장 작은 단위

→ 속성의 원자성 = **한 칸에 값을 딱 하나만 넣어야 한다**

❌ 원자성 위반 (한 칸에 값 두 개):

| 이름 | 전화번호 |
|------|----------|
| 김철수 | 010-1234, 010-5678 |
| 이영희 | 02-111, 010-9999 |

⭕ 원자성 준수 (한 칸에 값 하나):

| 이름 | 전화번호 |
|------|----------|
| 김철수 | 010-1234 |
| 김철수 | 010-5678 |
| 이영희 | 02-111 |
| 이영희 | 010-9999 |

이것이 바로 **제1정규형(1NF)**의 조건이기도 하다.

> 원자값 = 더 쪼갤 수 없는 값 하나 = 한 칸에 하나!

### 도메인(Domain)

속성이 가질 수 있는 **값의 범위(허용 범위)**

- "성별" 속성의 도메인 → {남, 여}
- "학점" 속성의 도메인 → {A, B, C, D, F}
- "나이" 속성의 도메인 → 1~150 사이 정수

비유: 도메인 = 그 칸에 들어갈 수 있는 **메뉴판**. 메뉴판에 없는 건 주문 불가!

## 엔티티 vs 릴레이션 ⭐

| 구분 | 엔티티 (Entity) | 릴레이션 (Relation) |
|------|-----------------|-------------------|
| 단계 | **개념적 설계** (ER 다이어그램) | **논리적 설계** (스키마/테이블) |
| 의미 | 현실에서 관리할 대상 (학생, 과목) | 엔티티를 실제 테이블로 구현한 것 |
| 비유 | 건축 설계도의 "방" | 실제로 지어진 "방" |
| 관계 | 엔티티 → 변환 → 릴레이션 |  |

> 엔티티는 "뭘 관리할까?" (개념), 릴레이션은 "실제 테이블로 만든 것" (구현)
> **릴레이션 = 테이블 = 모든 테이블을 지칭** (특정 엔티티 하나가 아님!)
