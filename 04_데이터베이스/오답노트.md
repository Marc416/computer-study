# 데이터베이스 오답노트

---

## ❌ TCL이 DCL에 포함되는 거 헷갈림
✅ **한 줄 정리**: DCL도 Control, TCL도 Control → 둘 다 "제어"니까 한 식구
💡 **암기팁**: DCL = 컨트롤 타워 (출입통제 GRANT/REVOKE + 작업확정 COMMIT/ROLLBACK)

---

## ❌ SQL 분류 짝짓기 문제 — COMMIT을 DCL로 착각
✅ **한 줄 정리**: COMMIT은 **TCL**이지 DCL이 아님! DCL은 GRANT/REVOKE만!
💡 **암기팁**: 선지에서 ① COMMIT이 DCL에 있으면 의심! ② 같은 분류가 2개 겹치는 선지는 탈락!
📝 **풀이법**: 각 선지의 3개 명령어가 DDL·DML·DCL에 **하나씩** 속하는지 확인
- UPDATE, SELECT → 둘 다 DML이면 DDL이 없으니 탈락 (②번 함정)
- RENAME, ALTER → 둘 다 DDL이면 DML이 없으니 탈락 (③번 함정)
- ④ ALTER(DDL) + UPDATE(DML) + GRANT(DCL) = 하나씩 완벽!

---

## ❌ 카티션 프로덕트 개념 모름 + 경험적 최적화 규칙 혼동
✅ **한 줄 정리**: 카티션 프로덕트 = 조건 없이 모든 행 × 모든 행 (비용 폭발!)
💡 **암기팁**: 최적화 핵심 = "**먼저 줄여라!**" → 선택·추출은 아래로(먼저), 조인은 위로(나중에)
⚠️ **함정**: "가장 제한적인 선택을 나중에/상위로" → ❌ 정반대! **먼저/하위로**가 맞음

---

## ❌ 프로젝션(Projection)이 뭔지 기억 안 남
✅ **한 줄 정리**: 프로젝션 = **열(컬럼) 골라내기** (π), 추출(Selection) = **행(튜플) 골라내기** (σ)
💡 **암기팁**: **프**로젝션 = **표**의 세로줄(컬럼) 뽑기 / **셀**렉션 = **셀**에서 줄(행) 고르기

---

## ❌ 정규화 단계별 제거 대상 기억 안 남
✅ **한 줄 정리**: 1NF=원자값, 2NF=**부분적** 함수종속 제거, 3NF=**이행적** 함수종속 제거, BCNF=모든 결정자가 후보키
💡 **암기팁**: **"부(2)분 → 이(3)행"** — 2는 부분, 3은 이행!

| 정규형 | 제거 대상 | 쉬운 설명 |
|--------|-----------|-----------|
| 1NF | 반복 그룹 | 한 칸에 값 하나만! |
| 2NF | 부분적 함수 종속 | 키 일부에만 의존하면 분리 |
| 3NF | 이행적 함수 종속 | A→B→C에서 A→C 끊기 |
| BCNF | 결정자≠후보키 | 결정하는 놈은 다 후보키여야 |

## ❌ 3단계 스키마 — 외부/개념/내부 구분 못 함
✅ **한 줄 정리**: 외부=사용자 개인 관점, 개념=전체 논리 구조, 내부=물리 저장 방식
💡 **암기팁**: **"외(사용자) → 개(전체) → 내(물리)"** — 밖에서 안으로!

| 스키마 | 누구의 관점? | 비유 |
|--------|-------------|------|
| 외부 | 사용자 개개인 | 각 부서의 업무화면 |
| 개념 | DBA/전체 | 회사 전체 조직도 |
| 내부 | 시스템/물리 | 서버실 하드디스크 배치 |

> 📌 출처: 모의고사 1회 (2026-03-31)

## ❌ 내부 스키마 vs 개념 스키마 구분 헷갈림
✅ **한 줄 정리**: 개념 = **무엇**을 저장? (논리적 테이블 구조) / 내부 = **어떻게** 저장? (물리적 인덱스·압축)
💡 **암기팁**: **"개(념)=개요(설계도), 내(부)=내장(하드디스크)"** — 개념은 구조, 내부는 저장!

| 구분 | 개념 스키마 | 내부 스키마 |
|------|------------|------------|
| SQL 예시 | `CREATE TABLE` | `CREATE INDEX`, `ENGINE=` |
| 비유 | 건물 설계도 | 시공 도면 |
| 변경 시 | 논리적 독립성 (외부↔개념) | 물리적 독립성 (개념↔내부) |

## ❌ 개념적 설계 vs 논리적 설계 구분 헷갈림
✅ **한 줄 정리**: 개념 = **ER 다이어그램**(그림) / 논리 = **테이블 변환 + 정규화**(표)
💡 **암기팁**: **"개(념)=개체 그림(ER), 논(리)=논리적 표(Table)"** — 그림이 먼저, 표가 다음!

| 구분 | 개념적 설계 | 논리적 설계 |
|------|------------|------------|
| 산출물 | ER 다이어그램 | 릴레이션 스키마 (테이블 명세) |
| DBMS | 독립적 (안 정함) | 데이터 모델 선택 (관계형 등) |
| 핵심 작업 | 개체·속성·관계 정의 | 정규화, PK/FK 설정 |
| 비유 | 손스케치 | 정식 도면 |

⚠️ **시험 함정**: "ER 다이어그램 = 논리 설계"로 낚는 문제 많음! → **개념 설계가 정답!**

## ❌ 트랜잭션 인터페이스 설계 vs 트랜잭션 분석 혼동
✅ **한 줄 정리**: 인터페이스 설계 = **뭘 할지 정의**(개념 설계) / 분석 = **얼마나 자주 쓰는지 통계**(물리 설계)
💡 **암기팁**: **"인터페이스=메뉴판(개념), 분석=인기메뉴 통계(물리)"**

| 구분 | 트랜잭션 인터페이스 설계 | 트랜잭션 분석 |
|------|----------------------|-------------|
| 단계 | **개념적 설계** | **물리적 설계** |
| 내용 | 어떤 작업을 할지 정의 | 빈도·성능 분석 |

⚠️ **시험 함정**: 둘 다 "트랜잭션"이라 같은 단계로 착각! → 단계가 다르다!

## ❌ 오버플로우 블록 개념 모름 — 어디서 생기는지 헷갈림
✅ **한 줄 정리**: 오버플로우 블록 = 블록이 꽉 차서 넘친 데이터의 임시 저장소 → **ISAM에서만** 발생!
💡 **암기팁**: **"오버플로우 = ISAM 전용!"** — 순차(없음), VSAM(자동분할), 히프(빈 데 넣으니 안 넘침)

| 파일 구조 | 오버플로우 | 이유 |
|-----------|----------|------|
| 순차 파일 | ❌ | 파일 전체를 다시 씀 |
| ISAM | ✅ | 블록 꽉 차면 넘김 → 재조직 필요 |
| VSAM | ❌ | B+트리 자동 분할 |
| 히프 파일 | ❌ | 순서 없이 빈 곳에 넣음 |

> 📌 출처: 2019 계리직 27번 복습 (2026-04-04)

## ❌ 2NF vs 3NF 위반 조건 혼동
✅ **한 줄 정리**: 2NF 위반 = 키의 **반쪽**(일부)이 결정 / 3NF 위반 = **징검다리**(2다리) 거쳐 결정
💡 **암기팁**: **"2(NF)=반(半)쪽키, 3(NF)=징검다리"** — 부(2)분 → 이(3)행!

| 구분 | 2NF 위반 (부분 종속) | 3NF 위반 (이행 종속) |
|------|-------------------|-------------------|
| 패턴 | (A,B) 중 B만 → C | 키 → A → B |
| 비유 | 열쇠 반쪽으로 열림 | 2다리 건너 결정 |
| 누가 결정? | 복합키의 **일부** | 비키 속성이 다른 비키 속성을 |

⚠️ **주의**: "한 컬럼이 다른 컬럼 결정 = 2NF"가 아님! 핵심은 **키의 일부**가 결정하느냐(2NF) vs **비키→비키 징검다리**냐(3NF)
