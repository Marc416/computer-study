SQL과 정규화 문제풀이

DDL·DML·DCL 구분 · SELECT 결과 세기 · 함수종속과 정규형 판별 · PART 05. 데이터베이스론

핵심 요약

SQL 문제는 명령어를 DDL/DML/DCL로 분류하거나 결과 투플 수를 세는 두 유형이 대부분이다.

정규형 판별은 "부분종속 있으면 1NF, 없으면 2NF, 이행종속까지 없으면 3NF" 순서로 위에서 아래로 훑으면 끝난다.

🎯이 단원을 왜 배우나

SQL — 명령어의 "소속"을 묻는 이유

SQL 명령어는 하는 일에 따라 세 부류로 나뉜다. 테이블 구조 자체를 만들고 고치는 명령(DDL), 그 안의 데이터를 넣고 빼고 찾는 명령(DML), 누가 쓸 수 있는지 권한을 통제하는 명령(DCL)이다. 시험이 이 분류를 집요하게 묻는 이유는, 실무에서 권한을 이 단위로 부여하기 때문이다 — 예를 들어 일반 사용자에게는 DML만 허용하고 DDL은 막아야 테이블이 함부로 삭제되지 않는다.

분류만 알면 끝나는 게 아니라 함정이 하나 더 있다. 명령어 이름만 보고 짐작하면 틀리는 경우가 있는데, 대표적으로 DELETE와 DROP이다. DELETE는 행을 지우는 DML이고, DROP은 테이블 자체를 지우는 DDL이다. 이름이 비슷해 보여도 소속이 완전히 다르다.

정규화 — 왜 테이블을 쪼개는가

한 테이블에 모든 걸 몰아넣으면 편할 것 같지만, 이상 현상(anomaly)이라는 세 가지 사고가 터진다. 데이터가 중복 저장되니 일부만 고치면 값이 어긋나고(수정 이상), 엉뚱한 정보 없이는 새 정보를 못 넣고(삽입 이상), 하나 지우려다 멀쩡한 정보까지 날아간다(삭제 이상).

정규화는 이 문제를 속성 간의 종속 관계를 분석해 릴레이션을 여러 개로 분해함으로써 해결한다. 여기서 핵심 단어는 "분해"다 — 시험에 "정규화는 릴레이션을 병합하는 과정"이라고 나오면 무조건 오답이다.

정규형 판별 문제는 겁먹기 쉽지만, 기본키를 확인하고 → 부분종속 찾고 → 이행종속 찾는 3단계 절차를 그대로 따라가면 기계적으로 답이 나온다. 아래에서 그 절차를 그림과 함께 익힌다.

이름이 헷갈리는 짝들 — 반드시 구별

  • DELETE(DML) vs DROP(DDL): DELETE는 행을 지우고 테이블은 남는다. DROP은 테이블 자체를 없앤다
  • DELETE vs TRUNCATE(DDL): 둘 다 데이터를 비우지만 TRUNCATE는 구조만 남기고 전부 삭제하며 되돌리기 어렵다
  • ALTER TABLE ... DROP COLUMN vs DROP TABLE: 앞은 열 하나를 지우는 것, 뒤는 테이블 전체를 지우는 것. 테이블을 지우려고 ALTER TABLE 배송업체 DROP;이라고 쓰면 틀린 문법이다 (2019 서울시 출제)
  • RENAME은 테이블 이름을 바꾸는 DDL이다 (데이터를 건드리지 않으므로 DML이 아님)

WHERE vs HAVING: WHERE는 그룹으로 묶기 전에 개별 행을 거르고, HAVING은 묶은 뒤 그룹 단위로 거른다. "평균 나이가 30 미만인 취미만 출력"처럼 집계 함수(avg, count 등)에 대한 조건은 반드시 HAVING에 써야 한다.
중복 처리: SQL의 SELECT는 기본적으로 중복을 허용한다. 중복을 없애려면 SELECT DISTINCT를 써야 한다. 관계대수의 π가 자동으로 중복을 제거하는 것과 정반대이므로 결과 투플 수를 세는 문제에서 반드시 확인할 것.

이상 현상(Anomaly) 3종 📖 기출문제집 p.561~562

이상무슨 일이 벌어지나
수정 이상반복 저장된 데이터 중 일부만 고치면 값이 서로 어긋나 불일치 발생
삽입 이상불필요한 정보를 함께 넣지 않고는 원하는 정보를 저장할 수 없음

예시 하나로 셋 다 이해하기: [학번, 이름, 학과, 학과사무실] 한 테이블에 다 넣었다고 하자. ① 학과사무실이 바뀌면 그 학과 학생 전원의 행을 고쳐야 하는데 일부만 고치면 불일치 → 수정 이상. ② 아직 학생이 없는 신설 학과의 사무실 정보를 넣으려면 가짜 학생을 만들어야 함 → 삽입 이상. ③ 어떤 학과의 마지막 학생을 지우면 그 학과 사무실 정보까지 사라짐 → 삭제 이상.

함수 종속(Functional Dependency)

A → B는 "A값이 정해지면 B값도 하나로 정해진다"는 뜻이고, "B는 A에 함수적으로 종속된다"고 읽는다. 정규형 판별은 결국 어떤 종류의 종속이 남아 있는지를 보는 일이다.

종속 종류정의예시 (기본키 = {A, B})
완전 함수 종속기본키 전체에 종속 (일부만으로는 결정 안 됨){A, B} → C
부분 함수 종속기본키의 일부분만으로도 결정됨A → C (A는 기본키의 일부)
이행 함수 종속A → B 이고 B → C 이면 A → C 가 간접적으로 성립A → B, B → C

정규형 단계와 판별 절차

정규형 판별 3단계 — 문제 푸는 순서 그대로

  1. 기본키를 확인한다. 복합키({A,B})인지 단일키(A)인지가 출발점이다
  2. 부분 함수 종속이 있는가? 기본키가 {A,B}인데 A → C처럼 키의 일부만으로 결정되는 속성이 있으면 → 1NF까지만 만족 (2NF 실패)
  3. 이행 함수 종속이 있는가? 부분종속은 없는데 A → B, B → C 사슬이 있으면 → 2NF까지만 만족 (3NF 실패)
  4. 둘 다 없으면 3NF. 여기서 모든 결정자가 후보키이기까지 하면 BCNF

결정적 한 줄: 이행종속이 있더라도 부분종속이 먼저 발견되면 그 릴레이션은 1정규형이다. 정규형은 낮은 단계부터 차례로 만족해야 하므로, 아래 단계에서 걸리면 위 단계는 볼 필요도 없다. 2019 지방직·2014 계리직 문제가 정확히 이 논리를 물었다.

정규화의 대가(代價): 정규화를 많이 하면 릴레이션이 여러 개로 쪼개지므로 조인이 늘어나 검색(질의 처리) 시간은 증가한다. 그래서 성능이 중요한 경우 일부러 합치는 반정규화(역정규화)를 하기도 한다. "정규화하면 검색 성능이 향상된다"는 선택지는 오답이다.

📌시험 빈출 포인트

  • DDL = CREATE·ALTER·DROP·RENAME·TRUNCATE, DML = SELECT·INSERT·UPDATE·DELETE, DCL = GRANT·REVOKE
  • DELETE는 DML(행 삭제), DROP은 DDL(테이블 삭제) — 최다 함정
  • 테이블 삭제는 DROP TABLE 이름; — ALTER TABLE 이름 DROP;은 잘못된 문법
  • SELECT문에서 SELECT·FROM은 필수, WHERE는 선택
  • SELECT는 중복 허용 → 결과 투플 수 = 원본 행 수, DISTINCT를 써야 중복 제거
  • 집계 함수 조건은 WHERE가 아니라 HAVING
  • 정규화는 릴레이션을 분해하는 과정 (병합 아님), 고려 대상은 속성 간 관계(튜플 간 관계 아님)
  • 정규형 판별: 부분종속 → 1NF / 이행종속 → 2NF / 둘 다 없음 → 3NF
  • 정규화를 진행하면 검색 시간은 오히려 증가할 수 있다

문제 12024 지방직 · 기출문제집 p.579

DDL(Data Definition Language) 명령어에 해당하지 않는 것은?

  1. ALTER
  2. DROP
  3. SELECT
  4. CREATE
해설 보기

정답 ③ SELECT

SELECT는 테이블에서 조건에 맞는 데이터를 검색하는 명령이므로 DML이다. ALTER·DROP·CREATE는 모두 테이블 구조를 다루는 DDL.

즉시 판별법: 그 명령을 실행했을 때 테이블의 모양(스키마)이 바뀌는가를 자문해라. 바뀌면 DDL, 안에 든 데이터만 바뀌면 DML이다. SELECT는 아무것도 바꾸지 않고 읽기만 하므로 DML(조작어)로 분류된다.

문제 22019 계리직 · 기출문제집 p.580

SQL의 명령을 DDL, DML, DCL로 구분할 경우, 이를 바르게 짝지은 것은?

DDLDMLDCL
①RENAMESELECTCOMMIT
②UPDATESELECTGRANT
③RENAMEALTERCOMMIT
④UPDATEALTERGRANT
해설 보기

정답 ①

  1. RENAME은 테이블 이름을 바꾸므로 DDL ✓ → DDL 자리에 UPDATE가 온 ②·④ 소거
  2. SELECT는 데이터 검색이므로 DML ✓ → DML 자리에 ALTER(DDL)가 온 ③ 소거
  3. 남은 ①에서 COMMIT은 엄밀히 TCL이지만, 제어 기능이라는 공통점 때문에 DCL의 일부로 분류하기도 하므로 3분류 문제에서는 DCL 자리에 올 수 있다

주의: COMMIT을 보고 "이건 TCL인데?"라며 ①을 배제하면 안 된다. 3분류로만 묻는 문제에서는 TCL을 DCL에 포함시키는 것이 관례다. 다른 선택지들이 명백히 틀렸다면 남은 것을 답으로 고르는 소거법이 안전하다.

문제 32017 하반기 국가직 · 기출문제집 p.581

관계형 데이터베이스 언어인 SQL에 대한 설명으로 옳은 것은?

  1. 데이터 정의어(DDL)를 이용하여 데이터를 검색한다.
  2. 데이터 조작어(DML)를 이용하여 권한을 부여하거나 취소한다.
  3. DELETE 문은 테이블을 삭제하는 데 사용한다.
  4. SELECT 문에서 FROM 절은 필수 항목이고, WHERE 절은 선택 항목이다.
해설 보기

정답 ④

  1. ① 데이터 검색은 DDL이 아니라 DML(SELECT)의 역할 → 틀림
  2. ② 권한 부여·취소는 DML이 아니라 DCL(GRANT/REVOKE) → 틀림
  3. ③ DELETE는 행을 삭제한다. 테이블 삭제는 DROP → 틀림
  4. ④ SELECT와 FROM은 없으면 문장이 성립하지 않는 필수, WHERE는 조건이 없으면 생략 가능한 선택 → 옳음

세 가지 함정이 한 문제에: ①②③은 각각 DDL↔DML 혼동, DML↔DCL 혼동, DELETE↔DROP 혼동이다. 이 세 쌍만 확실히 구분하면 SQL 분류 문제는 대부분 처리된다.

문제 42019 서울시 · 기출문제집 p.582

판매 데이터베이스에 대한 다음 SQL문 중 가장 옳지 않은 것은?
고객(고객아이디, 고객이름, 나이, 등급, 직업, 적립금) / 주문(주문번호, 주문제품, 주문고객, 수량, 배송지, 주문일자) / 배송업체(업체번호, 업체명, 주소, 전화번호)

  1. 고객 테이블에 가입날짜를 추가 — ALTER TABLE 고객 ADD 가입날짜 DATE;
  2. 주문 테이블에서 배송지를 삭제 — ALTER TABLE 주문 DROP COLUMN 배송지;
  3. 고객 테이블에 18세 이상 제약조건 추가 — ALTER TABLE 고객 ADD CONSTRAINT CHK_AGE CHECK(나이 >= 18);
  4. 배송업체 테이블을 삭제 — ALTER TABLE 배송업체 DROP;
해설 보기

정답 ④

테이블 전체를 삭제하려면 DROP TABLE 배송업체;라고 써야 한다. ALTER TABLE은 이미 존재하는 테이블의 "구조 일부"를 바꾸는 명령이라, 테이블 자체를 없애는 데 쓸 수 없다.

  1. ①은 열 추가 → ALTER TABLE ... ADD ✓
  2. ②는 열 삭제 → ALTER TABLE ... DROP COLUMN ✓ (COLUMN을 명시했다는 점에 주목)
  3. ③은 제약조건 추가 → ALTER TABLE ... ADD CONSTRAINT ✓
  4. ④는 테이블 삭제인데 ALTER를 썼다 → ✗

구별 한 줄: 테이블 안의 무언가를 바꾸면 ALTER, 테이블 자체를 없애면 DROP TABLE. ②번의 DROP COLUMN과 ④번의 DROP이 비슷해 보여 헷갈리게 만든 문제다.

문제 52007 국가직 7급 · 기출문제집 p.582

학생(STUDENT) 테이블에 영문학과 50명, 법학과 100명, 수학과 50명의 정보가 저장되어 있다. 다음 세 SQL문의 실행 결과 투플 수는 각각 얼마인가?
㉠ SELECT DEPT FROM STUDENT;
㉡ SELECT DISTINCT DEPT FROM STUDENT;
㉢ SELECT NAME FROM STUDENT WHERE DEPT = '영문학과';

해설 보기

정답: ㉠ 200, ㉡ 3, ㉢ 50

  1. ㉠ 전체 학생의 학과를 검색한다. 학생 수는 50+100+50 = 200명이고, SELECT는 중복을 허용하므로 같은 학과명이 반복 출력된다 → 200
  2. ㉡ DISTINCT가 붙었으므로 중복 학과명이 제거된다. 학과는 영문·법학·수학 3개 → 3
  3. ㉢ 영문학과 학생의 이름을 검색한다. 동명이인이 있어도 DISTINCT가 없으므로 그대로 출력 → 영문학과 학생 수인 50

이 문제의 교훈: SQL 결과 투플 수 문제는 DISTINCT의 유무만 확인하면 된다. 없으면 조건에 맞는 행 수 그대로, 있으면 서로 다른 값의 개수다. ㉢에서 "이름이니까 중복을 빼야지"라고 생각하면 틀린다 — 문법에 DISTINCT가 없으면 DBMS는 중복을 제거하지 않는다.

문제 62016 지방직 · 기출문제집 p.562~563

관계형 데이터베이스 설계에서의 정규화에 대한 설명으로 옳지 않은 것은?

  1. 질의처리 성능 향상을 위해 비효율적인 릴레이션들을 병합하는 과정이다.
  2. 데이터 중복을 감소시켜 저장 공간의 효율성을 향상시킨다.
  3. 삽입, 삭제, 수정 시 발생할 수 있는 이상(anomaly) 현상을 제거한다.
  4. 정규형에는 1NF, 2NF, 3NF, BCNF, 4NF, 5NF 등이 있다.
해설 보기

정답 ①

정규화는 애트리뷰트 간의 종속 관계를 분석해 여러 릴레이션으로 분해하는 과정이다. 병합이 아니라 분해다.

게다가 방향도 반대다 — 정규화를 진행하면 릴레이션이 여러 개로 쪼개져 조인이 늘어나므로 검색(질의 처리) 시간은 일반적으로 증가한다. 즉 ①번은 "병합"이라는 단어와 "성능 향상"이라는 목적 두 군데 모두 틀렸다.

참고 — 반정규화: 실무에서 조회 성능이 절실하면 일부러 테이블을 합치기도 하는데, 이것을 반정규화(역정규화)라 부른다. ①번 문장은 정규화가 아니라 반정규화의 설명에 가깝다.
문제 72010 계리직 · 기출문제집 p.562

데이터베이스 릴레이션을 정규화할 때 고려해야 할 사항과 가장 관련이 없는 것은?

  1. 원하지 않는 데이터의 중복을 제거한다.
  2. 원하지 않는 데이터의 종속을 제거한다.
  3. 한 릴레이션 내의 속성들 간의 관계를 고려한다.
  4. 한 릴레이션 내의 튜플들 간의 관계를 고려한다.
해설 보기

정답 ④

정규화는 속성(열) 사이의 함수적 종속 관계를 분석하는 작업이다. 튜플(행)끼리의 관계는 고려 대상이 아니다.

왜 그런가: 함수 종속 A → B는 "A라는 속성의 값이 B라는 속성의 값을 결정한다"는 진술이다. 행과 행 사이에는 애초에 이런 결정 관계를 정의하지 않는다(릴레이션의 특성상 튜플 간에는 순서도 관계도 없다).

선택지 대조: ③번(속성들 간)과 ④번(튜플들 간)이 한 글자만 다르게 나란히 배치된 전형적인 함정이다. 이런 쌍이 보이면 둘 중 하나가 답이라고 보면 된다.

문제 82019 지방직 · 기출문제집 p.565

릴레이션 R = {A, B, C, D, E}가 함수적 종속성 {A, B} → D, A → C, {A, B} → E를 만족할 때, R이 속할 수 있는 가장 높은 차수의 정규형은? (단, 기본키는 복합속성 {A, B}이고, 모든 속성값은 원자값이다)

  1. 제1정규형
  2. 제2정규형
  3. 제3정규형
  4. 보이스/코드 정규형
해설 보기

정답 ① 제1정규형

  1. 1NF 확인: 모든 속성값이 원자값이라고 주어졌으므로 1NF는 만족 ✓
  2. 2NF 확인 (부분종속 찾기): 기본키가 {A, B}인데, 종속성 중 A → C가 있다. A는 기본키의 일부이므로 이것은 부분 함수 종속이다 → 2NF 실패
  3. 2NF를 만족하지 못하므로 3NF·BCNF는 볼 필요도 없다 → 가장 높은 정규형은 1NF

풀이 요령: 복합키({A,B})가 주어지면 가장 먼저 "키의 일부만 왼쪽에 있는 종속"이 있는지 훑어라. A → ○ 또는 B → ○ 형태가 하나라도 보이면 그 즉시 답은 1NF로 확정된다. 다른 종속을 분석할 필요가 없어 10초 만에 풀린다.

함정: "이행종속은 없으니 3NF 아닌가?"라고 생각하면 틀린다. 정규형은 아래 단계를 먼저 통과해야 위 단계를 논할 수 있다. 부분종속에서 걸리면 거기서 끝이다.

문제 92018 교육청 · 기출문제집 p.565

릴레이션 스키마 R(A, B, C, D, E, F)에서 함수적 종속이 {(A,B) → C, B → D, A → E, E → F}일 때, 제3정규형을 만족하도록 R을 분해한 것으로 옳은 것은? (R의 기본키는 (A, B))

  1. R1(A,B,C,D) / R2(A,E) / R3(E,F)
  2. R1(A,B,C) / R2(B,D) / R3(A,E,F)
  3. R1(A,B,C) / R2(B,D) / R3(A,E) / R4(E,F)
  4. R1(A,C) / R2(B,C) / R3(B,D) / R4(A,E,F)
해설 보기

정답 ③ R1(A,B,C) / R2(B,D) / R3(A,E) / R4(E,F)

종속을 하나씩 보며 문제가 되는 것을 떼어내는 방식으로 푼다.

  1. (A,B) → C: 기본키 전체가 결정하므로 완전 함수 종속 — 정상. 이건 남긴다 → R1(A, B, C)
  2. B → D: 키의 일부(B)가 D를 결정 → 부분 종속. 분리해야 2NF → R2(B, D)
  3. A → E: 역시 키의 일부(A)가 E를 결정 → 부분 종속. 분리 → R3(A, E)
  4. E → F: E는 키가 아닌 속성인데 F를 결정한다. A → E → F 사슬이 되므로 이행 종속. 3NF를 만족하려면 따로 떼어내야 한다 → R4(E, F)

오답이 틀린 이유:

  • ① R1에 D가 남아 있어 B → D 부분종속이 그대로다
  • ② R3(A,E,F) 안에 A → E → F 이행종속이 살아 있다 → 3NF 아님
  • ④ R4(A,E,F)에 이행종속이 남아 있고, R1(A,C)·R2(B,C)로 쪼갠 것은 (A,B) → C라는 원래 종속을 표현하지 못한다(정보 손실)

핵심 감각: 분해 결과의 각 릴레이션에서 "키가 아닌 속성이 다른 비키 속성을 결정하고 있지 않은지"를 확인하면 3NF 위반을 잡아낼 수 있다. ②·④처럼 (A, E, F)가 한 덩어리로 남아 있으면 거의 항상 오답이다.

문제 102015 서울시 · 기출문제집 p.565~566

스키마 R(A, B, C, D)가 함수적 종속 {A → B, A → C}를 가질 때, 다음 중 BCNF 정규형을 만족하는 분해는?

  1. S(A, B, C, D)
  2. S(A, B)와 T(A, C, D)
  3. S(A, C)와 T(A, B, D)
  4. S(A, B, C)와 T(A, D)
해설 보기

정답 ④ S(A, B, C)와 T(A, D)

BCNF의 조건은 "모든 결정자(→의 왼쪽)가 후보키여야 한다"이다. 각 분해에서 이 조건을 검사한다.

  1. ① S(A,B,C,D): A는 B·C는 결정하지만 D는 결정하지 못하므로 후보키는 (A,D)다. 그런데 결정자 A는 후보키가 아니다 → BCNF 아님
  2. ② S(A,B)는 A가 키이므로 OK. 그러나 T(A,C,D)에서 A → C가 성립하는데 T의 키는 (A,D)이므로 A는 후보키가 아니다 → BCNF 아님
  3. ③ S(A,C)는 OK. 그러나 T(A,B,D)에서 A → B가 성립하고 키는 (A,D) → 같은 이유로 BCNF 아님
  4. ④ S(A,B,C): A → B, A → C가 성립하고 A가 이 릴레이션의 키다 → BCNF ✓ / T(A,D): 자명하지 않은 종속이 없고 (A,D)가 키다 → BCNF ✓ → 둘 다 만족

감각적으로 보는 법: A가 결정하는 속성들(B, C)은 A와 함께 한 테이블에 모으고, A가 결정하지 못하는 D는 따로 빼내면 된다. 즉 "같은 결정자에 딸린 것끼리 모아라"가 요령이다. ②·③처럼 A가 결정하는 속성 하나와 결정하지 못하는 D를 같은 테이블에 섞으면 반드시 위반이 생긴다.
