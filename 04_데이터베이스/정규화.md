# 정규화 (Normalization)

## 핵심 요약
> 정규화 = 데이터 중복과 이상(anomaly)을 제거하기 위해 릴레이션을 분해하는 과정
> **1NF → 2NF → 3NF → BCNF → 4NF → 5NF** 순서로 강화됨

## 주요 개념

### 함수 종속(FD) 표기법 읽는 법

**X → Y** = "X의 값이 정해지면 Y의 값이 **하나로** 결정된다"

| 표기 | 읽는 법 | 일상 비유 |
|------|---------|-----------|
| A → B | A가 정해지면 B가 결정됨 | 주민번호를 알면 이름이 결정됨 |
| {A, B} → C, D | A와 B를 **함께** 알면 C와 D가 결정됨 | (학번 + 과목코드)를 알면 성적과 담당교수가 결정됨 |
| B → C | B만 알아도 C가 결정됨 | 과목코드만 알아도 담당교수가 결정됨 |

핵심 규칙: **왼쪽 값이 같으면 오른쪽 값도 반드시 같아야 한다**

> 예: {A, B} → C, D는 기본키가 (A, B)이면 당연한 것!
> 기본키 = 열쇠이므로, 열쇠로 문을 열면 방 안의 모든 것(C, D)을 볼 수 있음
>
> 문제가 되는 건 B → C, C → D처럼 **기본키가 아닌 것이 다른 속성을 결정하는 경우**

### 용어 정리
- **함수 종속(FD)**: X → Y = "X가 정해지면 Y가 하나로 결정된다"
- **부분 함수 종속**: 기본키의 **일부분**만으로 다른 속성이 결정되는 것 (2NF 위반)
- **완전 함수 종속**: 기본키 **전체**에 의해서만 결정되는 것 (2NF 충족)
- **이행 함수 종속**: A → B → C처럼 징검다리를 거쳐 결정되는 것 (3NF 위반)

### 정규형 단계별 정리

| 정규형 | 조건 | 제거 대상 | 쉬운 비유 |
|--------|------|-----------|-----------|
| **1NF** | 모든 속성이 원자값 | 반복 그룹, 다중값 | 칸마다 값 하나씩만 |
| **2NF** | 1NF + 부분 함수 종속 제거 | 키 일부 → 비키 속성 | 복합키 전체에 의존해야 함 |
| **3NF** | 2NF + 이행 함수 종속 제거 | 비키 → 비키 종속 | 징검다리 종속 금지 |
| **BCNF** | 모든 결정자가 후보키 | 후보키 아닌 결정자 | 결정하는 놈은 반드시 키 |
| **4NF** | BCNF + 다치 종속 제거 | 다치 종속(MVD) | - |
| **5NF** | 4NF + 조인 종속 제거 | 조인 종속(JD) | - |

> 시험에는 **1NF ~ BCNF**가 가장 많이 출제됨!

## 판별 방법 (플로우차트)

```
1단계: 모든 속성이 원자값인가?
  → No  → 비정규형
  → Yes → 1NF 이상

2단계: 부분 함수 종속이 있는가? (복합키일 때만 해당)
  → Yes → 1NF에서 멈춤
  → No  → 2NF 이상

3단계: 이행 함수 종속이 있는가?
  → Yes → 2NF에서 멈춤
  → No  → 3NF 이상

4단계: 모든 결정자가 후보키인가?
  → No  → 3NF에서 멈춤
  → Yes → BCNF 이상

5단계: 다치 종속(MVD)이 있는가?
  → Yes → BCNF에서 멈춤
  → No  → 4NF 이상

6단계: 조인 종속(JD)이 있는가?
  → Yes → 4NF에서 멈춤
  → No  → 5NF (완전 정규형)
```

### 3NF vs BCNF 판별 포인트

3NF까지 왔는데 BCNF인지 아닌지 헷갈릴 때:
- **결정자**(화살표 왼쪽에 있는 것)를 모두 찾는다
- 그 결정자가 **후보키인지** 확인한다
- 후보키가 아닌 결정자가 하나라도 있으면 → 3NF (BCNF 아님)

> 예: 학번 → 학과, 학과 → 학과장
> "학과"는 결정자인데 후보키가 아님 → BCNF 위반 → 3NF에서 멈춤

### 4NF 판별 포인트: 다치 종속(MVD)

**다치 종속(Multi-Valued Dependency)**: X →→ Y
= "X 하나에 Y값이 **여러 개** 대응되는데, 다른 속성과는 **독립적**"

> 비유: 한 교수가 여러 과목도 가르치고, 여러 취미도 있는데
> 과목과 취미는 서로 아무 관계가 없는 상황
>
> | 교수 | 과목 | 취미 |
> |------|------|------|
> | 김 | DB | 등산 |
> | 김 | DB | 낚시 |
> | 김 | OS | 등산 |
> | 김 | OS | 낚시 |
>
> 교수 →→ 과목, 교수 →→ 취미 (서로 독립적인데 조합이 폭발)
> → 해결: (교수, 과목)과 (교수, 취미)로 분해

**BCNF인데 다치 종속이 존재하면 → BCNF에서 멈춤 (4NF 아님)**

다치 종속의 핵심 특징:
- 과목 2개 × 취미 2개 = 행 4개처럼 **조합이 폭발**하는 것이 신호
- 해결법: 독립적인 다중값 속성끼리 **별도 테이블로 분리**
- 위 예시에서는 (교수, 과목) 테이블과 (교수, 취미) 테이블로 나눔

### 5NF 판별 포인트: 조인 종속(JD)

**조인 종속(Join Dependency)**:
= "릴레이션을 2개로 쪼개면 정보 손실이 생기지만, 3개 이상으로 쪼개면 손실 없이 복원 가능한 상황"

> 예: 공급업체-부품-프로젝트 관계
> - A업체가 볼트를 공급할 수 있고
> - A업체가 X프로젝트에 참여하고
> - X프로젝트에 볼트가 필요하다고 해서
> - → "A업체가 X프로젝트에 볼트를 공급한다"는 **아닐 수도 있음**
>
> 해결: (업체,부품) + (업체,프로젝트) + (부품,프로젝트) 3개로 분해

### 다치 종속 vs 조인 종속 비교
| 구분 | 다치 종속 (4NF) | 조인 종속 (5NF) |
|------|----------------|----------------|
| 핵심 | 독립적인 다중값들이 조합 폭발 | 2개 분해로 안 되고 3개 이상 필요 |
| 표기 | X →→ Y | *(R1, R2, R3, ...) |
| 비유 | 과목과 취미가 무관한데 같이 있음 | 3자 관계가 꼬여있음 |
| 시험 빈도 | 가끔 출제 | 거의 안 나옴 |

실무와 시험에서 4NF, 5NF는 출제 빈도가 매우 낮음. **1NF~BCNF를 확실히 잡는 것이 우선!**

### 주의: 부분 함수 종속은 복합키일 때만 발생
- 기본키가 하나의 속성이면 → 부분 함수 종속 자체가 불가능
- 기본키가 (A, B) 같은 복합키일 때 → B만으로 C를 결정하면 부분 종속!

## 기출 예제 (2014 계리)

### 문제
R(A, B, C, D), 기본키 = (A, B)
- {A, B} → C, D
- B → C (부분 함수 종속!)
- C → D (이행 함수 종속!)

### 풀이
1. 원자값 조건 OK → 1NF 충족
2. B → C: B는 기본키(A,B)의 일부인데 C를 결정 → **부분 함수 종속 존재** → 2NF 미충족
3. 부분 함수 종속이 있으므로 → **제1정규형(1NF)**

> 답: 제1정규형

## 헷갈리는 개념 비교

### 부분 vs 완전 함수 종속
| 구분 | 부분 함수 종속 | 완전 함수 종속 |
|------|---------------|---------------|
| 의미 | 키의 **일부**로 결정 | 키 **전체**로만 결정 |
| 예시 | (학번, 과목) 중 학번만으로 이름 결정 | (학번, 과목) 전체로 성적 결정 |
| 정규형 | 2NF 위반 | 2NF 충족 |

### 이행 vs 부분 함수 종속
| 구분 | 부분 함수 종속 | 이행 함수 종속 |
|------|---------------|---------------|
| 형태 | 키의 일부 → 속성 | 키 → A → B (징검다리) |
| 위반 | 2NF 위반 | 3NF 위반 |
| 해결 | 부분 종속 속성을 분리 | 이행 종속 속성을 분리 |

### 3NF vs BCNF
| 구분 | 3NF | BCNF |
|------|-----|------|
| 조건 | 이행 종속 없음 | 모든 결정자가 후보키 |
| 차이 | 후보키 아닌 속성끼리 종속 금지 | 후보키 아닌 결정자 자체를 금지 |
| 관계 | BCNF가 더 엄격 (BCNF이면 반드시 3NF) |

## 정규화 관련 추가 포인트
- 정규화하면 **릴레이션 수가 증가** (분해되므로)
- 정규화하면 **이상현상(삽입/삭제/갱신 이상)이 해결**됨
- 과도한 정규화는 **조인 연산 증가** → 성능 저하 가능
- 이를 해결하기 위해 **반정규화(역정규화)**를 하기도 함
