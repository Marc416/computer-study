관계대수 연산과 결과 릴레이션

σ·π·⋈·÷ 연산이 표를 어떻게 바꾸는지 · 연산 트리 · 결과 구하기 · PART 05. 데이터베이스론

핵심 요약

σ(셀렉트)는 행을 거르고, π(프로젝트)는 열을 거른다. 이 한 줄이 관계대수 문제의 절반이다.

시험은 거의 항상 "이 식을 적용한 결과 릴레이션은?" 또는 "결과의 카디널리티(행 수)는?"를 묻는다 — 손으로 표를 그려가며 푸는 게 가장 빠르다.

🎯이 단원을 왜 배우나

SQL의 "속마음"이 관계대수다

우리가 쓰는 SELECT ... FROM ... WHERE ...는 사람이 읽기 좋은 표현일 뿐이다. DBMS는 이 문장을 받으면 곧바로 관계대수 식으로 번역한 뒤 실행 계획을 세운다. 즉 관계대수는 DBMS 내부에서 쿼리가 처리되는 실제 언어다.

대응 관계는 정확히 1:1이다 — SELECT절에 적는 컬럼 목록은 π(프로젝트), WHERE절에 적는 조건은 σ(셀렉트), FROM절에 테이블 여러 개를 적는 것은 ⋈(조인)이다. 이름이 헷갈리는 함정이 하나 있는데, SQL의 SELECT는 관계대수의 σ(셀렉트)가 아니라 π(프로젝트)에 해당한다. 매년 이걸 뒤집어 놓은 선택지가 나온다.

또 하나 배우는 이유는 질의 최적화 때문이다. 같은 결과를 내는 관계대수 식이 여러 개 있을 때, 어떤 순서로 연산하느냐에 따라 처리 속도가 수십 배 차이 난다. "먼저 걸러서(σ) 행을 줄인 뒤 조인하라"는 최적화 규칙이 나오는 근거가 바로 여기다.

출제 형태는 셋뿐이다 — ① 기호 ↔ 이름 매칭, ② SQL ↔ 관계대수 변환, ③ 표와 식을 주고 결과 구하기. ③번이 배점이 크고 시간도 걸리는데, 연산을 하나씩 적용하며 중간 표를 직접 그리는 습관만 들이면 확실히 맞힐 수 있다.

💡주요 개념 — 순수 관계연산 4가지

관계대수 연산은 순수 관계연산(관계 DB만의 연산)과 일반 집합연산(수학 집합에서 가져온 것)으로 나뉜다. 먼저 순수 관계연산 넷.

연산기호하는 일결과의 변화
셀렉트 (Select)σ (시그마)조건에 맞는 행(튜플)만 추출행 수 ↓, 열 수 그대로
프로젝트 (Project)π (파이)지정한 열(속성)만 추출열 수 ↓, 행 수는 중복 제거로 줄 수 있음
조인 (Join)⋈ (보타이)두 릴레이션을 공통 속성으로 합침열 수 ↑, 행 수는 매칭 결과에 따라
디비전 (Division)÷"~를 전부 가진 것"만 추출나눈 쪽의 열이 사라짐
σ와 π 구별법: σ는 그리스 문자 S(Select) → 가로줄을 Slice(가로로 자름). π는 기둥 두 개가 서 있는 모양 → 세로 기둥(열)을 고른다. 모양으로 외우면 시험장에서 안 헷갈린다.

σ와 π가 표를 바꾸는 모습

π의 중복 제거 — 자주 나오는 차이점: 관계대수의 프로젝트는 결과가 집합이므로 중복 튜플을 자동 제거한다. 반면 SQL의 SELECT는 중복을 허용하므로(제거하려면 DISTINCT 필요), "200개 튜플에서 SELECT하면 결과 튜플 수는?" 같은 문제의 답은 그대로 200이다.

조인(⋈) — 두 표를 공통 속성으로 붙이기

조인은 한쪽 릴레이션의 외래키와 다른 쪽의 기본키를 맞춰 옆으로 이어 붙이는 연산이다. 특히 자연 조인(natural join)은 공통 속성이 같은 값을 가진 행끼리 결합하고, 중복되는 공통 속성 열은 하나만 남긴다.

조인 결과의 행 수를 빠르게 세는 법

카디널리티(행 수)를 묻는 문제가 자주 나오는데, 전부 이어 붙여 세지 않아도 된다. 외래키 → 기본키 방향의 조인이라면, 결과 행 수는 외래키를 가진 쪽(N쪽)의 행 수와 같다. 외래키 값 하나당 참조되는 기본키 행이 정확히 하나씩이기 때문이다.

예를 들어 정책 5건이 각각 제안자(직원) 1명을 가리키고, 그 직원이 각각 부서 1개에 속한다면 — 두 번 조인해도 결과는 여전히 5행이다. 행이 늘어나는 경우는 조인 조건이 없는 카티션 프로덕트(×)거나, 공통 값이 양쪽에 여러 개씩 있을 때뿐이다.

디비전(÷) — "~를 전부 가진 것"

"필수과목을 모두 수강한 학생", "모든 부품을 다 공급하는 업체"처럼 전부(all)라는 말이 들어간 질의가 디비전이다.

디비전은 결과의 컬럼 수가 줄어든다는 점에서 셀렉트(σ, 컬럼 그대로)와 다르다. "과목" 컬럼이 사라지는 이유는, 필수과목 테이블의 컬럼을 검사에만 쓰고 결과에서는 빼기 때문이다. 즉 R ÷ S의 결과 속성 = R의 속성 − S의 속성이다.

연산 트리 — 복합 질의는 나무로 표현된다

연산을 여러 개 조합하면 DBMS는 이를 트리 구조로 표현하고 아래에서 위로 실행한다.

식을 읽는 순서 = 괄호 안쪽부터

π이름(σ등급='gold'(고객)) 같은 식은 가장 안쪽 괄호부터 바깥으로 계산한다. 즉 ① 고객 릴레이션에서 ② 등급이 gold인 행을 고르고 ③ 그 결과에서 이름 열만 뽑는다.

질의 최적화의 기본 규칙도 여기서 나온다 — σ(셀렉트)를 가능한 한 트리의 아래쪽(먼저)으로 내려라. 100만 행을 조인한 뒤 10행만 남기는 것보다, 먼저 10행으로 줄인 뒤 조인하는 쪽이 압도적으로 빠르기 때문이다. 같은 이유로 π도 일찍 수행해 불필요한 열을 미리 버린다.

관계대수 vs 관계해석

구분관계대수 (Relational Algebra)관계해석 (Relational Calculus)
성격절차적 — "어떻게(How)" 구할지 순서를 명시비절차적 — "무엇을(What)" 원하는지만 기술
표현σ, π, ⋈, ÷ 등 연산자를 조합수학의 술어 논리(predicate logic) 사용
표현력둘의 표현력은 동등하다 (하나로 표현 가능한 것은 다른 하나로도 가능)
비유: 관계대수는 "1번 국도 타고 가다 3번 출구로 나와라"(경로 지정), 관계해석은 "부산으로 가줘"(목적지만 지정). 목적지는 같지만 말하는 방식이 다르다.

📌시험 빈출 포인트

  • σ = 행(조건) 선택, π = 열(속성) 선택 — 기호와 역할 매칭이 기본
  • SQL의 SELECT절 = π, SQL의 WHERE절 = σ (이름이 같다고 SELECT를 σ로 착각하면 오답)
  • 관계대수 π는 중복 제거, SQL SELECT는 중복 허용
  • 조인 결과 카디널리티: FK→PK 조인이면 N쪽(외래키 쪽) 행 수 그대로
  • 카티션 프로덕트(×) 결과: 행 수 = m × n, 차수 = 두 차수의 합
  • 합집합·교집합·차집합은 합병 가능(차수 동일 + 도메인 동일) 조건 필요
  • 디비전(÷) 결과 속성 = R의 속성 − S의 속성 (나눈 쪽 컬럼이 사라짐)
  • 질의 최적화: σ와 π를 트리 아래쪽(먼저)으로 내려 중간 결과 크기를 줄인다
  • 관계대수 = 절차적, 관계해석 = 비절차적, 표현력은 동등

문제 12020 지방직 · 기출문제집 p.561

관계 데이터베이스 스키마 STUDENT(SNO, NAME, AGE)에 대하여 다음 SQL 질의문과 동일한 의미의 관계대수식은?
SELECT SNO, NAME
FROM STUDENT
WHERE AGE > 20;

  1. σSNO, NAME(πAGE>20(STUDENT))
  2. πSNO, NAME(σAGE>20(STUDENT))
  3. σAGE>20(πSNO, NAME(STUDENT))
  4. πAGE>20(σSNO, NAME(STUDENT))
해설 보기

정답 ② πSNO, NAME(σAGE>20(STUDENT))

  1. WHERE AGE > 20은 조건으로 행을 거르므로 → σAGE>20
  2. SELECT SNO, NAME은 출력할 열을 고르므로 → πSNO, NAME
  3. 실행 순서는 거르고(σ) → 뽑는다(π) 이므로, σ가 안쪽 괄호에 들어가야 한다

선택지 소거법: 아래첨자를 보면 즉시 판별된다. σ의 첨자에는 조건식, π의 첨자에는 속성 목록이 와야 한다. ①·④는 σ 첨자에 속성 이름이, π 첨자에 조건식이 붙어 있어 기호와 첨자가 뒤바뀐 오답이다.

③이 틀린 이유: 기호와 첨자는 맞지만 순서가 잘못됐다. 먼저 π로 SNO·NAME만 남기면 AGE 열이 사라져서 그 다음 σ에서 AGE 조건을 검사할 수 없다.

문제 22022 국가직 · 기출문제집 p.560

고객 릴레이션에서 등급이 gold이고 나이가 25 이상인 고객들을 검색하기 위한 관계대수 표현으로 옳은 것은? (검색 결과는 고객의 모든 속성을 포함한다)

  1. σ고객(등급='gold' ∧ 나이 ≥ 25)
  2. σ등급='gold' ∧ 나이 ≥ 25(고객)
  3. π고객(등급='gold' ∧ 나이 ≥ 25)
  4. π등급='gold' ∧ 나이 ≥ 25(고객)
해설 보기

정답 ② σ등급='gold' ∧ 나이 ≥ 25(고객)

  1. 조건을 만족하는 투플(행)을 추출하는 연산자는 σ → π를 쓴 ③·④ 소거
  2. σ의 아래첨자에 조건을 쓰고, 괄호 안에는 대상 릴레이션을 쓴다 → 위치가 반대인 ① 소거
  3. 남은 ②가 정답

표기법 규칙 한 줄: 연산자조건 또는 속성(릴레이션) — 릴레이션은 항상 괄호 안에 들어간다. ①번처럼 릴레이션 이름이 첨자로 가 있으면 표기법 자체가 틀린 것이다.

검색 결과에 모든 속성이 그대로 나와 있다는 점도 힌트다. 열이 줄지 않았으므로 π가 아니라 σ만 쓰인 식이어야 한다.

정답 ③ 4

안쪽 괄호(σ)부터 계산한다. 조건은 B > C이므로 각 행의 B와 C를 비교한다.

  1. 1행 (2, 5, 7): 5 > 7? 아니오 → 탈락
  2. 2행 (3, 3, 3): 3 > 3? 아니오 (같은 것은 크지 않다) → 탈락
  3. 3행 (4, 3, 2): 3 > 2? 예 → 통과
  4. 4행 (5, 2, 8): 2 > 8? 아니오 → 탈락
  5. σ 결과는 (4, 3, 2) 한 행 → 여기에 πA를 적용해 A 열만 남기면 4

함정: 2행의 (3,3,3)을 "같으니까 통과"로 처리하면 ②번 3을 고르게 된다. 부등호에 등호(≥)가 붙어 있는지를 반드시 확인해라. 여기서는 >(초과)이므로 같은 값은 탈락이다.

문제 42010 국가직 · 기출문제집 p.558~559

직원·부서·정책 세 릴레이션이 있다. 정책의 "제안자"는 직원번호를 참조하는 외래키이고, 직원의 "부서"는 부서번호를 참조하는 외래키다. 정책 릴레이션에는 5개의 정책(인력양성, 주택자금, 친절교육, 성과금, 신규고용)이 들어 있고, 각 정책의 제안자는 모두 실제 직원이며 각 직원은 모두 어떤 부서에 소속돼 있다.
다음 관계대수식을 적용한 결과의 카디널리티(cardinality)로 옳은 것은?
π이름, 부서명, 정책명( 부서 ⋈부서번호=부서 ( π정책명, 이름, 부서( 정책 ⋈제안자=직원번호 직원 ) ) )

  1. 3
  2. 4
  3. 5
  4. 6
해설 보기

정답 ③ 5

조인을 두 번 하지만 행 수는 처음부터 끝까지 5로 유지된다. 이유를 단계별로 보자.

  1. 정책 ⋈ 직원 (제안자 = 직원번호): 정책 5건 각각에 대해 제안자와 일치하는 직원이 정확히 1명씩 존재한다 → 결과 5행
  2. π로 정책명·이름·부서만 남긴다 → 열은 줄지만 행은 여전히 5행 (정책명이 모두 달라 중복 없음)
  3. 부서 ⋈ (위 결과) (부서번호 = 부서): 각 직원은 부서 하나에 속하므로 또다시 1:1 매칭 → 결과 5행
  4. 마지막 π로 이름·부서명·정책명만 남긴다 → 정책명이 전부 다르므로 중복 제거 없음 → 최종 5행

빠른 판단법: 외래키 → 기본키 방향의 조인은 행 수를 늘리지 않는다. 외래키 값 하나가 가리키는 기본키 행은 반드시 하나뿐이기 때문이다. 따라서 이 문제는 "정책이 몇 건인가"만 세면 끝난다.

주의할 점: 마지막 π에서 중복이 생기면 행이 줄어들 수 있다. 예컨대 같은 사람이 같은 부서에서 제안한 정책 2건이 있고 π에 정책명이 빠져 있었다면 두 행이 동일해져 1행으로 합쳐진다. 이 문제는 정책명이 결과에 포함되어 모두 다르므로 5행이 유지된다.

아래 두 릴레이션에 대해 π고객번호, 상품코드( σ가격 ≤ 40( 구매 ⋈ 상품 ) ) 을 수행한 결과는?

100P120
200P250
100P310
100P250
200P120

해설 보기

정답: (100, P1), (100, P3), (200, P1) — 총 3행

안쪽부터 순서대로, 중간 표를 직접 그리며 푼다.

  1. ① 자연조인 (구매 ⋈ 상품) — 공통 속성 상품코드로 결합해 각 구매 행에 가격을 붙인다:
    (100,P1,20,35) / (200,P2,50,65) / (100,P3,10,27) / (100,P2,50,65) / (200,P1,20,35) / (300,P2,50,65) → 6행
  2. ② σ가격 ≤ 40 — 가격이 40 이하인 행만 남긴다. P1은 35(통과), P3은 27(통과), P2는 65(탈락):
    (100,P1,20,35) / (100,P3,10,27) / (200,P1,20,35) → 3행
  3. ③ π고객번호, 상품코드 — 두 열만 남긴다:
    (100,P1) / (100,P3) / (200,P1) → 서로 다르므로 중복 제거 없이 3행

실수 포인트: 조인 단계에서 구매 테이블의 모든 행이 상품 정보를 받아온다는 것을 놓치면 안 된다. 상품 테이블은 3행이지만 구매는 6행이고, 조인 결과도 6행이다(각 구매 건마다 상품 1개가 매칭되므로).

시간 절약 팁: 최적화 관점에서는 σ를 먼저 적용해도 된다 — 가격 조건은 상품 테이블만 보면 되므로 먼저 상품에서 P1·P3만 골라낸 뒤 조인하면 중간 결과가 6행이 아니라 3행으로 줄어든다. 결과는 동일하다.

문제 6개념 확인 · 응용

릴레이션 A는 4개 속성·30개 튜플, 릴레이션 B는 3개 속성·20개 튜플이다. A × B(카티션 프로덕트)의 결과는 몇 개의 속성과 몇 개의 튜플을 갖는가?

해설 보기

정답: 속성 7개(차수 = 4+3), 튜플 600개(카디널리티 = 30×20)

  1. 차수(속성 수)는 더한다: 두 릴레이션의 열을 옆으로 모두 이어 붙이므로 4 + 3 = 7개
  2. 카디널리티(튜플 수)는 곱한다: A의 각 행마다 B의 모든 행과 짝을 짓기 때문에 30 × 20 = 600개

헷갈리지 않는 법: 차수는 "가로로 이어 붙이기(+)", 카디널리티는 "모든 조합(×)"이다. 두 연산이 반대로 적용된다는 점만 기억하면 된다.

왜 중요한가: 30행 × 20행이 벌써 600행이다. 실무에서 100만 행끼리 ×하면 1조 행이 된다. 그래서 질의 최적화에서 카티션 프로덕트는 반드시 조인으로 바꾸거나 σ로 먼저 줄인다.

문제 7개념 확인 · 응용

"모든 부품을 공급하는 공급업체를 찾아라"라는 질의를 처리하려면 어떤 관계대수 연산이 필요하며, 결과 릴레이션의 속성은 어떻게 되는가? (공급(업체명, 부품명), 부품(부품명))

해설 보기

정답: 디비전(÷) 연산 / 공급 ÷ 부품 → 결과 속성은 "업체명" 하나

  1. 질의에 "모든 ~를"이라는 표현이 들어가면 디비전(÷)을 떠올린다
  2. 식은 공급 ÷ 부품 — 공급 테이블에서, 부품 테이블의 모든 부품명을 갖춘 업체만 남긴다
  3. 결과 속성 = R의 속성 − S의 속성 = {업체명, 부품명} − {부품명} = {업체명}

키워드로 연산 고르기: "~이면서"(AND 조건) → σ / "~만 보여라"(컬럼 지정) → π / "두 표를 합쳐"(공통 속성) → ⋈ / "모두·전부 가진" → ÷. 이 대응만 익혀두면 서술형 질의를 식으로 옮기는 문제가 쉬워진다.

문제 8개념 확인 · 응용

200개의 튜플을 가진 릴레이션에 대해 SELECT 이름 FROM 학생; 을 실행했을 때 결과 튜플 수는? (동명이인이 여러 명 존재한다고 가정) 또 같은 작업을 관계대수 π이름(학생)으로 하면 결과는 어떻게 다른가?

해설 보기

정답: SQL은 200개 그대로 / 관계대수 π는 중복이 제거되어 200개보다 적어짐

  1. SQL의 SELECT는 기본적으로 중복을 허용한다 → 동명이인이 있어도 행이 합쳐지지 않고 200개 그대로 출력
  2. 중복을 없애려면 SELECT DISTINCT 이름 FROM 학생; 처럼 DISTINCT를 명시해야 한다
  3. 반면 관계대수의 결과는 집합(set)이므로 π는 자동으로 중복을 제거한다 → 서로 다른 이름의 개수만 남는다

시험에서의 함정: "SELECT 결과 튜플 수는?"이라는 문제에서 DISTINCT가 없는데도 중복을 제거해 계산하면 틀린다. SQL 문제인지 관계대수 문제인지부터 확인하는 것이 핵심이다.
