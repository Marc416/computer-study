IP 주소체계와 서브넷팅

IPv4 클래스 · 서브넷마스크 · CIDR · IPv6 · PART 03. 데이터통신론

핵심 요약

IPv4 주소(32비트)는 네트워크ID + 호스트ID로 나뉘고, 이 경계를 어디서 자르는지가 클래스(A/B/C)와 서브넷마스크다.

서브넷팅 계산은 매년 나온다 — "호스트 비트 몇 개를 서브넷ID로 빌려오는가"만 이해하면 나머지는 전부 이 규칙의 응용이다.

💡주요 개념 — IPv4 클래스 체계 📖 기출문제집 p.336~338

IPv4 주소는 32비트, 8비트씩 4묶음(옥텟)으로 나뉘고 각 묶음을 점(.)으로 구분해 10진수로 쓴다. 첫 옥텟의 맨 앞 비트 패턴으로 클래스가 정해지고, 그 패턴이 클래스마다 네트워크ID와 호스트ID의 경계를 다르게 만든다.

클래스첫 옥텟 시작비트첫 옥텟 범위네트워크ID호스트ID기본 서브넷마스크
A00~1271바이트(8bit)3바이트(24bit)255.0.0.0
B10128~1912바이트(16bit)2바이트(16bit)255.255.0.0
C110192~2233바이트(24bit)1바이트(8bit)255.255.255.0
D1110224~239멀티캐스트 전용 (호스트 개념 없음)-
암기 규칙: 첫 옥텟 값이 127 이하 → A, 191 이하 → B, 223 이하 → C. 딱 이 세 경계값(127/191/223)만 외우면 어떤 IP든 3초 안에 클래스 판별 가능.

🧮주요 개념 — 서브넷마스크와 CIDR 📖 기출문제집 p.338~342

서브넷마스크는 IP주소 32비트 중 네트워크(+서브넷) 부분을 1, 호스트 부분을 0으로 표시한 것이다. IP주소 AND 서브넷마스크 = 네트워크 주소가 계산의 전부다. 회사가 큰 네트워크 하나를 여러 부서용 작은 네트워크로 쪼갤 때, 원래 호스트ID 비트 중 앞쪽 몇 개를 "서브넷ID"로 빌려와 쓴다.

서브넷 개수 ↔ 필요 비트 수: 서브넷을 2ⁿ개로 나누려면 호스트ID에서 n비트를 빌려와야 한다 (2¹=2개, 2²=4개, 2³=8개...)

예제 1. C클래스 네트워크 하나를 8개의 서브넷으로 나눌 때 서브넷마스크는?

  1. C클래스 기본 마스크는 255.255.255.0 (호스트ID 8비트 전부 사용 가능)
  2. 8개의 서브넷 = 2³ 이므로 3비트를 호스트ID에서 서브넷ID로 빌려온다
  3. 마지막 옥텟을 비트로 쓰면: 앞 3비트가 서브넷용(1로 표시) → 11100000
  4. 11100000을 10진수로 변환 → 224
  5. 정답: 255.255.255.224 (남은 5비트가 서브넷당 호스트ID)

예제 2. IPv4 CIDR 표기법 "/27"이 의미하는 서브넷마스크는? (CIDR는 네트워크ID 비트 수를 "/숫자"로 바로 알려주는 표기법)

  1. /27 = 32비트 중 왼쪽 27비트가 네트워크ID(서브넷 포함)라는 뜻
  2. 27비트를 8비트씩 끊으면: 8+8+8=24비트(앞 3옥텟 전부 1) + 남은 3비트
  3. 4번째 옥텟은 8비트 중 앞 3비트만 1 → 11100000 = 224
  4. 정답: 255.255.255.224 (예제1과 결과가 같다 — /27과 "3비트 서브넷"은 동일한 말)

예제 3. IP주소 117.17.23.253/27이 속한 네트워크 주소와 사용 가능 호스트 수는?

  1. /27 → 서브넷마스크 255.255.255.224 (예제2에서 구함)
  2. 마지막 옥텟 253을 2진수로: 11111101
  3. 네트워크ID로 쓰이는 왼쪽 3비트만 남기고 나머지를 0으로: 11100000 = 224
  4. 네트워크 주소 = 117.17.23.224
  5. 호스트ID는 5비트 남았으므로 표현 가능한 값은 2⁵=32개, 그중 전부0(네트워크주소)·전부1(브로드캐스트주소) 2개는 호스트로 못 씀
  6. 사용 가능한 호스트 수 = 32 − 2 = 30개

예제 4. C클래스 211.168.83.0 네트워크를 서브넷마스크 255.255.255.224로 나눴을 때, 211.168.83.34가 속한 서브넷의 브로드캐스트 주소는?

  1. 서브넷마스크 224 = 11100000 → 호스트ID는 5비트, 서브넷 크기 = 2⁵ = 32개 주소 단위로 구획
  2. 34를 32로 나눈 몫만큼 구획이 이동: 34 ÷ 32 = 1구획 남고 2 → 34가 속한 구획은 32~63
  3. 그 구획의 마지막 주소(호스트ID 전부 1)가 브로드캐스트 주소
  4. 정답: 211.168.83.63
빠른 요령: 서브넷마스크가 224(=2⁵ 간격)면 네 번째 옥�터 값은 항상 0, 32, 64, 96... 단위로 구획이 나뉜다. 어떤 호스트든 "몇 번째 32칸 구획에 있는지"만 찾으면 그 구획의 시작(네트워크주소)과 끝(브로드캐스트주소)이 바로 나온다.

📌시험 빈출 포인트

  • 첫 옥텟 값만 보고 클래스 판별: 127이하=A, 191이하=B, 223이하=C
  • 서브넷 2ⁿ개로 나누려면 호스트ID에서 n비트를 빌려온다 — 개수↔비트수 변환이 핵심
  • CIDR "/n" = 네트워크ID 비트수 n개라는 뜻, 서브넷마스크로 직접 변환 가능
  • 네트워크주소 = IP AND 마스크, 브로드캐스트주소 = 호스트ID 전부 1
  • 사용 가능 호스트 수 = 2^(호스트비트수) − 2 (네트워크주소·브로드캐스트주소 제외)
  • 서브넷마스크 값(224, 192, 240 등)만 보고 "몇 칸 단위로 구획되는지" 바로 계산하는 연습 필수
  • IPv6은 128비트, 4배, 콜론표기, 체크섬없음, IPSec내장, 애니캐스트 추가 — 세트로 암기
