TCP/IP 응용계층과 전송계층

TCP/IP 4계층 모델, 응용계층 프로토콜, 포트번호, TCP 3-way handshake, TCP vs UDP, ARP·ICMP · PART 03. 데이터통신론

핵심 요약

TCP/IP는 OSI 7계층을 실무용으로 4계층(네트워크접속·인터넷·전송·응용)으로 단순화한 것이다. 세션·표현 계층은 따로 없고 응용 계층이 흡수했다.

TCP = 연결지향·신뢰성 (전화 통화처럼 먼저 연결하고 확인하며 주고받음), UDP = 비연결·빠름 (엽서처럼 그냥 보내고 끝).

🎯이 단원을 왜 배우나

OSI는 "교과서", TCP/IP는 "실제로 돌아가는 인터넷"

앞 단원의 OSI 7계층은 이론적 참조 모델이다. 정작 지금 여러분이 이 페이지를 보고 있는 인터넷은 OSI가 아니라 TCP/IP라는 다른 모델 위에서 돌아간다. OSI가 먼저 설계되었지만, 실제 구현은 더 단순하고 실용적인 TCP/IP가 먼저 널리 퍼져버렸기 때문이다.

그래서 시험은 두 모델의 대응 관계를 집요하게 묻는다. 핵심은 이것이다 — TCP/IP는 OSI의 세션·표현·응용 3개를 "응용 계층" 하나로 뭉치고, 물리·데이터링크 2개를 "네트워크 접속 계층" 하나로 뭉쳐서 7개를 4개로 줄였다. "TCP/IP에 세션 계층이 있느냐"는 문제가 나오면 답은 항상 없다이다.

그리고 이 단원에서 진짜 중요한 건 "어떤 프로토콜이 몇 계층인가"다. HTTP·SMTP·FTP·Telnet·DNS는 응용, TCP·UDP는 전송, IP·ICMP·ARP는 인터넷 계층. 매년 "나머지 셋과 다른 계층에 속하는 것" 형태로 반복 출제되므로, 프로토콜 이름을 보면 계층이 반사적으로 나와야 한다.

POP3 vs IMAP — 왜 둘 다 존재하나

POP3는 인터넷이 느리고 비싸던 시절 방식이다. 서버에 접속해 메일을 몽땅 내 컴퓨터로 내려받고 서버에서는 지운다. 그래야 서버 저장공간을 아끼고, 오프라인에서도 메일을 읽을 수 있었다. 단점은 회사 PC로 받은 메일을 집 노트북에서는 볼 수 없다는 것.

IMAP은 그 문제를 해결했다. 원본은 서버에 그대로 두고 복사본만 보여준다. 그래서 폰·노트북·회사PC 어디서 열어도 항상 같은 상태로 동기화된다. 요즘 쓰는 Gmail·네이버메일 앱이 전부 IMAP 방식인 이유다.

한 줄 정리: POP3 = 가져오고 지움(이사), IMAP = 두고 보여줌(열람).

왜 어떤 서비스는 일부러 신뢰성 없는 UDP를 쓰나

언뜻 생각하면 TCP가 무조건 좋아 보인다. 그런데 실시간 영상통화를 생각해보자. 0.5초 전 화면 조각 하나가 깨져서 사라졌다. TCP라면 그걸 다시 보내달라고 요청하고 기다린다. 그 사이 대화는 계속 진행 중인데 말이다. 이미 지나간 0.5초짜리 화면을 복구해봐야 아무 쓸모가 없고, 오히려 기다리느라 전체가 버벅인다.

그래서 이런 서비스는 "조금 깨져도 좋으니 제때 도착하는 것"이 훨씬 중요하다. UDP는 확인도 재전송도 하지 않으므로 지연이 최소다. DNS가 UDP를 쓰는 이유도 비슷하다 — 질의·응답이 짧은 한 번이라, 연결을 맺고 끊는 3-way handshake 비용이 정작 데이터보다 크기 때문이다. 응답이 안 오면 그냥 한 번 더 물어보는 게 더 싸다.

정리: 정확성이 생명이면 TCP(파일·웹·메일), 속도가 생명이면 UDP(스트리밍·DNS·게임).

TCP의 3-way Handshake — 연결을 맺는 절차

TCP는 데이터를 보내기 전에 "진짜 서로 통신할 준비가 됐는지" 3번의 신호를 주고받아 확인한다.

왜 하필 3번인가 (2번이면 안 되나?)

연결이 성립하려면 양쪽 모두 "내가 보낼 수 있다"와 "상대가 받을 수 있다"를 확인해야 한다.

  1. SYN: 클라이언트 → 서버. "나 보낼게" (서버는 클라이언트의 송신 능력을 확인)
  2. SYN+ACK: 서버 → 클라이언트. "받았어(ACK) + 나도 보낼게(SYN)". 클라이언트는 이걸로 자기 송신·서버 수신·서버 송신까지 확인
  3. ACK: 클라이언트 → 서버. "네 것도 받았어". 이제야 서버가 클라이언트의 수신 능력을 확인

2번에서 멈추면 서버는 "클라이언트가 내 응답을 받았는지" 영영 모른다. 그래서 최소 3번이 필요하고, 서버의 ACK와 SYN을 한 번에 묶어 보내기 때문에 4번이 아닌 3번으로 끝난다. (연결 종료는 각자 따로 끊어야 해서 4-way가 된다.)

기타 인터넷 계층 프로토콜 — ARP·RARP·ICMP 📖 기출문제집 p.321~323

프로토콜역할
ARP (Address Resolution Protocol)IP 주소 → MAC(물리) 주소로 변환. 요청은 브로드캐스트, 응답은 유니캐스트. 결과는 ARP 캐시 테이블에 저장해 효율↑
RARPARP의 반대 — MAC 주소는 아는데 내 IP를 모를 때 서버에 요청해서 IP를 받아옴
ICMPIP의 비연결성을 보조 — 오류 보고, 상황 보고, 경로 제어정보 전달 (ping이 이걸 이용)
IGMP멀티캐스트 그룹 관리
함정 주의: ① "IP는 오류제어·흐름제어로 패킷 전달을 보장한다" → ❌ IP는 비연결형이고 신뢰성을 보장하지 않는다. 재전송·오류복구는 상위의 TCP 담당. ② "IP가 라우팅 테이블을 갱신한다" → ❌ 갱신은 RIP·OSPF 같은 라우팅 프로토콜이 하고, IP는 그 테이블을 이용할 뿐이다. ③ "ARP는 MAC 주소에 대해 IP를 반환" → ❌ 그건 RARP.

📌시험 빈출 포인트

  • TCP/IP는 4계층: 응용/전송/인터넷/네트워크접속 — 세션 계층은 없음(OSI에만 있음)
  • 전송 계층 프로토콜은 TCP·UDP 딱 둘. FTP·SMTP·Telnet을 전송 계층에 넣으면 오답
  • 메일 송신은 SMTP, 수신은 POP3(원본삭제) 또는 IMAP(원본유지). MIME은 SMTP 확장 규격
  • FTP 포트: 제어=21, 데이터=20 (반대로 낸 오답 주의), 능동/수동 전송 모드 존재
  • DNS는 UDP 기반 — "TCP 기반이 아닌 것" 문제의 단골 정답
  • TCP=연결지향·신뢰성·느림·유니캐스트만 / UDP=비연결·비신뢰·빠름·브로드캐스트 가능
  • 3-way handshake 순서: SYN → SYN+ACK → ACK (연결 종료는 4-way)
  • ARP는 IP→MAC, RARP는 MAC→IP (방향 헷갈리지 않기)
  • ICMP = 오류보고·상황보고·경로제어정보 전달, 인터넷 계층(응용 아님)
  • IP는 신뢰성 보장 안 함(비연결) — 재전송·순서보장은 TCP만
  • IPv4=32비트, IPv6=128비트 (64비트로 착각하는 오답 자주 출제)
  • DNS는 도메인↔IP, DHCP는 IP 자동할당, ARP는 IP→MAC — 셋을 섞어놓는 문제 주의
  • HTML은 언어, HTTP는 통신 규약 (바꿔치기 단골)

문제 12011 지방직 · 기출문제집 p.305

TCP/IP 프로토콜 계층 구조가 아닌 것은?

  1. 응용 계층(application layer)
  2. 전송 계층(transport layer)
  3. 네트워크/인터넷 계층(network/internet layer)
  4. 세션 계층(session layer)
해설 보기

정답 ④ 세션 계층

TCP/IP는 4계층: 응용 / 전송 / 인터넷(네트워크) / 네트워크 접속.

세션 계층과 표현 계층은 OSI 7계층에만 있고, TCP/IP에서는 이 둘의 기능을 응용 계층이 흡수했다.

한 줄 암기: "TCP/IP에 세션·표현 없다. 응용이 다 먹었다."

문제 22009 지방직 · 기출문제집 p.306

TCP/IP의 계층구조에 대한 설명으로 옳지 않은 것은?

  1. 네트워크 접속 계층(Network Interface Layer)은 물리적 계층으로 IP 주소를 MAC 주소로 변환한다.
  2. 인터넷 계층(Internet Layer)에서는 데이터를 정의하고 라우팅(Routing) 업무를 담당한다.
  3. 전송 계층(Transport Layer)에서는 IP 프로토콜을 이용하여 데이터를 전송한다.
  4. 응용 계층(Application Layer)에서는 FTP, SMTP, Telnet 등과 같은 응용 프로그램을 제공한다.
해설 보기

정답 ③ (전송 계층은 TCP를 이용한다)

  1. 전송 계층의 프로토콜은 TCP와 UDP다
  2. IP 프로토콜은 인터넷 계층에서 데이터를 전송할 때 쓴다
  3. 따라서 "전송 계층에서 IP를 이용"은 계층을 한 칸 어긋나게 쓴 오답

주의: ①번은 표현이 어색해 보여도 정답이 아니다. IP↔MAC 변환은 엄밀히 ARP(인터넷 계층)의 일이지만, 이 문제에서 명백히 틀린 것은 ③이므로 "가장 틀린 것"을 고르는 눈이 필요하다. 계층-프로토콜 짝이 어긋난 선지를 우선 의심할 것.

문제 32013 국가직 · 기출문제집 p.306

TCP/IP 프로토콜의 계층과 그 관련 요소의 연결이 옳지 않은 것은?

  1. 데이터 링크 계층: IEEE 802, Ethernet, HDLC
  2. 네트워크 계층: IP, ICMP, IGMP, ARP
  3. 전송 계층: TCP, UDP, FTP, SMTP
  4. 응용 계층: POP3, DNS, HTTP, TELNET
해설 보기

정답 ③ (FTP·SMTP는 응용 계층)

  1. 전송 계층에 속하는 것은 TCP와 UDP 둘뿐이다
  2. FTP(파일 전송)와 SMTP(메일 송신)는 사용자 서비스이므로 응용 계층
  3. 나머지 ①②④는 모두 올바른 연결

공략법: 이 유형은 전송 계층 선지부터 본다. TCP·UDP 외에 다른 이름이 하나라도 섞여 있으면 그게 정답이다. 실제로 이 책 기출에서 "전송 계층 — TCP, TELNET"(2022 국회), "전송 계층 — ISDN"(2008 국가직)도 같은 방식으로 출제됐다.

문제 42023 지방직 · 기출문제집 p.307

TCP/IP 프로토콜 계층 구조에서 다음 중 나머지 셋과 다른 계층에 속하는 프로토콜은?

  1. HTTP
  2. SMTP
  3. DNS
  4. ICMP
해설 보기

정답 ④ ICMP

  1. HTTP(웹), SMTP(메일 송신), DNS(이름 해석) → 모두 응용 계층
  2. ICMP는 오류·상황 보고용으로 인터넷 계층 (IP의 짝꿍)

구분 요령: 이름에 "Internet Control"이 들어간 ICMP, "Internet Group"이 들어간 IGMP, 그리고 IP·ARP·RARP는 전부 인터넷 계층이다. 반면 사람이 직접 쓰는 서비스(웹·메일·파일·원격접속·이름조회)는 전부 응용 계층.

같은 유형: 2011 지방직에서도 HTTP/SMTP/IMAP 중 ICMP가 정답이었다. 거의 매년 ICMP가 "혼자 다른 계층"으로 등장한다.

문제 52018 지방직 · 기출문제집 p.309

전자메일의 송신 또는 수신을 목적으로 하는 응용 계층 프로토콜에 해당하지 않는 것은?

  1. IMAP
  2. POP3
  3. SMTP
  4. SNMP
해설 보기

정답 ④ SNMP

이메일 프로토콜은 딱 3개다: 송신 SMTP, 수신 POP3 / IMAP.

SNMP(Simple Network Management Protocol)는 이름이 SMTP와 한 글자 차이라 헷갈리게 만든 함정이다. 실제 용도는 네트워크 장비 관리(망 관리)이고 일반 사용자용 프로토콜이 아니다.

  • SMTP = Mail (메일)
  • SNMP = Network management (망 관리)

같은 유형의 다른 정답들: VPN(2008 국가직), FTP(2024 지방직), RTP(2022 계리직) — 전부 "이메일 프로토콜이 아닌 것"으로 출제됐다.

문제 62018 교육청 · 기출문제집 p.310

전자우편의 전달 과정에서 ㉠~㉢에 사용되는 프로토콜을 올바르게 짝지은 것은?
㉠ 발신자 단말기 → 발신측 메일서버 / ㉡ 발신측 메일서버 → 수신측 메일서버 / ㉢ 수신측 메일서버 → 수신자 단말기

  1. ㉠ SMTP · ㉡ SMTP · ㉢ IMAP
  2. ㉠ SMTP · ㉡ IMAP · ㉢ POP3
  3. ㉠ POP3 · ㉡ SMTP · ㉢ IMAP
  4. ㉠ POP3 · ㉡ IMAP · ㉢ POP3
해설 보기

정답 ① SMTP · SMTP · IMAP

  1. ㉠ 내 단말기에서 내 메일서버로 보내는 구간 → SMTP
  2. ㉡ 메일서버끼리 전달하는 구간 → 역시 SMTP
  3. ㉢ 수신자가 서버에서 꺼내오는 마지막 구간 → POP3 또는 IMAP (선지에서는 IMAP)

핵심: "보내는 방향은 끝까지 SMTP, 마지막 한 구간만 POP3/IMAP". 위 전자메일 흐름 다이어그램을 그대로 떠올리면 된다.

문제 72021 국회 · 기출문제집 p.317

파일 전송 프로토콜(FTP)에 대한 설명으로 옳은 것만을 모두 고르면?

ㄱ. 응용 계층 프로토콜이다.
ㄴ. FTP에서 제어 연결은 20번 포트, 데이터 연결은 21번 포트를 사용한다.
ㄷ. FTP 연결은 능동(Active) 전송 모드와 수동(Passive) 전송 모드로 구분한다.
  1. ㄱ
  2. ㄴ
  3. ㄱ, ㄷ
  4. ㄴ, ㄷ
  5. ㄱ, ㄴ, ㄷ
해설 보기

정답 ③ ㄱ, ㄷ

  1. ㄱ 맞음: FTP는 파일 전송을 위한 응용 계층 프로토콜
  2. ㄴ 틀림: 번호가 반대다. 제어 연결 = 21번, 데이터 연결 = 20번
  3. ㄷ 맞음: 서버의 20번 포트를 쓰는 능동(Active) 모드와, 클라이언트의 임의 포트를 데이터 포트로 쓰는 수동(Passive) 모드로 구분된다

암기법: "제어가 먼저 연결되니 번호도 큰 21"… 이 헷갈리면 이렇게 외우자 — 명령(제어)은 2·1, 데이터는 2·0. 한 문제를 위해서라도 두 숫자 순서를 반드시 확정해둘 것.

문제 82015 국회 · 기출문제집 p.317

다음 중 TCP(Transmission Control Protocol)에 대한 설명으로 옳지 않은 것은?

  1. OSI 7계층 모델에서 트랜스포트(transport) 계층에 해당한다.
  2. 다수의 기기에 대한 브로드캐스팅(broadcasting)을 지원한다.
  3. Connection-oriented 프로토콜이다.
  4. 패킷이 전송 도중 손상되거나 손실될 경우 재전송을 수행한다.
  5. 흐름 제어(flow control) 기능이 지원된다.
해설 보기

정답 ② (TCP는 브로드캐스팅을 지원하지 않는다)

TCP는 연결 지향형이다. 연결을 맺으려면 상대가 누구인지 특정되어야 하고, 3-way handshake로 1:1 연결을 수립한다. 불특정 다수에게 뿌리는 브로드캐스트는 애초에 "연결"이라는 개념과 맞지 않는다.

  1. TCP = 유니캐스트(1:1) 전용
  2. 브로드캐스트·멀티캐스트가 필요하면 UDP를 쓴다

나머지 선지는 전부 TCP의 정확한 특징이다: 전송 계층 소속, 연결지향, 손실 시 재전송, 흐름제어 지원. 여기에 혼잡제어(패킷 손실로 혼잡 정도를 측정)도 TCP 기능이다.

문제 92017 지방직 · 기출문제집 p.319

네트워크 프로토콜에 대한 설명으로 옳지 않은 것은?

  1. TCP와 UDP는 전송 계층에 속하는 프로토콜로서 데이터 전송의 신뢰성을 보장한다.
  2. IP는 네트워크 호스트의 주소 지정과 경로 설정을 담당하는 네트워크 계층 프로토콜이다.
  3. SMTP는 전자메일 전송을 위한 응용 계층 프로토콜이다.
  4. IPv4에서 예상되는 IP 주소의 고갈 문제 해결을 주요 목적으로 IPv6가 제안되었다.
해설 보기

정답 ① (UDP는 신뢰성을 보장하지 않는다)

선지 ①은 앞부분("TCP와 UDP는 전송 계층")은 맞지만 뒷부분이 틀렸다. 이렇게 절반만 맞는 문장이 가장 놓치기 쉬운 오답이다.

  1. TCP: 순서 보장·재전송·흐름제어 → 신뢰성 O
  2. UDP: 비연결형, 재전송 없음 → 신뢰성 X
  3. "TCP와 UDP는 … 신뢰성을 보장한다"처럼 둘을 묶어 서술하면 거의 항상 오답

읽기 요령: 선지에 "A와 B는 모두 ~하다"가 보이면 둘 중 하나만 반례여도 틀린 문장이다. TCP/UDP, ARP/RARP처럼 성격이 반대인 짝이 함께 묶여 있으면 특히 의심할 것.

문제 102012 국가직 · 기출문제집 p.319

TCP/IP 프로토콜에 대한 설명으로 옳지 않은 것은?

  1. ARP(Address Resolution Protocol)는 IP주소를 물리주소로 변환해준다.
  2. IP는 오류제어와 흐름제어를 통하여 패킷의 전달을 보장한다.
  3. TCP는 패킷 손실을 이용하여 혼잡(congestion) 정도를 측정하여 제어하는 기능도 있다.
  4. HTTP, FTP, SMTP와 같은 프로토콜은 전송 계층 위에서 동작한다.
해설 보기

정답 ② (오류·흐름제어로 전달을 보장하는 것은 TCP)

IP의 정체를 정확히 알아야 한다. IP는 비연결형(connectionless) 데이터그램 프로토콜로, 간단한 오류 검사만 할 뿐 도착을 보장하지 않는다. "최선을 다해 보내보지만 책임은 안 진다(best-effort)"가 IP의 성격이다.

  1. 패킷이 사라져도 IP는 모른 척한다
  2. 그 손실을 발견하고 재전송시키는 것이 위층의 TCP
  3. 그래서 둘을 합쳐 TCP/IP로 같이 쓰는 것이다 — IP가 길을 찾고, TCP가 책임진다

나머지 선지는 모두 옳다. 특히 ③의 혼잡제어는 TCP의 중요한 기능이고, ④처럼 응용 계층 프로토콜들은 전송 계층(TCP) 위에서 동작한다.

문제 112018 국회 · 기출문제집 p.312

사용자가 WWW을 사용하여 임의의 사이트에 접속하는 과정의 설명으로 옳지 않은 것은?

  1. 사용자의 웹브라우저에서 DNS 서버로 DNS 질의 메시지를 보낸다.
  2. DNS 간의 질의는 재귀형(recursive) 또는 반복형(iterative)으로 연계된다.
  3. 사용자의 웹브라우저는 DNS 서버로부터 사이트의 웹 서버 MAC 주소를 획득한다.
  4. HTTP 요청 메시지를 보내기 전에 TCP 3-방향 핸드셰이크를 수행한다.
  5. 웹 서버가 보낸 HTTP 응답 메시지의 바디로부터 HTML을 추출하여 웹 페이지를 보여준다.
해설 보기

정답 ③ (DNS 서버에서 얻는 것은 IP 주소)

  1. DNS가 하는 일은 도메인 이름 → IP 주소 변환뿐이다
  2. MAC 주소를 알아내는 것은 같은 네트워크 안에서 동작하는 ARP의 일이다
  3. 애초에 DNS 서버는 멀리 떨어진 웹서버의 MAC 주소를 알 방법도 없다 (MAC은 같은 로컬 네트워크에서만 의미가 있음)

나머지 선지는 위 "웹 접속 전체 흐름" 다이어그램과 정확히 일치한다: DNS 질의(①) → IP 획득 → TCP 3-way handshake 먼저(④) → HTTP 요청 → 응답 본문의 HTML 렌더링(⑤).

세트로 기억: DNS=이름→IP / ARP=IP→MAC / DHCP=IP 자동할당. 셋을 섞어놓는 문제가 매년 나온다.

문제 122014 국회 · 기출문제집 p.323

TCP/IP 프로토콜에서 IP 호스트가 자신의 물리 네트워크 주소(MAC)는 알지만 IP 주소를 모르는 경우, 서버에게 IP 주소를 요청하기 위해 사용하는 프로토콜은?

  1. RARP
  2. ICMP
  3. ARP
  4. IGMP
  5. UDP
해설 보기

정답 ① RARP

  1. 가진 것 = MAC 주소, 알고 싶은 것 = IP 주소
  2. 방향이 MAC → IP이므로 ARP의 역방향, 즉 Reverse ARP = RARP

방향 정리 (그림으로 외우기):

  • ARP: IP 알고 있음 → MAC 찾기 (같은 랜 안에서 실제로 프레임을 보내려면 MAC이 필요)
  • RARP: MAC 알고 있음 → IP 찾기 (하드디스크 없는 단말이 부팅할 때 자기 IP를 모르는 상황)

함정 선지 분석: ICMP는 오류·상황 보고, IGMP는 멀티캐스트 그룹 관리, UDP는 전송 계층 프로토콜 — 모두 주소 변환과 무관하다. "ARP"(③)를 고르면 방향을 반대로 읽은 것이다.
