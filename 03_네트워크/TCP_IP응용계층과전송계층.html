TCP/IP 응용계층과 전송계층

TCP/IP 4계층 모델, 응용계층 프로토콜, TCP 3-way handshake, TCP vs UDP · PART 03. 데이터통신론

핵심 요약

TCP/IP는 OSI 7계층을 실무용으로 4계층(네트워크접속·인터넷·전송·응용)으로 단순화한 것이다.

TCP = 연결지향·신뢰성 (전화 통화처럼 먼저 연결하고 확인하며 주고받음), UDP = 비연결·빠름 (엽서처럼 그냥 보내고 끝).

💡주요 개념

TCP/IP 4계층 vs OSI 7계층 📖 기출문제집 p.306~307

TCP/IP 계층대응하는 OSI 계층대표 프로토콜
응용 계층응용·표현·세션HTTP, FTP, TELNET, SMTP, POP3, IMAP, DNS, SNMP
전송 계층전송TCP, UDP
인터넷 계층네트워크IP, ARP, RARP, ICMP, IGMP
네트워크 접속 계층데이터링크·물리Ethernet, IEEE 802, PPP, HDLC
함정 주의: "네트워크 접속 계층은 IP주소를 MAC주소로 바꾼다" → 이건 인터넷 계층의 ARP가 하는 일이다. TCP/IP의 "네트워크 계층/인터넷 계층" 이름이 헷갈리기 쉬우니, TCP/IP에는 "세션 계층"이 없다는 것도 자주 나오는 함정(OSI에만 있음).

전자메일 프로토콜과 흐름 📖 기출문제집 p.309~311

프로토콜용도
SMTP메일을 보낼 때(송신) 사용 — 내 컴퓨터→내 메일서버, 메일서버→상대 메일서버 구간 모두 SMTP
POP3메일을 받을 때 사용. 서버의 메일을 다운로드하고 서버에서는 삭제(원본이 클라이언트로 이동)
IMAP메일을 받을 때 사용. 복사본만 전송하고 원본은 서버에 그대로 유지 (여러 기기에서 동기화 가능)

TCP vs UDP 📖 기출문제집 p.317~319

구분TCPUDP
연결 방식연결 지향형 (3-way handshake로 먼저 연결)비연결형 (그냥 보냄)
신뢰성높음 — 순서보장·재전송·흐름제어낮음 — 순서·도착 보장 안 함
속도상대적으로 느림(확인 절차 때문)빠름 (오버헤드 적음)
사용 예웹(HTTP), 파일전송(FTP), 이메일(SMTP)DNS, 스트리밍(RTP), 실시간 게임
흐름/혼잡제어슬라이딩 윈도우, 혼잡제어 있음없음
비유: TCP = 등기우편(받았는지 서명으로 확인, 안전하지만 느림) / UDP = 그냥 우편함에 던져넣는 전단지(빠르지만 도착 여부를 모름)

TCP의 3-way Handshake — 연결을 맺는 절차

TCP는 데이터를 보내기 전에 "진짜 서로 통신할 준비가 됐는지" 3번의 신호를 주고받아 확인한다.

기타 인터넷 계층 프로토콜

프로토콜역할
ARP (Address Resolution Protocol)IP 주소 → MAC(물리) 주소로 변환
RARPARP의 반대 — MAC 주소 → IP 주소
ICMP오류 보고, 상황 보고, 경로 제어정보 전달 (ping이 이걸 이용)
IGMP멀티캐스트 그룹 관리
함정 주의: "IP는 오류제어·흐름제어로 패킷 전달을 보장한다" → ❌ 틀림. IP는 비연결형이고 신뢰성을 보장하지 않는다 — 재전송·오류복구는 상위의 TCP가 담당한다.

📌시험 빈출 포인트

  • TCP/IP는 4계층: 응용/전송/인터넷/네트워크접속 — 세션 계층은 없음(OSI에만 있음)
  • 메일 송신은 SMTP, 수신은 POP3(원본삭제) 또는 IMAP(원본유지)
  • FTP 포트: 제어=21, 데이터=20 (반대로 낸 오답 주의)
  • TCP=연결지향·신뢰성·느림 / UDP=비연결·비신뢰·빠름 — 실시간 스트리밍/DNS는 UDP 사용
  • 3-way handshake 순서: SYN → SYN+ACK → ACK (2단계가 아니라 3단계)
  • ARP는 IP→MAC, RARP는 MAC→IP (방향 헷갈리지 않기)
  • IP는 신뢰성 보장 안 함(비연결) — TCP만 재전송·순서보장 담당
  • IPv4=32비트, IPv6=128비트 (64비트로 착각하는 오답 자주 출제)
