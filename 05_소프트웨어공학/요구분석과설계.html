요구분석과 설계 — 결합도·응집도

모듈 독립성의 두 척도 · PART 06. 소프트웨어공학

핵심 요약

결합도(모듈 사이의 관련성)는 낮을수록, 응집도(모듈 내부의 관련성)는 높을수록 좋은 설계다.

결합도·응집도는 모두 모듈의 독립성을 판단하는 척도이고, 시험은 거의 항상 "어느 쪽이 더 강하냐/약하냐 순서"를 묻는다.

💡주요 개념

결합도와 응집도, 뭐가 다른가

비유: 한 학교(프로그램)에 여러 반(모듈)이 있다고 하자.
응집도 = "우리 반 학생들이 얼마나 한 목표로 똘똘 뭉쳐있나" → 높을수록 좋음(같은 반끼리는 긴밀하게)
결합도 = "옆 반 일에 우리 반이 얼마나 간섭하나" → 낮을수록 좋음(반끼리는 독립적으로)

결합도(Coupling) 스펙트럼 — 약할수록 좋음 📖 기출문제집 p.634

응집도(Cohesion) 스펙트럼 — 강할수록 좋음 📖 기출문제집 p.635~636

모듈화 설계 원칙

  • 상세설계로 갈수록 추상화 수준은 낮아진다 (상위설계=추상적, 하위설계=구체적 — "낮아진다"를 "높아진다"로 바꿔치기하는 게 자주 나오는 함정)
  • 설계는 분석 단계에서 얻은 정보를 반영해 반복적으로 진행되어야 하며, 분석 모델까지 추적 가능해야 한다
  • 좋은 설계 = 결합도 낮게 + 응집도 높게 — 이 한 문장이 이 챕터 전체의 결론이다
계산/판별 순서: 문제에 결합도·응집도 종류가 여러 개 나오고 "약한 순 또는 강한 순으로 나열하라"고 하면, 위 스펙트럼 그림의 좌→우 순서 그대로 답하면 된다. 암기 문장("자스제공내", "우논시절교순기")만 외우면 계산이랄 것도 없다.

📌시험 빈출 포인트

  • 결합도는 낮을수록, 응집도는 높을수록 좋은 설계 — 반대로 서술하는 오답 함정 매우 잦음
  • 결합도 약한 순: 자료 < 스탬프 < 제어 < 공통 < 내용
  • 응집도 약한 순: 우연적 < 논리적 < 시간적 < 절차적 < 교환적 < 순차적 < 기능적
  • "여러 모듈이 공동 자료 영역을 사용" → 공통 결합 (자료 결합 아님, 헷갈리기 쉬움)
  • "한 모듈이 다른 모듈 내부를 직접 참조/수정" → 내용 결합 (가장 나쁜 결합도)
  • "모듈 내 한 요소의 출력이 다음 요소의 입력" → 순차적 응집
  • 가장 이상적인 응집 = 기능적 응집 (논리적 응집 아님 — 매년 나오는 오답 함정)
  • 상세설계로 갈수록 추상화 수준은 낮아진다 (높아진다 아님)
