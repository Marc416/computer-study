요구분석과 설계

요구사항 명세 · 구조적 분석(DFD) · 결합도·응집도 · PART 06. 소프트웨어공학

핵심 요약

요구사항은 기능적 요구(무엇을 하는가)와 비기능적 요구(성능·보안·신뢰성 등)로 나뉜다.

구조적 분석의 3대 도구: 자료흐름도(DFD) · 자료사전 · 소단위 명세서

결합도(모듈 사이의 관련성)는 낮을수록, 응집도(모듈 내부의 관련성)는 높을수록 좋은 설계다.

🎯이 단원을 왜 배우나

"잘 만든 프로그램"을 어떻게 객관적으로 판정할 것인가

분석·설계 단계는 코드를 한 줄도 쓰지 않는 단계다. 그런데 소프트웨어공학에서 가장 비중 있게 다루는 이유는, 여기서 잘못 정한 것을 나중에 고치는 비용이 기하급수적으로 커지기 때문이다. 요구분석에서 놓친 항목을 운영 단계에서 발견하면 수정 비용이 수십 배로 뛴다.

설계 단계의 핵심 질문은 "프로그램을 어떻게 쪼갤 것인가(모듈화)"다. 쪼개긴 쪼개야 하는데, 아무렇게나 쪼개면 오히려 더 나빠진다. 그래서 "잘 쪼갰는지"를 재는 자(척도)가 필요했고, 그게 결합도와 응집도다.

직관은 간단하다 — 한 덩어리 안은 서로 끈끈하게(응집도 ↑), 덩어리끼리는 최대한 남남처럼(결합도 ↓). 그래야 한 모듈을 고쳐도 다른 모듈이 안 깨지고, 모듈 하나만 떼어내 재사용할 수도 있다. 시험은 이 두 척도의 단계별 순서를 집요하게 묻는다 — 사실상 암기 문제이므로 두 개의 암기 문장만 확실히 잡으면 된다.

📋주요 개념 — 요구분석

요구사항의 두 종류 📖 기출문제집 p.629

구분내용예시
기능적 요구
(Functional)		시스템이 무엇을 해야 하는가 — 정보처리 능력, 절차, 입·출력에 대한 요구"회원가입 시 이메일 중복을 검사한다"
비기능적 요구
(Non-functional)		기능 자체와 직접 관련되지 않은 품질·제약 조건성능, 신뢰성, 가용성, 보안성, 안전성, 제약조건

좋은 요구사항의 조건

  • 각 요구사항은 명확하고, 구체적이고, 정확하며, 검증 가능해야 한다
  • 요구사항은 고품질 소프트웨어를 개발하고 검증할 수 있는 기초를 제공한다
  • "당연한 것"도 반드시 기술해야 한다 — 고객과 개발자가 서로 당연하다고 여기는 항목이 나중에 가장 크게 어긋난다

자주 나오는 함정: "고객과 개발자가 서로 당연한 것으로 인정하는 요구사항은 생략해도 무방하다" → ✗ 오답. 암묵적 가정이야말로 분쟁의 씨앗이라 반드시 문서화해야 한다.

요구분석 명세서(SRS)에 담기는 것 📖 기출문제집 p.629

  • 시스템에 영향을 주는 제약 조건 (비기능적 요구)
  • 사용자 인터페이스에 대한 명세
  • 시스템 인수를 위한 테스트 기준 (인수 테스트에서 쓸 테스트 케이스)
  • ❌ 자료 구조 명세는 포함하지 않는다 — 자료 구조는 설계 단계의 산출물이다
구분 기준: SRS는 "무엇을 만들 것인가"를 적는 문서다. "어떻게 만들 것인가"(자료구조, 알고리즘, 모듈 분할)는 설계 단계로 넘어간다. 이 경계가 시험 포인트다.

구조적 분석의 3대 도구와 작업 순서 📖 기출문제집 p.629~630

구조적 분석은 "전체를 크게 그린 뒤 점점 잘게 쪼개 들어가는(하향식)" 방식이다. 순서가 그대로 시험에 나온다.

도구역할
자료흐름도 (DFD)가장 보편적인 시스템 모델링 도구. 기능 중심 모델링에 적합. 구성요소 4가지: 프로세스, 자료 흐름, 자료 저장소, 자료 출처/도착지
자료 사전 (Data Dictionary)DFD에 등장하는 자료 흐름·자료 저장소의 의미와 값·단위를 서술
소단위 명세서 (mini-spec)DFD의 최하위(원시) 프로세스가 무슨 기능을 하는지 기술. 구조적 영어, 의사결정표, 전후 조건 등으로 작성
DFD 기호 함정 (2023 국가직 출제):
• 프로세스(처리) = 원 ○   • 자료 저장소 = 옆면이 없는 사각형(평행선) ▤
"자료저장소를 원으로 표현한다"는 문장은 오답 — 원은 프로세스다.
자료사전 기호 중 선택은 [ | ], ( )는 생략(옵션)을 뜻한다.

🧩주요 개념 — 설계 (모듈화)

결합도와 응집도, 뭐가 다른가

비유: 한 학교(프로그램)에 여러 반(모듈)이 있다고 하자.
응집도 = "우리 반 학생들이 얼마나 한 목표로 똘똘 뭉쳐있나" → 높을수록 좋음(같은 반끼리는 긴밀하게)
결합도 = "옆 반 일에 우리 반이 얼마나 간섭하나" → 낮을수록 좋음(반끼리는 독립적으로)

왜 "낮은 결합도 + 높은 응집도"가 좋은 설계인가

둘 다 결국 모듈의 독립성을 재는 척도다. 독립적인 모듈이 좋은 이유는 세 가지다.

  • 수정 파급이 작다 — 결합도가 높으면 A를 고쳤을 때 B, C까지 줄줄이 깨진다
  • 재사용이 쉽다 — 응집도가 높아 한 가지 일만 하는 모듈은 다른 프로젝트에 그대로 떼어 쓸 수 있다
  • 테스트·이해가 쉽다 — 모듈 하나만 따로 떼어 검증할 수 있다

반대로 최악인 내용 결합은 한 모듈이 다른 모듈 내부를 직접 뒤지는 것이라, 사실상 두 모듈이 한 덩어리로 묶여버린 상태다.

결합도(Coupling) 스펙트럼 — 약할수록 좋음 📖 기출문제집 p.634

응집도(Cohesion) 스펙트럼 — 강할수록 좋음 📖 기출문제집 p.635~636

헷갈리는 두 쌍 구별하기

① 순차적 응집 vs 교환적(통신) 응집 — 둘 다 "자료를 공유"하지만 방향이 다르다.

  • 순차적: 앞 요소의 출력이 뒤 요소의 입력이 된다 (A의 결과 → B가 받아 처리). 줄줄이 이어짐
  • 교환적: 요소들이 같은 입력 자료를 쓰거나 같은 출력을 만든다 (A도 X를 쓰고 B도 X를 씀). 나란히 붙음

② 자료 결합 vs 스탬프 결합 — 둘 다 파라미터 전달이지만 넘기는 양이 다르다.

  • 자료 결합: 꼭 필요한 값만 넘김 (예: 나이 하나만) → 가장 약하고 좋은 결합
  • 스탬프 결합: 자료구조 통째로 넘김 (예: 학생 레코드 전체를 넘겨놓고 나이만 씀) → 불필요한 노출

모듈화 설계 원칙

  • 상세설계로 갈수록 추상화 수준은 낮아진다 (상위설계=추상적, 하위설계=구체적 — "낮아진다"를 "높아진다"로 바꿔치기하는 게 자주 나오는 함정)
  • 설계는 분석 단계에서 얻은 정보를 반영해 반복적으로 진행되어야 하며, 분석 모델까지 추적 가능해야 한다
  • 설계는 계층적 조직으로 제시되며 모듈적이어야 한다
  • 좋은 설계 = 결합도 낮게 + 응집도 높게 — 이 한 문장이 이 챕터 전체의 결론이다
판별 순서: 문제에 결합도·응집도 종류가 여러 개 나오고 "약한 순 또는 강한 순으로 나열하라"고 하면, 위 스펙트럼 그림의 좌→우 순서 그대로 답하면 된다. 암기 문장("자스제공내", "우논시절교순기")만 외우면 계산이랄 것도 없다.

📌시험 빈출 포인트

  • 요구사항 = 기능적 + 비기능적(성능·신뢰성·가용성·보안성·안전성)
  • "당연한 요구사항은 생략해도 된다" → 오답, 반드시 문서화
  • SRS에는 제약조건·UI 명세·인수테스트 기준이 들어가고, 자료구조 명세는 설계 단계의 몫
  • 구조적 분석 순서: 배경도 → 상위 DFD → 하위 DFD → 자료사전 → 소단위 명세서
  • DFD에서 프로세스=원, 자료저장소=평행선(옆면 없는 사각형)
  • 소단위 명세서 작성 도구 = 구조적 영어, 의사결정표
  • 구조적 분석=DFD / 객체지향 분석=유스케이스 / 구조적 설계=구조도 / 객체지향 설계=시퀀스·클래스 등
  • 결합도는 낮을수록, 응집도는 높을수록 좋은 설계 — 반대로 서술하는 오답 함정 매우 잦음
  • 결합도 약한 순: 자료 < 스탬프 < 제어 < 공통 < 내용
  • 응집도 약한 순: 우연적 < 논리적 < 시간적 < 절차적 < 교환적 < 순차적 < 기능적
  • "여러 모듈이 공동 자료 영역을 사용" → 공통 결합 (자료 결합 아님, 헷갈리기 쉬움)
  • "한 모듈이 다른 모듈 내부를 직접 참조/수정" → 내용 결합 (가장 나쁜 결합도)
  • "모듈 내 한 요소의 출력이 다음 요소의 입력" → 순차적 응집
  • 가장 이상적인 응집 = 기능적 응집 (논리적 응집 아님 — 매년 나오는 오답 함정)
  • 상세설계로 갈수록 추상화 수준은 낮아진다 (높아진다 아님)

문제 12018 계리직 · 기출문제집 p.634

결합도(Coupling)를 약한 정도에서 강한 정도 순으로 올바르게 나열한 것은?
㉠ 내용 결합도   ㉡ 제어 결합도   ㉢ 자료 결합도   ㉣ 공통 결합도

  1. ㉢ → ㉡ → ㉣ → ㉠
  2. ㉢ → ㉣ → ㉡ → ㉠
  3. ㉣ → ㉢ → ㉡ → ㉠
  4. ㉠ → ㉡ → ㉣ → ㉢
해설 보기

정답 ① 자료(㉢) → 제어(㉡) → 공통(㉣) → 내용(㉠)

암기 문장 "자스제공내"(자료 < 스탬프 < 제어 < 공통 < 내용)에서 스탬프만 빼면 바로 답이 나온다.

  1. 가장 약함 = 자료 결합(㉢) — 필요한 값만 파라미터로 주고받음
  2. 제어 결합(㉡) — flag 같은 제어값을 넘겨 상대 모듈의 동작을 좌우함
  3. 공통 결합(㉣) — 여러 모듈이 전역 자료 영역을 함께 씀
  4. 가장 강함 = 내용 결합(㉠) — 남의 모듈 내부를 직접 건드림

이해 포인트: 순서의 논리는 "얼마나 깊이 남의 사정에 관여하는가"다. 값만 받으면(자료) 남남이지만, 전역 변수를 공유하면(공통) 서로 눈치를 봐야 하고, 내부를 직접 참조하면(내용) 아예 한 몸이 된다.

문제 22024 소방경채 · 기출문제집 p.635

소프트웨어 모듈 간 응집 관계에서 빈칸에 들어갈 용어로 옳은 것은?
낮은 응집도 → 우연적 응집, ( ㉠ ), ( ㉡ ), ( ㉢ ), 교환적 응집 → 높은 응집도

  1. ㉠ 논리적 응집, ㉡ 시간적 응집, ㉢ 절차적 응집
  2. ㉠ 논리적 응집, ㉡ 절차적 응집, ㉢ 시간적 응집
  3. ㉠ 절차적 응집, ㉡ 논리적 응집, ㉢ 시간적 응집
  4. ㉠ 절차적 응집, ㉡ 시간적 응집, ㉢ 논리적 응집
해설 보기

정답 ① 논리적 → 시간적 → 절차적

암기 문장 "우논시절교순기"를 그대로 대입하면 끝난다.

  1. 우연적 → 논리적(㉠) → 시간적(㉡) → 절차적(㉢) → 교환적 → 순차적 → 기능적
  2. 문제에서 앞은 우연적, 뒤는 교환적으로 고정돼 있으므로 사이에 들어갈 셋은 논리·시간·절차 순

의미로도 확인: 논리적(비슷해 보여서 묶음) → 시간적(같은 시점에 실행돼서 묶음) → 절차적(정해진 순서로 실행돼야 해서 묶음)으로, 뒤로 갈수록 묶인 이유가 점점 더 본질적이 된다.

키워드는 "다른 모듈의 내부를 직접 참조"다. 이름 그대로 내용(content) 결합이다.

문제 42011 국가직 · 기출문제집 p.633

모듈의 결합도(coupling)와 응집력(cohesion)에 대한 설명으로 옳은 것은?

  1. 결합도란 모듈 간에 상호 의존하는 정도를 의미한다.
  2. 결합도는 높을수록 좋고 응집력은 낮을수록 좋다.
  3. 여러 모듈이 공동 자료 영역을 사용하는 경우 자료 결합(data coupling)이라 한다.
  4. 가장 이상적인 응집은 논리적 응집(logical cohesion)이다.
해설 보기

정답 ①

나머지 셋은 전부 이 단원의 대표 함정 3종 세트다.

  1. ② 방향 반전 함정 — 결합도는 낮을수록, 응집력은 높을수록 좋다. 정반대로 서술
  2. ③ 용어 바꿔치기 — 공동 자료 영역 사용은 공통 결합이다. 자료 결합은 필요한 값만 넘기는 가장 좋은 결합
  3. ④ 최상위 오답 — 가장 이상적인 응집은 기능적 응집이다. 논리적 응집은 오히려 아래에서 두 번째로 나쁜 수준

풀이 요령: 이 유형은 선택지 4개 중 3개가 위 함정 중 하나이므로, "낮은 결합·높은 응집 / 공통≠자료 / 최고는 기능적"만 체크하면 소거법으로 답이 남는다.

  1. ㉠ → ㉢ → ㉣ → ㉤ → ㉡
  2. ㉣ → ㉢ → ㉠ → ㉤ → ㉡

해설 보기

정답 ② 배경도 → 상위 DFD → 하위 DFD → 자료사전 → 소단위 명세서

구조적 분석은 하향식(top-down)이다. 큰 그림부터 그리고 점점 쪼개 들어간다.

  1. 배경도(㉣) — 시스템 전체를 원 하나로 그리고 외부와의 관계만 표시. 가장 추상적
  2. 상위 자료흐름도(㉢) — 그 원을 몇 개의 큰 기능으로 분할
  3. 하위 자료흐름도(㉠) — 더 잘게 분할해 최하위(원시) 프로세스까지 내려감
  4. 자료 사전(㉤) — DFD에 등장한 자료들의 의미를 정의
  5. 소단위 명세서(㉡) — 최하위 프로세스가 실제로 무슨 일을 하는지 기술. 가장 구체적

암기: "배 → 상 → 하 → 사 → 소". 소단위 명세서는 최하위 프로세스가 확정된 뒤에야 쓸 수 있으므로 항상 마지막이라는 점을 기억하면 순서가 꼬이지 않는다.

  2. 자료사전은 계획(ISP), 분석(BAA), 설계(BSD), 구축(SC)의 절차로 작성한다.

  4. 소단위 명세서를 작성하는 도구에는 구조적언어, 의사결정표 등이 있다.

정답 ④

  1. ① 기호 바꿔치기 — 자료저장소는 옆면이 없는 사각형(평행선)이고, 원은 프로세스(처리)다

문제 8개념 확인 · 응용

다음 두 모듈 설계 중 어느 쪽이 더 좋은 설계인가? 각각의 결합도 종류도 함께 답하시오.
(가) 모듈 A가 전역 배열 scores[]를 직접 읽고, 모듈 B도 같은 전역 배열을 수정한다.
(나) 모듈 A가 모듈 B를 호출하며 B(avg)처럼 계산에 필요한 평균값 하나만 인자로 넘긴다.

해설 보기

정답: (나)가 더 좋은 설계. (가) = 공통 결합, (나) = 자료 결합

  1. (가)는 두 모듈이 전역 자료 영역(공동 자료 영역)을 공유한다 → 공통 결합
  2. (나)는 꼭 필요한 값 하나만 파라미터로 전달한다 → 자료 결합
  3. "자스제공내" 순서상 자료 < 공통이므로 (나)의 결합도가 더 약하다 = 더 좋은 설계

왜 (가)가 나쁜가: 전역 배열을 누가 언제 바꿨는지 추적할 수 없어서, A의 동작이 B의 실행 순서에 따라 달라진다. 테스트할 때도 A만 떼어내 검증할 수 없다. 반면 (나)는 A에게 avg 값만 주면 항상 같은 결과가 나오므로 단독 테스트와 재사용이 가능하다.

한 단계 더: 만약 (나)에서 평균값 하나만 쓰면서 B(studentRecord)처럼 레코드 전체를 넘긴다면 스탬프 결합이 되어 자료 결합보다 한 단계 나빠진다.
