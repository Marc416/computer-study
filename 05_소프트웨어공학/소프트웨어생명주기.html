소프트웨어 생명주기 (SDLC)

개발 모델별 흐름 시각화 · PART 06. 소프트웨어공학

핵심 요약

SDLC(Software Development Life Cycle) 표준 순서는 계획 → 분석 → 설계 → 구현 → 테스트 → 유지보수다.

각 개발 모델(폭포수·프로토타입·나선형·애자일)은 이 6단계를 "어떤 순서/반복 방식으로 밟느냐"가 다를 뿐이다. 모델별 키워드·비교표는 이미 개발방법론 문서에 자세히 있으니, 여기서는 그 흐름을 눈으로 보는 데 집중한다.

💡주요 개념

SDLC 6단계 순서 확인 문제 📖 기출문제집 p.606~607

시험은 순서를 살짝 뒤섞어서 "옳은 것은?" 형태로 자주 낸다. 실제 기출 선택지 예시:

  1. ① 계획 — 분석 — 설계 — 구현 — 테스트 — 유지보수 ← 정답
  2. ② 분석 — 계획 — 설계 — 구현 — 테스트 — 유지보수 (계획·분석 순서가 바뀜 → 오답)
  3. ③ 분석 — 계획 — 설계 — 테스트 — 구현 — 유지보수 (테스트·구현 순서가 바뀜 → 오답)
  4. ④ 계획 — 설계 — 분석 — 구현 — 테스트 — 유지보수 (설계·분석 순서가 바뀜 → 오답)
암기 순서: "계획 없이 분석 못하고, 분석 없이 설계 못하고, 설계 없이 못 만들고(구현), 만든 건 테스트하고, 다 끝나도 고쳐야(유지보수) 한다" — 당연한 흐름이라 순서 자체는 상식적으로 유추 가능.

4대 모델의 흐름 비교 (한눈에 보기)

모델별 키워드·세부 비교표(코코모, XP 실천법, V-모델 대응관계 등)는 이미 정리되어 있음: → 개발방법론 문서 보기

📌시험 빈출 포인트

  • SDLC 표준 순서: 계획 → 분석 → 설계 → 구현 → 테스트 → 유지보수 (순서 뒤섞은 오답 선택지 주의)
  • 폭포수 모델은 되돌아가는 흐름이 없다 — 유일하게 "일직선"인 모델
  • 나선형 모델의 핵심 키워드는 위험 분석(Risk Analysis) — 매 반복(나선 한 바퀴)마다 수행
  • 프로토타입 모델은 "시제품 → 평가 → 재개발" 루프가 있다는 것이 폭포수와의 결정적 차이
  • 애자일은 문서보다 동작하는 소프트웨어, 짧은 주기(스프린트) 반복이 핵심

⚖️헷갈리는 개념 비교

구분되돌아가기결과물을 보는 시점핵심 키워드
폭포수없음맨 마지막에순차적, 산출물
프로토타입평가 후 재개발시제품 단계에서 일찍시제품, 피드백
나선형매 나선마다반복할 때마다 점점위험 분석
애자일매 스프린트마다매 스프린트 종료 시동작하는 SW, 고객 소통
