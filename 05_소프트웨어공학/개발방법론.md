# 소프트웨어 개발방법론

## 핵심 요약
> 시험에서는 **각 모델의 특징을 섞어서** 헷갈리게 출제한다. 각 모델의 **키워드**를 확실히 구분하자!

## 소프트웨어 개발 생명 주기 (SDLC)

> **계획 → 분석 → 설계 → 구현 → 테스트 → 유지보수**
> (💡 암기: **계분설구테유** — "계란 분석 설계 구현 테스트 유지")

| 단계 | 하는 일 | 쉬운 비유 |
|------|---------|-----------|
| 계획 | 목표 설정, 일정/비용 산정, **타당성 검토(Feasibility Study)** | 치킨집 차려도 될까? 돈/기간 판단 |
| **분석 (=요구사항 분석)** | **고객이 원하는 것 파악, 요구사항 명세서(SRS) 작성** | **"방 3개, 화장실 2개 필요해요" 정리** |
| 설계 | 시스템 구조 설계 (DB, UI 등) | 설계도(도면) 그리기 |
| 구현 | 실제 코딩 | 집 짓기 |
| 테스트 | 오류 발견 및 수정 | 준공 검사 |
| 유지보수 | 운영 중 수정/개선 | 하자 보수 |

- 📌 출처: 2017 서울시 기출

---

## 주요 개발 모델

### 1. 폭포수(Waterfall) 모델
- 가장 오래된, 가장 기본적인 모델
- **순차적**으로 진행 (요구분석 → 설계 → 구현 → 테스트 → 유지보수)
- 각 단계가 끝나면 **산출물(문서)** 을 만들고 다음 단계로 넘어감
- 이전 단계로 **되돌아가기 어려움**
- 최종 단계까지 가야 결과물을 볼 수 있음
- 💡 비유: **계단을 한 칸씩 내려가는 것** — 올라가기 힘듦

### 2. 프로토타입(Prototype, 원형) 모델
- **시제품**을 먼저 빠르게 만들어서 사용자에게 보여줌
- 사용자 피드백 반영 → 요구사항을 더 정확히 파악
- 목적: 초반에 고객의 요구 사항을 제대로 파악하기 위함
- 💡 비유: **시식 코너** — 맛보고 결정

**📌 단계별 진행 과정 (기출!)**
> 요구 사항 분석 → 시제품 설계 → 시제품 개발 → 고객의 시제품 평가 → 시제품 정제 → 완제품 생산

- 핵심: **설계 → 개발 → 평가** 순서! (만들어야 평가할 수 있다)
- 평가 후 만족할 때까지 **개발/개선/평가를 반복**
- 📌 출처: 2020 국가직 기출

### 3. 나선형(Spiral) 모델
- **보엠(Boehm)**이 제안
- 핵심 키워드: **위험 분석** (매 반복마다 수행!)
- 폭포수 + 프로토타입의 장점을 합친 모델
- **대규모 프로젝트**에 적합 (비용이 많이 들 수 있음)
- 💡 비유: **놀이공원을 단계별로 확장** — 매번 위험 체크하면서 점점 커짐

**📌 4단계 반복 과정 (기출!)**
> 계획 수립 → 위험 분석 → 개발 및 검증 → 고객 평가 → (다시 반복)

- 나선을 한 바퀴 돌 때마다 점점 완성도가 높아짐
- 시험 포인트: "위험 분석"이 들어가면 → 나선형!

### 4. RAD(Rapid Application Development) 모델
- **빠른 개발**을 목표로 하는 모델
- **CASE(Computer Aided Software Engineering) 도구**를 활용하여 자동화
- CASE = 컴퓨터가 개발을 도와주는 도구 (코드 자동 생성, 설계 자동화 등)
  - 상위 CASE: 분석/설계 지원 | 하위 CASE: 구현/테스트 지원 | 통합 CASE: 전체 지원
- 컴포넌트 재사용으로 개발 속도 향상
- 보통 **60~90일** 내 개발 목표
- 💡 비유: 손으로 도면 그리지 않고 **CAD 프로그램**으로 빠르게 설계
- 시험 키워드: **RAD = CASE 도구 = 빠른 개발**
- 📌 출처: 2018 서울시 기출

### 5. 애자일(Agile) 모델
- **실제 동작하는 소프트웨어**를 중시 (문서보다!)
- 짧은 주기(스프린트)로 반복 개발
- 고객과 **지속적 소통**
- 변화에 유연하게 대응
- 대표: 스크럼(Scrum), XP(eXtreme Programming), 칸반(Kanban)
- 💡 비유: **매주 피드백 받으면서 조금씩 완성**하는 것

#### XP(eXtreme Programming) — 애자일의 대표 방법론

**핵심 가치 5가지 (기출!)**: 의사소통, 단순성, 피드백, 용기, 존중

**주요 실천 방법 (기출 키워드!):**

| 기법 | 뜻 | 쉬운 비유 |
|------|-----|-----------|
| **페어 프로그래밍** | 2명이 한 컴퓨터로 같이 코딩 | 운전자 + 내비게이터 |
| **TDD** (테스트 주도 개발) | 테스트를 **먼저** 만들고 코딩 | 정답지 먼저 만들고 시험 출제 |
| **리팩토링** | 기능은 그대로, 코드 구조 개선 | 방 정리 (물건 그대로, 배치만 변경) |
| **CI** (지속적 통합) | 수시로 통합/빌드 | 매일매일 중간점검 |
| **소규모 릴리즈** | 짧은 주기로 자주 배포 | 매주 시식회 |

- 시험 포인트: "페어 프로그래밍", "TDD" → XP!
- 📌 출처: 2015 국회 기출

### 6. V-모델
- **폭포수 모델의 확장판** (폭포수 약점인 "늦은 테스트" 보완)
- 각 개발 단계에 대응하는 **테스트 단계**가 미리 정해져 있음
- **검증(Verification)과 확인(Validation)**을 강조
- 💡 비유: 단원 정리하면서 **확인 문제를 미리 만들어 놓고** 나중에 풀기

**📌 대응 관계 (기출!)**

| 개발 단계 (왼쪽 ↓) | 테스트 단계 (오른쪽 ↑) | 연결고리 |
|---|---|---|
| 요구 분석 | 인수 테스트 | 고객 **요구**대로 됐는지 **인수** |
| 시스템설계 | 시스템테스트 | **시스템** 짝꿍 |
| 상세설계 | 통합테스트 | **상세** 모듈들을 **통합** 확인 |
| 코딩 (꼭짓점) | 단위테스트 | 코드 **단위**별 확인 |

**📌 전체 순서 (2007 국가직 7급 기출!)**
> 요구분석 → 시스템설계 → 상세설계 → **코딩** → 단위테스트 → 통합테스트 → 시스템테스트 → 인수 및 설치

- 테스트 순서: **작은 것 → 큰 것** (단위 → 통합 → 시스템 → 인수)
- 시험 포인트: "검증과 확인", "개발-테스트 대응" → V-모델!

- 폭포수: "단계별 산출물", "순차적", "되돌아가기 어려움"

- 나선형: "위험 분석", "반복"
- 애자일: "동작하는 소프트웨어", "고객 소통", "변화 대응"
- V-모델: "검증과 확인", "개발-테스트 대응", "폭포수 확장"

## 헷갈리는 개념 비교

| 구분 | 폭포수 | 프로토타입 | 나선형 | 애자일 |
|------|--------|-----------|--------|--------|
| 핵심 | 순차적 산출물 | 시제품 활용 | 위험 분석 | 동작하는 SW |
| 반복 여부 | ❌ 없음 | 피드백 반복 | 반복(나선) | 스프린트 반복 |
| 문서 중요도 | ⭐⭐⭐ 매우 높음 | 보통 | 높음 | ⭐ 낮음 |
| 고객 참여 | 초기에만 | 초기~중기 | 각 반복마다 | 상시 참여 |
| 되돌아가기 | 어려움 | 가능 | 가능 | 자유로움 |
