# CGI / ASP / JSP (동적 웹페이지 기술)

## 핵심 요약
> CGI는 웹서버가 외부 프로그램을 호출하는 **규약(인터페이스)**이다.
> ASP·JSP는 CGI의 성능 문제를 개선한 **서버 사이드 스크립트 기술**이다.

## 주요 개념

### CGI (Common Gateway Interface)
- 웹서버가 사용자 요청을 **외부 프로그램**에 넘겨서 동적 페이지를 생성하는 **표준 인터페이스**
- 요청마다 **새로운 프로세스를 생성** → 자원 소모가 큼
- C, Perl, Python 등 다양한 언어로 작성 가능
- **비유:** 손님이 올 때마다 요리사를 새로 고용하는 식당

### ASP (Active Server Pages)
- **Microsoft**가 개발한 서버 사이드 스크립트 기술
- **IIS(Internet Information Services)** 웹서버에서 동작 (Windows 전용)
- VBScript, JScript 사용
- 요청을 **스레드**로 처리 → CGI보다 빠름

### JSP (JavaServer Pages)
- **Java 기반** 서버 사이드 스크립트 기술
- 내부적으로 **서블릿(Servlet)**으로 변환되어 실행
- Tomcat, JBoss 등의 서블릿 컨테이너에서 동작
- **플랫폼 독립적** (Windows, Linux 등 어디서든 실행 가능)

## 기술 발전 흐름

```
CGI (1993~, 원조)
 │  한계: 요청마다 프로세스 생성 → 느림, 자원 낭비
 │
 ├─→ ASP (1996~, Microsoft)
 ├─→ JSP (1999~, Java/Sun)
 ├─→ PHP (1995~, 오픈소스)
 └─→ FastCGI (CGI 개선판, 프로세스 재사용)
```

## 헷갈리는 개념 비교

| 구분 | CGI | ASP | JSP |
|------|-----|-----|-----|
| **정체** | 규약/표준 인터페이스 | MS 웹 기술 | Java 웹 기술 |
| **처리 방식** | 요청마다 **프로세스** 생성 | **스레드** 방식 | **스레드** 방식 |
| **성능** | 낮음 (동시접속 약함) | 높음 | 높음 |
| **사용 언어** | C, Perl, Python 등 | VBScript, JScript | Java |
| **실행 환경** | 웹서버 + 외부 프로그램 | IIS (Windows 전용) | Tomcat 등 (플랫폼 독립) |
| **플랫폼** | 다양 | Windows 전용 | 플랫폼 독립적 |

## 프로세스 vs 스레드 (왜 중요한가)

| 구분 | 프로세스 (CGI) | 스레드 (ASP/JSP) |
|------|---------------|-----------------|
| 메모리 | 각각 독립 공간 (무거움) | 메모리 공유 (가벼움) |
| 생성 속도 | 느림 | 빠름 |
| 동시접속 | 수십~수백 명 한계 | 수천 명 이상 가능 |

## 시험 빈출 포인트

1. **CGI의 최대 단점** = 요청마다 프로세스 생성 → 성능 저하
2. **ASP는 Windows(IIS) 전용**, JSP는 **플랫폼 독립적**
3. JSP는 내부적으로 **서블릿(Servlet)**으로 변환
4. FastCGI = CGI 개선판 (프로세스를 **재사용**하여 성능 향상)
5. 서버 사이드 스크립트 = 서버에서 실행 → 결과(HTML)만 클라이언트에 전송

## 함께 알아둘 개념

- **서블릿(Servlet):** Java로 작성된 서버 프로그램. JSP가 변환되는 대상
- **FastCGI:** CGI의 개선판. 프로세스를 미리 띄워놓고 재사용
- **PHP:** 오픈소스 서버 사이드 언어. CGI 대안 중 가장 널리 쓰임
- **서버 사이드 vs 클라이언트 사이드:** 서버에서 실행(ASP/JSP/PHP) vs 브라우저에서 실행(JavaScript)
