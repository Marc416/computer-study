소프트웨어 테스트와 유지보수

화이트박스·블랙박스 · 순환복잡도 · 테스트 단계 · 유지보수 · 형상관리 · PART 06. 소프트웨어공학

핵심 요약

화이트박스 = 코드 내부(경로·로직)를 보고 테스트, 블랙박스 = 내부는 몰라도 입력·출력만 보고 테스트.

테스트 단계는 단위 → 통합 → 시스템 → 인수 순으로 점점 커진다.

유지보수는 수정·적응·완전(기능보강)·예방 4종류로 나뉘며, 실무 비중이 가장 큰 건 완전(기능보강) 유지보수다.

🎯이 단원을 왜 배우나

"테스트는 오류가 없음을 증명하는 게 아니라, 오류를 찾는 활동이다"

소프트웨어를 완벽하게 테스트하는 것은 수학적으로 불가능하다. 조건문이 10개만 있어도 실행 경로가 수백~수천 가지로 갈라지고, 입력값이 정수 하나만 있어도 경우의 수가 40억 개가 넘는다. 전수 테스트는 못 한다.

그래서 테스트 공학의 목표는 "적은 수의 테스트 케이스로 최대한 많은 오류를 잡는 것"이 된다. 이 목표를 향한 두 가지 전략이 화이트박스와 블랙박스다. 화이트박스는 "코드의 모든 길을 한 번씩은 밟아보자"는 접근이고(그래서 경로 개수를 세는 순환복잡도가 필요하다), 블랙박스는 "입력값을 비슷한 것끼리 묶어서 대표값만 넣어보자"는 접근이다(그래서 동등분할·경계값분석이 나온다).

유지보수는 시험에서 작게 다뤄지지만 실무에서는 전체 소프트웨어 비용의 절반 이상을 차지한다. 그래서 "만들 때 잘 만들어야 한다"는 소프트웨어공학의 모든 주장(모듈화·낮은 결합도·문서화)은 결국 유지보수 비용을 줄이기 위한 것이다. 이 단원이 사실상 소프트웨어공학 전체의 결론인 셈이다.

💡주요 개념 — 테스트 기법 📖 기출문제집 p.655~657

테스트 기법을 가르는 기준은 딱 하나다: "코드 내부를 들여다보는가?"

구분화이트박스 (White Box)블랙박스 (Black Box)
다른 이름구조적 테스트, 글래스 박스명세 기반 테스트, 기능 테스트
보는 것내부 논리 구조·경로기능 명세(입력→출력)
기법 예시기초경로시험, 루프시험, 조건시험, 데이터흐름시험, 논리위주검사, 문장·분기·조건 커버리지동등분할, 경계값분석, 원인-효과 그래프, 비교시험, 상태전이, 신택스 기법
담당 시기주로 단위 테스트 단계주로 인수 테스트 단계
함정 주의: "동등분할(equivalence partitioning)"·"경계값분석"·"원인-효과 그래프"는 블랙박스 기법이다. "기초경로시험(basis path test)"·"조건/문장 커버리지"는 화이트박스 기법 — 시험에서 두 그룹을 섞어 놓고 골라내라는 문제가 매년 반복 출제된다.

화이트박스 — 커버리지 3종 구별

커버리지무엇을 한 번씩 거치게 하나
문장 커버리지 (Statement)프로그램의 모든 문장을 최소 한 번씩 실행
분기 커버리지 (Branch / 결정)모든 조건문의 참·거짓 두 분기를 모두 실행
조건 커버리지 (Condition)결정문 안의 개별 조건식 각각이 참·거짓을 모두 갖도록

분기 vs 조건, 예제로 구별하기

if (A > 0 && B > 0) 라는 결정문이 있다고 하자. 여기서 결정(분기)은 전체 괄호의 참/거짓이고, 조건은 A>0과 B>0 각각이다.

  • 분기 커버리지: 전체가 참인 경우 한 번, 거짓인 경우 한 번만 통과하면 만족
  • 조건 커버리지: A>0이 참인 경우·거짓인 경우, B>0이 참인 경우·거짓인 경우가 각각 나와야 만족

그래서 문제에 "각 조건식이 참·거짓을 한 번 이상 갖도록"이라는 표현이 나오면 답은 조건 커버리지다.

순환복잡도(Cyclomatic Complexity) — 계산하는 법 📖 기출문제집 p.660

기초 경로 테스트(맥케이브의 basis path test)에서는 "독립적인 실행 경로가 몇 개인가"를 먼저 구한 뒤, 그 개수만큼 테스트 케이스를 만든다. 이 경로 개수가 순환복잡도 V(G)이며, 구하는 방법이 세 가지인데 셋 다 결과가 같다.

실전 팁: 코드가 주어지면 if, while, for, case 같은 분기점의 개수를 세고 +1 하면 끝이다. &&나 ||로 조건이 여러 개 묶인 경우에는 단순 조건 하나하나를 각각 1개로 센다.

테스트 단계와 V-모델

개발 단계와 테스트 단계는 서로 짝을 이룬다. 왼쪽에서 세운 계획을 오른쪽에서 그대로 검증한다고 생각하면 된다.

단계대상핵심
단위 테스트개별 모듈 하나드라이버(driver)와 스텁(stub)을 사용
통합 테스트모듈들을 합칠 때모듈 간 인터페이스 오류를 찾음. 빅뱅·하향식·상향식·연쇄식 방식
시스템 테스트통합된 전체 시스템복구·보안·스트레스·성능 테스트 등
인수 테스트사용자 관점사용자 요구사항 만족 여부. 알파(개발자 사이트)·베타(고객 사이트) 테스트

통합 테스트의 4가지 방식 📖 기출문제집 p.658~659

  • 빅뱅(Big-bang): 모든 모듈을 한꺼번에 통합해 테스트
  • 하향식(Top-down): 제어 구조상 상위 모듈부터 통합 → 하위 모듈 대신 스텁(stub) 필요
  • 상향식(Bottom-up): 가장 하부 모듈부터 통합 → 상위 모듈 대신 드라이버(driver) 필요
  • 연쇄식(Threads): 중요 기능을 담당하는 최소 단위(스레드)부터 통합 → 초기에 시스템 골격을 보여줄 수 있다(장점)

드라이버 vs 스텁: 드라이버는 하위 모듈을 불러주는 가짜 상위 모듈, 스텁은 아직 없는 하위 모듈 흉내를 내는 가짜다. "상향식엔 드라이버, 하향식엔 스텁"으로 외운다.

함정: "연쇄식 통합은 초기에 시스템 골격을 파악하기 어렵다" → ✗ 오히려 초기에 골격을 보여주는 것이 연쇄식의 장점이다.

함정: "시스템 테스트는 넓이 우선/깊이 우선 방식을 사용한다" → ✗ 넓이·깊이 우선은 통합 테스트에서 모듈을 결합하는 순서 개념이다.

특수 테스트무엇을 확인하나
회귀(Regression) 테스트한 모듈의 수정이 다른 부분에 미친 영향을 검사. 수정 모듈뿐 아니라 관련 모듈까지 재검사. 방식: Retest All / Selective / Priority
알파 테스트개발자 사이트에서 통제된 환경으로 수행
베타 테스트고객 사이트에서 실제 사용자가 수행 (출시 전 최종 피드백)
스트레스 테스트비정상적으로 과도한 분량·빈도로 자원을 요청할 때의 영향

🔧주요 개념 — 유지보수 📖 기출문제집 p.665

종류언제 하는가
수정(corrective) 유지보수인도 후 사용 중 발견된 오류를 잡을 때
적응(adaptive) 유지보수환경(OS·하드웨어 등)이 바뀌어 그에 맞게 수정할 때
완전(perfective) 유지보수 (기능보강)새 기능 추가·기존 기능 개선·성능 향상을 원할 때 — 비중이 가장 큼
예방(preventive) 유지보수문제가 터지기 전에 미리 예측되는 오류를 손볼 때
암기팁: "고쳐서(수정) - 맞추고(적응) - 더 좋게(완전) - 미리(예방)" 순서로 이야기를 만들면 헷갈리지 않는다. 특히 "새 기능 추가 = 완전(perfective)"이 가장 자주 나온다.

리먼(Lehman)의 소프트웨어 진화의 법칙 📖 기출문제집 p.664~665

법칙내용
지속적 변경의 법칙시스템 요구는 항상 변하므로 소프트웨어도 계속 진화해야 한다 → 유지보수성이 중요
복잡도 증가(엔트로피)의 법칙변경이 계속되면 구조가 나빠지고 점점 복잡해진다 → 재구조화·리엔지니어링 필요
자기 통제의 법칙시스템 진화 과정은 피드백을 통한 자기 통제 과정이다
안정성 유지의 법칙유지보수 프로세스는 소멸까지 일정한 평균 작업량을 보인다
친근성 유지의 법칙시스템의 평균 성장률이 일정하다
품질 저하의 법칙운영환경 변화에 적응하지 못하면 품질은 떨어진다
피드백 시스템의 법칙진화는 여러 관련자의 피드백으로 구성되며, 다른 모든 법칙의 근원

구별 포인트: "요구가 변하니 계속 진화해야 한다" → 지속적 변경 / "고칠수록 구조가 나빠진다" → 복잡도 증가 / "길게 보면 일정한 추세를 보인다" → 자기 통제.

소프트웨어 재사용 vs 재공학

  • 재사용(Reuse): 기존 소프트웨어(부품)를 새 소프트웨어에 그대로 활용 — 부품이 작고 일반적일수록 재사용률이 높음
  • 재공학(Reengineering): 기존 소프트웨어의 취약한 부분을 단계적으로 개선해 품질을 끌어올림
  • 역공학(Reverse Engineering): 소스코드를 분석해 더 추상화된 설계 명세를 역으로 복구하는 것

가용성(Availability) 계산 📖 기출문제집 p.663~664

MTTF(Mean Time To Failure) = 평균 가동시간  |  MTTR(Mean Time To Repair) = 평균 수리시간
가용성 = MTTF ÷ (MTTF + MTTR) × 100(%)  — 전체 시간 중 "쓸 수 있었던 시간"의 비율

형상 관리 (Configuration Management)

여러 사람이 코드를 동시에 고칠 때 "무엇이 언제 왜 바뀌었는지"를 체계적으로 관리하는 것. Git·SVN·CVS가 대표적인 형상관리 도구다.

용어의미
저장소 (Repository)최신 버전 파일과 변경 이력이 저장되는 곳
Import버전 관리가 안 된 파일을 저장소에 처음으로 등록
Check-out수정하려고 저장소에서 파일을 받아옴
Check-in / Commit수정 완료한 파일을 저장소에 새 버전으로 반영
Update저장소의 최신 버전을 내 로컬로 동기화
함정 주의: 형상관리 항목(SCI)에는 원시코드(소스코드)도 포함된다 — "원시코드는 형상관리 대상이 아니다"는 틀린 지문으로 자주 나온다. 분석서·설계서·프로그램·사용자지침서 모두 형상관리 대상.

📌시험 빈출 포인트

  • 동등분할·경계값분석·원인효과그래프·비교검사 = 블랙박스 / 기초경로시험·루프검사·논리위주검사·커버리지 계열 = 화이트박스
  • 화이트박스의 다른 이름 = 구조적 테스트, 글래스박스 / 블랙박스 = 명세 기반 테스트
  • "결정문 내 각 조건식이 참·거짓을 갖도록" → 조건 커버리지
  • 순환복잡도 V(G) = 간선 − 노드 + 2 = 분기 수 + 1 = 영역 수 (세 방법 결과 일치)
  • 테스트 단계: 단위 → 통합 → 시스템 → 인수, 단위 테스트엔 드라이버·스텁 사용
  • 통합 방식: 빅뱅 / 하향식(스텁) / 상향식(드라이버) / 연쇄식(초기 골격 파악 가능)
  • 알파=개발자 사이트, 베타=고객 사이트, 회귀=수정이 다른 부분에 준 영향 검사
  • 경계값 분석: 유효범위 1~99라면 0, 1, 99, 100이 테스트 대상 — 중간값(70 등)은 부적합
  • 유지보수 4종 중 "새 기능 추가" = 완전(perfective) 유지보수
  • 가용성 = MTTF ÷ (MTTF + MTTR)
  • 원시코드도 형상관리 대상이라는 점 (제외된다는 지문은 오답)
  • Check-in(=Commit, 반영) vs Check-out(받아옴) 방향 헷갈리지 않기
  • ISO/IEC 12207 = 프로세스 품질 표준, CMMI 3단계(정의) = 표준 프로세스는 있으나 정량 측정 불가
  • ERP·CRM·SCM·EAI·BPR·KMS 정의 매칭 문제

문제 12024 지방직 · 기출문제집 p.655

블랙박스 테스트 기법에 해당하는 것은?

  1. 조건 커버리지(condition coverage)
  2. 기본 경로 테스트(basis path test)
  3. 문장 커버리지(statement coverage)
  4. 동등 분할(equivalence partitioning)
해설 보기

정답 ④ 동등 분할

"커버리지"와 "경로"라는 단어가 보이면 무조건 화이트박스다. 코드 내부의 문장·분기·경로를 얼마나 덮었는지 세는 개념이기 때문이다.

  1. ①③ 커버리지 계열 → 코드 내부를 봐야 계산 가능 → 화이트박스
  2. ② 기본(기초) 경로 테스트 → 제어흐름 그래프의 경로를 따짐 → 화이트박스
  3. ④ 동등 분할 → 입력값을 비슷한 그룹으로 나눠 대표값만 테스트 → 내부를 몰라도 가능 → 블랙박스

블랙박스 4대 기법 암기: 동등분할, 경계값분석, 원인-효과 그래프, 비교검사 (+ 상태전이, 신택스).

결정 명령문 내의 각 조건식이 참, 거짓을 한 번 이상 갖도록 조합하여 테스트 케이스를 설계하는 방법은?

  1. 문장 검증 기준(Statement Coverage)
  2. 조건 검증 기준(Condition Coverage)
  3. 분기 검증 기준(Branch Coverage)
  4. 다중 조건 검증 기준(Multiple Condition Coverage)
해설 보기

정답 ② 조건 검증 기준(Condition Coverage)

핵심 단어는 "각 조건식"이다. 전체 결정문이 아니라 개별 조건 하나하나를 따지고 있다.

기준무엇을 보나예: if (A>0 && B>0)

문제 32007 국가직 7급 · 기출문제집 p.657

입력값의 유효 범위가 1~99인 프로그램을 경계값 분석으로 테스트하려 한다. 가장 적합하지 않은 테스트케이스는?

  1. 1
  2. 70
  3. 99
  4. 100
해설 보기

정답 ② 70

경계값 분석은 "오류는 범위의 한가운데가 아니라 경계에서 터진다"는 경험에 기반한 기법이다. <를 <=로 잘못 쓰는 실수가 딱 경계에서 드러나기 때문이다.

  1. 유효 범위 1~99의 경계는 1과 99 → 이 값들로 정상 동작(true)을 확인
  2. 경계 바로 바깥인 0과 100 → 거부(false)되는지 확인
  3. 따라서 의미 있는 테스트값은 0, 1, 99, 100
  4. 70은 범위 한가운데의 평범한 값 → 경계값 분석 관점에서는 얻을 정보가 가장 적다

주의: 70이 "틀린 테스트"라는 뜻은 아니다. 70은 동등 분할 기법에서는 유효 클래스의 대표값으로 적절하다. 문제가 어떤 기법을 지정했는지를 보고 답해야 한다.

문제 42016 국가직 · 기출문제집 p.658

소프트웨어 테스트에 대한 설명으로 옳지 않은 것은?

  1. 단위 테스트는 개별적인 모듈에 대한 테스트이며 테스트 드라이버와 테스트 스텁을 사용할 수 있다.
  2. 통합 테스트는 모듈을 통합하는 방식에 따라 빅뱅 기법, 하향식 기법, 상향식 기법을 사용한다.
  3. 시스템 테스트는 모듈들이 통합된 후 넓이 우선 방식 또는 깊이 우선 방식을 사용하여 테스트한다.
  4. 인수 테스트는 인수 전에 사용자의 요구 사항이 만족되었는지 테스트한다.
해설 보기

정답 ③

넓이 우선/깊이 우선은 통합 테스트에서 트리 구조의 모듈을 어떤 순서로 결합할지를 가리키는 말이다. 시스템 테스트와는 무관하다.

  1. 시스템 테스트가 실제로 하는 일: 모든 모듈이 하나의 시스템으로 동작할 때 복구·보안·스트레스·성능 테스트를 수행
  2. 통합 테스트가 하는 일: 모듈 간 인터페이스와 결합을 검사하며, 결합 순서에 따라 깊이/너비 우선으로 나뉨

나머지 선택지 확인: ① 단위 테스트의 드라이버·스텁 ✓, ② 통합 방식 3종(+연쇄식) ✓, ④ 인수 테스트의 정의 ✓ — 모두 옳다.

문제 52021 국회 · 기출문제집 p.659~660

한 모듈의 수정이 다른 부분에 영향을 끼칠 수도 있다고 보아, 수정한 모듈뿐 아니라 관련된 모듈까지 문제가 없는지 검사하는 테스트는?

  1. 회귀 테스트(Regression Test)
  2. 인수 테스트(Acceptance Test)
  3. 통합 테스트(Integration Test)
  4. 단위 테스트(Unit Test)
해설 보기

정답 ① 회귀 테스트

회귀(regression)는 "되돌아간다"는 뜻으로, 고친 것 때문에 멀쩡하던 기능이 예전 상태(고장)로 되돌아가지 않았는지 확인하는 테스트다.

  1. 버그를 고침 → 그 부분이 고쳐졌는지 확인(확정 테스트, confirmation test)
  2. 그런데 그 수정이 다른 모듈을 망가뜨렸을 수도 있다
  3. 그래서 관련 모듈까지 다시 한 번 테스트하는 것이 회귀 테스트

회귀 테스트 3가지 방식: Retest All(전부 재수행) / Selective(영향 범위 위주) / Priority(핵심 기능 위주). "모듈 회귀 테스트와 증분적 회귀 테스트로 나뉜다"는 서술은 오답이다.

특징: 이미 만들어 둔 테스트 케이스를 재실행하므로 자동화 도구를 쓰기에 가장 적합한 테스트다.

문제 62016 계리직 · 기출문제집 p.660

소프트웨어 테스트에 대한 설명으로 옳지 않은 것은?

  1. 베타(beta) 테스트는 고객 사이트에서 사용자에 의해서 수행된다.
  2. 회귀(regression) 테스트는 한 모듈의 수정이 다른 부분에 미치는 영향을 검사한다.
  3. 화이트 박스(white box) 테스트는 모듈의 내부 구현보다는 입력과 출력에 의해 기능을 검사한다.
  4. 스트레스(stress) 테스트는 비정상적으로 과도한 분량 또는 빈도로 자원을 요청할 때의 영향을 검사한다.
해설 보기

정답 ③ — 그것은 블랙박스 테스트의 설명이다

③은 화이트박스와 블랙박스의 정의를 통째로 맞바꾼 전형적인 함정이다.

  1. 화이트박스: 모듈 안의 작동을 자세히 관찰, 논리적 구조를 체계적으로 점검
  2. 블랙박스: 내부 구현은 보지 않고 입력과 출력으로 기능을 검사 ← ③이 설명한 것

나머지 확인: ① 베타=고객 사이트 ✓ (알파=개발자 사이트), ② 회귀 테스트 정의 ✓, ④ 스트레스 테스트 정의 ✓

이 유형의 공략법: 선택지에 "화이트박스"가 나오면 "내부·구조·경로·논리"라는 단어가 함께 있는지 확인하라. "입력과 출력", "기능", "명세"가 붙어 있으면 그 선택지는 틀린 것이다.

문제 7기출문제집 p.663~664 (가용성 계산)

어떤 시스템의 가동시간이 각각 8, 7, 9이고 고장시간이 각각 1, 2, 3일 때, 이 시스템의 가용성(availability)은?

  1. 80%
  2. 400%
  3. 25%
  4. 75%
해설 보기

정답 ① 80%

가용성은 "전체 시간 중 시스템을 쓸 수 있었던 시간의 비율"이다. 평균값부터 구하고 비율을 계산하면 된다.

  1. MTTF(평균 가동시간) = (8 + 7 + 9) ÷ 3 = 8
  2. MTTR(평균 수리시간) = (1 + 2 + 3) ÷ 3 = 2
  3. 전체 사이클 = MTTF + MTTR = 8 + 2 = 10
  4. 가용성 = 8 ÷ 10 × 100 = 80%

함정: ② 400%는 MTTF ÷ MTTR(8÷2=4)로 잘못 계산한 값이다. 분모는 반드시 가동 + 고장(전체 시간)이어야 한다. ③ 25%는 분자·분모를 뒤집어 MTTR÷(MTTF+MTTR)로 계산한 경우다.

문제 82025 계리직 · 기출문제집 p.665

개발된 소프트웨어에 새로운 기능을 추가하는 유지보수는?

  1. 수정(corrective) 유지보수
  2. 예방(preventive) 유지보수
  3. 완전(perfective) 유지보수
  4. 적응(adaptive) 유지보수
해설 보기

정답 ③ 완전(perfective) 유지보수

영어 단어의 뜻으로 접근하면 헷갈리지 않는다.

유지보수영어 뜻언제
수정 (corrective)바로잡다오류를 발견해 고칠 때
적응 (adaptive)적응하다환경(OS·HW)이 바뀌었을 때
완전 (perfective)완벽하게 만들다새 기능 추가·성능 개선 ← 정답
예방 (preventive)예방하다문제 나기 전에 미리

함정: "새 기능 추가"를 ①수정으로 고르는 실수가 흔하다. 수정은 "있던 것이 잘못돼서" 고치는 것이고, 완전은 "잘 돌아가지만 더 좋게" 만드는 것이다. 참고로 실무 유지보수 비용 중 완전 유지보수의 비중이 가장 크다.

문제 9개념 확인 · 응용 (순환복잡도)

다음 의사코드의 순환복잡도 V(G)를 구하고, 필요한 최소 테스트 케이스 수를 답하시오.

input(score)
if (score >= 90)
    grade = "A"
else if (score >= 80)
    grade = "B"
else
    grade = "C"
if (grade == "A")
    print("우수")
print(grade)
해설 보기

정답: V(G) = 4, 최소 테스트 케이스 4개

가장 빠른 방법인 "분기(조건문) 수 + 1"로 푼다.

  1. 조건문을 센다: if (score>=90) → 1개
  2. else if (score>=80) → 2개 (else if도 독립된 판단이므로 센다)
  3. if (grade=="A") → 3개
  4. V(G) = 분기 3 + 1 = 4
  5. 독립 경로가 4개이므로 테스트 케이스도 최소 4개 필요

실제 경로 4가지로 검증: ①score=95(A, "우수" 출력) ②score=85(B) ③score=70(C) ④A가 아닌 경우 마지막 if를 건너뛰는 경로 — ②③이 이를 포함한다. 테스트 데이터로는 95, 85, 70과 경계값을 조합하면 된다.

주의: else 자체는 분기점으로 세지 않는다. 판단(조건식)이 있는 if, else if, while, for, case만 센다. 만약 if (A && B)처럼 조건이 묶여 있으면 단순 조건 각각을 1개씩 센다.
