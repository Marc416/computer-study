소프트웨어 테스트와 유지보수

화이트박스·블랙박스 테스트, V-모델, 유지보수 4종, 형상관리 · PART 06. 소프트웨어공학

핵심 요약

화이트박스 = 코드 내부(경로·로직)를 보고 테스트, 블랙박스 = 내부는 몰라도 입력·출력만 보고 테스트.

유지보수는 수정·적응·완전(기능보강)·예방 4종류로 나뉘며, 실무에서 가장 많은 비중을 차지하는 건 완전(기능보강) 유지보수다.

💡주요 개념 — 테스트 기법 📖 기출문제집 p.655~656

테스트 기법을 가르는 기준은 딱 하나다: "코드 내부를 들여다보는가?"

구분화이트박스 (White Box)블랙박스 (Black Box)
보는 것내부 논리 구조·경로기능 명세(입력→출력)
기법 예시기초경로시험, 루프시험, 조건시험, 데이터흐름시험, 조건/문장 커버리지동등분할, 경계값분석, 원인-효과 그래프, 비교시험
담당 시기주로 단위 테스트 단계주로 인수 테스트 단계
함정 주의: "동등분할(equivalence partitioning)"·"경계값분석"·"원인-효과 그래프"는 블랙박스 기법이다. "기초경로시험(basis path test)"·"조건/문장 커버리지"는 화이트박스 기법 — 시험에서 두 그룹을 섞어 놓고 골라내라는 문제가 반복 출제된다.

테스트 단계와 V-모델

개발 단계와 테스트 단계는 서로 짝을 이룬다. 왼쪽에서 세운 계획을 오른쪽에서 그대로 검증한다고 생각하면 된다.

🔧주요 개념 — 유지보수 📖 기출문제집 p.665

종류언제 하는가
수정(corrective) 유지보수인도 후 사용 중 발견된 오류를 잡을 때
적응(adaptive) 유지보수환경(OS·하드웨어 등)이 바뀌어 그에 맞게 수정할 때
완전(perfective) 유지보수 (기능보강)새 기능 추가·기존 기능 개선·성능 향상을 원할 때 — 비중이 가장 큼
예방(preventive) 유지보수문제가 터지기 전에 미리 예측되는 오류를 손볼 때
암기팁: "고쳐서(수정) - 맞추고(적응) - 더 좋게(완전) - 미리(예방)" 순서로 이야기를 만들면 헷갈리지 않는다.

소프트웨어 재사용 vs 재공학

  • 재사용(Reuse): 기존 소프트웨어(부품)를 새 소프트웨어에 그대로 활용 — 부품이 작고 일반적일수록 재사용률이 높음
  • 재공학(Reengineering): 기존 소프트웨어의 취약한 부분을 단계적으로 개선해 품질을 끌어올림
  • 역공학(Reverse Engineering): 소스코드를 분석해 더 추상화된 설계 명세를 역으로 복구하는 것

형상 관리 (Configuration Management)

여러 사람이 코드를 동시에 고칠 때 "무엇이 언제 왜 바뀌었는지"를 체계적으로 관리하는 것. Git·SVN·CVS가 대표적인 형상관리 도구다.

용어의미
저장소 (Repository)최신 버전 파일과 변경 이력이 저장되는 곳
Import버전 관리가 안 된 파일을 저장소에 처음으로 등록
Check-out수정하려고 저장소에서 파일을 받아옴
Check-in / Commit수정 완료한 파일을 저장소에 새 버전으로 반영
Update저장소의 최신 버전을 내 로컬로 동기화
함정 주의: 형상관리 항목(SCI)에는 원시코드(소스코드)도 포함된다 — "원시코드는 형상관리 대상이 아니다"는 틀린 지문으로 자주 나온다. 분석서·설계서·프로그램·사용자지침서 모두 형상관리 대상.

🏢참고 — 기업 정보시스템 용어

약어의미

KMSKnowledge Management System — 조직의 지식을 창출·저장·공유

📌시험 빈출 포인트

  • 동등분할·경계값분석·원인효과그래프 = 블랙박스 / 기초경로시험·커버리지 계열 = 화이트박스
  • V-모델: 요구분석↔인수테스트, 시스템설계↔시스템테스트, 상세설계↔통합테스트 짝 맞추기
  • 유지보수 4종 중 실무 비중이 가장 큰 것은 완전(기능보강) 유지보수
  • 원시코드도 형상관리 대상이라는 점 (제외된다는 지문은 오답)
  • Check-in(=Commit, 반영) vs Check-out(받아옴) 방향 헷갈리지 않기
  • ERP·CRM·SCM·EAI·BPR·KMS 정의 매칭 문제
