객체지향과 UML

객체지향 4대 특징 · UML 다이어그램 · 디자인 패턴 · PART 06. 소프트웨어공학

핵심 요약

객체지향의 4대 특징은 캡슐화, 상속, 다형성, 추상화다. 각각 "숨긴다", "물려받는다", "다르게 반응한다", "중요한 것만 남긴다"로 외운다.

UML은 방법론이 아니라 그림 표기법이다. 시스템의 "생김새(구조)"를 그리면 구조 다이어그램, "움직임(동작)"을 그리면 행위 다이어그램이다.

GoF 디자인 패턴은 목적에 따라 생성·구조·행위 세 가지로 분류된다.

🎯이 단원을 왜 배우나

"기능 중심"에서 "사물 중심"으로 세상을 보는 방법을 바꾼 것

구조적 방법론은 프로그램을 "기능(할 일)의 모음"으로 본다. 그래서 자료흐름도로 "데이터가 어떤 처리를 거치는가"를 그린다. 문제는 요구사항이 바뀔 때다. 기능이 바뀌면 자료 흐름 전체가 흔들려서 수정 범위를 예측할 수 없다.

객체지향은 관점을 바꿨다 — 프로그램을 "사물(객체)들이 서로 메시지를 주고받는 세계"로 본다. 현실 세계의 "학생"이 그대로 학생 객체가 되므로, 요구사항이 바뀌어도 바뀐 그 객체만 고치면 된다. 데이터(속성)와 그 데이터를 다루는 코드(메서드)를 한 덩어리로 묶어두었기(캡슐화) 때문이다.

그런데 객체들의 관계를 말로 설명하면 아무도 못 알아듣는다. 그래서 그림으로 통일된 표기법을 만든 것이 UML이다. UML은 "어떻게 개발할지"를 정한 방법론이 아니라, 설계를 "어떻게 그릴지"만 정한 표기법이라는 점이 시험에 자주 나온다.

마지막으로 디자인 패턴은 선배 개발자들이 반복해서 마주친 상황의 정답 모음집이다. "이런 상황에서는 이렇게 설계하면 된다"를 23가지로 정리한 것이 GoF 패턴이고, 시험은 주로 어떤 패턴이 생성·구조·행위 중 어디에 속하는가를 묻는다.

💡주요 개념 — 객체지향 4대 특징

특징정의쉬운 설명
캡슐화 (Encapsulation)데이터와 처리 방법(메서드)을 하나로 묶고, 외부에는 필요한 인터페이스만 드러냄리모컨 버튼(인터페이스)만 보이고, 내부 회로(구현)는 케이스 안에 숨겨져 있음
상속 (Inheritance)상위 클래스(부모)의 속성·메서드를 하위 클래스(자식)가 그대로 물려받음"동물" 클래스를 만들어두면 "강아지", "고양이"가 이름·나이 속성을 다시 안 만들어도 됨
다형성 (Polymorphism)같은 이름의 메서드가 클래스마다 다르게 동작함 (오버라이딩/오버로딩으로 구현)"소리내기()"를 강아지는 "멍멍", 고양이는 "야옹"으로 각자 다르게 구현
추상화 (Abstraction)객체의 불필요한 세부사항을 제거하고 중요한 속성만 클래스로 뽑아냄실제 강아지는 특징이 무수히 많지만, 프로그램에는 "이름·나이·소리내기"만 클래스로 정의
함정 주의: "재귀용법(Recursion)"은 객체지향의 특징이 아니다 — 함정 선택지로 자주 나온다. 객체지향 4대 특징은 캡슐화·상속·다형성·추상화 뿐.

기본 용어 정리 📖 기출문제집 p.638~641

  • 객체(Object): 상태(state) + 행위(behavior) + 정체성(identity)을 가진 것
  • 클래스(Class): 객체의 타입(틀). 같은 클래스에 속하는 개개의 객체를 그 클래스의 인스턴스(instance)라 한다
  • 메서드(Method): 객체가 가진 데이터를 처리하는 연산(operation)
  • 메시지(Message): 객체들 사이의 상호작용은 메시지를 통해 이루어진다
  • 다중 상속: 한 클래스가 두 개 이상의 상위 클래스로부터 물려받는 것

함정 ①: "다중 상속은 두 개 이상의 클래스가 한 클래스로부터 상속받는 것" → ✗ 방향이 반대다. 한 자식이 여러 부모에게 물려받는 것이 다중 상속이다.

함정 ②: "다형성은 몇 개의 클래스 객체들을 묶어서 하나처럼 다루는 기법" → ✗ 그건 집합/합성에 가깝다. 다형성은 같은 메시지에 객체마다 다르게 반응하는 것.

실제 코드로 보는 상속과 다형성

말로만 들으면 추상적이니, 실제 클래스 구조로 그려보자. Animal이라는 부모 클래스를 Dog, Cat이 상속받고, 각자 makeSound()라는 같은 이름의 메서드를 자기만의 방식으로 오버라이딩(재정의)한다 — 이게 다형성이다.

다형성의 두 가지 구현 방법 — 오버로딩 vs 오버라이딩

구분오버로딩(Overloading)오버라이딩(Overriding)
어디서같은 클래스 안에서상속 관계에서 (부모 ↔ 자식)
무엇이 같고 다른가이름은 같고 매개변수(개수·자료형)가 다름이름·매개변수까지 완전히 같고 내용만 다름
예add(int,int) / add(double,double)Animal의 makeSound()를 Dog가 재정의

둘 다 "같은 이름으로 다른 동작"이므로 다형성의 구현 수단이다. 시험에서 "Java의 오버로딩·오버라이딩으로 구현되는 개념은?"이라 물으면 답은 다형성이다.

범주형/매개변수화 다형성: 연산이나 부프로그램이 특정 하나의 자료형이 아니라 여러 자료형을 처리할 수 있는 특성도 다형성이며, 특수 범주형과 매개변수화로 나뉜다.

클래스 사이의 관계 📖 기출문제집 p.638

관계의미예시
연관 (Association)한 객체가 다른 객체의 서비스를 사용학생 — 강의를 수강한다
집합 (Aggregation)전체-부분 관계지만, 부분이 전체 없이도 독립적으로 존재 가능학과 — 학생 (학과가 없어져도 학생은 존재)
합성 (Composition)전체-부분 관계이면서, 부분이 전체에 종속되어 함께 소멸자동차 — 엔진 (자동차가 폐차되면 엔진도 폐기)

🗺️주요 개념 — UML 다이어그램 📖 기출문제집 p.647~648

UML은 "생김새를 그리는가, 움직임을 그리는가"로 크게 둘로 나뉜다. 시험에는 특정 다이어그램이 구조냐 행위냐를 구분하는 문제가 자주 나온다.

분류포함 다이어그램공통점
구조 다이어그램
(Structural)		클래스, 객체, 컴포지트 구조, 배치(deployment), 컴포넌트, 패키지시스템이 어떻게 생겼는지(정적)를 그림
행위 다이어그램
(Behavioral)		액티비티, 유스케이스, 상태머신(state machine), 상호작용 다이어그램(시퀀스·커뮤니케이션·타이밍·인터랙션오버뷰)시스템이 어떻게 동작하는지(동적)를 그림
함정 주의: 시퀀스 다이어그램은 "행위 다이어그램"의 하위 항목인 "상호작용 다이어그램"에 속한다 — 구조 다이어그램이 아니다. 반대로 클래스·패키지·배치 다이어그램은 전부 구조 다이어그램이다.
다이어그램무엇을 표현하나
클래스클래스의 속성·연산과 클래스들 사이의 관계
객체특정 시점의 객체(인스턴스) 정보
배치(Deployment)시스템의 물리적 구조 (서버·장비 배치)
컴포넌트컴포넌트의 구조와 관계
패키지패키지 구성과 패키지 사이의 관계
유스케이스사용자(액터)와 시스템 간의 상호작용 방법 — 요구분석 단계의 대표 도구
시퀀스(순차)시간 흐름에 따른 객체들의 상호작용
커뮤니케이션(협력)객체 사이의 관계를 중심으로 상호작용 표현
상태머신이벤트에 의한 객체의 상태 변화
액티비티처리의 흐름(절차적·병렬적 행위)

유스케이스 다이어그램 — 객체지향 분석의 출발점

객체지향 분석은 "누가(액터) 이 시스템으로 무엇을 하려 하는가(유스케이스)"를 찾는 것에서 시작한다. 액터는 사람 모양(스틱 피겨), 유스케이스는 타원, 시스템 범위는 사각형 경계로 그린다.

객체지향 분석·설계 절차 📖 기출문제집 p.631~632

  1. 요구를 사용 사례(유스케이스)로 정리하고 유스케이스 다이어그램 작성
  2. 클래스 후보를 찾아내 개념적 객체 모형 작성
  3. 유스케이스를 기초로 순서(시퀀스) 다이어그램 작성
  4. 클래스의 속성·오퍼레이션과 클래스 간 관계를 찾아 객체 모형 완성
  5. 상태·액티비티 다이어그램 등을 추가해 UML 모델 완성
  6. 서브시스템을 파악하고 전체 시스템 구조 설계

유스케이스 찾는 세부 절차: 액터 찾기 → 시나리오 찾기 → 사용 사례 찾기 → 사용 사례 구체화 → 사용 사례 간 관계 찾기 → 비기능적 요구 찾기

대표 예시 — 시퀀스 다이어그램으로 "동작" 그려보기

시퀀스 다이어그램은 시간 흐름에 따라 객체들이 주고받는 메시지를 그린다. 아래는 "고객이 주문하면 결제가 처리되는" 흐름이다 — 세로 점선이 각 객체의 생명선(lifeline), 화살표가 메시지다.

🧱주요 개념 — 디자인 패턴 (GoF) 📖 기출문제집 p.644~645

디자인 패턴은 자주 마주치는 설계 상황의 정형화된 해법이다. 좋은 설계·아키텍처를 재사용하기 쉽게 해준다는 것이 존재 이유다. GoF는 패턴을 목적(생성·구조·행위)과 범위(클래스·객체)로 분류한다.

패턴한 줄 설명분류
Singleton특정 클래스의 객체가 오직 하나만 존재하도록 보장생성
Abstract Factory관련 객체들의 집합을 구체 클래스 없이 생성생성
Builder복잡한 객체를 단계별로 조립해 생성생성
Adapter (적응자)호환되지 않는 기존 클래스의 인터페이스를 변환해 재사용구조
Facade서브시스템 앞에 창구 객체를 세워 단순화된 하나의 인터페이스만 제공 → 클래스 간 의존·복잡성 감소구조
Bridge (가교)기능과 구현을 분리해 독립적으로 확장구조
Composite (복합체)개별 객체와 복합 객체를 동일하게 다룸구조
Strategy알고리즘들을 각각 캡슐화해 필요할 때 교체해 사용행위
Template Method상위 클래스는 뼈대만, 구체적 내용은 하위 클래스가 결정행위
Observer상태가 바뀌면 의존 객체들에게 자동 통보행위
최다 출제 함정: Bridge(가교)·Adapter(적응자)·Composite(복합체)는 전부 "구조" 패턴인데, 이것들을 "행위 패턴"이라고 서술하는 선택지가 반복해서 나온다. 반대로 Template Method는 행위 패턴인데 구조 패턴 목록에 섞어 넣는 문제도 있다.

📌시험 빈출 포인트

  • 객체지향 4대 특징: 캡슐화·상속·다형성·추상화 (재귀용법은 함정 오답)
  • "상위 클래스 속성을 물려받음" → 상속, "인터페이스만 노출·내부 은닉" → 캡슐화, "같은 메시지에 다르게 반응" → 다형성, "불필요한 세부사항 제거" → 추상화 — 지문 매칭 문제 반복 출제
  • 오버로딩·오버라이딩으로 구현되는 개념 = 다형성
  • 다중 상속 = 한 클래스가 여러 상위 클래스로부터 상속 (방향 반대로 쓴 선택지 주의)
  • UML은 방법론이 아니라 표기법(그래픽 언어)이라는 점 — "UML은 방법론이다"는 오답
  • 구조 다이어그램(클래스·객체·배치·컴포넌트·패키지) vs 행위 다이어그램(액티비티·유스케이스·상태머신·시퀀스 등) 구분
  • 시퀀스 다이어그램 = 시간 흐름에 따른 객체 간 메시지 교환 → 행위(상호작용) 다이어그램
  • 객체지향 분석의 대표 도구 = 유스케이스 다이어그램
  • 집합(Aggregation) vs 합성(Composition): 부분이 전체 없이 독립 존재 가능한지 여부로 구분
  • 디자인 패턴 3분류: 생성(Singleton·Builder·Abstract Factory·Prototype) / 구조(Adapter·Bridge·Composite·Decorator·Proxy·Facade) / 행위(Strategy·Observer·Template Method 등)
  • Facade = 서브시스템 앞의 단순 창구, Singleton = 객체 딱 하나, Adapter = 인터페이스 변환

㉠, ㉡에 들어갈 단어를 바르게 연결한 것은?
• 기존 현실 세계의 객체에서 불필요한 속성을 제거하고, 중요한 정보만 클래스로 표현하는 모델링 기법을 ( ㉠ )(이)라 한다.
• 객체의 상세한 내용을 외부에 철저히 숨기고 메시지만으로 상호작용하게 하는 것을 ( ㉡ )(이)라 한다.

  1. ㉠ 추상화, ㉡ 다형성
  2. ㉠ 추상화, ㉡ 캡슐화
  3. ㉠ 다형성, ㉡ 캡슐화
  4. ㉠ 상속, ㉡ 다형성
해설 보기

정답 ② 추상화 / 캡슐화

각 특징의 핵심 동사 하나만 잡아두면 이런 매칭 문제는 전부 풀린다.

특징핵심 동사문제 속 표현
추상화추려낸다"불필요한 속성 제거, 중요한 정보만" ← ㉠
캡슐화숨긴다"외부에 철저히 숨기고" ← ㉡
상속물려받는다—
다형성다르게 반응한다—

주의: 추상화와 캡슐화는 둘 다 "세부를 감춘다"는 느낌이라 헷갈린다. 추상화 = 설계 단계에서 무엇을 남길지 고르는 것, 캡슐화 = 구현을 묶어서 밖에서 못 보게 막는 것으로 구분하자.

문제 22008 국가직 · 기출문제집 p.638

객체지향 시스템의 특성이 아닌 것은?

  1. 캡슐화(Encapsulation)
  2. 재귀용법(Recursion)
  3. 상속성(Inheritance)
  4. 다형성(Polymorphism)
해설 보기

정답 ② 재귀용법(Recursion)

재귀용법은 함수가 자기 자신을 호출하는 프로그래밍 기법으로, 객체지향과는 무관하다(절차적 언어에도 있다).

객체지향 4대 특징은 캡슐화·상속·다형성·추상화 뿐이며, 이 자리에 섞여 들어오는 단골 오답은 다음과 같다:

  • 재귀용법(Recursion) — 이 문제
  • 모듈화 — 소프트웨어공학 일반 개념이지 객체지향 고유 특징이 아님
  • 구조화 — 구조적 방법론 쪽 용어

풀이 요령: "캡·상·다·추" 네 글자 안에 없으면 답이다.

문제 32015 국가직 · 기출문제집 p.640~641

객체지향 프로그래밍의 특징 중, 상속 관계에서 상위 클래스에 정의된 메소드 호출에 대해 각 하위 클래스가 가지고 있는 고유한 방법으로 응답할 수 있도록 유연성을 제공하는 것은?

  1. 재사용성(reusability)
  2. 추상화(abstraction)
  3. 다형성(polymorphism)
  4. 캡슐화(encapsulation)

정답 ③ 다형성

키워드는 "같은 호출 → 클래스마다 다른 응답"이다. 이것이 다형성의 정의 그 자체다.

  1. 상위 클래스 Animal에 makeSound()가 정의되어 있다
  2. Dog와 Cat이 각각 이를 오버라이딩해 "멍멍", "야옹"으로 다르게 구현한다
  3. 상위 타입 변수로 호출해도 실제 객체에 맞는 메서드가 실행된다 → 다형성

비슷한 표현의 다른 기출: "같은 이름의 메시지를 다른 객체에 호출할 수 있는 특징", "하나의 함수 이름이 여러 목적으로 사용될 수 있는 것", "오버로딩·오버라이딩으로 구현되는 개념" — 전부 답은 다형성이다.

구조 다이어그램(structural diagram)에 해당하는 것으로 옳은 것은?

  1. 클래스 다이어그램
  2. 시퀀스 다이어그램
  3. 액티비티 다이어그램
  4. 유스케이스 다이어그램
해설 보기

정답 ① 클래스 다이어그램

판별 기준은 하나다 — "시간이나 순서가 등장하는가?" 등장하면 행위, 안 하면 구조다.

선택지분류이유
① 클래스구조클래스들이 어떻게 생기고 연결됐는지만 그림 (정적)
② 시퀀스행위시간 순서대로 메시지를 그림
③ 액티비티행위처리 흐름·절차를 그림
④ 유스케이스행위사용자와 시스템의 상호작용을 그림

구조 다이어그램 6개 암기: 클래스, 객체, 컴포지트구조, 배치, 컴포넌트, 패키지 — "클·객·컴·배·컴·패". 이 여섯 개 외에는 전부 행위 다이어그램이라고 봐도 시험에서는 무방하다.

문제 52023 지방직 · 기출문제집 p.648

다음에서 설명하는 UML 다이어그램은?
"객체들이 어떻게 상호 동작하는지를 메시지 순서에 초점을 맞춰 나타낸 것으로, 어떠한 작업이 객체 간에 발생하는지를 시간 순서에 따라 보여준다."

  1. 클래스(class) 다이어그램
  2. 순차(sequence) 다이어그램
  3. 배치(deployment) 다이어그램
  4. 패키지(package) 다이어그램
해설 보기

정답 ② 순차(시퀀스) 다이어그램

"시간 순서"라는 단어가 나오면 시퀀스다. 이름 자체가 sequence(순서)다.

  1. 세로 점선 = 각 객체의 생명선(lifeline), 위에서 아래로 갈수록 시간이 흐름
  2. 가로 화살표 = 객체 간 메시지 (실선=요청, 점선=반환)
  3. 따라서 "누가 → 누구에게 → 몇 번째로" 를 한눈에 볼 수 있다

비슷한 것과 구별: 커뮤니케이션(협력) 다이어그램도 객체 간 상호작용을 그리지만, 시간 순서가 아니라 객체들의 연결 관계를 중심으로 그린다. 문제에 "시간"이 들어가면 시퀀스, "관계"가 들어가면 커뮤니케이션이다.

문제 62015 지방직 · 기출문제집 p.644

디자인 패턴에 대한 설명으로 옳지 않은 것은?

  1. 일반적으로 디자인 패턴을 이용하면 좋은 설계나 아키텍처를 재사용하기 쉬워진다.
  2. 패턴은 사용 목적에 따라서 생성 패턴, 구조 패턴, 행위 패턴으로 분류할 수 있다.
  3. 생성 패턴은 빌더(builder), 추상 팩토리(abstract factory) 등을 포함한다.
  4. 행위 패턴은 가교(bridge), 적응자(adapter), 복합체(composite) 등을 포함한다.
해설 보기

정답 ④ — 가교·적응자·복합체는 구조 패턴이다

①②③은 모두 맞는 서술이고, ④만 분류가 바뀌어 있다.

  1. Bridge(가교), Adapter(적응자), Composite(복합체) → 전부 구조 패턴. 클래스·객체를 어떻게 조립·연결할지에 관한 패턴이다
  2. 행위 패턴은 객체들이 어떻게 상호작용하고 책임을 나눌지를 다룬다 → Observer, Strategy, Command, State, Iterator, Mediator, Memento, Visitor, Template Method 등

구분 요령: 패턴 이름이 "무엇을 연결/감싸는 물건"처럼 들리면(다리=Bridge, 어댑터=Adapter, 복합체=Composite, 대리인=Proxy, 정면=Facade) 거의 구조 패턴이다. 반대로 "행동을 묘사하는 말"이면(관찰자=Observer, 전략=Strategy, 명령=Command, 상태=State) 행위 패턴이다.

같이 나오는 함정: "구조 패턴에 해당하지 않는 것은?" → Template Method(행위 패턴)가 정답인 문제도 출제되었다.

문제 72018 국가직 · 기출문제집 p.645

개발자가 사용해야 하는 서브시스템의 가장 앞쪽에 위치하면서 서브시스템에 있는 객체들을 사용할 수 있도록 인터페이스 역할을 하는 디자인 패턴은?

  1. Facade 패턴
  2. Strategy 패턴
  3. Adapter 패턴
  4. Singleton 패턴
해설 보기

정답 ① Facade 패턴

Facade는 건물의 "정면(외관)"이라는 뜻이다. 복잡한 내부를 가리고 깔끔한 정문 하나만 보여주는 이미지로 기억하면 된다.

패턴역할기억법
Facade서브시스템 앞의 단일 창구. 복잡한 내부 관계를 몰라도 쓸 수 있게 함 → 의존관계·복잡성 감소건물 정문
Strategy알고리즘들을 캡슐화해 필요할 때 교체전략을 갈아끼움
Adapter기존 클래스의 인터페이스를 변환해 재사용110V→220V 변환 어댑터
Singleton객체를 딱 하나만 존재하게 보장single = 하나

Facade vs Adapter 구별: Facade는 "복잡한 여러 개를 하나로 단순화", Adapter는 "안 맞는 인터페이스를 맞게 변환"이다. 문제에 "서브시스템", "복잡성 감소", "단순화된 하나의 인터페이스"가 나오면 Facade다.

문제 8개념 확인 · 응용

다음 상황에 가장 알맞은 디자인 패턴을 각각 고르고, 그 분류(생성/구조/행위)를 답하시오.
(가) 프로그램 전체에서 설정 정보를 담는 객체가 여러 개 생기면 안 되는 상황
(나) 주식 가격이 바뀌면 그것을 구독 중인 여러 화면에 자동으로 알려주고 싶은 상황

해설 보기

정답: (가) Singleton — 생성 패턴 / (나) Observer — 행위 패턴

  1. (가) "객체가 하나만 있어야 한다" = 객체 생성을 통제하는 문제 → Singleton, 분류는 생성 패턴
  2. (나) "상태가 바뀌면 관련된 여러 객체에 통보" = 객체들 사이의 상호작용·책임 분배 문제 → Observer, 분류는 행위 패턴

분류를 가르는 질문 한 줄:

  • 문제가 "객체를 어떻게 만들까"이면 → 생성 패턴
  • 문제가 "객체들을 어떻게 조립·연결할까"이면 → 구조 패턴
  • 문제가 "객체들이 어떻게 주고받으며 일할까"이면 → 행위 패턴
