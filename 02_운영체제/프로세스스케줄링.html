프로세스 스케줄링

CPU를 어떤 프로세스에 언제 줄지 결정하는 방식 · PART 02. 운영체제론

핵심 요약

비선점(Non-preemptive) = FCFS, SJF, HRN — 한 번 CPU를 잡으면 끝날 때까지 안 뺏김

선점(Preemptive) = RR, SRT, MLQ, MFQ — 더 급한 프로세스가 오면 중간에 CPU를 뺏을 수 있음

💡주요 개념

스케줄링 평가 기준

기준의미
처리량 (Throughput)단위 시간당 완료되는 프로세스 수 — 클수록 좋음
대기 시간 (Waiting Time)준비 큐에서 CPU를 기다린 시간 — 작을수록 좋음
반환 시간 (Turnaround Time)도착부터 완료까지 전체 시간 (대기시간+실행시간) — 작을수록 좋음
응답 시간 (Response Time)도착부터 (처음 또는 완료까지) 반응이 오기까지 시간
CPU 이용률CPU가 놀지 않고 일한 시간의 비율 — 클수록 좋음

선점 vs 비선점 분류 ⭐ (매년 출제)

구분알고리즘
비선점 (Non-preemptive)FCFS, SJF(비선점), HRN(HRRN)
선점 (Preemptive)RR, SRT(=선점 SJF), MLQ, MFQ
함정 주의: "RR은 비선점 방식이다"는 틀린 설명 — RR은 대표적인 선점형이다.

FCFS (First Come First Served)

  • 도착한 순서대로 CPU를 할당하는 가장 단순한 비선점 방식
  • 구현이 쉽지만, 실행시간이 긴 프로세스가 먼저 오면 뒤 프로세스들이 오래 기다림
  • 일괄처리 시스템에는 효율적이나, 빠른 응답이 필요한 대화식 시스템에는 부적합
계산 예시 (2018 계리직): P1(도착0,실행2) P2(도착2,실행2) P3(도착3,실행3) P4(도착4,실행9)를 FCFS로 처리 → 응답시간(도착~완료) 각각 2, 2, 4, 12초 → 평균 응답시간 = (2+2+4+12)/4 = 5초

SJF (Shortest Job First) / SRT (Shortest Remaining Time)

  • SJF: 실행시간이 가장 짧은 작업부터 처리하는 비선점 방식 → 평균 대기시간이 이론상 최소
  • SRT: SJF의 선점(preemptive) 버전 — 새 프로세스가 도착할 때마다 "남은 실행시간"을 비교해서 더 짧은 쪽이 CPU를 뺏음
  • 실행시간이 긴 프로세스는 계속 밀려서 기아상태(Starvation)에 빠질 위험 있음
SJF 계산 예시 (2014 서울시): P1(0,6) P2(1,4) P3(2,1) P4(3,2) → 실행순서 P1→P3→P4→P2, 대기시간 합 0+4+4+8=16 → 평균 대기시간 = 16/4 = 4초

SRT 계산 예시 (2015 국가직): P1(0,8) P2(2,4) P3(4,1) P4(6,4) → 도착할 때마다 남은시간 비교해 재배정 → 평균 반환시간 = 7

RR (Round Robin)

  • 각 프로세스에게 동일한 시간 할당량(Time Slice/Quantum)만큼만 CPU를 주고, 다 쓰면 강제로 준비 큐 맨 뒤로 보냄
  • 대표적인 선점 방식, 시분할 시스템에 적합
  • Time Slice가 너무 크면 → FCFS와 동일해짐
  • Time Slice가 너무 작으면 → 문맥교환(Context Switching)이 잦아져 오버헤드 증가
  • 도착 순서대로 순환하므로 기아상태가 발생하지 않음

계산 방법: Quantum만큼 실행하다 다 못 끝내면 도착한 순서대로 준비 큐 맨 뒤에 다시 줄을 세운다. 타임라인을 시간 순서대로 손으로 따라가며 "지금 큐 맨 앞이 누구인지"만 계속 갱신하면 된다.

계산 예제 (2016 계리직, Quantum=2): P1(도착0,실행3) P2(도착1,실행4) P3(도착3,실행2) 📖 기출문제집 p.215
  1. t=0: P1 도착 → 준비큐가 비어있으므로 즉시 CPU 할당, 2초 실행(0~2)
  2. t=1: P2 도착 → 준비큐에서 대기 [P2]
  3. t=2: P1의 Quantum(2초) 소진, 잔여 1초 남음 → 준비큐 맨 뒤로 이동 [P1(잔여1)]. 큐 맨 앞 P2가 CPU 할당, 2초 실행(2~4)
  4. t=3: P3 도착 → 준비큐 맨 뒤에 추가 [P1(잔여1), P3]
  5. t=4: P2의 Quantum 소진, 잔여 2초 남음 → 준비큐 맨 뒤로 [P1(잔여1), P3, P2(잔여2)]. 큐 맨 앞 P1이 CPU 할당, 남은 1초 실행(4~5) → P1 완료(t=5)
  6. t=5: 큐 맨 앞 P3이 CPU 할당, 2초 실행(5~7) → P3 완료(t=7)
  7. t=7: 큐에 남은 P2(잔여2)가 CPU 할당, 2초 실행(7~9) → P2 완료(t=9)
  8. 이 문제의 "응답시간" = 도착~종료(반환시간과 동일하게 정의): P1=5−0=5, P2=9−1=8, P3=7−3=4 → 평균 = (5+8+4)/3 ≈ 5.7초

우선순위(Priority) 스케줄링

  • 프로세스의 상대적 중요도(우선순위)가 높은 것부터 CPU 할당
  • 선점/비선점 둘 다 구현 가능 (선점 방식으로만 되는 것 아님 — 자주 나오는 오답 함정)
  • 우선순위가 낮은 프로세스는 계속 밀려 기아상태 위험
  • 해결책: 노화(Aging) 기법 — 오래 기다린 프로세스의 우선순위를 점점 높여줌

HRN / HRRN (Highest Response-ratio Next)

SJF의 단점(긴 작업의 기아상태)을 보완한 비선점 방식. 대기시간이 길수록 우선순위가 올라가도록 만든 공식을 사용한다.

우선순위 공식: (대기시간 + 서비스시간) / 서비스시간 → 값이 클수록 먼저 처리
예시(2017 지방직): P1(대기10,서비스5)=3, P2(12,4)=4, P3(8,12)=1.67, P4(15,3)=6 → 값이 가장 큰 P4가 최우선

MLQ / MFQ (다단계 큐 / 다단계 피드백 큐)

구분설명
MLQ (Multilevel Queue)준비 큐를 우선순위별로 여러 개로 나누고, 각 큐마다 서로 다른 스케줄링 알고리즘을 쓸 수 있음
MFQ (Multilevel Feedback Queue)MLQ에서 한 단계 발전 — 프로세스가 CPU를 많이 쓸수록 하위 큐로 이동시켜, 입출력 위주/CPU 위주 프로세스에 서로 다른 시간 할당량을 준다 (하위 큐일수록 할당시간을 크게)

📌시험 빈출 포인트

  • 비선점 = FCFS·SJF·HRN(HRRN), 선점 = RR·SRT·MLQ·MFQ — 분류 문제 매년 출제
  • FCFS/SJF/RR/HRRN 각각에 대한 평균 대기시간·반환시간·응답시간 계산 문제 (간트차트 그려보는 게 핵심)
  • SRT = SJF의 선점 버전 (같은 원리, 선점 여부만 다름)
  • 기아상태 발생 가능: SJF, 우선순위 방식 / 기아상태 없음: FCFS, RR, HRRN
  • 기아상태 해결책 = Aging(노화) 또는 HRN 방식 적용
  • RR의 Time Slice가 너무 크면 FCFS와 동일, 너무 작으면 문맥교환 오버헤드 증가
  • 우선순위 스케줄링은 선점·비선점 둘 다 가능 ("항상 선점 방식"이라는 표현은 오답)
  • HRRN 공식: (대기시간+서비스시간)/서비스시간, 값이 클수록 우선
