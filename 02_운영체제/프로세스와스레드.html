프로세스와 스레드

프로세스 상태·PCB·메모리 영역·멀티스레딩 · PART 02. 운영체제론

핵심 요약

프로세스 = 실행 중인 프로그램. 스레드 = 프로세스 내에서 실행 흐름만 분리한 단위(경량 프로세스).

한 프로세스는 여러 스레드를 가질 수 있지만, 하나의 스레드가 여러 프로세스에 속할 수는 없다.

🎯이 단원을 왜 배우나

"프로그램"과 "프로세스"는 왜 다른 말인가

하드디스크에 저장된 game.exe는 그냥 파일이다. 아무 일도 하지 않는다. 이걸 더블클릭하면 OS가 메모리로 올리고, CPU 시간을 배정하고, 열린 파일 목록과 현재 실행 위치를 관리하기 시작한다. 이렇게 "살아 움직이는 상태"가 된 것이 프로세스다. 같은 game.exe를 세 번 실행하면 프로세스는 3개가 된다 — 프로그램은 하나인데 프로세스는 셋이다.

그런데 CPU는 하나뿐이니 프로세스 100개가 진짜로 동시에 달릴 수는 없다. OS는 아주 빠르게 번갈아 가며 실행시켜 동시에 도는 것처럼 보이게 한다. 이때 "지금 실행 중", "CPU를 기다리는 중", "디스크 읽기를 기다리는 중" 같은 상태를 구분해서 관리해야 하고, 프로세스를 바꿀 때마다 진행 상황을 어딘가에 저장해 둬야 한다. 그 저장소가 PCB, 저장하고 바꿔치는 작업이 문맥 교환이다.

스레드는 여기서 한 단계 더 나아간다. 크롬에서 탭 하나가 동영상을 재생하는 동안 다른 탭에서 스크롤이 되려면 실행 흐름이 여러 개여야 하는데, 그때마다 프로세스를 새로 만들면 메모리를 통째로 복사해야 해서 너무 무겁다. 그래서 "메모리는 같이 쓰고 실행 흐름만 여러 개"로 만든 것이 스레드다. 이 단원 문제의 절반은 "무엇을 공유하고 무엇을 따로 갖는가"를 묻는다.

💡주요 개념 — 프로세스

프로세스 상태 전이 📖 기출문제집 p.189~190

상태설명
생성 (New)사용자가 요청한 작업이 커널에 등록되어 커널 공간에 PCB가 만들어진 상태
준비 (Ready)기억장치 등 필요한 자원을 모두 할당받고, 오직 CPU(프로세서) 할당만 기다리는 상태. 준비 큐(ready queue)에 들어가 있다
실행 (Running)CPU를 할당받아 실제로 처리되는 상태
대기/블록 (Waiting/Blocked)입출력 완료·신호 수신 등 어떤 사건(event)이 일어나기를 기다리는 상태
종료 (Terminated)프로세스의 수행이 끝난 상태

"준비"와 "대기"를 헷갈리면 이 단원 절반을 틀린다

둘 다 "뭔가를 기다린다"라서 헷갈리지만, 기다리는 대상이 완전히 다르다.

  • 준비(Ready) = CPU만 기다린다. 다른 건 다 준비됐다. CPU만 주면 당장 달릴 수 있다.
  • 대기(Blocked) = CPU 말고 다른 것(디스크 읽기 완료, 키보드 입력 등)을 기다린다. 지금 CPU를 줘도 할 일이 없다.

그래서 스케줄러는 준비 큐만 쳐다본다. 대기 상태 프로세스는 아예 스케줄링 대상에서 제외된다 — CPU를 줘봤자 디스크를 기다리며 놀 테니까.

여기서 매년 나오는 함정이 파생된다: "대기 중이던 입출력이 완료되면 바로 실행 상태가 된다"? → 틀림. 입출력이 끝나면 "이제 CPU만 있으면 됨" 상태가 된 것이니 준비 상태로 가서 줄을 서야 한다. 그 뒤 스케줄러가 뽑아줘야(Dispatch) 실행된다.

상태 전이 용어 4가지

용어전이 방향의미
Dispatch준비 → 실행스케줄러가 준비 큐에서 하나를 골라 CPU를 할당
Block실행 → 대기지정된 시간 이전에 입출력 요청 등으로 스스로 CPU를 반납
Wake-up대기 → 준비기다리던 입출력·이벤트가 완료됨 (바로 실행 상태로 가는 것 아님!)
Time-out실행 → 준비할당된 시간(타임 슬라이스)을 다 씀, 또는 우선순위 높은 프로세스에 선점당함
화살표 방향 암기: 실행으로 들어가는 화살표는 Dispatch 하나뿐이다. 어떤 경로로 왔든 CPU를 받으려면 반드시 준비 상태를 거쳐 스케줄러의 선택을 받아야 한다. "대기 → 실행" 화살표는 상태 전이도에 존재하지 않는다.

프로세스 생성 4단계 📖 기출문제집 p.191

한 프로세스는 실행 중에 시스템 호출로 새 프로세스를 만들 수 있다. 만든 쪽이 부모, 만들어진 쪽이 자식이다. 생성 절차는 순서를 묻는 문제로 자주 나온다.

  1. 프로세스 식별자(PID) 할당 — 먼저 "이름"부터 정한다
  2. 주소 공간과 PCB 할당 — 살 집(메모리 영역)과 신상명세서(PCB) 자리를 확보
  3. PCB 초기화 — 신상명세서에 초기값을 채워 넣는다
  4. 스케줄링 큐(준비 리스트)에 연결 — 준비 상태가 되어 줄을 선다
순서 암기: "이름 짓고 → 집 마련하고 → 서류 작성하고 → 줄 선다". 준비 큐 연결이 항상 마지막이라는 것만 확실히 잡아도 선택지 대부분이 걸러진다.

문맥 교환 (Context Switching) 📖 기출문제집 p.193~195

  • CPU를 다른 프로세스로 넘길 때, 이전 프로세스의 상태(레지스터 등)를 저장하고 새 프로세스의 상태를 적재하는 작업
  • 이 과정 자체는 유용한 작업을 하지 않으므로 시스템 오버헤드가 된다
  • 같은 프로세스 안의 스레드 간 문맥교환이 서로 다른 프로세스 간 문맥교환보다 비용이 더 작다 (주소공간을 안 바꿔도 되므로)

왜 오버헤드인가 — 이사 비용으로 생각하기

문맥 교환은 책상 정리와 같다. A의 작업을 멈추고 B에게 책상을 내주려면, A가 펼쳐둔 자료(레지스터, PC, 스택 포인터)를 전부 상자에 담아 치우고(저장), B의 상자를 꺼내 다시 펼쳐야(적재) 한다. 이 정리 시간 동안에는 A도 B도 아무 일을 하지 못한다. 그래서 순수한 낭비, 즉 오버헤드다.

스레드 간 교환이 더 싼 이유도 같은 비유로 설명된다. 스레드는 같은 책상(주소 공간·코드·데이터)을 쓰기 때문에 책상을 통째로 비울 필요가 없다. 자기 노트(스택)와 펜 위치(레지스터·PC)만 바꾸면 된다.

시험 포인트: "문맥 교환이 반드시 발생하는 경우"를 묻는 문제가 있다. 답은 라운드 로빈에서 시간 할당량(time quantum)이 만료된 경우다 — 준비 큐가 비어 있지 않은 이상 그 프로세스는 무조건 내려오고 다른 프로세스가 올라간다. 반면 시스템 호출이나 인터럽트는 처리 후 같은 프로세스가 계속 실행될 수도 있어 "반드시"가 아니다.

PCB (Process Control Block) 📖 기출문제집 p.195

프로세스 관리의 핵심 데이터 구조로, 커널이 프로세스 실행·스케줄링·메모리 관리·파일 입출력 등 여러 상황에서 참조·갱신한다. 한마디로 프로세스의 신상명세서다.

좀비 프로세스 vs 고아 프로세스

구분의미
좀비 (Zombie)자식 프로세스가 실행은 종료했지만, 부모가 아직 종료 상태를 확인(회수)하지 않아 프로세스 목록에 남아있는 상태
고아 (Orphan)자식이 아직 실행 중인데 부모가 먼저 종료되어버린 상태

🗂️주요 개념 — 프로세스 메모리 영역

프로세스가 메모리를 할당받으면 용도에 따라 4개 구역으로 나뉜다. 어느 변수가 어디에 저장되는지를 뒤섞어 묻는 문제가 매년 나오므로, 아래 그림의 위치를 통째로 외우는 편이 빠르다.

영역저장 내용대표 예시
코드(Text)실행할 명령어 (CPU가 실행)컴파일된 함수 본체
데이터(Data)전역변수, 정적(static) 변수 — 실행 전 초기화됨int count = 0; (함수 밖)
스택(Stack)지역변수, 매개변수, 함수 복귀 주소, CPU 레지스터 내용 — LIFO 구조, 함수 호출마다 생성int a = 10; (함수 안)
힙(Heap)동적으로 할당되는 메모리, 주소가 커지는 방향으로 증가malloc(), new
함정 주의 (매년 출제): 전역변수 = 데이터 영역 (스택 아님). 지역변수·매개변수·복귀주소 = 스택 영역 (데이터 아님). 동적 할당 = 힙 (스택 아님). 이 세 쌍을 서로 바꿔치기한 선택지가 반복해서 나온다.
한 줄 암기: "전역은 데이터, 지역은 스택, 동적은 힙, 명령어는 코드" — 네 글자씩 리듬으로 외우면 시험장에서 바로 떠오른다.

🧵주요 개념 — 스레드와 멀티스레딩

스레드란? 📖 기출문제집 p.196

  • 프로세스에서 실행(제어)의 개념만 분리한 단위 → "경량 프로세스(Light-Weight Process)"
  • 같은 프로세스 내 스레드는 코드·데이터·힙·파일 등을 공유하지만, 스택과 레지스터(PC 포함)는 스레드마다 독립
  • 하나의 프로세스는 여러 스레드를 가질 수 있지만, 하나의 스레드가 여러 프로세스에 속할 수는 없다
방향 함정: "하나의 스레드 내에 여러 프로세스가 존재할 수 있다"(2014 서울시), "하나의 스레드는 여러 프로세스에 포함될 수 있다"(2019 국가직) — 둘 다 오답이다. 포함 관계는 언제나 프로세스 ⊃ 스레드 한 방향뿐이다.

스레드 간 공유 여부 📖 기출문제집 p.197

공유 O공유 X (스레드별 독립)
코드, 전역변수(데이터 영역), 힙, 파일, 프로세스 자원 전체레지스터, 프로그램 카운터(PC), 스택

왜 하필 스택과 PC만 따로인가

스레드는 "서로 다른 곳을 실행하는 흐름"이다. 그러려면 최소 두 가지가 각자 있어야 한다.

  • PC(프로그램 카운터): "나는 지금 코드 몇 번째 줄을 실행 중인가". 이게 공유되면 두 스레드가 같은 줄을 실행하게 되어 흐름이 하나로 합쳐져 버린다.
  • 스택: 함수 호출 기록과 지역변수. 공유하면 스레드 A가 호출한 함수의 지역변수를 스레드 B가 덮어써 값이 뒤섞인다.

반대로 코드·전역변수·힙은 공유해야 이득이다. 같은 프로그램이니 코드는 한 벌이면 충분하고, 데이터를 공유해야 스레드끼리 값을 빠르게 주고받을 수 있다. "각자 어디를 실행 중인지"에 관한 것만 따로, 나머지는 전부 공유"가 원칙이다.

멀티스레딩의 장점

  • 사용자 응답성 증가
  • 프로세스 생성보다 스레드 생성이 오버헤드가 적음 (자원 공유하므로)
  • 멀티프로세서 환경에서 스레드별로 다른 프로세서에서 병렬 수행 가능
  • 스레드 간 통신은 커널 개입이 필요 없어 프로세스 간 통신(IPC)보다 효율적
함정 주의: "한 스레드에 문제가 생겨도 전체 프로세스에 영향 없다"는 틀렸다 — 스레드들은 같은 프로세스 자원을 공유하므로 하나가 잘못되면 프로세스 전체에 영향을 줄 수 있다. 이것이 멀티스레딩의 대표적 단점이다(안정성 ↓).

스레드와 교착상태

교착상태는 프로세스 단위 자원 할당에서 발생하므로, 서로 다른 프로세스에 속한 스레드 간에도 교착상태가 발생할 수 있다 ("발생하지 않는다"는 틀린 설명). 자세한 내용은 임계영역과 교착상태 문서 참고.

📌시험 빈출 포인트

  • 준비 상태 = CPU 대기, 대기 상태 = 이벤트(입출력) 대기 — 절대 헷갈리면 안 됨
  • 대기 → 준비 → 실행 순서. "대기에서 바로 실행"은 항상 오답
  • Block / Wake-up / Dispatch / Time-out 4가지 상태 전이 용어 구분
  • 프로세스 생성 순서: 식별자 → 주소공간·PCB 할당 → PCB 초기화 → 준비 큐 연결(마지막)
  • 문맥교환은 오버헤드 — 같은 프로세스 내 스레드 간이 더 저렴, RR의 시간 할당량 만료 시 반드시 발생
  • PCB에 포함되지 않는 것 = 인터럽트 정보
  • 좀비 = 종료됐지만 회수 안 됨 / 고아 = 부모가 먼저 죽음
  • 메모리 4영역: 전역=데이터, 지역·매개변수·복귀주소=스택, 동적=힙, 명령어=코드
  • 스레드 공유(코드·데이터·힙) vs 비공유(스택·레지스터·PC) 구분
  • 프로세스 ⊃ 스레드 — 반대 방향 서술은 무조건 오답

문제 12021 지방직 · 기출문제집 p.189~190

프로세스(process)에 대한 설명으로 옳지 않은 것은?

  1. 실행 중인 프로그램이다.
  2. 프로그램 코드 외에도 현재의 활동 상태를 갖는다.
  3. 준비(ready) 상태는 입출력 완료 또는 신호의 수신 같은 사건(event)이 일어나기를 기다리는 상태이다.
  4. 호출한 함수의 반환 주소, 매개변수 등을 저장하기 위해 스택을 사용한다.
해설 보기

정답 ③

  1. ③에서 서술한 "입출력 완료나 신호 수신 같은 사건을 기다리는 상태"는 대기(waiting/blocked) 상태의 정의다
  2. 준비(ready) 상태는 다른 자원은 다 받았고 오직 CPU 할당만 기다리는 상태
  3. ①·②·④는 모두 맞는 설명이다 (특히 ④: 복귀주소·매개변수는 스택에 저장)

함정: 두 상태를 서로 바꿔 서술하는 것이 이 단원의 1번 단골 함정이다. "사건·이벤트·입출력"이라는 단어가 나오면 대기, "CPU·프로세서"가 나오면 준비로 즉시 매칭하자.

문제 22010 지방직 · 기출문제집 p.190~191

프로세스 상태(process state)에 대한 설명으로 옳은 것은?

  1. 종료상태(terminated)는 프로세스가 기억장치를 비롯한 모든 필요한 자원을 할당받은 상태에서 프로세서의 할당을 기다리고 있는 상태이다.
  2. 대기상태(waiting/blocked)는 프로세스가 원하는 자원을 할당받지 못해서 기다리고 있는 상태이다.
  3. 실행상태(running)는 사용자가 요청한 작업이 커널에 등록되어 커널 공간에 PCB 등이 만들어진 상태이다.
  4. 준비상태(ready)는 프로세스의 수행이 끝난 상태이다.
해설 보기

정답 ②

이 문제는 네 상태의 정의를 통째로 섞어 놓은 유형이다. 각 선택지가 실제로는 어느 상태의 설명인지 되짚어보면 답이 보인다.

  1. ① "자원 다 받고 프로세서 할당을 기다림" → 사실은 준비(ready) 상태의 정의
  2. ② "원하는 자원을 할당받지 못해 기다림" → 대기(blocked) 상태가 맞다 (정답)
  3. ③ "커널에 등록되어 PCB가 만들어진 상태" → 생성(new) 상태의 정의
  4. ④ "수행이 끝난 상태" → 종료(terminated) 상태의 정의

풀이 요령: 이런 "정의 뒤섞기" 문제는 선택지마다 "이건 원래 무슨 상태 설명이지?"를 적어가며 풀면 실수가 없다.

문제 32017 하반기 국가직 · 기출문제집 p.191

운영체제가 프로세스(process)를 생성하는 과정을 순서대로 바르게 나열한 것은?

  • ㄱ. 새로운 프로세스를 위한 프로세스 식별자를 할당한다.
  • ㄴ. 새로운 프로세스를 스케줄링 큐의 준비 또는 준비/보류 리스트에 연결한다.
  • ㄷ. 새로운 프로세스를 위한 주소 공간과 프로세스 제어블록(PCB)을 할당한다.
  • ㄹ. 새로운 프로세스의 프로세스 제어블록을 초기화한다.
  1. ㄱ → ㄴ → ㄷ → ㄹ
  2. ㄱ → ㄷ → ㄹ → ㄴ
  3. ㄷ → ㄹ → ㄱ → ㄴ
  4. ㄷ → ㄹ → ㄴ → ㄱ
해설 보기

정답 ② ㄱ → ㄷ → ㄹ → ㄴ

  1. ㄱ 식별자 할당 — 프로세스를 구분할 이름(PID)부터 정해야 이후 작업에서 그것을 지칭할 수 있다
  2. ㄷ 주소공간·PCB 할당 — 프로세스가 쓸 메모리 영역과 정보를 담을 PCB 자리를 확보
  3. ㄹ PCB 초기화 — 확보한 PCB에 초기값을 채워 넣음 (자리가 있어야 채울 수 있으므로 ㄷ 다음)
  4. ㄴ 준비 큐 연결 — 모든 준비가 끝났으니 준비 상태로 전이시켜 줄을 세운다

선택지 소거법: 준비 큐 연결(ㄴ)은 논리적으로 가장 마지막일 수밖에 없다. ㄴ이 끝에 없는 ①·④를 바로 지우면 ②·③만 남고, 식별자(ㄱ)가 먼저라는 것만 알면 ②가 답이다.

문제 42018 국회직 · 기출문제집 p.192

프로세스의 상태 변이에 대한 설명으로 옳지 않은 것은?

  1. 시간 할당량을 사용하는 우선순위 기반 스케줄링에서 실행 상태 프로세스의 시간 할당량이 소진되면, 커널에 의해 준비(ready) 상태로 전이된다.
  2. 실행 상태의 프로세스가 동기식 입출력 요청을 하면, 입출력이 완료될 때까지 CPU를 반납하고 대기 상태로 전이된다.
  3. 대기 상태의 프로세스가 요청하였던 입출력이 완료되면, 해당 프로세스는 CPU 연산이 가능해지므로 바로 실행 상태로 전이된다.
  4. 다중 처리기 시스템에서는 실행 상태의 프로세스가 여러 개 있을 수 있다.
  5. 대기 상태의 프로세스들은 CPU 할당을 위한 스케줄링에서 제외된다.
해설 보기

정답 ③

  1. 입출력이 완료되면 프로세스는 Wake-up 되어 준비(ready) 상태로 간다
  2. 준비 큐에서 기다리다가 스케줄러가 선택(Dispatch)해줘야 비로소 실행 상태가 된다
  3. 따라서 "바로 실행 상태로 전이"라고 한 ③이 틀렸다

왜 바로 못 가나: CPU는 지금 다른 프로세스가 쓰고 있을 수 있다. 입출력이 끝났다고 해서 남이 쓰던 CPU를 빼앗을 권리가 생기는 게 아니므로, 줄(준비 큐)을 서는 것이 원칙이다.

참고: ④도 맞는 설명이다 — CPU(처리기)가 여러 개면 실행 상태 프로세스도 그 수만큼 존재할 수 있다. 헷갈려서 ④를 고르지 않도록 주의.

문제 52019 지방직 · 기출문제집 p.193

프로세스 상태 전이에서 준비(Ready) 상태로 전이되는 상황만을 모두 고르면? (단, 동일한 우선순위의 프로세스가 준비 상태로 한 개 이상 대기하고 있다)

  • ㄱ. 실행 상태에 있는 프로세스가 우선순위가 높은 프로세스에 의해 선점되었을 때
  • ㄴ. 블록된(Blocked) 상태에 있는 프로세스가 요청한 입출력 작업이 완료되었을 때
  • ㄷ. 실행 상태에 있는 프로세스가 작업을 마치지 못하고 시간 할당량을 다 썼을 때
  1. ㄱ, ㄴ
  2. ㄱ, ㄷ
  3. ㄴ, ㄷ
  4. ㄱ, ㄴ, ㄷ
해설 보기

정답 ④ ㄱ, ㄴ, ㄷ 전부

  1. ㄱ 우선순위 높은 프로세스에 선점당함 → 실행 → 준비 (Preemption) ✔
  2. ㄴ 입출력 완료 → 대기 → 준비 (Wake-up) ✔ — 실행이 아니라 준비로 간다는 것이 핵심
  3. ㄷ 시간 할당량 소진 → 실행 → 준비 (Time Run-out) ✔
  4. 세 경우 모두 준비 상태로 가므로 전부 정답

정리: 준비 상태로 들어오는 화살표는 세 방향이다 — 생성에서(admit), 실행에서(time-out·선점), 대기에서(wake-up). 반대로 준비에서 나가는 화살표는 Dispatch 하나뿐이다.

문제 62024 법원직 · 기출문제집 p.195

다음에서 문맥 교환(Context switch)이 반드시 발생하는 경우는? (단, CPU 대기 큐(Ready queue)는 비어있지 않다고 가정한다)

  1. 프로세서가 요청한 I/O가 완료되어 인터럽트가 발생한 경우
  2. 라운드 로빈(Round Robin) 방식으로 CPU 스케줄링을 하는 시스템에서 프로세스의 CPU 할당시간(Time quantum)이 만료되었음을 알려주는 인터럽트가 발생한 경우
  3. 프로세스가 시스템콜(System call)을 하는 경우
  4. 다중 쓰레드로 구성된 프로세스 내에서 쓰레드 중 하나가 I/O 요청을 하는 경우
해설 보기

정답 ②

핵심은 "반드시"라는 단어다. 각 경우에 안 바뀔 수도 있는지를 따져보면 된다.

  1. ② 라운드 로빈에서 시간 할당량이 끝나면 그 프로세스는 규칙상 무조건 CPU를 내려놓고 준비 큐 뒤로 간다. 준비 큐가 비어있지 않으므로 다른 프로세스가 반드시 올라온다 → 문맥 교환 확정 (정답)
  2. ① I/O 완료 인터럽트는 대기 중이던 다른 프로세스를 준비 상태로 깨울 뿐, 현재 실행 중인 프로세스는 계속 실행될 수 있다 → 반드시는 아님
  3. ③ 시스템 호출은 커널 모드로 모드 전환(mode switch)이 일어날 뿐, 프로세스가 바뀌는 문맥 교환과는 다르다 → 반드시는 아님
  4. ④ 스레드 하나가 I/O를 요청해도 같은 프로세스의 다른 스레드가 계속 실행될 수 있다 → 반드시는 아님

함정: ③의 모드 전환(mode switch)과 문맥 교환(context switch)은 다른 개념이다. 모드 전환은 같은 프로세스가 사용자 모드↔커널 모드를 오가는 것이고, 문맥 교환은 실행 주체가 다른 프로세스로 바뀌는 것이다.

문제 72022 국가직 · 기출문제집 p.195

운영체제에서 프로세스의 정보를 관리하는 프로세스 제어블록(PCB)의 포함 요소로 옳지 않은 것은?

  2. 인터럽트 정보

  4. 프로세스의 상태
해설 보기

정답 ② 인터럽트 정보

  2. 인터럽트는 하드웨어나 커널이 처리하는 시스템 전체 차원의 사건이지 특정 프로세스의 신상정보가 아니다 → PCB 항목이 아님

판별 기준: "이 프로세스만의 정보인가?"를 물어보면 된다. PID·상태·우선순위·PC값·페이지테이블 주소·열린 파일 목록은 전부 프로세스마다 다르지만, 인터럽트 처리 정보는 프로세스마다 다른 값이 아니다.

문제 82019 국가직 · 기출문제집 p.196

프로세스와 스레드(thread)에 대한 설명으로 옳지 않은 것은?

  2. 스레드는 프로세스에서 제어를 분리한 실행단위이다.

해설 보기

정답 ①

  1. 포함 관계는 프로세스 1개 ⊃ 스레드 여러 개 한 방향뿐이다
  2. 스레드는 프로세스의 주소 공간 안에서 만들어진 실행 흐름이므로, 두 프로세스에 걸칠 수 없다

  • ㄴ. 프로그램 코드는 텍스트(text) 영역에 적재된다.
  • ㄷ. 힙(heap) 영역은 프로세스 실행 중 동적으로 할당된 메모리이다.
  • ㄹ. 함수의 매개변수, 복귀 주소 및 지역변수는 데이터(data) 영역에 할당된다.
  1. ㄱ, ㄴ
  2. ㄱ, ㄹ
  3. ㄴ, ㄷ
  4. ㄷ, ㄹ
해설 보기

정답 ③ ㄴ, ㄷ

  1. ㄱ 틀림: 전역 변수는 스택이 아니라 데이터(data) 영역에 할당된다
  2. ㄴ 맞음: 프로그램 코드(명령어)는 텍스트(코드) 영역에 적재된다
  3. ㄷ 맞음: 힙은 실행 중 malloc/new로 동적 할당되는 영역
  4. ㄹ 틀림: 매개변수·복귀주소·지역변수는 데이터가 아니라 스택(stack) 영역이다

함정 구조: ㄱ과 ㄹ은 데이터와 스택을 정확히 맞바꿔 놓은 전형적 오답이다. "전역=데이터, 지역=스택"만 확실하면 두 개가 동시에 걸러진다.

문제 102022 계리직 · 기출문제집 p.198~199

운영체제 상의 프로세스(process)에 관한 설명으로 옳지 않은 것은?

  1. 프로세스의 영역 중 스택 영역은 동적 메모리 할당에 활용된다.
  2. 디스패치(dispatch)는 CPU 스케줄러가 준비 상태의 프로세스 중 하나를 골라 실행 상태로 바꾸는 작업을 말한다.
  3. 프로세스 제어 블록은 프로세스 식별자, 메모리 관련 정보, 프로세스가 사용했던 중간값을 포함한다.
  4. 문맥교환은 CPU를 점유하고 있는 프로세스를 CPU에서 내보내고 새로운 프로세스를 받아들이는 작업이다.
해설 보기

정답 ①

  1. 동적 메모리 할당에 쓰이는 영역은 스택이 아니라 힙(heap)이다
  2. 스택은 함수 호출과 관련된 지역변수·매개변수·복귀주소를 담으며, 함수가 끝나면 자동으로 정리된다(자동 할당)
  3. ②·③·④는 모두 맞는 설명 — 디스패치·PCB 구성요소·문맥교환의 정의가 정확하다

구분 요령: 자동으로 생기고 사라지면 스택, 프로그래머가 직접 요청하고 해제하면 힙이다. "동적(dynamic)"이라는 단어가 보이면 거의 항상 힙을 가리킨다.
