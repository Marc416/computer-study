프로세스와 스레드

프로세스 상태·PCB·메모리 영역·멀티스레딩 · PART 02. 운영체제론

핵심 요약

프로세스 = 실행 중인 프로그램. 스레드 = 프로세스 내에서 실행 흐름만 분리한 단위(경량 프로세스).

한 프로세스는 여러 스레드를 가질 수 있지만, 하나의 스레드가 여러 프로세스에 속할 수는 없다.

💡주요 개념 — 프로세스

프로세스 상태 전이 📖 기출문제집 p.189

상태설명
생성 (New)작업이 커널에 등록되어 PCB가 만들어짐
준비 (Ready)모든 자원을 할당받고 CPU 할당만 기다리는 상태
실행 (Running)CPU를 할당받아 실제로 처리되는 상태
대기/블록 (Waiting/Blocked)입출력 등 이벤트가 일어나기를 기다리는 상태
종료 (Terminated)수행이 끝난 상태
함정 주의: "준비 상태는 입출력 완료 같은 사건을 기다리는 상태"는 틀렸다 — 그건 대기 상태다. 준비 상태는 오직 CPU 할당을 기다린다.

상태 전이 용어

용어전이 방향의미
Dispatch준비 → 실행스케줄러가 CPU를 할당
Block (Time-out 아님)실행 → 대기입출력 요청 등으로 CPU 반납
Wake-up대기 → 준비기다리던 입출력·이벤트가 완료됨 (바로 실행 상태로 가는 것 아님!)
Time-out실행 → 준비할당된 시간(타임 슬라이스)을 다 씀
함정 주의: 대기 상태의 프로세스가 입출력을 완료하면 준비 상태로 갔다가 스케줄링을 거쳐 실행 상태가 된다 — "바로 실행 상태로 전이"는 틀린 설명이다.

문맥 교환 (Context Switching)

  • CPU를 다른 프로세스로 넘길 때, 이전 프로세스의 상태(레지스터 등)를 저장하고 새 프로세스의 상태를 적재하는 작업
  • 이 과정 자체는 유용한 작업을 하지 않으므로 시스템 오버헤드가 된다
  • 같은 프로세스 안의 스레드 간 문맥교환이 서로 다른 프로세스 간 문맥교환보다 비용이 더 작다 (주소공간을 안 바꿔도 되므로)

PCB (Process Control Block)

프로세스 관리의 핵심 데이터 구조로, 커널이 프로세스 실행·스케줄링을 위해 참조·갱신한다.

  • 프로세스 식별자(PID), 부모프로세스 식별자(PPID)
  • 프로세스 상태, 프로세스 컨텍스트(PC·SP·범용 레지스터)
  • 스케줄링 정보(우선순위, CPU 사용시간)
  • 메모리 관리 정보(페이지 테이블 주소 등), 오픈 파일 테이블, 종료 코드

좀비 프로세스 vs 고아 프로세스

구분의미
좀비 (Zombie)자식 프로세스가 실행은 종료했지만, 부모가 아직 종료 상태를 확인(회수)하지 않아 프로세스 목록에 남아있는 상태
고아 (Orphan)자식이 아직 실행 중인데 부모가 먼저 종료되어버린 상태

🗂️주요 개념 — 프로세스 메모리 영역

영역저장 내용
코드(Text)실행할 명령어 (CPU가 실행)
데이터(Data)전역변수, 정적(static) 변수 — 실행 전 초기화됨
스택(Stack)지역변수, 매개변수, 함수 복귀 주소, CPU 레지스터 내용 — LIFO 구조, 함수 호출마다 생성
힙(Heap)동적으로 할당되는 메모리 (malloc/new 등)
함정 주의: 전역변수 = 데이터 영역 (스택 아님). 지역변수·매개변수·복귀주소 = 스택 영역 (데이터 아님). 동적 할당 = 힙 (스택 아님). 시험에서 이 4가지를 뒤섞어서 출제한다.

🧵주요 개념 — 스레드와 멀티스레딩

스레드란?

  • 프로세스에서 실행(제어)의 개념만 분리한 단위 → "경량 프로세스(Light-Weight Process)"
  • 같은 프로세스 내 스레드는 코드·데이터·힙·파일 등을 공유하지만, 스택과 레지스터(PC 포함)는 스레드마다 독립
  • 하나의 스레드는 하나의 프로세스에만 속할 수 있다 (여러 프로세스에 걸칠 수 없음)

스레드 간 공유 여부 📖 기출문제집 p.197

공유 O공유 X (스레드별 독립)
코드, 전역변수(데이터 영역), 힙, 파일, 프로세스 자원 전체레지스터, 프로그램 카운터(PC), 스택

멀티스레딩의 장점

  • 사용자 응답성 증가
  • 프로세스 생성보다 스레드 생성이 오버헤드가 적음 (자원 공유하므로)
  • 멀티프로세서 환경에서 스레드별로 다른 프로세서에서 병렬 수행 가능
  • 스레드 간 통신은 커널 개입이 필요 없어 프로세스 간 통신(IPC)보다 효율적
함정 주의: "한 스레드에 문제가 생겨도 전체 프로세스에 영향 없다"는 틀렸다 — 스레드들은 같은 프로세스 자원을 공유하므로 하나가 잘못되면 프로세스 전체에 영향을 줄 수 있다.

스레드와 교착상태

교착상태는 프로세스 단위 자원 할당에서 발생하므로, 서로 다른 프로세스에 속한 스레드 간에도 교착상태가 발생할 수 있다 ("발생하지 않는다"는 틀린 설명).

📌시험 빈출 포인트

  • 준비 상태 = CPU 대기, 대기 상태 = 이벤트(입출력) 대기 — 절대 헷갈리면 안 됨
  • Block/Wake-up/Dispatch/Time-out 4가지 상태 전이 용어 구분
  • 문맥교환은 오버헤드 — 같은 프로세스 내 스레드 간이 더 저렴
  • PCB에 포함되지 않는 것 찾기 유형 (인터럽트 자체 정보는 PCB 항목이 아님)
  • 좀비 = 종료됐지만 회수 안 됨 / 고아 = 부모가 먼저 죽음
  • 메모리 4영역(코드/데이터/스택/힙)에 무엇이 저장되는지 뒤섞어 묻는 문제 매년 출제
  • 스레드 공유 자원(코드·데이터·힙) vs 비공유 자원(스택·레지스터·PC) 구분
  • 다른 프로세스의 스레드 간에도 교착상태 발생 가능
