임계영역과 교착상태

상호배제·세마포어·교착상태 4조건과 해결법 · PART 02. 운영체제론

핵심 요약

임계영역 문제 해결의 3조건: 상호배제·진행·한정대기. 세마포어(P/V 연산)로 이를 구현한다.

교착상태는 상호배제·점유와대기·비선점·순환대기 4가지 조건을 모두 만족해야 발생한다 — 예방은 이 중 하나(상호배제 제외)를 부정하는 것.

🔒주요 개념 — 임계영역과 상호배제

임계영역(Critical Section)이란?

둘 이상의 프로세스가 동시에 접근하면 안 되는 공유자원(임계자원)을 이용하는 프로그램 코드 부분. 한 프로세스가 임계영역에서 실행 중이면 다른 프로세스는 진입할 수 없고, 그 시점에는 공유데이터의 읽기·쓰기가 불가능하다.

임계영역 문제 해결의 3가지 필수 조건

조건의미
상호 배제 (Mutual Exclusion)한 프로세스가 임계영역에 있으면 다른 프로세스는 진입 불가
진행 (Progress)임계영역이 비어있을 때, 누가 들어갈지는 무한정 연기되지 않고 유한 시간 내 결정되어야 함
한정 대기 (Bounded Waiting)진입 요청 후 허용될 때까지, 다른 프로세스가 먼저 진입하는 횟수에 한계가 있어야 함
함정 주의: 해결책은 프로세스의 수행 속도에 대해 어떤 가정도 하면 안 된다 (속도와 무관하게 항상 일정한 결과가 보장돼야 함).

세마포어 (Semaphore)

  • 다익스트라(Dijkstra)가 제안한 동기화 도구, 정수형 공유 변수(counter)와 P·V 연산으로 정의
  • P 연산(wait): counter를 1 감소, 자원 사용 허가를 기다리며 임계영역에 진입하는 연산
  • V 연산(signal): counter를 1 증가, 자원 사용을 마치고 임계영역에서 나오며 대기 중인 프로세스를 깨움
  • 종류: 이진(binary) 세마포어 (0/1만 가짐), 계수형(counting) 세마포어 (여러 개 자원 관리)
  • 세마포어 연산 자체는 수행 중 인터럽트되지 않는다 (원자적 연산)
함정 주의: "P연산=signal, V연산=wait"처럼 뒤바꿔 내는 문제 주의. P=wait=진입, V=signal=탈출. 또한 세마포어 구현 시 바쁜 대기(busy waiting)는 CPU 시간을 낭비하는 단점이 있다 (장점 아님).

모니터(Monitor)

공유자원을 내부적으로 숨기고 접근을 위한 인터페이스만 제공하여, 자원을 보호하고 프로세스 간 동기화를 자동으로 처리하는 고수준 동기화 도구.

🔗주요 개념 — 교착상태(Deadlock)

교착상태 발생 4대 필요조건 (모두 만족해야 발생) 📖 기출문제집 p.231

조건의미
상호 배제 (Mutual Exclusion)한 번에 한 프로세스만 자원 사용 가능
점유와 대기 (Hold and Wait)자원을 가진 채로 다른 자원을 요청하며 대기
비선점 (Non-preemption)자원을 강제로 빼앗을 수 없음 — 점유 프로세스가 끝나야 해제
순환 대기 (Circular Wait)프로세스들이 원형으로 서로 상대의 자원을 요청
함정 주의: "조건 중 하나만 만족해도 발생한다"는 틀렸다 — 4가지를 모두 만족해야 교착상태가 발생한다. 또한 이 4조건은 "비환형 대기"가 아니라 "순환(환형) 대기"가 맞는 조건 이름이다.

교착상태 처리 방법 4가지

방법전략구체적 기법
예방 (Prevention)4조건 중 상호배제를 제외한 하나를 부정 → 발생 가능성을 원천 차단점유대기 부정(자원 일괄할당), 비선점 부정(자원 강제회수), 순환대기 부정(자원에 고유번호 부여, 오름차순으로만 요청)
회피 (Avoidance)발생 가능성은 인정하되, 안전 상태를 유지하도록 자원 할당을 통제은행원(banker's) 알고리즘
탐지/발견 (Detection)발생을 허용한 뒤 자원 할당 그래프의 사이클 등으로 탐지자원할당그래프 사이클 검사
회복 (Recovery)탐지된 교착상태 관련 프로세스·자원을 제거/철회프로세스 강제 종료, 자원 선점
함정 주의: 상호배제는 예방 대상에서 제외 — 상호배제 자체를 부정하면 임계영역 보호가 무너지므로 교착상태 예방 방법으로 쓸 수 없다.

은행원(Banker's) 알고리즘 — 교착상태 회피

  • 자원 요청이 들어오면, 일단 할당했다고 가정(시뮬레이션)하고 안전 상태(safe state)가 유지되는지 검사
  • 안전하면 할당, 불안전(unsafe) 상태가 될 것 같으면 할당을 거부(대기)
  • 회피(avoidance) 알고리즘이지 회복(recovery) 알고리즘이 아님
함정 주의: "불안전 상태는 항상 교착상태로 빠진다"는 틀렸다 — 불안전 상태는 교착상태로 빠질 가능성이 있을 뿐, 반드시 빠지는 것은 아니다.

기타 관련 문제

  • 가변분할 메모리의 외부 단편화는 통합(coalescing)·압축(compaction)으로 해결 (교착상태와는 별개 문제, 짝지어 나오는 문제 주의)
  • 자원형이 1개, 자원 수 R, 프로세스 수 P, 프로세스당 최대 요구자원 수 k일 때 교착상태를 근본적으로 방지하는 조건: R ≥ (k-1) × P + 1

📌시험 빈출 포인트

  • 임계영역 해결 3조건: 상호배제·진행·한정대기 (순서·이름 정확히 암기)
  • 세마포어 P(wait)=진입/감소, V(signal)=탈출/증가 — 뒤바꿔 내는 문제 많음
  • 교착상태 4조건은 모두 만족해야 발생 (하나만 만족 X)
  • 예방(prevention)은 상호배제 제외한 3조건 중 하나를 부정
  • 은행원 알고리즘 = 회피(avoidance), 회복(recovery) 아님
  • 자원에 고유번호를 매겨 오름차순으로만 요청하게 하는 것 = 순환대기 조건의 부정
  • 바쁜 대기(busy waiting)는 세마포어의 단점 (CPU 시간 낭비)
