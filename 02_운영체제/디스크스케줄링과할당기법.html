디스크 스케줄링과 할당 기법

헤드 이동을 최소화하는 스케줄링과 파일을 블록에 배치하는 방법 · PART 02. 운영체제론

핵심 요약

디스크 스케줄링은 헤드가 어떤 순서로 요청을 처리할지 정하는 것(FCFS·SSTF·SCAN·C-SCAN·LOOK·C-LOOK).

디스크 할당은 파일을 디스크 블록에 어떻게 배치할지 정하는 것(연속·연결·색인 할당).

🎯이 단원을 왜 배우나

"디스크는 느리다"가 아니라 "디스크는 움직여야 해서 느리다"

메모리(RAM)는 전기 신호만 보내면 나노초 단위로 데이터가 나온다. 그런데 하드디스크는 금속 팔(헤드)이 물리적으로 움직여서 원하는 트랙까지 가야 한다. 이 이동에 걸리는 시간이 밀리초(ms) 단위 — RAM보다 약 10만 배 느리다. 그래서 디스크 성능에서 "데이터를 읽는 시간"은 거의 무시해도 되고, "헤드가 얼마나 돌아다녔는가"가 사실상 전부다.

여기서 운영체제가 개입할 여지가 생긴다. 여러 프로그램이 동시에 디스크를 요청하면 요청들이 큐에 쌓이는데, 이 요청들을 어떤 순서로 처리하느냐에 따라 헤드의 총 이동거리가 몇 배씩 차이난다. 아래에서 보겠지만 같은 요청 집합인데도 FCFS는 430, LOOK은 190으로 2배 이상 벌어진다. 순서만 바꿨는데 디스크가 2배 빨라지는 셈이다.

뒷부분의 디스크 할당 기법은 한 단계 앞의 문제다 — "애초에 파일을 디스크 어디에 놓을 것인가". 파일 조각들을 흩어놓으면 읽을 때마다 헤드가 멀리 뛰어야 하고, 붙여놓으면 빠르지만 빈 공간을 찾기 어려워진다. 이 트레이드오프가 연속·연결·색인 할당의 차이를 만든다.

시험 출제 패턴은 딱 두 가지다: ① 요청 큐를 주고 처리 순서 또는 총 이동거리를 계산시키기, ② 기법 이름과 설명을 서로 바꿔치기한 선택지 찾기. 계산은 규칙만 알면 기계적이고, 바꿔치기는 아래 비교표를 외우면 잡힌다.

💿먼저 알아야 할 것 — 디스크의 물리적 구조

디스크는 접시(플래터)가 회전하고 그 위를 팔(암)에 달린 헤드가 안팎으로 이동하는 구조다. 같은 반지름에 있는 원형 경로가 트랙(track)이고, 트랙을 부채꼴로 자른 것이 섹터(sector)다. 여러 장의 플래터에서 같은 번호 트랙들을 세로로 묶으면 실린더(cylinder)가 된다.

왜 트랙 번호 차이가 곧 "이동거리"인가: 트랙은 안에서 밖으로 번호가 매겨져 있고 간격이 일정하다. 그래서 트랙 50에서 트랙 80으로 가는 비용은 |80 − 50| = 30으로 계산한다. 시험의 모든 계산 문제가 이 뺄셈의 반복이다.

💡주요 개념 — 디스크 스케줄링

디스크 스케줄링 기법 비교 📖 기출문제집 p.262~266

기법동작 방식
FCFS요청 도착 순서대로 처리. 공평하지만 성능은 가장 좋지 않음
SSTF현재 헤드 위치에서 가장 가까운 트랙부터 처리 (방향 무관). 특정 요청이 계속 밀리는 기아현상 가능
SCAN한쪽 끝까지 이동하며 만나는 요청 모두 처리 → 반대로 방향 바꿔 왕복
C-SCANSCAN처럼 이동하되 한쪽 방향으로만 서비스, 끝에 도달하면 서비스 없이 반대쪽 끝으로 되돌아가 다시 그 방향으로만 처리
LOOKSCAN과 비슷하지만 맨 끝(0번/최대트랙)까지 가지 않고 마지막 요청에서 방향 전환
C-LOOKC-SCAN처럼 한쪽으로만 서비스하되, 맨 끝까지 가지 않고 마지막 요청에서 바로 반대쪽 시작점으로 복귀
N-Step-SCANSCAN의 변형. 스케줄링 시작 시점의 큐만 처리하고, 처리 중 새로 도착한 요청은 다음 회차 큐로 미룸 (기아 방지)
섹터 큐잉(Sector Queuing)고정 헤드 장치용. 헤드 이동이 없으므로 회전 지연시간을 기준으로 스케줄링
비유: SCAN·LOOK은 "엘리베이터"처럼 양방향 왕복 운행, C-SCAN·C-LOOK은 "지하철 순환선"처럼 한 방향으로만 돌고 반대편으로 순간이동해 다시 그 방향으로만 돈다.

이름 4개를 구조로 외우는 법

SCAN·C-SCAN·LOOK·C-LOOK은 독립된 4개가 아니라 2×2 조합이다. 두 개의 질문에 각각 예/아니오로 답하면 이름이 결정된다.

  • 질문 1 — "C"가 붙었나? → 붙었으면 한 방향으로만 서비스(Circular, 순환선). 안 붙었으면 왕복하며 양방향 서비스.
  • 질문 2 — "LOOK"인가 "SCAN"인가? → LOOK은 마지막 요청까지만 가고 돌아선다("가보고(look) 요청 없으면 안 감"). SCAN은 디스크 끝(0번/최대번호)까지 무조건 간다.

그래서 C-LOOK = 한 방향 + 끝까지 안 감이 되고, 네 기법 중 보통 이동거리가 가장 짧은 축에 속한다. 반대로 C-SCAN은 한 방향 규칙에 더해 양 끝까지 왕복하므로 손해가 크다.

같은 요청 큐를 6가지 기법으로 처리해보기 📖 기출문제집 p.263

아래는 모두 같은 조건(헤드 위치 50, 요청 큐 80·20·100·30·70·130·40, 디스크 범위 0~150, 초기 이동 방향은 큰 번호 쪽)에서 여섯 기법이 각각 어떻게 움직이는지를 그린 것이다. 세로 방향이 시간(처리 순서), 가로 방향이 트랙 번호다. 선이 가로로 길게 튈수록 손해다.

기법처리 순서총 이동거리
FCFS80→20→100→30→70→130→40430
SSTF40→30→20→70→80→100→130140
SCAN70→80→100→130→(150)→40→30→20230
C-SCAN70→80→100→130→(150)→(0)→20→30→40290
LOOK70→80→100→130→40→30→20190
C-LOOK70→80→100→130→20→30→40210
주의: 위 순위는 이 요청 집합에서만 그렇다. "SSTF가 항상 최적"이라거나 "LOOK이 항상 1등"이라는 문장은 오답이다. 다만 "FCFS가 성능이 가장 좋다"는 항상 틀린 문장이므로 이건 그대로 외워도 된다.

SSTF 계산 방법: 매 순간 "지금 헤드 위치에서 남은 요청 중 가장 가까운 트랙이 어디인가"만 반복해서 확인하면 된다. 방향은 상관없이 오직 거리만 비교한다.

SSTF 계산 예제 (2022 국가직): 헤드 위치 50, 요청 큐 = 80,20,100,30,70,130,40 📖 기출문제집 p.263
  1. 현재 50 → 남은 요청 중 가장 가까운 트랙은 40 (거리 10) → 이동
  2. 현재 40 → 가장 가까운 트랙은 30 (거리 10) → 이동
  3. 현재 30 → 가장 가까운 트랙은 20 (거리 10) → 이동
  4. 현재 20 → 남은 건 80,100,70,130뿐, 가장 가까운 트랙은 70 (거리 50) → 이동
  5. 현재 70 → 가장 가까운 트랙은 80 (거리 10) → 이동
  6. 현재 80 → 가장 가까운 트랙은 100 (거리 20) → 이동
  7. 현재 100 → 마지막 남은 130 (거리 30) → 이동
  8. 총 이동 거리 = 10+10+10+50+10+20+30 = 140
C-LOOK 계산 예제 (2014 서울시): 헤드 50, 이동방향 0→199, 큐 = 65,112,40,16,90,170,165,35,180 📖 기출문제집 p.265
  1. 요청을 정렬한다: 16, 35, 40, 65, 90, 112, 165, 170, 180
  2. 방향이 증가 쪽이므로 50보다 큰 것을 오름차순으로 먼저: 65 → 90 → 112 → 165 → 170 → 180
  3. 여기까지 거리: (180 − 50) = 130  (중간에 되돌아가지 않고 쭉 올라가므로 끝점−시작점으로 한 번에 계산해도 된다)
  4. C-LOOK이므로 199까지 가지 않고, 남은 요청 중 가장 작은 16으로 곧장 복귀: 180 → 16 = 164
  5. 다시 증가 방향으로: 16 → 35 → 40, 거리 = (40 − 16) = 24
  6. 총 이동거리 = 130 + 164 + 24 = 318

계산을 빠르게 하는 요령

SCAN 계열(SCAN·C-SCAN·LOOK·C-LOOK)은 한 방향으로 쭉 가는 구간 안에서는 개별 거리를 더할 필요가 없다. 그 구간의 끝 − 시작만 계산하면 된다. 위 예제에서 50→65→90→112→165→170→180을 하나씩 더하면 15+25+22+53+5+10인데, 그냥 180−50=130으로 끝난다.

그래서 SCAN 계열 문제는 "방향 전환점이 몇 개인가"만 파악하면 뺄셈 2~3번으로 답이 나온다. 반면 SSTF와 FCFS는 반드시 한 칸씩 더해야 한다 — 방향이 제멋대로 바뀌기 때문이다.

함정 주의: "N-Step-SCAN이 한 방향으로 움직이는 요구만 처리" 같은 설명은 사실 C-SCAN의 특징을 잘못 붙인 오답 패턴이다. 기법 이름과 설명을 서로 바꿔치기한 선택지에 주의.

🗄️주요 개념 — 디스크 할당 기법

데이터 단위 계층 📖 기출문제집 p.267

필드 < 레코드 < 파일 < 데이터베이스 (필드의 집합=레코드, 레코드의 집합=파일, 파일의 집합=데이터베이스)

비유: 학생부에서 "이름" 칸 하나가 필드, 학생 한 명의 줄 전체가 레코드, 반 전체 명단이 파일, 학교 전체 명단 모음이 데이터베이스다.

📌시험 빈출 포인트

  • SSTF·C-SCAN·C-LOOK 등 주어진 요청 큐로 헤드 이동 순서·총 이동거리 계산 문제 매년 출제
  • SCAN vs C-SCAN vs LOOK vs C-LOOK 이름과 설명 짝짓기 문제 (설명을 서로 바꿔서 오답 유도)
  • "FCFS가 가장 성능이 좋다"는 항상 오답 — 공평할 뿐 성능은 나쁘다
  • C-SCAN·SCAN은 디스크 끝(0·최대트랙)까지 가고, C-LOOK·LOOK은 마지막 요청까지만 간다
  • 문제에 최대 트랙 번호가 안 적혀 있으면 끝까지 가는 것으로 계산할 수 없으므로 LOOK 계열로 처리한다
  • SSTF는 가까운 요청만 처리하므로 멀리 있는 요청이 밀리는 기아(starvation) 발생 가능
  • 연속 할당 = 빠른 검색 + 외부 단편화 + 압축 필요 / 연결 할당 = 직접접근 불가 + 단편화 없음
  • 색인 할당은 색인(인덱스) 블록이 파일 구성 블록 주소를 관리 (디렉터리가 아님 — 자주 나오는 함정)
  • 자료 단위 크기 순서: 필드 < 레코드 < 파일 < 데이터베이스
  • 접근 시간 = 탐색 시간 + 회전 지연 + 전송 시간, 이 중 탐색 시간이 가장 큼

다음에서 설명하는 디스크 스케줄링은?
디스크 헤드가 한쪽 방향으로 트랙의 끝까지 이동하면서 만나는 요청을 모두 처리한다. 트랙의 끝에 도달하면 반대 방향으로 이동하면서 만나는 요청을 모두 처리한다. 이러한 방식으로 헤드가 디스크 양쪽을 계속 왕복하면서 남은 요청을 처리한다.

  1. 라운드 로빈(RR) 스케줄링
  2. 스캔(SCAN) 스케줄링
  3. 최소 탐색 시간 우선(SSTF) 스케줄링
  4. 선입 선처리(FCFS) 스케줄링
해설 보기

정답 ② 스캔(SCAN) 스케줄링

지문에서 두 가지 단서를 잡으면 끝난다.

  1. "트랙의 끝까지 이동" → 끝까지 가는 건 SCAN 계열(LOOK 계열은 마지막 요청에서 턴)
  2. "반대 방향으로 이동하면서 만나는 요청을 모두 처리 · 양쪽을 계속 왕복" → 돌아오면서도 서비스하므로 양방향 = C가 안 붙은 SCAN

함정: ①번 라운드 로빈은 CPU 스케줄링 기법이지 디스크 스케줄링이 아니다. 선택지에 CPU 스케줄링 이름을 섞어 놓는 것이 전형적인 패턴이다.

문제 22012 국회 · 기출문제집 p.263

SSTF(Shortest Seek Time First) 스케줄링 알고리즘을 사용할 경우, 아래 요구 큐에 있는 트랙의 이동을 올바르게 표현한 것은?
요구 큐: 20, 47, 169, 13, 83, 67, 52  /  head 시작 위치: 72

  1. 169, 13, 20, 47, 52, 83, 67
  2. 13, 20, 47, 52, 67, 83, 169
  3. 169, 83, 67, 52, 47, 20, 13
  4. 67, 52, 47, 20, 13, 83, 169
해설 보기

정답 ④ 67, 52, 47, 20, 13, 83, 169

SSTF는 방향 무시하고 매번 현재 위치에서 제일 가까운 트랙을 고른다. 한 칸씩 따라가자.

  1. 현재 72 → 후보와의 거리: 67은 5, 83은 11, 52는 20, 47은 25 … → 가장 가까운 67
  2. 현재 67 → 52는 15, 83은 16, 47은 20 … → 52 (83과 1 차이라 실수하기 쉬운 지점)
  3. 현재 52 → 47은 5, 83은 31 … → 47
  4. 현재 47 → 20은 27, 13은 34, 83은 36 … → 20
  5. 현재 20 → 13은 7, 83은 63 … → 13
  6. 현재 13 → 남은 건 83(70), 169(156) → 83 → 마지막 169

함정: ②번은 그냥 오름차순 정렬한 것이고 ③번은 내림차순이다. SSTF는 정렬이 아니라 현재 위치 기준이라는 걸 놓치면 이런 선택지에 낚인다. 2단계에서 52(15) vs 83(16)을 대충 보면 ⑤번류 오답으로 빠진다.

문제 32022 국가직 · 기출문제집 p.263

디스크 큐에 다음과 같이 I/O 요청이 들어와 있다. 최소탐색시간 우선(SSTF) 스케줄링 적용 시 발생하는 총 헤드 이동 거리는? (단, 추가 I/O 요청은 없으며 디스크 헤드는 0부터 150까지 이동 가능하고, 현재 위치는 50이다)
큐: 80, 20, 100, 30, 70, 130, 40

  1. 100
  2. 140
  3. 180
  4. 430
해설 보기

정답 ② 140

  1. 50 → 40 (10) → 30 (10) → 20 (10)  아래쪽이 촘촘하므로 먼저 훑는다
  2. 20에서 남은 요청은 70·80·100·130뿐 → 가장 가까운 70 (50)  여기서 한 번 크게 점프

함정: ④번 430은 FCFS(도착 순서대로)로 계산했을 때의 값이다. 문제가 어떤 기법을 묻는지 먼저 확인하는 습관이 필요하다. ①번 100은 시작(50)과 끝(130)의 단순 차이+α 같은 함정값이다.

문제 42010 국가직 · 기출문제집 p.264

트랙 번호가 0부터 199인 200개 트랙 디스크에서 C-SCAN으로 아래 대기 큐를 처리할 때, 처리되는 트랙의 순서는? (현재 헤드는 트랙 35에서 트랙 47로 이동해 왔다고 가정)
작업 대기 큐: 139, 22, 175, 86, 13, 158  /  헤드 시작 위치: 47

  1. 47 → 86 → 139 → 158 → 175 → 22 → 13
  2. 47 → 86 → 139 → 158 → 175 → 199 → 0 → 13 → 22
  3. 47 → 22 → 13 → 86 → 139 → 158 → 175
  4. 47 → 86 → 139 → 158 → 175 → 199 → 22 → 13
해설 보기

정답 ② 47 → 86 → 139 → 158 → 175 → 199 → 0 → 13 → 22

  1. 방향 파악: "35에서 47로 이동해 왔다" → 번호가 증가하는 방향으로 진행 중
  2. 증가 방향의 요청을 오름차순 처리: 86 → 139 → 158 → 175
  3. C-SCAN이므로 디스크 끝 199까지 간다 (LOOK이 아니므로 175에서 멈추지 않음)
  4. 끝에 닿으면 서비스 없이 반대쪽 끝 0으로 점프
  5. 다시 같은(증가) 방향으로: 13 → 22

선택지가 곧 기법 사전이다. 이 문제의 오답들은 각각 다른 기법의 정답이다:
① = LOOK(끝까지 안 가고 175에서 턴, 양방향) · ③ = SSTF(가까운 22·13 먼저) · ④ = SCAN(199까지 간 뒤 되돌아오며 22→13 감소 순서)
특히 ②와 ④의 차이는 "0을 찍고 오름차순(13→22)이냐, 되돌아오며 내림차순(22→13)이냐"다. C가 붙으면 항상 같은 방향이므로 13→22가 맞다.

문제 52014 서울시 · 기출문제집 p.265

C-LOOK 스케줄링 알고리즘에 의한 헤드의 총 이동거리는? (현재 헤드 위치 50, 헤드 이동방향은 0에서 199 방향)
요청 대기열: 65, 112, 40, 16, 90, 170, 165, 35, 180

  1. 388
  2. 318
  3. 362
  4. 347
해설 보기

정답 ② 318

  1. 요청 정렬: 16, 35, 40, |50|, 65, 90, 112, 165, 170, 180
  2. 증가 방향 먼저: 50 → 65 → 90 → 112 → 165 → 170 → 180. 쭉 올라가므로 180 − 50 = 130
  3. C-LOOK은 199까지 가지 않고 남은 요청 중 최솟값 16으로 바로 복귀: 180 − 16 = 164
  4. 다시 증가 방향: 16 → 35 → 40 → 40 − 16 = 24
  5. 총합 = 130 + 164 + 24 = 318

함정: ①번 388은 C-SCAN으로 계산한 값에 가깝다 — 199와 0을 찍고 오면 (199−50) + (199−0) + 40 식으로 커진다. "LOOK이면 끝을 찍지 않는다"를 놓치면 이쪽으로 빠진다.

문제 62017 국가직 · 기출문제집 p.265

디스크 헤드의 위치가 55이고 0의 방향으로 이동할 때, C-SCAN 기법으로 디스크 대기 큐 25, 30, 47, 50, 63, 75, 100을 처리한다면 제일 마지막에 서비스 받는 트랙은?

  1. 50
  2. 63
  3. 75
  4. 100
해설 보기

정답 ② 63

  1. 방향이 감소(0 쪽)이므로 55보다 작은 것부터 내림차순: 50 → 47 → 30 → 25
  2. 가장 작은 쪽 끝에 도달하면 반대쪽 끝으로 점프한 뒤 다시 감소 방향으로 처리
  3. 남은 요청 중 가장 큰 100부터 내림차순: 100 → 75 → 63
  4. 따라서 마지막은 63

핵심 감각: C가 붙은 기법은 "항상 같은 방향으로만 서비스"하므로, 복귀 후에도 방향이 같다. 감소 방향이면 복귀 후에도 큰 값 → 작은 값 순이다. 그래서 마지막에 서비스되는 것은 진행 방향 기준 가장 끝에 있는 요청(여기서는 남은 것 중 가장 작은 63)이 된다.

함정: ④번 100을 고르기 쉽다 — "복귀해서 100으로 갔으니 100이 마지막"이라고 착각하는 것. 100은 복귀 직후 첫 번째로 처리된다.

문제 72011 국가직 · 기출문제집 p.266

운영체제의 디스크 스케줄링에 대한 설명으로 옳지 않은 것은?

  1. FCFS 스케줄링은 공평성이 유지되며 스케줄링 방법 중 가장 성능이 좋은 기법이다.
  2. SSTF 스케줄링은 현재 헤드 위치에서 가장 가까운 요청을 우선적으로 처리하는 기법이다.
  3. C-SCAN 스케줄링은 양쪽 방향으로 요청을 처리하는 SCAN과 달리 한쪽 방향으로 헤드를 이동해 갈 때만 요청을 처리하는 기법이다.
  4. 섹터 큐잉(sector queuing)은 고정 헤드 장치에 사용되는 기법으로 디스크 회전 지연 시간을 고려한 기법이다.
해설 보기

정답 ① (FCFS가 가장 성능이 좋다는 설명이 틀림)

FCFS는 공평성만 보장한다. 요청이 디스크 양 끝을 번갈아 가리키면 헤드가 계속 왕복하게 되어 이동거리가 폭증한다 — 앞의 비교 그래프에서 FCFS가 430으로 최악이었던 이유다.

  1. ②는 SSTF의 정확한 정의 → 맞음
  2. ③은 C-SCAN의 정확한 정의(한 방향으로만 서비스) → 맞음
  3. ④ 섹터 큐잉은 헤드가 고정된 장치(트랙마다 헤드가 따로 있는 구조)에서 쓰는 기법이라 탐색 시간이 없고, 대신 회전 지연을 기준으로 정렬한다 → 맞음

암기 포인트: "FCFS = 공평하지만 느리다"는 CPU 스케줄링에서도 디스크 스케줄링에서도 똑같이 성립한다. 공평함과 성능은 다른 축이다.

문제 82013 서울시 · 기출문제집 p.268

보조기억장치의 공간할당 방식에 대한 설명으로 옳은 것은?

  1. 연결 할당 방식은 파일을 검색하는데 많은 시간이 소요된다.
  2. 연속 할당 방식은 파일을 연속하여 저장하므로 디스크 공간 사용의 효율성이 높아진다.
  3. 색인 할당 방식은 각 파일을 구성하는 디스크 섹터 주소를 디렉터리가 관리한다.
  4. 블록 할당 방식은 단편화 문제를 해결하기 위해 압축을 요구한다.
해설 보기

정답 ① 연결 할당 방식은 파일 검색에 많은 시간이 소요된다

연결 할당은 블록이 디스크 전체에 흩어져 있고 포인터를 하나씩 따라가야 하므로, N번째 블록을 읽으려면 앞의 N−1개를 모두 거쳐야 한다. 당연히 느리다.

  1. ② 오답 — 연속 할당은 검색은 빠르지만, 외부 단편화 때문에 공간 효율은 낮다. "빠르다"와 "공간 효율이 좋다"를 섞어놓은 함정
  2. ③ 오답 — 색인 할당에서 블록 주소를 관리하는 건 디렉터리가 아니라 색인 블록이다. 디렉터리는 "색인 블록이 몇 번인지"만 안다
  3. ④ 오답 — 압축이 필요한 건 연속 할당이다. 블록(불연속) 할당은 애초에 외부 단편화가 없어서 압축할 이유가 없다

정리: 이 유형은 "누가 무엇을 관리하는가"와 "어떤 방식에 단편화가 생기는가" 두 축만 정확하면 전부 잡힌다.

문제 92011 지방직 · 기출문제집 p.268

디스크 할당(disk allocation)에 대한 설명으로 옳지 않은 것은?

  1. 연속영역(contiguous portion)은 할당 방법에 따라 고정크기와 가변크기로 구분된다.
  2. 블록의 할당방법에는 연속할당, 인덱스 할당 등이 있다.
  3. 블록의 연속할당 방법에서는 단편화(fragmentation) 문제가 발생하지 않는다.
  4. 새로 포맷한 초기 상태의 하드 디스크에는 단편화가 없다.
해설 보기

정답 ③ (연속할당에 단편화가 없다는 설명이 틀림)

연속 할당의 최대 약점이 바로 외부 단편화다. 파일이 생성·삭제를 반복하면 디스크 곳곳에 작은 빈칸들이 생기는데, 전체 빈 공간을 합치면 충분한데도 "연속된" 공간이 없어서 새 파일을 못 넣는 상황이 벌어진다.

  1. 그래서 연속 할당은 주기적인 압축(compaction)으로 파일들을 한쪽으로 몰아 빈칸을 합쳐줘야 한다
  2. ④번은 맞는 설명이다 — 갓 포맷한 디스크는 전체가 하나의 연속된 빈 공간이므로 단편화가 있을 수 없다

연결 지식: 이 "외부 단편화 → 압축" 구조는 기억장치 관리정책의 메모리 가변분할과 완전히 동일한 문제다. 디스크냐 메모리냐만 다를 뿐 원리가 같으니 함께 묶어 외우면 좋다.

문제 10개념 확인 · 응용

헤드 위치 100, 요청 큐 30, 60, 120, 180, 디스크 범위 0~199, 초기 방향은 증가(199 쪽)일 때 SCAN과 LOOK의 총 이동거리를 각각 구하고, 두 값의 차이가 왜 생기는지 설명하시오.

해설 보기

정답: SCAN = 268, LOOK = 230, 차이 38

  1. SCAN: 증가 방향으로 120 → 180 → 끝인 199까지 감 → 방향 전환 → 60 → 30
    거리 = (199 − 100) + (199 − 30) = 99 + 169 = 268
  2. LOOK: 증가 방향으로 120 → 180(마지막 요청)에서 바로 턴 → 60 → 30
    거리 = (180 − 100) + (180 − 30) = 80 + 150 = 230
  3. 차이 = 268 − 230 = 38

왜 38인가: SCAN은 180에서 199까지 갔다가 다시 180으로 돌아오는 왕복 19+19 = 38만큼을 "요청도 없는 구간"에 낭비한다. LOOK은 그걸 안 한다. LOOK이 SCAN보다 손해 볼 일이 없는 이유가 바로 이 구조다 — 최선의 경우 같고, 보통은 더 짧다.

확장 — 네 기법을 같은 조건으로 모두 계산해보면:

기법경로계산거리
LOOK120→180→(턴)→60→30(180−100) + (180−30)230
C-LOOK120→180→(복귀)→30→60(180−100) + (180−30) + (60−30)260
SCAN120→180→199→(턴)→60→30(199−100) + (199−30)268
C-SCAN120→180→199→(복귀)→0→30→60(199−100) + (199−0) + (60−0)358

C 계열에서 흔한 실수: 복귀한 뒤에도 같은 방향으로 다시 훑어 올라간다는 것을 빼먹으면 안 된다. C-LOOK은 30에 도착해서 끝나는 게 아니라 30 → 60까지 처리하므로 마지막 30이 더 붙고, C-SCAN도 0에서 멈추는 게 아니라 0 → 60까지 올라가므로 60이 더 붙는다.
