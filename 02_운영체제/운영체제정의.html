운영체제 정의

운영체제의 역할·목적·구조 · PART 02. 운영체제론

핵심 요약

운영체제(OS)는 시스템 소프트웨어의 핵심으로, 사용자에게는 편리성을, 시스템에는 자원의 효율적 관리를 제공한다.

운영체제의 목적은 처리량↑, 응답시간↓(감소), 신뢰도↑, 사용가능도↑ — "응답시간 증가"는 틀린 표현이다.

🎯이 단원을 왜 배우나

"컴퓨터에 프로그램이 100개 떠 있는데 CPU는 하나다"

컴퓨터의 자원 — CPU, 메모리, 디스크, 프린터 — 은 한정되어 있는데 그것을 쓰겠다는 프로그램은 수십 개다. 누구에게 CPU를 얼마나 줄지, 메모리 어디에 올릴지, 프린터를 두 프로그램이 동시에 잡으려 하면 어떻게 할지를 누군가는 정해야 한다. 그 "누군가"가 운영체제다.

그래서 운영체제를 한마디로 정의하면 "자원 관리자(resource manager)"다. PART 02 전체가 결국 이 한 문장의 각론이다 — 프로세스 스케줄링은 CPU라는 자원을 나눠주는 방법, 메모리 관리·가상메모리는 메모리라는 자원을, 디스크 스케줄링은 디스크 헤드라는 자원을 나눠주는 방법이다.

또 하나의 얼굴은 "편의 제공자"다. 응용 프로그램이 하드디스크에 직접 자기력을 걸어 데이터를 쓸 수는 없다. 대신 파일에 쓰기라고 요청하면 OS가 알아서 해준다. 이 요청 창구가 시스템 호출(System Call)이고, 이 단원의 구조 문제는 거의 전부 이 창구를 누가 어떤 순서로 거치는지를 묻는다.

💡주요 개념

시스템 소프트웨어 vs 응용 소프트웨어 📖 기출문제집 p.185

가장 자주 나오는 첫 문제 유형이 "이 중 시스템 소프트웨어가 아닌 것은?"이다. 구분 기준은 간단하다 — 컴퓨터 자체를 돌아가게 하는 것이면 시스템 소프트웨어, 사용자의 일(문서작성·게임·계산)을 하는 것이면 응용 소프트웨어다.

운영체제의 위치 — 계층 구조

운영체제(Windows, 유닉스, 리눅스, 안드로이드 등)는 하드웨어와 응용 소프트웨어 사이의 매개체 역할을 한다. 아래 그림에서 화살표가 계층을 하나도 건너뛰지 않는다는 점이 핵심이다 — 응용 프로그램이 하드웨어로 직행하는 화살표는 존재하지 않는다.

2025 국가직 출제: "사용자나 응용 프로그램이 커널을 거치지 않고 하드웨어에 직접 접근할 수 있도록 제공하는 함수의 집합을 시스템 호출이라 한다" → 틀림. 시스템 호출은 정반대로 직접 접근할 수 없기 때문에 커널에 대신 요청하는 창구다. "거치지 않고"라는 표현이 보이면 오답이다.

정보처리 시스템의 분류 (응답시간·입력방식 기준) 📖 기출문제집 p.185~186

종류특징성능 평가 기준
일괄처리 (Batch)작업을 모아두었다가 한꺼번에 처리. 초창기엔 천공카드·자기테이프, 요즘은 OMR/OCR 카드로 입력처리량(throughput)
반환시간(turnaround time)
대화식 (Interactive)터미널로 직접 명령 입력, 즉각적인 피드백 제공. 응답시간은 동시 접속 이용자 수에 따라 수 초~수 분응답시간(response time)
실시간 (Real-time)결과가 현재 결정에 즉시 영향을 주므로 매우 빠른 처리 필요 (예: 항공 관제, 공장 제어)마감시간(deadline) 준수
하이브리드 (Hybrid)대화형 + 일괄처리 결합. 대화형 작업이 없을 때 백그라운드에서 배치 작업 수행둘 다
분류 근거: "응답 시간"과 "데이터 입력 방식"이 기준 — 고급언어 사용 여부, 버퍼링 수행 여부, 데이터 보호 필요성이 아니다. (2010 계리직 출제)

운영체제의 목적 — 4가지 📖 기출문제집 p.186

  • 처리량(Throughput) 향상 — 단위 시간당 처리하는 작업량을 늘린다
  • 응답 시간(Response Time) 감소 (증가 X — 자주 나오는 오답 함정)
  • 신뢰도(Reliability) 향상 — 주어진 작업을 정확하게 처리하는 정도
  • 사용 가능도(Availability) 향상 — 필요할 때 즉시 쓸 수 있는 정도

왜 하필 "응답시간만 감소"인가

네 가지 중 셋은 향상(↑), 하나만 감소(↓)다. 헷갈릴 이유가 없어 보이지만 시험은 바로 이 하나를 "증가"로 바꿔 놓고 낸다. 이유를 알면 안 헷갈린다 — 응답시간은 "기다리는 시간"이기 때문이다. 기다리는 시간이 늘어나서 좋을 리 없다.

나머지 셋은 전부 "많을수록·좋을수록 이득"인 양(量)이다. 처리량은 많이 처리할수록, 신뢰도는 정확할수록, 사용가능도는 언제든 쓸 수 있을수록 좋다. "시간"이 들어간 지표만 줄이는 게 목표라고 기억하면 된다.

운영체제의 기능 분류 📖 기출문제집 p.186

구분내용
자원관리주기억장치 관리, 보조기억장치 관리, 프로세스 관리, 입출력(주변)장치 관리, 파일(데이터) 관리
시스템관리시스템 보호(사용자 권한 부여), 네트워킹, 명령 해석기
함정 주의: "사용자 권한 관리"는 자원관리가 아니라 시스템관리에 속한다. 자원관리는 전부 "○○장치 관리 / 프로세스·파일 관리" 형태로 물리적 자원을 다루는 것들이고, 권한·보안·네트워킹은 시스템관리 쪽이라고 나눠 기억하면 된다.

운영체제 구조 — 커널과 인터페이스 📖 기출문제집 p.187

  • 커널(Kernel): 운영체제의 핵심 기능을 모아둔 부분 (프로세스 관리, 메모리 관리 등)
  • 인터페이스: 사용자·응용프로그램과 인접해 커널에 명령을 전달하고 실행 결과를 돌려줌
  • 디바이스 드라이버: 다양한 장치를 효율적으로 쓰기 위한 하드웨어 인터페이스
  • 시스템 호출(System Call): 사용자 프로그램이 하드웨어에 직접 접근할 수 없으므로, 커널 기능을 대신 요청하도록 해주는 인터페이스
커널 구조특징장단점
단일형(모놀리식) 구조 커널초창기 구조, 모듈이 거의 분리되지 않음모듈 간 통신비용은 적지만 유지보수·확장에 불리, 한 부분 오류가 전체에 영향
계층형 구조 커널기능을 계층별로 분리오류 추적·유지보수가 쉬워짐, 계층 통과 비용 발생
마이크로 구조 커널핵심 기능만 커널에 남기고 나머지는 별도 프로세스로 분리안정성·확장성 높음, 프로세스 간 통신이 잦아 성능 부담
함정 주의: 커널의 프로세스 관리는 CPU 배분·작업공간 배치가 핵심이며, 가상 메모리(실제 메모리보다 큰 가상공간) 제공은 메모리 관리 기능에 해당한다. 2025 법원직에서 이 둘을 섞어 출제했다.

프로세스의 종류 📖 기출문제집 p.188

종류설명
운영체제 프로세스시스템 관리 기능 담당, 프로세스 실행 순서를 제어하고 사용자 프로세스가 다른 영역을 침범하지 못하게 감시
사용자 프로세스사용자 응용프로그램(사용자 코드)을 수행
병행 프로세스여러 프로세스가 동시에 실행 중인 상태
독립 프로세스다른 프로세스에 영향을 주지도 받지도 않음
협동 프로세스다른 프로세스와 서로 영향을 주고받음 (통신·동기화 수단 필요)
함정 주의: "여러 프로세스가 동시에 수행 상태에 있다 = 교착상태"라는 설명은 틀렸다. 동시 수행은 병행 프로세스이며, 교착상태는 자원을 서로 기다리며 멈춰버린 상태를 말한다.

좀비 프로세스와 고아 프로세스 📖 기출문제집 p.188~189

부모 프로세스는 자식 프로세스를 만들고, 자식은 일이 끝나면 부모에게 결과를 돌려주고 종료된다. 그런데 이 정상적인 순서가 깨지면 두 가지 비정상 상태가 생긴다. 2025 계리직에서 타임라인 그림으로 출제됐다.

암기: 좀비는 "죽었는데 목록에 남아 돌아다니는 것", 고아는 "부모를 잃고 혼자 남은 것" — 단어 뜻 그대로다. 죽은 쪽이 자식이면 좀비, 죽은 쪽이 부모면 고아.

📌시험 빈출 포인트

  • 운영체제 목적: 응답시간은 감소가 맞음, "증가"라고 나오면 오답
  • 시스템 SW vs 응용 SW: 워드·엑셀·MS오피스는 응용, 컴파일러·OS·드라이버는 시스템
  • 정보처리 시스템 분류 기준 = 응답시간 + 데이터 입력방식
  • 사용자 권한 관리는 자원관리(X), 시스템관리(O)
  • 시스템 호출 = 사용자 프로그램이 하드웨어에 직접 접근 못하니 커널에 요청하는 인터페이스 ("직접 접근하게 해준다"는 오답)
  • 커널의 가상메모리 제공 = 메모리 관리 기능 (프로세스 관리 아님)
  • 단일형 구조 커널은 모듈 분리가 안 돼 통신비용이 적은 것이지, 유지보수·확장은 불리
  • 좀비 = 자식이 종료됐는데 목록에 남음 / 고아 = 부모가 먼저 종료
  • 모바일 특화 OS: Android, iOS, Symbian — Solaris는 서버용 유닉스라 모바일 아님

  2. ②는 전부 인공지능 프로그램 → 동일 분류 (맞음)
  3. ③은 전부 프로그래밍 언어 → 동일 분류 (맞음)
  4. ④에서 유닉스·리눅스·안드로이드는 운영체제(시스템 SW)인데 MS오피스만 응용 SW → 한 항목이 섞여 있으므로 옳지 않음

풀이 요령: "분류가 옳지 않은 것"은 한 개만 이질적인 묶음을 찾는 문제다. 각 묶음에서 "얘만 성격이 다른데?" 싶은 항목이 있는지 훑으면 빠르다.

  2. 처리량(throughput) 향상

  4. 사용 가능도(availability) 향상

정답 ③ 응답 시간 증가

  1. 운영체제의 4대 목적: 처리량 향상, 신뢰도 향상, 사용가능도 향상, 응답시간 감소

  2. 시스템관리: 시스템 보호(사용자 권한 부여), 네트워킹, 명령 해석기

운영체제 구조에 대한 설명으로 옳지 않은 것은?

  1. 커널은 운영체제의 핵심 기능을 모아 놓은 것이다.
  2. 다양한 장치를 효율적으로 사용할 수 있는 하드웨어와의 인터페이스를 디바이스 드라이버라고 한다.
  3. 사용자 인터페이스는 커널에 명령을 전달하고, 실행 결과를 사용자와 응용 프로그램에 전달한다.
  4. 사용자나 응용 프로그램이 커널을 거치지 않고 하드웨어에 직접 접근할 수 있도록 제공하는 함수의 집합을 시스템 호출이라고 한다.
해설 보기

정답 ④

시스템 호출의 정의가 정확히 반대로 서술되어 있다.

  1. 사용자 프로그램은 보안·안정성 문제로 하드웨어나 중요 시스템 자원에 직접 접근할 수 없다
  2. 그래서 "대신 해주세요"라고 커널에게 요청하는 창구가 필요하다 → 그것이 시스템 호출
  3. 즉 시스템 호출은 커널을 "거치지 않게" 하는 게 아니라 반드시 거치게 하는 통로다

함정 감지법: 이 단원 지문에서 "커널을 거치지 않고", "직접 접근"이라는 표현이 보이면 거의 항상 오답이다. 계층 구조 그림에서 응용→하드웨어 직행 화살표가 없다는 것과 같은 이야기다.

문제 72012 국가직 · 기출문제집 p.188

운영체제의 프로세스에 대한 설명으로 옳지 않은 것은?

  1. 운영체제 프로세스는 사용자 작업 처리를 위해 시스템 관리 기능을 담당하는 프로세스이다.
  2. 사용자 프로세스는 사용자 응용프로그램을 수행하는 프로세스이다.
  3. 여러 개의 프로세스들이 동시에 수행상태에 있다면 교착상태(deadlock) 프로세스라고 한다.
  4. 독립 프로세스는 한 프로세스가 시스템 안에서 다른 프로세스에게 영향을 주지 않거나 또는 다른 프로세스에 의해 영향을 받지 않는 프로세스이다.
해설 보기

정답 ③

  1. 여러 프로세스가 동시에 실행되는 것은 병행(concurrent) 프로세스다 — 지극히 정상이고 오히려 바람직한 상태
  2. 교착상태는 서로가 가진 자원을 기다리며 아무도 진행하지 못하고 멈춘 비정상 상태
  3. "동시 실행"과 "서로 기다리며 멈춤"은 완전히 다른 개념이므로 ③이 틀렸다

함정: "동시에 여러 개"라는 표현만 보고 뭔가 문제 상황 같다고 느끼기 쉽다. 하지만 멀티태스킹 자체가 병행 프로세스이며, 교착상태는 진행이 멈춰야 성립한다.

문제 82025 계리직 · 기출문제집 p.188~189

부모 프로세스가 자식 프로세스 1·2·3을 만들었고, 다음과 같이 진행되었다. 고아(orphan) 프로세스와 좀비(zombie) 프로세스를 바르게 짝지은 것은? (단, 부모 프로세스는 자식 프로세스의 종료 상태를 확인한 후 자원을 회수한다)

  • 자식 2: 시작 후 비정상 종료 → 부모가 자원 회수 완료
  • 자식 3: 시작 후 종료 → 부모가 자원 미회수
  • 자식 1: 시작 후 작업 수행 중인 상태에서 부모 프로세스가 종료
  1. 고아 = 자식 2, 좀비 = 자식 1
  2. 고아 = 자식 3, 좀비 = 자식 1
  3. 고아 = 자식 1, 좀비 = 자식 2
  4. 고아 = 자식 1, 좀비 = 자식 3
해설 보기

정답 ④ 고아 = 자식 1, 좀비 = 자식 3

  1. 고아 = 부모가 먼저 죽은 경우. 자식 1은 아직 작업 수행 중인데 부모가 종료됐다 → 자식 1이 고아
  2. 좀비 = 자식이 끝났는데 목록에 남은 경우. 자식 3은 종료됐지만 부모가 자원을 회수하지 않아 프로세스 목록에 남아 있다 → 자식 3이 좀비
  3. 자식 2는 비정상 종료이긴 하나 부모가 자원을 회수했으므로 깔끔히 정리된 상태 → 둘 다 아님

함정: 자식 2의 "비정상 종료"라는 말에 끌려 좀비로 고르기 쉽다. 하지만 좀비를 만드는 건 종료가 정상이냐 비정상이냐가 아니라 부모가 자원을 회수했느냐다. 자원 회수 여부만 보면 된다.
