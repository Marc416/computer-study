운영체제 실무 (UNIX·Windows)

UNIX 커널·파일시스템·프로세스 통신, Windows 실행창 명령어 · PART 02. 운영체제론

핵심 요약

UNIX 커널은 프로세스·파일·메모리·입출력 관리를 담당하고, 명령어 해석은 쉘(shell)의 몫이다.

fork()는 프로세스를 복사해서 자식을 만들고, 부모는 자식 PID를, 자식은 0을 반환받는다.

💡주요 개념 — UNIX 커널과 파일시스템

UNIX 커널의 기능

  • 사용자 프로세스 관리 (Process Management)
  • 파일 관리 (File Management)
  • 기억장치 관리 (Memory Management)
  • 입/출력 시스템 관리 (I/O System Management)
함정 주의: 사용자 명령어 관리, 윈도우(창) 관리는 커널의 기능이 아니라 쉘(shell)의 기능이다. "커널에 속하지 않는 것" 문제에서 자주 정답으로 나온다.

UNIX와 BSD 계열은 대부분 C언어로 작성되어 이식성이 높다 (어셈블리어 아님 — 자주 나오는 오답).

UNIX 파일 시스템 구조 (디스크 블록 4단계) 📖 기출문제집 p.274~275

블록내용
부트 블록 (Boot Block)파일 시스템의 첫 블록. 시스템을 실행하는 프로그램·정보 저장
슈퍼 블록 (Super Block)전체 블록 수, 블록 크기, 사용 중인 블록 수 등 파일시스템 전체 정보
i-node 블록각 파일·디렉터리의 모든 속성 정보 저장
데이터 블록실제 파일·디렉터리 내용 저장
i-node가 담고 있는 정보: 파일 종류, 소유자, 접근권한, 접근/생성 시간, 크기, 링크 수, 저장 블록 주소(직접/단일·이중·삼중 간접 블록 포인터)
i-node에 없는 것: 파일 이름 — 파일 이름은 디렉터리 엔트리가 아이노드 번호와 함께 따로 관리한다

파일 접근 권한 (rwx, 8진수 표기)

권한은 소유자(user) · 그룹(group) · 나머지(other) 3자리, 각 자리는 r(4)+w(2)+x(1)의 합으로 8진수 표기

예시의미
rwxr-xr--소유자: rwx(7), 그룹: r-x(5), 나머지: r--(4) → 754
chmod 531 A소유자 5(r-x)=읽기+실행, 그룹 3(-wx)=쓰기+실행, 나머지 1(--x)=실행만
chmod go-x A그룹(g)·나머지(o)에서 실행(x) 권한 제거
계산 순서 예: chmod 531 A 실행 후 소유자는 r-x(읽기+실행). 이어서 chmod go-x A는 소유자에는 영향 없음(g·o만 대상) → 소유자는 최종적으로 읽기+실행만 가능, 쓰기는 불가.

ls -l 결과 읽는 법

-rwxr-xr-- 2 peter staff 3542 8월 31일 10:00 aaash

필드의미
맨 앞 -파일 종류 (- 는 일반파일, d는 디렉터리)
rwxr-xr--소유자/그룹/나머지 권한
2하드 링크 개수 (심볼릭 링크 개수 아님 — 자주 나오는 오답)
peter / staff소유자 / 소유그룹
3542파일 크기(byte)
날짜·시간파일 최종 변경 시간 (생성시간 아님)

🔗주요 개념 — 프로세스 간 통신과 fork()

파이프 · 시그널 · 공유메모리

방식특징
익명 파이프 (Anonymous Pipe)부모-자식 관계인 프로세스끼리만 공유 가능, 일시적
지명 파이프 (Named Pipe)파일처럼 이름을 가져 관계 없는 프로세스끼리도 공유 가능, 영구적
시그널 (Signal)커널·프로세스가 다른 프로세스에게 비동기적으로 사건을 통지
공유 메모리 (Shared Memory)여러 프로세스가 같은 메모리 영역 공유. 상호배제는 OS가 보장하지 않음 → 프로그래머가 직접 책임
함정 주의: "지명 파이프는 부모-자식 관계가 필요하다"는 틀렸다 — 그건 익명 파이프의 특징. 지명 파이프는 관계 없는 프로세스끼리도 통신 가능하다.

주요 시그널

시그널의미
SIGKILL프로세스를 강제 종료
SIGTERM프로세스를 정상적으로 종료 요청
SIGILL잘못된(illegal) 명령어 실행 시 발생
SIGCHLD자식 프로세스가 종료될 때 부모에게 전달

fork() / exec() / wait()

  • fork(): 실행 중인 프로세스를 복사해 자식 프로세스 생성. 부모에게는 자식의 PID를, 자식에게는 0을 반환
  • 자식 프로세스는 부모의 메모리를 복사해서 가짐 (동일한 메모리 위치를 공유하는 것 아님)
  • exec(): 현재 프로세스의 이미지를 다른 프로그램으로 교체 (이미 만들어진 프로세스 구조를 재활용)
  • wait(): 자식 프로세스의 종료를 기다림
fork() 예제 (핵심 포인트):
pid = fork(); 이후 if (pid == 0) 이면 자식 프로세스, else이면 부모 프로세스 코드가 실행된다.
자식과 부모는 fork() 호출 시점 이후부터 각자의 메모리 공간에서 독립적으로 실행을 이어간다.

📌시험 빈출 포인트

  • 커널 기능 vs 쉘 기능 구분 — 사용자 명령어 관리·윈도우 관리는 쉘
  • i-node에는 파일 이름이 없다 (디렉터리가 이름↔i-node 매핑을 관리)
  • chmod 숫자 표기(rwx=4+2+1) 계산 문제, ls -l 결과 해석 문제
  • 익명 파이프(부모-자식 필요) vs 지명 파이프(관계 무관) 구분
  • fork() 자식은 0, 부모는 자식 PID 반환 — if(pid==0) 분기 결과 예측 문제
  • SIGKILL(강제종료) vs SIGTERM(정상종료) vs SIGCHLD(자식종료 알림) 구분
  • dxdiag·msconfig·regedit·mstsc 등 Windows 실행창 명령어 기능 매칭
