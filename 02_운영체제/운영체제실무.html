운영체제 실무 (UNIX·Windows)

UNIX 커널·파일시스템·권한·프로세스 통신, Windows 실행창 명령어 · PART 02. 운영체제론

핵심 요약

UNIX 커널은 프로세스·파일·메모리·입출력 관리를 담당하고, 명령어 해석은 쉘(shell)의 몫이다.

fork()는 프로세스를 복사해서 자식을 만들고, 부모는 자식 PID를, 자식은 0을 반환받는다.

🎯이 단원을 왜 배우나

앞에서 배운 이론이 "실제로 어떻게 생겼는지" 보는 단원

지금까지 프로세스·메모리·파일시스템을 개념으로 배웠다. 이 단원은 그 개념들이 실제 UNIX 시스템에서 어떤 모습으로 존재하는지를 다룬다. 프로세스 생성은 fork()라는 함수 호출이고, 파일 속성은 i-node라는 자료구조이며, 접근 권한은 9개 비트다. 추상적이던 것이 손에 잡히는 형태로 내려온다.

출제 비중이 낮지 않은 이유는 계산·추적 문제로 만들기 좋기 때문이다. 개념 문제는 "맞다/틀리다"뿐이지만, chmod 권한 계산과 fork 출력 예측은 정확히 한 가지 답이 나오므로 변별력 있는 문제가 된다. 실제로 이 단원의 기출 절반이 이 두 유형이다.

그래서 공부 방향도 둘로 나뉜다. ① 암기 파트 — 커널 vs 쉘, i-node에 뭐가 들어있나, 명령어 이름과 기능, 시그널 종류. 이건 헷갈리게 섞어놓은 선택지를 잡아내는 게 전부다. ② 계산 파트 — chmod, ls -l, fork. 이건 규칙을 이해하면 무조건 맞는다. 아래에서 두 계산 유형은 그림으로 완전히 분해해 두었다.

💡주요 개념 — UNIX 커널과 파일시스템

커널과 쉘의 역할 분담 📖 기출문제집 p.269

UNIX 구조는 양파처럼 하드웨어 → 커널 → 쉘 → 사용자 순으로 감싸져 있다. 커널은 하드웨어를 직접 주무르는 핵심부이고, 쉘은 사용자가 입력한 명령어를 해석해 커널에 전달하는 통역사다.

커널(Kernel)의 기능쉘(Shell)의 기능
사용자 프로세스 관리 (Process Management)사용자 명령어 해석·관리
파일 관리 (File Management)윈도우(창) 관리
기억장치 관리 (Memory Management)스크립트 실행, 환경변수 관리
입/출력 시스템 관리 (I/O System Management)입출력 리다이렉션·파이프 연결
스케줄러사용자와 커널 사이의 인터페이스
함정 주의: "사용자 명령어 관리", "윈도우 관리자"는 커널 기능이 아니라 쉘이다. "커널에 속하지 않는 것" 문제의 단골 정답. 반대로 스케줄러·파일 관리자·메모리 관리자는 커널이다.
또 다른 함정: "BSD 유닉스의 모든 코드는 어셈블리 언어로 작성되었다" → 오답. UNIX와 BSD는 거의 대부분 C언어로 작성되었고, 그 덕분에 다른 기종으로 이식(porting)이 쉬운 것이 최대 장점이다.

UNIX 파일 시스템 구조 (디스크 블록 4단계) 📖 기출문제집 p.274~275

블록내용
부트 블록 (Boot Block)파일 시스템의 첫 블록. 시스템을 실행하는 프로그램·정보 저장
슈퍼 블록 (Super Block)전체 블록 수, 블록 크기, 사용 중인 블록 수, 사용 가능한 i-node 개수 등 파일시스템 전체 정보
i-node 블록각 파일·디렉터리의 모든 속성 정보 저장 (파일 하나당 i-node 하나)
데이터 블록실제 파일·디렉터리 내용 저장

왜 파일 이름만 i-node 밖에 있나 — 하드 링크의 비밀

언뜻 비효율적으로 보이지만 이유가 있다. 파일 이름과 파일 실체를 분리해 두면, 같은 파일에 이름을 여러 개 붙일 수 있다. 디렉터리 A에서 "보고서.txt → i-node 42", 디렉터리 B에서 "report.txt → i-node 42"처럼 서로 다른 이름이 같은 i-node를 가리키게 하면 된다. 이것이 하드 링크다.

그래서 ls -l에 나오는 숫자(링크 수)는 "이 i-node를 가리키는 이름이 몇 개인가"를 뜻한다. 이 값이 0이 되어야 비로소 파일이 실제로 삭제된다. 만약 파일 이름이 i-node 안에 들어 있었다면 이런 구조 자체가 불가능했을 것이다.

주의: i-node 안에 있는 직접/단일·이중·삼중 간접 블록 포인터도 i-node의 일부다. "인덱스 블록을 별도로 가지고 있다"는 표현은 오답이다 (2019 서울시 기출).

파일 접근 권한 (rwx, 8진수 표기) 📖 기출문제집 p.274

권한은 소유자(user) · 그룹(group) · 나머지(other) 3개 집단에 대해 각각 읽기(r) · 쓰기(w) · 실행(x) 3가지를 정한다. 총 9개의 비트이고, 3개씩 묶어 8진수 한 자리로 표기한다.

기호 방식 chmod도 알아둘 것: chmod go-x A 는 "group과 other에서 execute 권한을 빼라(−)"는 뜻이다.
대상: u(소유자) g(그룹) o(나머지) a(전체) · 연산: +(추가) −(제거) =(지정) · 권한: r w x
핵심은 대상에 포함되지 않은 집단은 전혀 건드리지 않는다는 것. go-x는 소유자(u) 권한을 바꾸지 않는다.

방식특징
익명 파이프 (Anonymous Pipe)부모-자식 관계인 프로세스끼리만 공유 가능, 일시적
지명 파이프 (Named Pipe)파일처럼 이름을 가져 관계 없는 프로세스끼리도 공유 가능, 영구적

공유 메모리 (Shared Memory)여러 프로세스가 같은 메모리 영역 공유. 상호배제는 OS가 보장하지 않음 → 프로그래머가 직접 책임
세마포어 (Semaphore)동기화 도구. 연산은 중간에 끊기지 않는 원자성(atomic)을 가짐
함정 주의 (2017·2025 국가직 반복 출제): "지명 파이프는 부모-자식 관계가 필요하다"는 틀렸다 — 그건 익명 파이프의 특징. 지명 파이프는 파일시스템에 이름이 있어서 생판 남인 프로세스끼리도 통신 가능하다. 같은 문장이 해마다 그대로 나온다.
비유: 익명 파이프 = 부모가 자식에게 몰래 건넨 쪽지(가족만 가능, 다 쓰면 사라짐) / 지명 파이프 = 동네 게시판(이름이 붙어 있어 아무나 쓰고 읽을 수 있고, 계속 남아 있음)

fork() / exec() / wait() — 프로세스가 둘로 갈라지는 순간 📖 기출문제집 p.276

  • fork(): 실행 중인 프로세스를 복사해 자식 프로세스 생성. 부모에게는 자식의 PID(양수)를, 자식에게는 0을 반환
  • 자식은 부모의 메모리를 복사해서 따로 가진다 (같은 메모리를 공유하는 것이 아님 — 2023 국가직 함정)
  • exec(): 현재 프로세스의 내용을 다른 프로그램으로 통째 교체 (프로세스를 새로 만들지 않고 껍데기를 재활용)
  • wait(): 자식 프로세스가 끝날 때까지 부모가 기다림

fork 문제를 푸는 3단계 절차

  1. 분기부터 확정한다. pid < 0 = fork 실패(문제에서 "성공했다고 가정"하면 이 분기는 실행 안 됨), pid == 0 = 자식, else = 부모. 세 갈래 중 실제로 도는 건 두 개다.
  2. 각 분기의 계산을 따로 한다. 자식과 부모는 메모리가 복사본으로 분리되어 있으므로, 한쪽에서 v를 바꿔도 다른 쪽 v는 영향받지 않는다. 둘 다 v=1부터 시작한다.
  3. 출력 순서를 정한다. 부모에 wait()가 있으면 자식 먼저, 없으면 순서는 보장되지 않는다(보통 문제는 wait를 넣어 순서를 확정시킨다).

계산 실수 방지: for(i=0; i<5; i++) v *= (i+1); 은 v에 1,2,3,4,5를 차례로 곱하므로 5! = 120이다. v += 1을 5번이면 1+5 = 6이다. 초기값 v=1을 빼먹고 5!나 5로 답하는 실수가 잦다.

📌시험 빈출 포인트

  • 커널 기능 vs 쉘 기능 구분 — 사용자 명령어 관리·윈도우 관리는 쉘, 스케줄러·파일·메모리 관리자는 커널
  • UNIX·BSD는 C언어로 작성 (어셈블리 아님) → 이식성이 높음
  • i-node에는 파일 이름이 없다 (디렉터리가 이름↔i-node 매핑을 관리)
  • 간접 블록 포인터는 i-node 안에 있다 — "별도 인덱스 블록을 가진다"는 오답
  • chmod 숫자 계산(r=4, w=2, x=1) 및 기호 방식(go-x 등) 문제
  • ls -l에서 숫자는 하드 링크 수, 날짜는 최종 변경 시간
  • 익명 파이프(부모-자식 필요) vs 지명 파이프(관계 무관) — 매년 같은 문장으로 출제
  • 공유메모리의 상호배제는 OS가 보장하지 않는다 (프로그래머 책임)
  • fork() 자식은 0, 부모는 자식 PID 반환 — if(pid==0) 분기 결과 예측 문제
  • fork()로 만든 자식의 메모리는 복사본이지 같은 위치가 아니다
  • SIGKILL(강제종료) vs SIGTERM(정상종료) vs SIGILL(잘못된 명령) vs SIGCHLD(자식종료 알림)
  • dxdiag·msconfig·regedit·mstsc 등 Windows 실행창 명령어 기능 매칭

정답 ② 사용자 명령어 관리

명령어를 해석하는 것은 쉘(shell)의 일이다. 커널은 사용자가 직접 마주하지 않고 하드웨어에 붙어 있는 안쪽 계층이라, "사용자가 타이핑한 문자열을 해석"하는 일은 하지 않는다.

구조로 기억하기: 하드웨어 ← 커널(프로세스·파일·메모리·I/O 관리) ← 쉘(명령어 해석, 창 관리) ← 사용자. 선택지에 "명령어"나 "윈도우"라는 단어가 보이면 그것이 정답(커널 아님)일 가능성이 매우 높다.

같은 유형 (2015 지방직): "유닉스 커널에 속하지 않는 것" → ① 스케줄러 ② 파일 관리자 ③ 메모리 관리자 ④ 윈도우 관리자 → 정답 ④. 완전히 같은 논리다.

정답 ② (어셈블리 언어가 아니라 C언어)

UNIX의 역사적 의의가 바로 여기 있다. 그전까지 운영체제는 기계마다 어셈블리로 새로 짜야 했는데, UNIX는 대부분을 C언어로 작성해서 다른 기종으로 옮길 때 다시 컴파일만 하면 되게 만들었다. 이식성(portability)이 UNIX가 널리 퍼진 결정적 이유다. BSD(버클리 배포판)도 마찬가지로 대부분 C로 작성되었다.

정답 ① 파일 이름

i-node에는 파일에 관한 거의 모든 것이 들어 있다 — 종류, 소유자, 접근 권한, 접근·생성 시간, 크기, 링크 수, 데이터가 저장된 블록 주소. 딱 하나 없는 것이 파일 이름이다.

  2. 덕분에 서로 다른 이름이 같은 i-node를 가리킬 수 있다 → 이것이 하드 링크
  3. 그래서 파일 이름만 바꾸는 mv는 i-node를 전혀 건드리지 않고 디렉터리 엔트리만 고친다

정답 ③ (인덱스 정보는 별도 블록이 아니라 i-node 안에 있음)

직접/단일·이중·삼중 간접 블록 포인터는 i-node의 구성 요소다. 별개의 "인덱스 블록"이라는 것이 따로 존재하는 게 아니다.

왜 포인터가 여러 단계인가: 작은 파일은 직접 포인터(i-node에 데이터 블록 주소가 바로 적힘)만으로 충분하다. 파일이 커지면 주소를 다 담을 수 없으므로, 단일 간접(주소들이 모인 블록을 가리킴) → 이중 간접(주소 블록들의 주소 블록) → 삼중 간접으로 단계를 늘린다. 작은 파일은 빠르게, 큰 파일도 가능하게 만든 절충안이다.

①②④는 모두 정확한 설명이다. 특히 ④는 문제 3번의 "파일 이름은 디렉터리가 관리"와 같은 이야기다.

  2. 읽기와 쓰기 권한은 있으나 실행 권한은 없다.
  3. 읽기와 실행 권한은 있으나 쓰기 권한은 없다.
  4. 쓰기와 실행 권한은 있으나 읽기 권한은 없다.
해설 보기

정답 ③ 읽기와 실행 권한은 있으나 쓰기 권한은 없다

참고로 최종 상태 전체는 소유자 r-x(5), 그룹 -w-(3에서 x 제거 → 2), 나머지 ---(1에서 x 제거 → 0)이 되어 520이다.

UNIX에서의 프로세스 간 통신(IPC)에 대한 설명으로 옳지 않은 것은?

  2. 시그널(signal)은 커널 혹은 프로세스가 다른 프로세스에게 비동기적으로 특정 사건을 통지하는 데 사용된다.
  3. 지명 파이프(named pipe)를 통해 통신하는 프로세스 간에는 부모-자식 관계가 요구된다.
  4. 공유메모리(shared memory)에 대한 상호 배제(mutual exclusion)는 운영체제가 보장하지 않는다.
해설 보기

정답 ③ (부모-자식 관계가 필요한 건 익명 파이프)

파이프는 두 종류인데 딱 이 점에서 갈린다.

  1. 익명 파이프: 이름이 없으므로 "내가 만든 파이프가 어느 것인지" 알려줄 방법이 상속밖에 없다 → 부모가 만들어서 자식에게 물려주는 가족 관계 필수
  2. 지명 파이프: 파일시스템에 이름이 있으므로 아무 프로세스나 그 이름으로 열면 된다 → 관계 불필요, 파일처럼 영구적

④번이 맞는 설명이라는 점도 중요하다. 공유 메모리는 OS가 "여기 메모리 같이 써라"까지만 해주고, 두 프로세스가 동시에 같은 자리에 쓰는 사고는 프로그래머가 세마포어 등으로 직접 막아야 한다.

2025 국가직에도 똑같은 문장이 그대로 출제되었다 — "지명 파이프는 부모-자식 관계가 반드시 필요하다"가 정답(틀린 설명)이었다. 이 문장은 통째로 외워도 된다.

유닉스 시스템 신호에 대한 설명으로 옳은 것은?

  1. SIGKILL : abort()에서 발생되는 종료 시그널
  2. SIGTERM : 잘못된 하드웨어 명령어를 수행하는 시그널
  3. SIGILL : 터미널에서 CTRL+Z 할 때 발생하는 중지 시그널
  4. SIGCHLD : 프로세스의 종료 혹은 중지를 부모에게 알리는 시그널
해설 보기

정답 ④ SIGCHLD

시그널 이름은 대부분 영어 약자가 곧 뜻이라 이름만 풀어도 답이 나온다.

  1. SIGCHLD = SIGnal + CHiLD → 자식 프로세스가 종료·중지될 때 부모에게 알림 → ④번 맞음
  2. ① SIGKILL은 강제 종료(무시할 수 없는 킬 명령)다. abort()로 발생하는 것은 SIGABRT
  3. ② SIGTERM은 TERMinate — 정상적으로 종료해 달라는 요청이다 (잘못된 하드웨어 명령이 아님)
  4. ③ SIGILL은 ILLegal — 잘못된 명령어 실행 시 발생한다 (CTRL+Z 중지는 SIGTSTP)

패턴: 이 문제는 네 개의 설명을 서로 한 칸씩 밀어서 섞어 놓은 전형적인 구조다. ②번 설명(잘못된 하드웨어 명령)은 사실 ③번 SIGILL의 것이다. 이름 뜻만 알면 이런 뒤섞기는 바로 보인다.

문제 102023 국가직 · 기출문제집 p.276

운영체제 시스템 호출에 대한 설명으로 옳지 않은 것은?

  1. fork()는 실행 중인 프로세스를 복사하는 함수이다.
  2. fork() 호출 시 부모 프로세스와 자식 프로세스가 차지하는 메모리 위치는 동일하다.
  3. exec()는 이미 만들어진 프로세스의 구조를 재활용하는 함수이다.
  4. exec() 호출에 사용되는 함수 중 wait()는 프로세스 종료 대기를 처리한다.
해설 보기

정답 ② (메모리 위치는 동일하지 않고 복사본을 가짐)

fork()의 핵심은 "복사"라는 단어에 있다. 자식은 부모의 메모리 내용을 그대로 복제한 자기만의 공간을 갖는다. 같은 공간을 나눠 쓰는 것이 아니다.

  1. 그래서 fork 직후 두 프로세스의 변수 값은 같지만, 한쪽에서 값을 바꿔도 다른 쪽은 영향받지 않는다
  2. 만약 정말 메모리를 공유하고 싶다면 공유 메모리(shared memory)를 따로 써야 한다 — 그래서 IPC가 별도로 존재하는 것이다
  3. ①③④는 모두 맞는 설명이다. exec()는 프로세스를 새로 만들지 않고 내용만 갈아끼우므로 "구조를 재활용"이 맞다

연결해서 이해하기: "자식이 부모 메모리를 복사한다"는 사실이 바로 다음 문제(fork 출력 예측)에서 부모와 자식이 각자 v=1부터 따로 계산하는 이유다.

문제 112020 지방직 · 기출문제집 p.276

다음은 리눅스에서 fork() 시스템 호출을 이용해 자식 프로세스를 생성하는 C 프로그램이다. 출력 결과로 옳은 것은? (단, pid = fork(); 수행 결과 자식 프로세스 생성에 성공했다고 가정)

int main(void) {
  int i=0, v=1, n=5;
  pid_t pid;
  pid = fork();
  if( pid < 0 ) {
    for(i=0; i < n; i++) v+=(i+1);
    printf("c = %d ", v);
  } else if( pid == 0 ) {
    for(i=0; i < n; i++) v*=(i+1);
    printf("b = %d ", v);
  } else {
    wait(NULL);
    for(i=0; i < n; i++) v+=1;
    printf("a = %d ", v);
  }
  return 0;
}
  1. b=120, a=6
  2. c=16, b=120
  3. b=120, c=16
  4. a=6, c=16
해설 보기

정답 ① b=120, a=6

  1. 실행되는 분기 확정: 문제에서 fork가 성공했다고 했으므로 pid < 0(실패) 분기는 절대 실행되지 않는다 → "c = ..." 출력은 나올 수 없다 → ②③④ 즉시 탈락
  2. 자식 프로세스 (pid == 0): v=1에서 시작해 i=0~4 동안 v *= (i+1) → 1×1×2×3×4×5 = 120 → b = 120
  3. 부모 프로세스 (else): v=1에서 시작해 v += 1을 5번 → 1+5 = 6 → a = 6
  4. 순서: 부모가 wait(NULL)로 자식을 기다리므로 자식(b) 먼저, 부모(a) 나중 → "b = 120 a = 6"

이 문제는 사실 선택지만 봐도 절반이 풀린다. "fork 성공"이라고 명시했으면 c는 나올 수 없으므로, c가 들어간 선택지를 전부 지우면 ①만 남는다. 시간이 없을 때 쓸 수 있는 요령이다.

계산 함정: 자식의 v를 5! = 120이 아니라 초기값을 잊고 다르게 계산하거나, 부모의 v를 1+5=6이 아니라 5로 세는 실수가 흔하다. v의 초기값이 1이라는 점을 항상 먼저 확인할 것.

유닉스 계열 운영체제에서 사용하는 명령과 그 설명이 옳은 것은?

  2. umount : 저장장치의 파일시스템을 디렉터리 트리에 연결한다.
  3. ln : 파일을 복사한다.
  4. pwd : 사용자의 비밀번호를 설정하거나 변경한다.

정답 ① grep

나머지는 모두 비슷한 이름의 다른 명령어와 바꿔치기한 것이다.

  1. ② umount는 연결 해제다. 연결하는 건 mount — 앞의 u가 un(해제)을 뜻한다
  2. ③ ln은 링크(link) 생성이다. 복사는 cp. 기본은 하드링크이고 -s를 붙이면 심볼릭 링크
  3. ④ pwd는 print working directory, 즉 현재 경로 출력이다. 비밀번호는 passwd

grep 어원: global regular expression print — "전체에서 정규식에 맞는 걸 찾아 출력". 이름 자체가 기능 설명이다.
