기억장치 관리정책

오버레이·스와핑·분할방식·메모리 배치 정책 · PART 02. 운영체제론

핵심 요약

가변분할 방식에서 빈 공간에 프로세스를 배치하는 3가지 정책 — 최초적합(First-fit) · 최적적합(Best-fit) · 최악적합(Worst-fit).

고정분할은 내부 단편화, 가변분할은 외부 단편화가 발생한다.

🎯이 단원을 왜 배우나

"메모리는 항상 모자란다"에서 출발한 기술들

프로그램을 실행하려면 주기억장치(RAM)에 올려야 한다. 그런데 RAM은 언제나 부족하다. 이 부족함을 어떻게 메울 것인가 — 운영체제의 메모리 관리는 전부 이 질문에 대한 답이다. 역사적으로 답이 세 단계로 발전했다.

  • 1단계 오버레이: "프로그램이 메모리보다 크다" → 프로그램을 조각내서 지금 필요한 조각만 올린다. 단, 어느 조각을 언제 올릴지 프로그래머가 직접 지정해야 했다.
  • 2단계 스와핑: "프로세스가 여러 개라 다 못 올린다" → 당장 안 쓰는 프로세스는 통째로 디스크에 내려두고 필요할 때 다시 올린다.
  • 3단계 가상메모리: 위 두 아이디어를 운영체제가 자동으로, 페이지 단위로 해주는 것. (→ 가상 메모리 문서)

그리고 메모리를 나눠 쓰려면 "어떻게 자를 것인가(분할 방식)"와 "빈칸 중 어디에 넣을 것인가(배치 정책)"를 정해야 한다. 자르는 방식에 따라 버려지는 자투리(단편화)의 종류가 달라지고, 넣는 위치를 고르는 방식이 최초·최적·최악 적합이다. 시험은 거의 항상 이 두 가지 — 단편화 종류 구분과 배치 정책 계산 — 에서 나온다.

💡주요 개념

오버레이 (Overlay)

프로그램 크기가 실제 메모리보다 클 때, 전체를 한 번에 올리지 않고 필요한 부분만 적당한 크기로 잘라서 순차적으로 가져오는 기법.

비유: 책상(메모리)이 좁아 두꺼운 참고서 전체를 못 올려놓으니, 지금 푸는 단원만 복사해서 올려놓고 다음 단원으로 넘어갈 때 바꿔 끼우는 것. 어느 단원을 언제 올릴지는 내가(프로그래머가) 직접 정해야 한다는 것이 한계다.

스와핑 (Swapping) 📖 기출문제집 p.238

용어방향외우는 법
스왑 인 (Swap-in)보조기억장치 → 주기억장치로 프로세스를 가져옴메모리 안(in)으로 들여온다
스왑 아웃 (Swap-out)주기억장치 → 보조기억장치로 프로세스를 내보냄메모리 밖(out)으로 내보낸다
함정 주의: "스왑 영역(보조기억장치)에서 메모리로 데이터를 가져오는 작업"은 스왑 아웃이 아니라 스왑 인이다. 방향을 바꿔서 내는 문제가 반복 출제된다. 기준점은 항상 주기억장치(메모리)다 — 메모리 쪽으로 오면 in, 메모리에서 나가면 out.

분할 방식과 단편화 📖 기출문제집 p.243

구분고정 분할방식가변 분할방식 (세그멘테이션)
분할 기준프로세스 크기와 무관하게 동일 크기로 분할프로세스 크기에 맞춰 분할
발생하는 단편화내부 단편화외부 단편화 (내부 단편화는 없음)
해결 방법페이지 크기 조정압축(Compaction, 조각모음) — 쓰레기 수집
비유: 내부 단편화 = 큰 상자에 작은 물건을 넣어 상자 안에 남는 빈틈, 외부 단편화 = 여러 상자 사이사이에 남는, 너무 작아서 못 쓰는 빈 공간.

가변분할에 내부 단편화가 "없는" 이유 (출제 포인트)

가변분할은 프로세스 크기에 딱 맞춰서 공간을 잘라준다. 12KB 프로세스에는 정확히 12KB를 준다. 그러니 할당받은 영역 안쪽에 남는 자투리가 생길 수 없다 → 내부 단편화 0.

대신 프로세스가 들어오고 나가기를 반복하면 사이사이에 어중간하게 작은 빈칸이 흩어져 남는다. 전부 합치면 충분한데 연속되지 않아서 쓸 수 없는 상태 — 이것이 외부 단편화다. 그래서 해결책도 "합치기"다: 압축(compaction)으로 사용 중인 영역을 한쪽으로 몰아 빈칸을 하나로 모으거나, 통합(coalescing)으로 인접한 빈칸끼리 합친다.

고정분할은 정반대다. 12KB 프로세스에 20KB짜리 칸을 통째로 주므로 칸 안에 8KB가 버려진다(내부 단편화). 대신 칸 크기가 정해져 있어 빈칸은 언제나 "한 칸" 단위로 재사용 가능하다.

메모리 배치 정책 (가변분할에서 어디에 넣을까) 📖 기출문제집 p.239

정책방식특징
최초 적합
(First-fit)		맨 앞부터 탐색해 처음으로 맞는 공간에 배치탐색 시간이 짧음 (찾는 즉시 멈춤)
최적 적합
(Best-fit)		요청 크기에 가장 가깝게 맞는(가장 작은 여유) 공간에 배치남는 조각 최소화, 탐색 시간이 김 (전체 탐색 필요)
최악 적합
(Worst-fit)		가장 큰 공간에 배치배치 후 남는 공간을 크게 남겨 재사용성을 높이려는 의도

세 정책 문제를 3초 만에 푸는 순서

  1. 후보 거르기: 요청 크기보다 작은 빈칸은 전부 지운다 (애초에 못 들어감). 이 단계를 건너뛰어서 틀리는 경우가 가장 많다.
  2. 최초적합이면 남은 후보 중 번호(주소)가 가장 앞선 것 → 끝. 전체를 볼 필요 없다.
  3. 최적적합이면 남은 후보 중 크기가 가장 작은 것 (= 남는 자투리가 최소).
  4. 최악적합이면 남은 후보 중 크기가 가장 큰 것.

주의: "최적"과 "최악"은 후보 중에서 크기 순으로 고르는 것이지, 순서(주소)와는 무관하다. 반대로 "최초"는 순서만 보고 크기는 안 본다.

계산 예제 ① (2025 지방직): 빈 공간 1번(10KB)·2번(25KB)·3번(30KB)·4번(15KB), 12KB 프로세스 요청 📖 기출문제집 p.239
  1. 1번(10KB)은 12KB보다 작아 애초에 후보에서 제외 — 남은 후보: 2번(25KB), 3번(30KB), 4번(15KB)
  2. 최초적합: 앞에서부터 순서대로 탐색 → 처음 만나는 2번(25KB)에 배치, 남는 공간 13KB
  3. 최적적합: 후보 전부를 비교해 가장 작게 남는 곳 선택 → 4번(15KB)에 배치, 남는 공간 3KB(최소)
  4. 최악적합: 후보 전부를 비교해 가장 크게 남는 곳 선택 → 3번(30KB)에 배치, 남는 공간 18KB(최대)
계산 예제 ② (2017 지방직): 프로세스가 연속으로 들어올 때 — 여기서 난이도가 올라간다 📖 기출문제집 p.242
가용 공간: w(30KB), x(20KB), y(15KB), z(35KB). 프로세스 25KB → 30KB → 15KB → 10KB가 순차 요청, 최악적합 적용.
  1. 25KB 요청: 들어갈 수 있는 곳 w(30), z(35) → 가장 큰 z(35)에 배치. z의 남은 크기 = 35−25 = 10KB
  2. 30KB 요청: 현재 w(30), x(20), y(15), z(10) → 30 이상인 곳은 w(30)뿐 → w에 배치. w 남은 크기 = 0
  3. 15KB 요청: 현재 x(20), y(15), z(10) → 후보 x(20), y(15) 중 가장 큰 x(20)에 배치. x 남은 = 5KB
  4. 10KB 요청: 현재 y(15), z(10), x(5) → 후보 y(15), z(10) 중 가장 큰 y(15)에 배치
  5. 정답 순서: z → w → x → y
핵심: 프로세스가 연달아 들어오는 문제는 한 번 배치할 때마다 그 칸의 남은 크기를 갱신해야 한다. 원래 크기로 계속 계산하면 반드시 틀린다.

버디 시스템 (Buddy System)

메모리를 2의 거듭제곱 크기로 반복적으로 이등분하여 관리하다가, 인접한 빈 버퍼(버디)끼리는 다시 합쳐서(병합) 재사용한다. 고정분할·가변분할 방식의 단편화 문제를 절충해서 완화하는 기법이다.

버디 시스템의 동작과 한계

1024KB 메모리에서 70KB를 요청하면 → 1024를 512+512로 쪼개고 → 512를 256+256으로 → 256을 128+128로 쪼갠 뒤, 128KB짜리 한 칸을 통째로 준다. 70KB만 필요한데 128KB를 받았으니 58KB가 내부 단편화로 버려진다.

그래서 시험에서 "버디 시스템은 내부 단편화를 최소화한다"는 선택지는 틀린 설명이다 (2022 국회 기출). 버디 시스템의 진짜 장점은 해제할 때 짝(버디)끼리 빠르게 병합되어 외부 단편화를 억제하고 관리가 단순하다는 점이다.

📌시험 빈출 포인트

  • 스왑인(보조→주기억) vs 스왑아웃(주기억→보조) 방향 구분 — 자주 뒤집어서 오답 유도
  • First-fit / Best-fit / Worst-fit 각각 어디에 배치되는지 계산하는 문제 (거의 매년 출제)
  • 연속 요청 문제는 배치할 때마다 남은 크기를 갱신해야 함
  • 가변분할 방식은 내부 단편화가 발생하지 않는다 (외부 단편화만 발생)
  • 고정분할 방식은 크기가 고정되어 있어 내부 단편화가 발생한다
  • 외부 단편화 해결책 = 압축(Compaction, 조각모음) / 통합(Coalescing)
  • Best-fit은 남는 조각을 최소화하지만, 전체 공간 목록을 다 봐야 해서 느림
  • 버디 시스템은 2의 거듭제곱 단위 할당 → 내부 단편화가 발생한다 (최소화한다는 설명은 오답)

✏️연습문제

먼저 스스로 풀어본 뒤 "해설 보기"를 눌러 확인하세요.

문제 12024 법원직 · 기출문제집 p.238

다음 설명 중 가장 옳지 않은 것은?

  1. 메모리 오버레이는 프로그램의 크기가 실제 메모리보다 클 때 전체 프로그램을 메모리에 가져오는 대신 적당한 크기로 잘라서 가져오는 기법이다.
  2. 스왑 영역에서 메모리로 데이터를 가져오는 작업을 스왑아웃이라 한다.
  3. 메모리 분할방식은 가변분할방식과 고정분할방식으로 구분한다.
  4. 가변분할방식은 프로세스의 크기에 맞춰 메모리를 할당하는 방법으로 세그먼테이션 메모리관리기법이라 한다.
해설 보기

정답 ② (스왑인이 맞다)

  1. 기준점은 언제나 주기억장치(메모리)다.
  2. 스왑 영역(보조기억장치) → 메모리로 들어오는 것이므로 스왑 인(swap-in).
  3. 반대로 메모리 → 스왑 영역으로 나가는 것이 스왑 아웃(swap-out)이다.

암기법: "메모리 안으로 = in / 메모리 밖으로 = out". 디스크를 기준으로 생각하면 방향이 반대로 헷갈리니, 항상 메모리를 기준으로 잡아라.

문제 22025 지방직 · 기출문제집 p.239

가변 분할 메모리 관리 기법을 사용하며, 비어 있는 메모리 상태가 순서대로 1번 10KB, 2번 25KB, 3번 30KB, 4번 15KB이다. 새로운 프로세스가 12KB를 요청하여 4번 위치로 할당되었다면, 적용된 메모리 할당 기법은?

  1. 중앙 적합(center fit)
  2. 최악 적합(worst fit)
  3. 최적 적합(best fit)
  4. 최초 적합(first fit)
해설 보기

정답 ③ 최적 적합

  1. 후보 거르기: 12KB가 들어갈 수 있는 곳은 2번(25KB), 3번(30KB), 4번(15KB). 1번(10KB)은 탈락.
  2. 각 정책이 고를 곳을 미리 계산해 본다 — 최초적합 = 2번(앞에서 처음 맞는 곳), 최적적합 = 4번(15KB, 가장 작게 남음 3KB), 최악적합 = 3번(30KB, 가장 크게 남음 18KB).
  3. 문제에서 실제 배치된 곳이 4번이므로 → 최적 적합.

함정: ①번 "중앙 적합"은 존재하지 않는 용어다. 배치 정책은 최초·최적·최악 3가지뿐이라는 것도 함께 기억할 것.

문제 32010 계리직 · 기출문제집 p.241

주기억장치의 사용 가능 영역이 시작 부분부터 순서대로 M1=16KB, M2=14KB, M3=5KB, M4=30KB이다. 13KB를 요구하는 작업이 최초적합·최적적합·최악적합으로 각각 배치될 때 결과로 옳은 것은? (순서대로 최초적합, 최적적합, 최악적합)

  1. M1, M2, M3
  2. M1, M2, M4
  3. M2, M1, M4
  4. M4, M2, M3
해설 보기

정답 ② M1, M2, M4

  1. 후보 거르기: 13KB 이상인 곳만 남긴다 → M1(16), M2(14), M4(30). M3(5KB)는 탈락.
  2. 최초적합: 앞에서부터 처음 맞는 곳 → M1(16KB)
  3. 최적적합: 후보 중 가장 작은 곳 → M2(14KB) — 남는 공간 1KB로 최소 → M2
  4. 최악적합: 후보 중 가장 큰 곳 → M4(30KB)

함정: ①·④번은 M3(5KB)를 답에 포함했는데, 13KB가 5KB 칸에 들어갈 수 없으므로 애초에 불가능하다. 후보 거르기를 먼저 하면 선택지 절반이 바로 날아간다.

문제 42017 지방직 · 기출문제집 p.242

가용 공간이 w(30KB), x(20KB), y(15KB), z(35KB)일 때, 크기가 각각 25KB, 30KB, 15KB, 10KB인 프로세스가 순차적으로 적재 요청된다. 최악적합(worst-fit)을 사용할 경우 할당되는 가용 공간의 시작주소를 순서대로 나열한 것은?

  1. w → x → y → z
  2. x → y → z → w
  3. y → z → w → x
  4. z → w → x → y
해설 보기

정답 ④ z → w → x → y

한 번 배치할 때마다 그 칸의 남은 크기를 갱신하는 것이 이 문제의 전부다.

요청배치 직전 가용 공간선택(가장 큰 것)배치 후
25KBw30, x20, y15, z35zz = 35−25 = 10
30KBw30, x20, y15, z10w (30 이상은 w뿐)w = 0
15KBw0, x20, y15, z10xx = 20−15 = 5
10KBw0, x5, y15, z10yy = 5

함정: 2번째 요청(30KB)에서 "가장 큰 건 z니까 z" 라고 하면 틀린다 — z는 이미 25KB를 받아 10KB만 남았다. 갱신된 크기로 다시 판단해야 한다.

문제 52022 지방직 · 기출문제집 p.243

다중 프로그래밍 환경에서 연속 메모리 할당 방법에 대한 설명으로 옳지 않은 것은?

  1. 가변분할 메모리 할당은 프로세스의 크기에 따라 메모리를 나누는 것으로 단편화 문제가 발생하지 않는다.
  2. 가변분할 메모리 할당의 메모리 배치방법으로는 최초 적합, 최적 적합, 최악 적합 방법이 있다.
  3. 고정분할 메모리 할당은 프로세스의 크기와 상관없이 메모리를 같은 크기로 나누는 것이다.
  4. 고정분할 메모리 할당에서는 쓸모없는 공간으로 인해 메모리 낭비가 발생할 수 있다.
해설 보기

정답 ①

  1. 가변분할은 내부 단편화는 발생하지 않는다 — 여기까지는 맞다.
  2. 그러나 프로세스가 들락날락하면서 사이사이에 작은 조각이 남는 외부 단편화는 발생한다.
  3. 따라서 "단편화 문제가 발생하지 않는다"는 과장된 서술이라 틀림. (외부 단편화는 압축·통합으로 해결)

구분 요령: 선택지에 "가변분할 + 단편화"가 나오면 어떤 단편화인지를 확인해라. "내부 단편화 없음" = 맞음 / "단편화 전혀 없음" = 틀림.

문제 62022 국회직 · 기출문제집 p.238~239

메모리 관리 방안에 대한 설명으로 옳은 것만 모두 고르면?

  1. ㄱ. Worst-fit 할당은 가장 큰 공간에 프로세스를 배치하는 방식이다.
  2. ㄴ. Best-fit 할당 방식은 요청 크기에 가장 일치하는 블록을 할당함으로써 외부 단편화를 최소화할 수 있다.
  3. ㄷ. First-fit 할당 방식은 요청 크기를 할당할 수 있는 블록을 찾았을 때 바로 할당함으로써 탐색 시간을 줄일 수 있다.
  4. ㄹ. Buddy 할당 방식은 메모리를 2의 거듭제곱 단위 크기로 할당하여 내부 단편화를 최소화할 수 있다.
해설 보기

정답: ㄱ, ㄷ

  1. ㄱ 맞음: Worst-fit = 가장 큰 공간에 배치. 정의 그대로.
  2. ㄴ 틀림: Best-fit이 최소화하는 것은 내부 단편화(= 남는 자투리)다. "외부"로 바꿔 쓴 함정.
  3. ㄷ 맞음: First-fit은 처음 맞는 곳을 찾으면 즉시 멈추므로 탐색 시간이 짧다.
  4. ㄹ 틀림: Buddy는 2의 거듭제곱 단위로 올려서 할당하므로(70KB 요청 → 128KB 할당) 오히려 내부 단편화가 발생한다. 최소화가 아니다.

패턴: 이 유형은 정의는 맞게 쓰고 "내부/외부" 한 단어만 바꿔 함정을 만든다. 단편화 단어가 보이면 종류부터 확인할 것.

문제 72010 지방직 · 기출문제집 p.239~240

주기억장치의 사용 가능 영역이 1번(40K), 3번(145K), 5번(300K), 7번(15K)이고 2·4·6번은 사용 중이다. 최악적합으로 15K 기억공간을 요청받은 경우 배당되는 영역 번호는?

  1. 1
  2. 3
  3. 5
  4. 7
해설 보기

정답 ③ 5번(300K)

  1. 후보: 15K 이상인 곳 → 1번(40K), 3번(145K), 5번(300K), 7번(15K) — 모두 가능 (7번은 딱 맞음)
  2. 최악적합은 가장 큰 곳을 고른다 → 5번(300K)

함정: ④번 7번(15K)은 최적적합의 답이다(딱 맞아떨어져 남는 공간 0). ①번 1번(40K)은 최초적합의 답이다(앞에서 처음 맞는 곳). 이렇게 세 정책의 답을 모두 선택지에 깔아두는 것이 이 유형의 전형적인 구성이므로, 문제에서 요구한 정책이 무엇인지부터 다시 확인하는 습관을 들여라.

문제 8개념 확인 · 응용

고정분할 방식에서 블록 크기가 모두 32KB이고, 크기가 20KB·35KB·8KB인 세 프로세스를 적재했다. 발생하는 내부 단편화의 총합은? (35KB 프로세스는 두 블록에 걸쳐 적재된다고 가정)

해설 보기

정답: 53KB

  1. 20KB 프로세스: 32KB 블록 1개 사용 → 내부 단편화 32 − 20 = 12KB
  2. 35KB 프로세스: 32KB 블록 2개(=64KB) 사용 → 내부 단편화 64 − 35 = 29KB
  3. 8KB 프로세스: 32KB 블록 1개 사용 → 내부 단편화 32 − 8 = 12KB
  4. 총합 = 12 + 29 + 12 = 53KB

계산 원리: 내부 단편화 = (할당받은 블록들의 총 크기) − (프로세스 실제 크기). 프로세스가 블록 크기의 배수가 아닐 때 마지막 블록에서 반드시 자투리가 생긴다. 평균적으로 프로세스당 블록 크기의 절반이 낭비된다고 보는 것이 일반적인 추정이다.
