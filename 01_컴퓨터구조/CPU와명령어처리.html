CPU 레지스터와 명령어 처리

레지스터 종류 · 명령어 사이클 · 주소지정방식 · PART 01. 전자계산기구조론

핵심 요약

CPU는 PC(다음 주소) → MAR(접근 주소) → MBR(주고받는 데이터) → IR(현재 명령어) → AC(연산 결과) 순서로 레지스터를 거쳐 명령어를 처리한다.

명령어 처리는 인출(Fetch) → 해독(Decode) → 실행(Execute) → 인터럽트 확인의 반복이다.

🎯이 단원을 왜 배우나

CPU는 "한 번에 한 명령어씩" 똑같은 동작을 반복하는 기계다

CPU가 하는 일은 겉보기엔 복잡해 보이지만, 실제로는 딱 네 동작을 죽을 때까지 반복하는 것뿐이다 — 메모리에서 명령어를 꺼내오고(인출), 그게 무슨 명령인지 해독하고(해독), 시키는 대로 하고(실행), 급한 일이 생겼는지 확인한다(인터럽트 확인). 전원이 켜진 순간부터 꺼질 때까지 이 사이클이 초당 수십억 번 돌아간다.

그런데 "메모리에서 꺼내온다"는 말은 물리적으로 주소를 어딘가에 적어서 메모리에 보내고, 돌아온 데이터를 어딘가에 받아둔다는 뜻이다. 그 "어딘가"가 바로 레지스터다. PC는 다음에 읽을 주소, MAR은 지금 접근할 주소, MBR은 주고받는 데이터, IR은 지금 해독 중인 명령어를 담는다. 레지스터 이름을 외우는 게 아니라, 사이클의 어느 단계에서 어떤 레지스터가 쓰이는지 흐름으로 이해하면 관련 문제가 전부 한 덩어리로 풀린다.

마지막으로, 명령어 안에는 "무엇을 할지(OP-Code)"와 "누구를 대상으로 할지(오퍼랜드)"가 적혀 있다. 오퍼랜드가 대상을 가리키는 방법이 여러 가지인데 이것이 주소지정 방식이고, 시험에서는 특히 "메모리에 몇 번 접근하는가"를 집요하게 묻는다.

💡주요 개념

CPU 내부 레지스터 📖 기출문제집 p.91~95

레지스터이름역할
PCProgram Counter (프로그램 카운터)다음에 인출할 명령어의 주소를 기억. 인출할 때마다 자동 증가, 분기 시 목적지 주소로 갱신
IRInstruction Register (명령어 레지스터)가장 최근에 인출된 명령어(코드+오퍼랜드)를 저장
MARMemory Address RegisterCPU가 기억장치에 접근할 때 필요한 주소를 저장
MBRMemory Buffer Register기억장치에 쓰거나 읽은 데이터를 일시 저장 (기억장치 출입 데이터는 반드시 이곳을 거침)
ACAccumulator (누산기)연산 과정의 데이터와 결과값을 일시 저장
자주 나오는 함정: "가장 최근에 인출한 명령어를 보관" → IR이 정답 (MAR 아님). MAR·MBR은 오답 선택지로 자주 뒤바뀌어 나온다.

명령어 실행 사이클 (Instruction Cycle) 📖 기출문제집 p.96~97

순서단계레지스터 이동
1인출 (Fetch)MAR ← PC → MBR ← M[MAR] → IR ← MBR
2해독 (Decode)IR의 내용을 해석해 명령어 종류 파악
3실행 (Execute)해독 결과에 따라 제어신호를 보내 연산 수행
4인터럽트 확인요청이 있으면 인터럽트 사이클로, 없으면 다시 인출로
비유: PC = "다음에 읽을 페이지 번호", MAR = "책장에서 그 페이지를 찾기 위한 색인", MBR = "찾은 내용을 옮겨 담는 바구니", IR = "지금 읽고 있는 문장"

순서를 묻는 문제가 매년 나오므로, 레지스터 사이로 값이 옮겨 다니는 경로를 그림으로 한 번 익혀두면 외울 필요가 없어진다.

순서 문제를 푸는 요령

기출은 늘 다음 5개를 섞어놓고 순서를 맞추라고 한다: ㄱ. PC값을 MAR로 적재 / ㄴ. 메모리에서 읽어 MBR로 적재 / ㄷ. MBR의 명령어를 IR로 적재 / ㄹ. IR을 해독해 연산 수행 / ㅁ. 인터럽트 발생 유무 확인.

정답 순서는 언제나 ㄱ → ㄴ → ㄷ → ㄹ → ㅁ이다. 외우기 어려우면 이렇게 생각하라 — "주소부터 보내야(ㄱ) 읽어올 수 있고(ㄴ), 읽어와야 해독할 자리에 놓고(ㄷ), 놓아야 해독·실행하며(ㄹ), 다 끝나고 나서야 다른 일을 확인한다(ㅁ)." 각 단계는 앞 단계 없이는 불가능하므로 논리적으로 순서가 하나뿐이다.

PC 증가 시점 주의: PC는 인출 직후(ㄴ 단계 무렵)에 이미 +1 된다. "실행이 끝난 뒤에 증가한다"는 선택지는 오답이다.

제어장치 vs 연산장치 구성요소 구분 📖 기출문제집 p.90~91

제어장치 (CU)연산장치 (ALU)
PC, IR, MAR, MBR누산기(AC), 시프트 레지스터
순서 제어 논리장치, 명령어 해독기가산기, 보수기
함정: "시프트 레지스터"는 제어장치가 아니라 연산장치에 해당한다 (자주 나오는 오답 선택지)

ALU는 실제로 어떻게 동작하나 — CPU 안에서의 위치

ALU 자체는 "생각"하지 않는다. 제어장치(CU)가 보낸 연산선택 신호(Opcode)에 따라 미리 만들어둔 회로 중 하나를 골라 전기 신호를 흘려보내는 것뿐이다. 덧셈/뺄셈은 4비트 병렬 가산기/감산기 같은 회로가, AND·OR 같은 논리연산은 게이트 배열이, 곱셈·나눗셈은 덧셈과 시프트의 반복으로 처리된다.

Flag가 쓰이는 예: "만약 계산 결과가 0이면 점프하라"는 조건분기 명령어는 CU가 ALU 연산 직후의 Zero 플래그를 확인해서 처리한다 — ALU와 제어장치가 분리돼 있어도 반드시 협업해야 하는 이유.

오퍼랜드 수에 따른 명령어 분류

분류설명
0-주소 명령어스택(Stack)을 이용. PUSH/POP만으로 연산 (연산자를 만나면 스택에서 2개 꺼내 계산 후 다시 삽입)
1-주소 명령어누산기(AC)를 암묵적으로 사용, 오퍼랜드 1개만 명시
2-주소 명령어연산 결과가 오퍼랜드 중 하나에 저장 (일반적인 CPU 명령어 형태)
3-주소 명령어두 개의 피연산자 + 결과 저장 위치까지 모두 명시

계산 방법: 스택은 후입선출(LIFO)이다. 숫자를 만나면 그냥 쌓고(PUSH), 연산자를 만나면 스택 맨 위에서 2개를 꺼내 계산한 뒤 그 결과를 다시 쌓는다(PUSH). 이 규칙만 지키면 순서대로 손으로 따라가도 답이 나온다.

0-주소 명령어(스택) 계산 예제: PUSH C → PUSH A → PUSH B → ADD → MUL → POP Z 📖 기출문제집 p.97
  1. PUSH C → 스택: [C]
  2. PUSH A → 스택: [C, A]
  3. PUSH B → 스택: [C, A, B]
  4. ADD → 맨 위 2개(B, A)를 꺼내 A+B 계산 후 다시 삽입 → 스택: [C, (A+B)]
  5. MUL → 맨 위 2개((A+B), C)를 꺼내 C×(A+B) 계산 후 다시 삽입 → 스택: [C×(A+B)]
  6. POP Z → 결과를 꺼내 Z에 저장 → Z = (A+B) × C

OP-Code(연산자) 비트 수가 많을수록 표현 가능한 명령어 종류가 많아진다. (오퍼랜드 필드가 아니라 OP-Code 필드가 명령어 종류 개수를 결정)

주소지정 방식 (Addressing Mode)

방식유효주소 결정 방법메모리 접근 횟수
즉치 (Immediate)오퍼랜드 자체가 데이터0회 (데이터 인출 불필요)
직접 (Direct)오퍼랜드가 곧 데이터의 주소1회
간접 (Indirect)오퍼랜드가 가리키는 곳에 또 다른 주소가 있고, 그 주소가 진짜 데이터 위치2회 (가장 많음)
레지스터 (Register)레지스터 안에 데이터가 직접 존재0회 — 접근속도 가장 빠름
레지스터 간접 (Register Indirect)레지스터 안에 유효주소가 있고, 그 주소로 메모리 접근1회
상대 (Relative)PC + 오퍼랜드(변위) = 유효주소. 주로 분기 명령어에서 사용1회
인덱스 (Indexed)인덱스 레지스터 값 + 오퍼랜드 = 유효주소1회
간접 주소지정을 쓰는 이유: 오퍼랜드 비트 수의 한계로 표현 가능한 주소 범위가 좁아지는 문제를 해결하기 위해 — 메모리 1워드 전체를 주소로 활용해 지정 가능한 주소 범위를 확대한다.

속도 순서와 그 이유

레지스터(0회) > 즉치(0회) > 직접·레지스터간접·상대·인덱스(1회) > 간접(2회) 순으로 빠르다. 메모리를 한 번 더 갈 때마다 느려지기 때문이다.

특히 "레지스터 주소지정이 직접 주소지정보다 느리다"는 서술은 틀린 문장이다(2019 지방직 출제). 레지스터는 CPU 안에 있고 직접 주소지정은 CPU 밖 주기억장치를 다녀와야 하므로, 레지스터 쪽이 압도적으로 빠르다.

상대 주소지정(PC + 변위)은 분기 명령어 전용이라고 봐도 된다. "지금 위치에서 몇 칸 떨어진 곳으로 점프"라는 뜻이라 프로그램을 메모리 어디에 올려도 그대로 동작한다(재배치 가능).

📌시험 빈출 포인트

  • 레지스터 기능 짝짓기: PC(다음 명령어 주소) / IR(현재 명령어) / MAR(접근 주소) / MBR(주고받는 데이터) / AC(연산결과)
  • 기억장치 출입 데이터는 반드시 MBR을 거친다 — "기억장치를 출입하는 데이터를 저장하는 레지스터" 문제의 정답
  • 명령어 처리 순서: PC→MAR, MBR←M[MAR], IR←MBR, 해독·실행, 인터럽트 확인
  • 0-주소 명령어(스택) 계산 문제 — PUSH/POP 순서를 스택에 직접 그려보며 풀 것
  • 간접 주소지정 방식은 메모리 접근 2회, 유효주소 확장이 목적 (보안과는 무관)
  • 레지스터 주소지정 > 직접 주소지정 > 간접 주소지정 순으로 접근 속도가 빠름
  • 상대 주소지정 = PC + 변위 → 분기(branch) 명령어에서 사용된다는 것 암기
  • 캐시 메모리는 CPU 내부 "레지스터"가 아니다 — 레지스터 목록을 고르는 문제의 단골 오답
  • 제어장치 구성요소 = PC·IR·MAR·MBR·명령어 해독기·순서 제어 논리장치 / 시프트 레지스터·가산기·보수기는 연산장치
  • "기억장치에서 꺼내진 명령어를 누산기가 기억한다" → 오답 (MBR을 거쳐 IR로 간다. 누산기는 LOAD된 데이터를 받음)
  • CPU와 주기억장치 사이 통신은 DMA가 아니다 — DMA는 주기억장치↔입출력장치 사이를 CPU 없이 잇는 방식

  2. 캐시 메모리 (cache memory)
  3. 프로그램 카운터 (program counter)
  4. 메모리 버퍼 레지스터 (memory buffer register)
해설 보기

정답 ② 캐시 메모리

CPU 내부 레지스터는 PC, IR, MAR, MBR, AC(누산기) 등이다. 캐시 메모리는 CPU와 주기억장치 사이의 속도 차이를 줄이기 위한 별도의 고속 기억장치로, 지역성(locality)을 이용해 자주 쓰는 데이터를 미리 담아두는 장치다.

함정: 요즘 CPU는 캐시를 칩 안에 내장하고 있어서 "CPU 안에 있으니 레지스터 아닌가?" 싶을 수 있다. 하지만 물리적 위치와 논리적 분류는 별개다 — 레지스터는 명령어가 직접 이름을 불러 쓰는 저장소이고, 캐시는 프로그래머에게 보이지 않는 자동 버퍼다. 자세한 내용은 캐시기억장치 문서 참고.

문제 22020 국가직 · 기출문제집 p.93

CPU 내의 레지스터에 대한 설명으로 옳지 않은 것은?

  1. Accumulator(AC): 연산 과정의 데이터를 일시적으로 저장하는 레지스터
  2. Program Counter(PC): 다음에 인출될 명령어의 주소를 보관하는 레지스터
  3. Memory Address Register(MAR): 가장 최근에 인출한 명령어를 보관하는 레지스터
  4. Memory Buffer Register(MBR): 기억장치에 저장될 데이터 혹은 기억장치로부터 읽힌 데이터가 일시적으로 저장되는 버퍼 레지스터
해설 보기

정답 ③ — "가장 최근에 인출한 명령어"를 보관하는 것은 IR이다

  1. MAR은 CPU가 주기억장치에 접근할 때 필요한 주소를 담는다 (명령어 자체가 아니라 그 명령어가 있는 번지)
  2. 가장 최근에 인출된 명령어 자체를 담는 것은 IR(Instruction Register)
  3. ①·②·④는 모두 올바른 설명

구분 요령: 이름에 Address가 들어가면 주소(MAR), Buffer가 들어가면 데이터(MBR), Instruction이 들어가면 명령어(IR)다. 이름이 곧 답이다.

정답 ① PC (Program Counter)

두 조건이 동시에 가리키는 레지스터를 찾아야 한다.

  1. "다음에 수행할 명령의 주소를 기억" → PC의 기본 정의
  2. "상대주소지정에서 오퍼랜드에 더하는 값" → 상대 주소지정의 공식은 유효주소 = PC + 변위(오퍼랜드)이므로 역시 PC
  3. 두 조건 모두 만족 → PC

추가 정리: PC는 명령어를 인출할 때마다 1 또는 명령어 길이만큼 자동 증가하고, 분기 명령을 만나면 목적지 주소로 갱신된다. 이 세 가지(주소 보관·자동 증가·분기 시 갱신)가 PC 문제의 출제 포인트 전부다.

문제 52012 계리직 · 기출문제집 p.97~98

〈보기〉는 스택을 이용한 0-주소 명령어 프로그램이다. 이 프로그램이 수행하는 계산으로 옳은 것은?
PUSH C / PUSH A / PUSH B / ADD / MUL / POP Z

  1. Z = C + A * B
  2. Z = (A + B) * C
  3. Z = B + C * A
  4. Z = (C + B) * A
해설 보기

정답 ② Z = (A + B) * C

규칙 하나만 지키면 된다 — 숫자는 쌓고, 연산자를 만나면 위에서 2개를 꺼내 계산한 뒤 결과를 다시 쌓는다.

  1. PUSH C → 스택: [C]
  2. PUSH A → 스택: [C, A]
  3. PUSH B → 스택: [C, A, B]
  4. ADD → 위 2개(B, A)를 꺼내 A+B → 스택: [C, (A+B)]
  5. MUL → 위 2개((A+B), C)를 꺼내 곱함 → 스택: [C×(A+B)]
  6. POP Z → Z = (A+B) × C

함정: ①번은 ADD와 MUL의 적용 대상을 뒤바꾼 경우다. 연산자는 항상 "가장 최근에 쌓인 2개"에만 적용되므로, ADD 시점에 스택 맨 위인 A와 B가 먼저 묶인다는 점이 핵심이다. 위 스택 흐름 다이어그램을 함께 보면 확실하다.

문제 62011 국가직 · 기출문제집 p.99

CPU가 명령어를 실행할 때 피연산자를 얻기 위해 메모리에 접근하는 횟수가 가장 많은 주소지정 방식은?

  1. 직접 주소지정 방식 (direct addressing mode)
  2. 간접 주소지정 방식 (indirect addressing mode)
  3. 인덱스 주소지정 방식 (indexed addressing mode)
  4. 상대 주소지정 방식 (relative addressing mode)
해설 보기

정답 ② 간접 주소지정 방식 (2회)

  1. 직접: 오퍼랜드가 곧 데이터 주소 → 메모리 1회
  2. 인덱스: (인덱스 레지스터 + 오퍼랜드)로 주소 계산 후 접근 → 레지스터 읽기는 메모리 접근이 아니므로 1회
  3. 상대: (PC + 변위)로 주소 계산 후 접근 → 1회
  4. 간접: 오퍼랜드가 가리키는 곳에서 진짜 주소를 먼저 읽고(1회), 그 주소로 데이터를 읽는다(2회) → 2회

핵심: "레지스터를 읽는 것은 메모리 접근으로 세지 않는다." 이 원칙 때문에 인덱스·상대 방식은 계산이 끼어 있어도 접근 횟수가 1회다.
