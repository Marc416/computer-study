CPU 레지스터와 명령어 처리

레지스터 종류 · 명령어 사이클 · 주소지정방식 · PART 01. 전자계산기구조론

핵심 요약

CPU는 PC(다음 주소) → MAR(접근 주소) → MBR(주고받는 데이터) → IR(현재 명령어) → AC(연산 결과) 순서로 레지스터를 거쳐 명령어를 처리한다.

명령어 처리는 인출(Fetch) → 해독(Decode) → 실행(Execute) → 인터럽트 확인의 반복이다.

💡주요 개념

CPU 내부 레지스터

레지스터이름역할
PCProgram Counter (프로그램 카운터)다음에 인출할 명령어의 주소를 기억. 인출할 때마다 자동 증가, 분기 시 목적지 주소로 갱신
IRInstruction Register (명령어 레지스터)가장 최근에 인출된 명령어(코드+오퍼랜드)를 저장
MARMemory Address RegisterCPU가 기억장치에 접근할 때 필요한 주소를 저장
MBRMemory Buffer Register기억장치에 쓰거나 읽은 데이터를 일시 저장 (기억장치 출입 데이터는 반드시 이곳을 거침)
ACAccumulator (누산기)연산 과정의 데이터와 결과값을 일시 저장
자주 나오는 함정: "가장 최근에 인출한 명령어를 보관" → IR이 정답 (MAR 아님). MAR·MBR은 오답 선택지로 자주 뒤바뀌어 나온다.

명령어 실행 사이클 (Instruction Cycle)

순서단계레지스터 이동
1인출 (Fetch)MAR ← PC → MBR ← M[MAR] → IR ← MBR
2해독 (Decode)IR의 내용을 해석해 명령어 종류 파악
3실행 (Execute)해독 결과에 따라 제어신호를 보내 연산 수행
4인터럽트 확인요청이 있으면 인터럽트 사이클로, 없으면 다시 인출로
비유: PC = "다음에 읽을 페이지 번호", MAR = "책장에서 그 페이지를 찾기 위한 색인", MBR = "찾은 내용을 옮겨 담는 바구니", IR = "지금 읽고 있는 문장"

제어장치 vs 연산장치 구성요소 구분

제어장치 (CU)연산장치 (ALU)
PC, IR, MAR, MBR누산기(AC), 시프트 레지스터
순서 제어 논리장치, 명령어 해독기가산기, 보수기
함정: "시프트 레지스터"는 제어장치가 아니라 연산장치에 해당한다 (자주 나오는 오답 선택지)

오퍼랜드 수에 따른 명령어 분류

분류설명
0-주소 명령어스택(Stack)을 이용. PUSH/POP만으로 연산 (연산자를 만나면 스택에서 2개 꺼내 계산 후 다시 삽입)
1-주소 명령어누산기(AC)를 암묵적으로 사용, 오퍼랜드 1개만 명시
2-주소 명령어연산 결과가 오퍼랜드 중 하나에 저장 (일반적인 CPU 명령어 형태)
3-주소 명령어두 개의 피연산자 + 결과 저장 위치까지 모두 명시
0-주소 명령어(스택) 계산 예제: PUSH C → PUSH A → PUSH B → ADD → MUL → POP Z
ADD 시점에 스택 맨 위 B, A를 꺼내 A+B를 다시 삽입 → MUL 시점에 (A+B)와 C를 꺼내 C×(A+B) 삽입 → Z = (A+B) × C

OP-Code(연산자) 비트 수가 많을수록 표현 가능한 명령어 종류가 많아진다. (오퍼랜드 필드가 아니라 OP-Code 필드가 명령어 종류 개수를 결정)

주소지정 방식 (Addressing Mode)

방식유효주소 결정 방법메모리 접근 횟수
즉치 (Immediate)오퍼랜드 자체가 데이터0회 (데이터 인출 불필요)
직접 (Direct)오퍼랜드가 곧 데이터의 주소1회
간접 (Indirect)오퍼랜드가 가리키는 곳에 또 다른 주소가 있고, 그 주소가 진짜 데이터 위치2회 (가장 많음)
레지스터 (Register)레지스터 안에 데이터가 직접 존재0회 — 접근속도 가장 빠름
레지스터 간접 (Register Indirect)레지스터 안에 유효주소가 있고, 그 주소로 메모리 접근1회
상대 (Relative)PC + 오퍼랜드(변위) = 유효주소. 주로 분기 명령어에서 사용1회
인덱스 (Indexed)인덱스 레지스터 값 + 오퍼랜드 = 유효주소1회
간접 주소지정을 쓰는 이유: 오퍼랜드 비트 수의 한계로 표현 가능한 주소 범위가 좁아지는 문제를 해결하기 위해 — 메모리 1워드 전체를 주소로 활용해 지정 가능한 주소 범위를 확대한다.

📌시험 빈출 포인트

  • 레지스터 기능 짝짓기: PC(다음 명령어 주소) / IR(현재 명령어) / MAR(접근 주소) / MBR(주고받는 데이터) / AC(연산결과)
  • 기억장치 출입 데이터는 반드시 MBR을 거친다 — "기억장치를 출입하는 데이터를 저장하는 레지스터" 문제의 정답
  • 명령어 처리 순서: PC→MAR, MBR←M[MAR], IR←MBR, 해독·실행, 인터럽트 확인
  • 0-주소 명령어(스택) 계산 문제 — PUSH/POP 순서를 스택에 직접 그려보며 풀 것
  • 간접 주소지정 방식은 메모리 접근 2회, 유효주소 확장이 목적 (보안과는 무관)
  • 레지스터 주소지정 > 직접 주소지정 > 간접 주소지정 순으로 접근 속도가 빠름
  • 상대 주소지정 = PC + 변위 → 분기(branch) 명령어에서 사용된다는 것 암기
