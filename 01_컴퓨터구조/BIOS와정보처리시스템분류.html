BIOS · 정보처리 시스템 · 마이크로프로세서 분류

부팅 과정, 운영체제 처리방식 분류, RISC vs CISC · PART 01. 전자계산기구조론

핵심 요약

BIOS는 ROM에 저장되어 부팅 시 하드웨어를 점검·초기화하고 운영체제를 불러오는 역할을 한다.

운영체제의 처리 방식은 일괄처리·다중프로그래밍·시분할·실시간·분산처리로 나뉘고, 마이크로프로세서는 CISC와 RISC로 구분된다.

🎯이 단원을 왜 배우나

"전원을 켜면 대체 누가 먼저 움직이나"라는 닭과 달걀 문제

운영체제는 하드디스크(보조기억장치)에 파일로 저장돼 있다. 그런데 그 파일을 읽으려면 디스크를 읽을 줄 아는 프로그램이 이미 돌고 있어야 한다. 전원을 갓 켠 순간 RAM은 텅 비어 있는데, 누가 그 첫 프로그램을 실행하는가? 이 닭과 달걀 문제를 푸는 것이 BIOS다. BIOS는 전원이 꺼져도 지워지지 않는 ROM에 미리 새겨져 있어서, 전원이 들어오는 즉시 CPU가 곧장 실행할 수 있다.

그래서 이 단원의 BIOS 문제는 "무엇이 어디에 저장되어 있는가"를 집요하게 묻는다 — BIOS는 ROM, 운영체제는 보조기억장치, 실행 시에는 주기억장치. 이 세 칸만 정확히 채워 넣으면 대부분 풀린다.

후반부는 "컴퓨터에게 일을 시키는 방식"의 역사다. 옛날엔 작업을 모아서 한 번에 돌렸고(일괄), 그러다 CPU가 노는 시간이 아까워 여러 프로그램을 메모리에 올렸고(다중 프로그래밍), 사람이 기다리기 답답해서 시간을 잘게 쪼갰다(시분할). 각 방식이 어떤 불만을 해결하려고 나왔는지를 알면 정의를 외우지 않아도 구분된다.

💡주요 개념

BIOS(Basic Input Output System) 📖 기출문제집 p.23~24

  • 운영체제가 입출력장치·주변장치를 구동하기 위한 가장 기본적인 루틴들의 집합
  • IBM-PC 호환기종에서는 ROM에 저장 → 흔히 롬바이오스(ROM-BIOS)라 부름
  • 구성: 스타트업 루틴(POST), 서비스 처리 루틴(입출력 기본 서비스), 하드웨어 인터럽트 처리 루틴

왜 하필 ROM인가 — 그리고 "부트스트랩"이라는 이름의 유래

BIOS가 RAM에 있으면 안 되는 이유는 명확하다. RAM은 휘발성이라 전원을 끄면 내용이 날아간다. 전원을 켠 직후에는 RAM이 비어 있으므로, 거기에 BIOS가 있을 리 없다. 비휘발성인 ROM이어야만 전원 투입 즉시 실행할 코드가 존재한다.

부팅(booting)은 부트스트랩(bootstrap)의 준말인데, 원래 "제 신발끈을 잡아당겨 스스로를 들어올린다"는 영어 관용구에서 왔다. 아무 도움 없이 자기 힘만으로 일어서야 하는 상황을 가리킨다 — 컴퓨터가 아무것도 실행 중이지 않은 상태에서 스스로 운영체제를 올리는 과정이 딱 그 모습이라 붙은 이름이다.

정리하면 순서는 이렇다: ROM의 BIOS가 먼저 깨어나 하드웨어를 점검하고(POST), ROM에 있는 부트스트랩 로더가 보조기억장치에서 운영체제를 찾아 RAM에 올린 뒤, CPU 제어권을 운영체제에게 넘기고 물러난다.

시험 함정 3종: ① "부트스트랩 프로그램은 하드디스크에 저장되어 있다" → ROM이다. ② "BIOS는 하드디스크에 저장된다" → ROM이다. ③ "BIOS가 없어도 컴퓨터는 제대로 동작한다" → BIOS 없이는 부팅 자체가 불가능하다.

함정 주의: CMOS 셋업(메인보드에서 값 설정)은 BIOS가 부팅 중에 "항상 하는 일"이 아니다 — POST·시스템 초기화·부트스트랩 로더 로드와 구분할 것.

정보처리 시스템(운영체제 처리방식)의 분류 📖 기출문제집 p.25

방식정의비고
일괄 처리 시스템 (Batch)일정 기간·양의 작업을 모아 한꺼번에 처리CPU와 I/O 속도차로 CPU 유휴시간 많음
다중 프로그래밍 (Multi-programming)여러 프로그램을 주기억장치에 적재해두고 하나의 CPU를 번갈아 사용목적: CPU 활용의 극대화(처리량 증가)
시분할 시스템 (Time Sharing)CPU 시간을 일정 간격(타임 슬라이스)으로 쪼개 여러 사용자에게 순차 할당목적: 응답시간 최소화. 선점(preemptive) 스케줄링 사용
실시간 시스템 (Real Time)정해진 시간 내 반드시 응답을 보장예: 심장 모니터링, 좌석 예약. 선점 스케줄링 사용
분산 처리 시스템 (Distributed)네트워크로 연결된 여러 컴퓨터가 작업을 분산 처리네트워크 구축이 반드시 필요, 신뢰도·확장성 향상
함정 주의: "CPU 운영 시간을 잘게 쪼개 여러 사용자에게 공평하게 제공"하는 것은 분산 처리 시스템이 아니라 시분할 시스템에 대한 설명이다.

이 방식들은 "불만 → 해결"의 순서로 진화했다

정의를 따로따로 외우면 헷갈리지만, 앞 방식의 불만을 다음 방식이 해결하는 흐름으로 보면 저절로 구분된다.

  • ① 일괄 처리 — 천공카드 시절, 작업을 잔뜩 모았다가 한꺼번에 돌렸다. 불만: CPU가 느린 입출력(I/O)을 기다리며 노는 시간(유휴시간)이 너무 많다.
  • ② 다중 프로그래밍 — 그럼 프로그램 여러 개를 메모리에 올려두고, A가 I/O 하는 동안 B에게 CPU를 주자. 목적은 오직 CPU를 쉬지 않게 하는 것(처리량 증가). 불만: 내 작업이 언제 끝날지 모른다 — 앞 작업이 CPU를 붙잡고 안 놓으면 하염없이 기다려야 한다.
  • ③ 시분할(Time Sharing) — 그럼 시간을 잘게 쪼개(타임 슬라이스) 강제로 돌아가며 쓰게 하자. 목적은 응답시간 단축 — 사용자마다 "나 혼자 쓰는 것 같은" 느낌을 준다. 강제로 뺏어야 하므로 반드시 선점(preemptive) 스케줄링이다.
  • ④ 실시간(Real Time) — 심장 모니터처럼 늦으면 큰일 나는 작업용. "빠르다"가 아니라 "정해진 시간 안에 반드시 끝남을 보장한다"가 핵심이다.
  • ⑤ 분산 처리 — 아예 컴퓨터 여러 대를 네트워크로 묶어 나눠 처리한다. 그래서 네트워크가 필수인 유일한 방식이다.

가장 많이 틀리는 구분 — 다중 프로그래밍 vs 다중 처리(다중 프로세서): 이름이 비슷하지만 CPU 개수가 다르다. 다중 프로그래밍은 CPU 1개를 여러 프로그램이 번갈아 쓰는 것(소프트웨어 기법), 다중 처리는 CPU가 실제로 여러 개인 것(하드웨어 구성)이다.

다중 프로세서 시스템의 결합 방식

구분밀결합 (Tightly-Coupled)약결합 (Loosely-Coupled)
통신 방식공유 기억장치(Shared Memory) 이용각자 지역 기억장치를 갖고 네트워크로 통신
대응 개념다중처리(Multi-processing)분산처리(Distributed Processing)

다중 프로세서 시스템에서는 각 프로세서의 로컬 캐시 간 데이터 일치를 보장하는 캐시 일관성(Cache Coherence) 문제를 반드시 고려해야 한다.

두 철학의 대립 — 표를 통째로 외우지 말고 한 문장에서 유도하라

이 표는 9줄이지만 외울 것은 한 문장뿐이다: "CISC는 명령어 하나에 일을 많이 시키고, RISC는 명령어를 잘게 쪼개 단순하게 만든다." 나머지는 전부 여기서 논리적으로 따라 나온다.

  • 명령어가 복잡하다(CISC) → 종류가 많아지고 → 길이도 제각각(가변) → 해독이 어려워 제어장치를 마이크로프로그램으로 구현 → 하드웨어가 복잡 → 전력을 많이 먹는다
  • 명령어가 단순하다(RISC) → 종류가 적고 → 길이가 고정 → 해독이 쉬워 고정배선(hard-wired)으로 구현 → 매 클록마다 하나씩 착착 처리 가능 → 파이프라인에 최적
  • 단, 명령어가 단순하니 같은 일을 하려면 명령어를 여러 개 써야 한다 → 그래서 프로그램 길이는 RISC가 더 길다 (역설적이지만 시험 단골)
  • 또 메모리 접근을 Load/Store로만 제한하니 데이터를 CPU 안에 오래 들고 있어야 한다 → 그래서 범용 레지스터를 많이 둔다

딱 두 개만 조심: ① RISC는 레지스터가 많다(적다 아님), ② 프로그램 길이는 RISC가 길다(짧다 아님). 이 둘이 "단순하니까 전부 작을 것"이라는 직관과 반대라서 함정으로 가장 많이 쓰인다.

📌시험 빈출 포인트

  • BIOS는 ROM에 저장, 운영체제는 보조기억장치에 저장되어 있다가 부팅 시 주기억장치로 적재
  • 부팅 순서: POST → BIOS 정보 RAM 복사 → 부트스트랩 로더가 OS 적재
  • 다중프로그래밍 목적 = CPU 활용 극대화, 시분할 목적 = 응답시간 최소화 (목적 구분 문제)
  • 시분할 시스템은 선점 스케줄링 (비선점 아님 — 자주 나오는 오답 함정)
  • "CPU 시간을 잘게 쪼개 공평 배분" → 시분할 (분산처리로 헷갈리지 않기)
  • 밀결합=공유기억장치, 약결합=네트워크 통신 — 다중처리 vs 분산처리와 대응
  • RISC는 명령어 종류가 적고, 레지스터 수는 많고, 고정 길이 명령어 사용
  • RISC가 CISC보다 파이프라이닝·슈퍼스칼라 구현에 더 유리

문제 12016 국가직 · 기출문제집 p.25

다음은 PC의 전원을 켰을 때 일어나는 과정들을 순서대로 나열한 것이다. ㉠~㉢에 들어갈 말로 바르게 짝지어진 것은?

  • ( ㉠ )에 저장된 바이오스(BIOS)가 실행되어 컴퓨터에 장착된 하드웨어 장치들의 상태를 점검한다.
  • ( ㉡ )에 저장되어 있는 운영체제가 ( ㉢ )(으)로 로드(load)된다.
  • 운영체제의 실행이 시작된다.
  1. ㉠ 보조기억장치   ㉡ ROM   ㉢ 주기억장치
  2. ㉠ 보조기억장치   ㉡ 주기억장치   ㉢ ROM
  3. ㉠ ROM   ㉡ 보조기억장치   ㉢ 주기억장치
  4. ㉠ ROM   ㉡ 주기억장치   ㉢ 보조기억장치
해설 보기

정답 ③ ROM → 보조기억장치 → 주기억장치

  1. ㉠ BIOS의 집 = ROM. 전원을 켠 직후 RAM은 비어 있으므로, 비휘발성인 ROM에 있어야만 즉시 실행할 수 있다.
  2. ㉡ 운영체제의 집 = 보조기억장치(하드디스크/SSD). OS는 용량이 크고 자주 업데이트되므로 ROM이 아니라 디스크에 파일로 저장된다.
  3. ㉢ 실행하려면 = 주기억장치(RAM). CPU는 RAM에 올라온 것만 실행할 수 있으므로 디스크의 OS를 RAM으로 옮긴다.

한 줄 요약: "ROM이 깨워서, 디스크에 있는 OS를, RAM으로 올린다." 이 문장만 기억하면 순서 문제는 전부 맞는다.

문제 22009 국가직 · 기출문제집 p.24~25

컴퓨터를 작동시켰을 때 발생하는 부트(boot) 과정에 대한 설명으로 옳지 않은 것은?

  1. 부트스트랩 프로그램은 일반적으로 운영체제가 저장된 하드디스크에 저장되어 있다.
  2. 부트 과정의 목적은 운영체제를 하드디스크로부터 메모리로 적재하는 것이다.
  3. 부트 과정은 여러 가지 중요한 시스템 구성 요소들의 진단 검사를 수행한다.
  4. 부트 과정을 완료하면 중앙처리장치는 제어권을 운영체제로 넘겨준다.
해설 보기

정답 ① (부트스트랩 프로그램은 ROM에 저장된다)

  1. 부트스트랩 프로그램이 하드디스크에 있다면 모순이 생긴다 — 하드디스크를 읽으려면 이미 뭔가가 실행 중이어야 하는데, 그 "뭔가"가 바로 부트스트랩이기 때문이다.
  2. 따라서 부트스트랩은 전원 투입 즉시 실행 가능한 ROM에 있어야 한다.
  3. ②(OS를 디스크→메모리로 적재), ③(POST로 진단 검사), ④(제어권 이관)는 모두 부트 과정의 정확한 서술이다.

구분: 부트스트랩 로더(ROM에 있는, OS를 불러오는 프로그램)와 운영체제(하드디스크에 있는, 불려오는 대상)를 헷갈리지 말 것.

문제 32024 지방직 · 기출문제집 p.26

운영체제에서 일괄 처리 시스템(batch processing system)에 대한 설명으로 옳은 것은?

  1. 사용자로부터 작업이 요구되는 즉시 처리한다.
  2. 일정량 또는 일정 기간의 작업을 모아 한꺼번에 처리한다.
  3. 네트워크로 연결된 여러 대의 컴퓨터에서 작업을 분산하여 처리한다.
  4. CPU 운영시간을 골고루 할당하여 여러 사용자가 순환하며 작업을 수행한다.
해설 보기

정답 ②

이 문제는 오답 선택지 하나하나가 다른 시스템의 정의라서, 네 방식을 한 번에 복습할 수 있는 좋은 문제다.

  1. ① "즉시 처리" → 실시간 시스템
  2. ② "모아서 한꺼번에" → 일괄 처리 ✓ 정답
  3. ③ "네트워크로 연결된 여러 컴퓨터" → 분산 처리 시스템
  4. ④ "CPU 시간을 골고루 할당, 순환" → 시분할 시스템

일괄 처리의 약점도 함께 기억: 작업을 모아 돌리므로 CPU가 느린 I/O를 기다리는 유휴시간이 많이 발생한다. 이 약점을 해결하려고 나온 것이 다중 프로그래밍이다.

문제 42011 지방직 · 기출문제집 p.26

다중 프로그래밍(multi-programming)의 특징에 대한 설명으로 가장 적절한 것은?

  1. 메인 메모리와 캐시 메모리 등의 다중 계층 메모리 사용을 통해 소프트웨어 수행 시간을 단축시킨다.
  2. I/O 작업과 CPU 작업을 중첩함으로써 시스템 효율을 향상시킨다.
  3. 여러 개의 저장장치를 동시에 지원한다.
  4. 하나의 프로그램을 여러 개의 프로세서에서 처리하여 프로그램 수행 시간을 단축시킨다.
해설 보기

정답 ②

  1. 다중 프로그래밍의 존재 이유는 단 하나 — 어떤 프로그램이 I/O를 하느라 CPU를 안 쓰는 동안 다른 프로그램에게 CPU를 넘겨 CPU가 놀지 않게 하는 것. ②가 정확히 이 서술이다.
  2. ①은 캐시·메모리 계층에 대한 설명이지 다중 프로그래밍이 아니다.
  3. ④는 다중 처리(multi-processing) — CPU가 여러 개인 경우다. 다중 프로그래밍은 CPU가 하나다.

핵심 대비: 다중 프로그래밍 = CPU 1개를 번갈아(소프트웨어), 다중 처리 = CPU 여러 개(하드웨어).

문제 52008 국가직 · 기출문제집 p.27

다중 프로세서 시스템에 대한 설명으로 옳지 않은 것은?

  1. 다수의 프로세서가 하나의 운영체제 하에서 동작할 수 있는 시스템이다.
  2. 밀결합 시스템(Tightly-Coupled System)은 모든 프로세서들이 공유 기억장치를 이용하여 통신한다.
  3. 다중 프로세서 시스템에서는 캐시 일관성(Cache Coherence) 문제를 고려할 필요가 없다.
  4. 프로그램 작성이나 컴파일 과정에서 데이터 의존성이 없는 부분들을 분류해 병렬처리가 가능하도록 할 수 있다.
해설 보기

정답 ③ (오히려 반드시 고려해야 한다)

  1. 프로세서가 여러 개면 각자 자기 캐시를 갖는다. CPU-A가 어떤 값을 자기 캐시에서 고쳤는데 CPU-B의 캐시에는 옛날 값이 남아 있으면, 두 CPU가 서로 다른 값을 보게 된다.
  2. 이 불일치를 막는 것이 캐시 일관성(Cache Coherence) 문제다 — 다중 프로세서 시스템에서만 생기는, 반드시 해결해야 할 핵심 과제다.
  3. ②의 밀결합/약결합 구분은 정확하다: 밀결합=공유 기억장치로 통신, 약결합=각자 지역 기억장치 + 네트워크 통신(=분산처리).

덤: 다중 프로세서의 장점은 신뢰성(CPU 하나가 고장나도 나머지가 계속 동작) + 연산능력 향상이다.

문제 62014 국회직 · 기출문제집 p.32

RISC(Reduced Instruction Set Computer) 방식 컴퓨터에 대한 설명으로 옳지 않은 것은?

  1. RISC 방식은 CISC 방식보다 간단한 명령어 구조를 사용한다.
  2. RISC 방식은 CISC 방식보다 파이프라이닝 구현이 용이하다.
  3. RISC 방식은 CISC 방식보다 주소 지정방식이 간단하다.
  4. RISC 방식은 고정된 길이의 명령어 형식으로 디코딩이 간단하다.
  5. RISC 방식의 CPU는 CISC 방식보다 상대적으로 적은 수의 레지스터를 사용한다.
해설 보기

정답 ⑤ (RISC는 오히려 많은 범용 레지스터를 갖는다)

  1. RISC는 메모리 접근을 Load/Store 명령어로만 제한한다. 메모리에 자주 못 가니, 데이터를 CPU 안에 오래 들고 있어야 한다.
  2. 그러려면 보관할 자리가 많이 필요하다 → 범용 레지스터를 많이 둔다. 이것이 RISC가 빠른 이유 중 하나다.
  3. ①~④는 모두 RISC의 정확한 특징이다(단순한 명령어·파이프라인 용이·단순한 주소지정·고정 길이).

함정 원리: "Reduced(줄였다)"라는 이름 때문에 모든 게 적을 것이라고 착각하게 만드는 문제다. 줄인 것은 명령어의 종류와 복잡도일 뿐, 레지스터 수는 오히려 늘렸다.

문제 72018 서울시 · 기출문제집 p.33

CISC(Complex Instruction Set Computer)에 대한 설명으로 가장 옳은 것은?

  1. 고정 길이의 명령어 형식을 가진다.
  2. 명령어의 길이가 짧다.
  3. 다양한 어드레싱 모드를 사용한다.
  4. 하나의 명령으로 복잡한 명령을 수행할 수 없어 복잡한 하드웨어가 필요하다.
해설 보기

정답 ③ 다양한 어드레싱 모드를 사용한다

  1. ① 고정 길이는 RISC의 특징이다. CISC는 명령어마다 하는 일이 달라 길이도 제각각인 가변 길이다.
  2. ② CISC의 명령어는 길 수도 짧을 수도 있다. "짧다"고 단정할 수 없다.
  3. ③ 명령어가 복잡한 만큼 피연산자를 지정하는 방법도 다양하다 → 다양한 어드레싱 모드 ✓ 정답
  4. ④ 앞뒤가 뒤집혔다. CISC는 하나의 명령으로 복잡한 작업을 수행할 수 있고, 그렇게 만들려다 보니 하드웨어가 복잡해진 것이다.

(가) 항공기 자동 조종 장치 — 센서 입력에 0.1초 안에 반드시 반응해야 함

해설 보기
