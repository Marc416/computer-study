# 파이프라인 (Pipeline)

## 핵심 요약
> CPU가 명령어 처리 과정을 **여러 단계로 나눠서 동시에 처리**하는 병렬 처리 기법.
> k단계 파이프라인은 이론적으로 **최대 k배** 성능 향상.

## 주요 개념

### 파이프라인이란?
- 명령어 하나를 처리하는 과정을 **여러 단계(스테이지)**로 나눔
- 각 단계를 **동시에 겹쳐서 실행** (마치 공장 컨베이어 벨트처럼)
- 각 단계가 서로 다른 명령어를 동시에 처리

> 비유: 세탁소에서 세탁기, 헹굼기, 탈수기, 건조기를 **동시에 돌려서** 여러 벌의 옷을 병렬 처리하는 것

### 4단계 파이프라인 (가장 기본)

| 단계 | 약어 | 설명 |
|------|------|------|
| **1. 명령어 인출** | IF (Instruction Fetch) | 메모리에서 명령어를 가져옴 |
| **2. 명령어 해독** | ID (Instruction Decode) | 명령어의 종류와 피연산자를 해석 |
| **3. 실행** | EX (Execute) | ALU에서 실제 연산 수행 |
| **4. 쓰기** | WB (Write Back) | 결과를 레지스터/메모리에 저장 |

### 파이프라인 동작 예시 (4단계, 4개 명령어)

```
클럭:    1     2     3     4     5     6     7
명령1: [IF]  [ID]  [EX]  [WB]
명령2:       [IF]  [ID]  [EX]  [WB]
명령3:             [IF]  [ID]  [EX]  [WB]
명령4:                   [IF]  [ID]  [EX]  [WB]
```

- 파이프라인 없이: 4 × 4 = **16 클럭**
- 파이프라인 있으면: 4 + (4-1) = **7 클럭**

## 성능 계산 공식 ⭐ (시험 필수!)

### 기본 변수
- **k** = 파이프라인 단계 수 (스테이지 수)
- **N** = 처리할 명령어 수

### 처리 시간

| 구분 | 공식 | 설명 |
|------|------|------|
| 파이프라인 **없이** | **N × k** | 순차적으로 하나씩 처리 |
| 파이프라인 **있으면** | **k + (N - 1)** | 첫 명령어 k클럭 + 이후 매 클럭마다 1개씩 완료 |

### 속도 향상 (Speedup)

```
         N × k
S = ─────────────
     k + (N - 1)
```

### N이 매우 크면 (N → ∞)

```
         N × k        k
S ≈ ─────────── = ─── ≈ k
       N - 1         1
```

> **결론: k단계 파이프라인의 최대 속도 향상 = k배**

### 계산 예제

**[예제 1] 4단계 파이프라인, 100개 명령어**
- 파이프라인 없이: 100 × 4 = 400 클럭
- 파이프라인: 4 + 99 = 103 클럭
- **속도 향상: 400 / 103 ≈ 3.88배** (최대 4배에 근접)

**[예제 2] 5단계 파이프라인, 200개 명령어**
- 파이프라인 없이: 200 × 5 = 1000 클럭
- 파이프라인: 5 + 199 = 204 클럭
- **속도 향상: 1000 / 204 ≈ 4.90배** (최대 5배에 근접)

**[예제 3] 6단계 파이프라인, 10개 명령어**
- 파이프라인 없이: 10 × 6 = 60 클럭
- 파이프라인: 6 + 9 = 15 클럭
- **속도 향상: 60 / 15 = 4배** (N이 작아서 최대 6배에 못 미침)

## 파이프라인 해저드 (Hazard) — 성능 저하 원인

파이프라인이 항상 이상적으로 동작하진 않음. 다음 상황에서 **지연(스톨)**이 발생:

| 해저드 종류 | 설명 | 예시 |
|------------|------|------|
| **구조적 해저드** (Structural) | 하드웨어 자원 충돌 | 메모리를 동시에 읽고 쓰려 할 때 |
| **데이터 해저드** (Data) | 이전 명령어 결과가 필요한데 아직 안 나옴 | A=B+C 다음에 D=A+E |
| **제어 해저드** (Control) | 분기(조건문) 때문에 다음 명령어를 모름 | if문으로 점프할 때 |

### 해저드 해결 방법

| 방법 | 설명 |
|------|------|
| **전방전달 (Forwarding)** | 결과를 기다리지 않고 바로 다음 단계에 전달 (데이터 해저드) |
| **분기 예측 (Branch Prediction)** | 분기 결과를 미리 예측하여 처리 (제어 해저드) |
| **지연 슬롯 (Delay Slot)** | 분기 후 빈 시간에 다른 명령어 실행 |
| **파이프라인 스톨 (Stall/Bubble)** | 잠시 멈추고 기다림 (최후의 수단) |

## 시험 빈출 포인트
- k단계 파이프라인의 처리 시간 = **k + (N-1)**
- 최대 속도 향상 = **k배** (단계 수만큼)
- 속도 향상 공식: **S = (N×k) / (k+N-1)**
- 파이프라인 해저드 3가지: 구조적, 데이터, 제어
- "4단계 파이프라인으로 100개 명령어" 같은 계산 문제

## 헷갈리는 개념 비교

| 구분 | 파이프라인 | 슈퍼스칼라 | VLIW |
|------|-----------|-----------|------|
| **원리** | 단계를 겹쳐 실행 | 여러 파이프라인을 동시 운용 | 컴파일러가 병렬 명령어 묶음 |
| **병렬화** | 명령어 수준 | 명령어 수준 | 명령어 수준 |
| **누가 관리** | 하드웨어 | 하드웨어 | 컴파일러(소프트웨어) |
| **최대 향상** | k배 | k × n배 (n=파이프라인 수) | 컴파일러 능력에 따라 |

| 구분 | 파이프라인 (Pipeline) | 병렬처리 (Parallel Processing) |
|------|---------------------|-------------------------------|
| **방식** | 하나의 작업을 단계별로 겹쳐 처리 | 여러 작업을 동시에 처리 |
| **비유** | 공장 컨베이어 벨트 | 여러 공장을 동시에 운영 |
| **단위** | 명령어의 각 단계 | 여러 프로세서/코어 |
