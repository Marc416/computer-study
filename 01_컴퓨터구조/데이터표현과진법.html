데이터의 표현과 진법

데이터 단위, 문자 코드 체계, 진법 변환 · PART 01. 전자계산기구조론

핵심 요약

데이터의 최소 단위는 비트이고, 8비트 = 1바이트, CPU가 한 번에 처리하는 단위는 워드다.

진법 변환은 2진 ↔ 8진 ↔ 16진을 자릿수 묶음(3비트=8진 1자리, 4비트=16진 1자리)으로 빠르게 변환하는 것이 핵심이다.

🎯이 단원을 왜 배우나

컴퓨터는 0과 1밖에 모르는데, 사람은 그걸 못 읽는다

컴퓨터 내부의 모든 데이터는 결국 전기가 흐른다(1) / 안 흐른다(0)의 나열일 뿐이다. 그런데 사람이 10101010111100001101 같은 걸 눈으로 읽고 다루기는 불가능하다. 그래서 등장한 게 8진수와 16진수다. 이 둘은 "2진수를 사람이 읽기 좋게 압축한 표기법"이지, 별개의 숫자 체계가 아니다.

왜 하필 8과 16인가? 8 = 2³, 16 = 2⁴이기 때문이다. 2의 거듭제곱이라서 2진수를 3개씩(또는 4개씩) 딱 잘라 묶기만 하면 변환이 끝난다. 계산이 필요 없다. 반면 10진수는 2의 거듭제곱이 아니라서 2진수로 바꾸려면 나눗셈을 반복해야 한다 — 시험에서 10진수 변환 문제만 유독 귀찮은 이유가 이것이다.

그래서 이 단원의 문제는 딱 두 종류다. (1) 2진 ↔ 8진 ↔ 16진 — 묶어서 자르기만 하면 되는 쉬운 문제. (2) 10진수가 끼어드는 변환 — 나눗셈(정수부)·곱셈(소수부)을 해야 하는 문제. 둘을 구분해서 접근하면 실수가 확 줄어든다.

왜 유니코드가 필요했나

ASCII는 7비트라 128자밖에 못 쓴다. 영어 알파벳·숫자·기호만으로도 빠듯한데 한글은 조합만 1만 자가 넘는다. 그래서 나라마다 자기 방식으로 한글·한자 코드를 따로 만들었고, 결과적으로 같은 파일이 다른 나라 컴퓨터에서 깨지는 문제가 생겼다(이게 흔히 보는 "???" 또는 "뷁" 현상이다).

유니코드는 이 혼란을 끝내려고 전 세계 문자에 전 지구적으로 유일한 번호를 하나씩 부여한 체계다. 16비트라서 6만 자 이상 표현 가능하다. 시험에서는 "한 문자 = 2바이트"라는 점이 용량 계산 문제로 자주 나온다(아래 연습문제 8번).

진법 변환의 전체 지도 📖 기출문제집 p.40~42

진법 변환 문제는 겉보기엔 다양해 보여도 경로는 딱 두 갈래다. 2·8·16진수끼리는 2진수를 거쳐 묶기만 하면 되고, 10진수가 끼면 나눗셈/곱셈을 해야 한다. 아래 그림이 그 지도다.

① 2진 ↔ 8진 ↔ 16진 (묶어서 자르기)

변환규칙
2진 ↔ 4진2진수 2자리 = 4진수 1자리
2진 ↔ 8진2진수 3자리 = 8진수 1자리
2진 ↔ 16진2진수 4자리 = 16진수 1자리
묶는 방향이 생명이다: 소수점을 기준으로 정수부는 오른쪽에서 왼쪽으로, 소수부는 왼쪽에서 오른쪽으로 묶는다. 비트가 모자라면 바깥쪽(정수부는 왼쪽, 소수부는 오른쪽)에 0을 채운다.
틀리는 사람의 90%가 소수부를 왼쪽부터 채우다 틀린다. 예: .11은 .1100(=C)이지 .0011(=3)이 아니다.

4비트 ↔ 16진수 대응표 (통째로 외워야 빠르다)

2진00000001001000110100010101100111
16진01234567
2진10001001101010111100110111101111
16진89A(10)B(11)C(12)D(13)E(14)F(15)
암기 요령: 4비트의 자릿값은 왼쪽부터 8-4-2-1이다. 1011이면 8+0+2+1 = 11 = B. 이 "8421"만 외우면 표를 통째로 안 외워도 즉시 계산된다.
예제: 8진수 (56.13)₈ → 16진수 (기출 2014 국가직)
  1. 8진수 각 자리를 3비트로 펼친다: 5→101, 6→110, .1→001, 3→011 ⇒ 101110.001011
  2. 정수부 101110을 오른쪽부터 4비트씩 묶는다 → 0010 1110 (왼쪽에 0 채움)
  3. 소수부 001011을 왼쪽부터 4비트씩 묶는다 → 0010 1100 (오른쪽에 0 채움)
  4. 각 묶음을 16진수로: 0010=2, 1110=E, 0010=2, 1100=C ⇒ 2E.2C

② 10진수 → 2진수 (나눗셈과 곱셈) 📖 기출문제집 p.39

정수부는 몫이 0이 될 때까지 2로 계속 나누고 나머지를 아래에서 위로(역순) 읽는다. 소수부는 2를 계속 곱해서 넘어가는 정수부를 위에서 아래로(순서대로) 읽는다.

소수부 0.1875를 곱셈으로 푸는 전 과정
  1. 0.1875 × 2 = 0.375 → 정수부 0
  2. 0.375 × 2 = 0.75 → 정수부 0
  3. 0.75 × 2 = 1.5 → 정수부 1 (소수부 0.5만 남기고 계속)
  4. 0.5 × 2 = 1.0 → 정수부 1, 소수부가 0이 되었으므로 종료
  5. 나온 정수부를 위에서 아래 순서대로 읽으면 0.0011₂
합친 결과: 45.1875 → 101101.0011₂

왜 정수부는 역순이고 소수부는 순서대로인가

정수부를 2로 나눌 때 처음 나오는 나머지가 가장 작은 자리(2⁰)다. 2진수는 왼쪽이 큰 자리이므로, 작은 자리부터 구한 것을 뒤집어야 제자리를 찾는다.

반대로 소수부는 2를 곱할 때 처음 넘어온 정수부가 소수점 바로 다음 자리(2⁻¹)다. 큰 자리부터 순서대로 나오므로 뒤집을 필요가 없다.

③ N진수 → 10진수 (자릿값 곱해서 더하기)

예: 16진수 (1B4.C)₁₆ → 10진수
1×16² + B(11)×16¹ + 4×16⁰ + C(12)×16⁻¹
= 256 + 176 + 4 + 0.75 = 436.75
예: 8진수 (13754)₈ → 10진수
1×8⁴ + 3×8³ + 7×8² + 5×8¹ + 4×8⁰
= 4096 + 1536 + 448 + 40 + 4 = 6124

소수부 자릿값은 음수 지수가 된다: 16⁻¹ = 1/16 = 0.0625, 8⁻¹ = 0.125, 2⁻¹ = 0.5. 소수 첫째 자리가 C(12)면 12 × 0.0625 = 0.75가 되는 식이다.

📌시험 빈출 포인트

  • 서로 다른 진법 값 중 크기 비교 / 값이 다른 것 찾기 → 전부 10진수 또는 2진수로 통일해서 비교
  • 10진수 ↔ 2진수 변환 (정수부는 나눗셈 나머지 역순, 소수부는 곱셈 정수부 순서대로)
  • 2진 ↔ 8진(3비트 묶음), 2진 ↔ 16진(4비트 묶음) — 8진↔16진은 2진수를 거쳐서
  • 소수부 묶기는 왼쪽부터, 모자라면 오른쪽에 0을 채운다 (가장 많이 틀리는 지점)
  • 문자 코드 비트 수: BCD(6) < ASCII(7) < EBCDIC(8) < 유니코드(16)
  • 니블 = 4비트, 바이트 = 8비트, 워드 크기는 시스템마다 다름
  • N비트로 표현 가능한 정수 개수는 2ⁿ개 (0 ~ 2ⁿ−1). 거꾸로 "2ⁿ개를 표현하려면 n비트" 형태로도 출제
  • 유니코드 문자 1개 = 2바이트로 놓고 푸는 저장 용량 계산 문제

문제 12023 지방직 · 기출문제집 p.39

10진수 45.1875를 2진수로 변환한 것은?

  1. 101100.0011
  2. 101100.0101
  3. 101101.0011
  4. 101101.0101
해설 보기

정답 ③ 101101.0011

  1. 정수부 45: 2로 계속 나눈 나머지를 역순으로 → 101101 (검산: 32+8+4+1 = 45 ✓)
  2. 소수부 0.1875: ×2 반복 → 0.375(0), 0.75(0), 1.5(1), 1.0(1) → 0011
  3. 검산: 0.125 + 0.0625 = 0.1875 ✓ (소수 셋째·넷째 자리 = 2⁻³ + 2⁻⁴)
  4. 합치면 101101.0011

빠른 검산법: 선택지 정수부가 101100(=44)과 101101(=45)로 갈린다. 45를 만들려면 마지막 비트가 1이어야 하므로 ①②는 바로 탈락. 남은 ③④는 소수부만 비교하면 된다.

문제 22015 서울시 · 기출문제집 p.38

다음 중 값이 나머지 셋과 다른 것은?

  1. 10진수 436.625
  2. 8진수 (664.5)₈
  3. 16진수 (1B4.C)₁₆
  4. 10진수 0.436625 × 10³
해설 보기

정답 ③ (1B4.C)₁₆ = 436.75

기준값이 되는 ①과 ④부터 확인하면 빠르다.

  1. ④ 0.436625 × 10³ = 436.625 → ①과 같다. 따라서 기준값은 436.625
  2. ② (664.5)₈ = 6×64 + 6×8 + 4 + 5×(1/8) = 384 + 48 + 4 + 0.625 = 436.625 ✓ 같다
  3. ③ (1B4.C)₁₆ = 1×256 + 11×16 + 4 + 12×(1/16) = 256 + 176 + 4 + 0.75 = 436.75 ✗

포인트: 정수부는 셋 다 436으로 같고 소수부에서만 갈린다. 8진수의 .5는 5/8 = 0.625, 16진수의 .C는 12/16 = 0.75 — 소수부 자릿값이 각각 1/8, 1/16임을 기억할 것.

문제 32007 국가직 · 기출문제집 p.40

다음 2진수 1010101110.11₂을 16진수로 정확히 표현한 것은?

  1. 2AE.3₁₆
  2. AB2.C₁₆
  3. 2AE.C₁₆
  4. AB2.3₁₆
해설 보기

정답 ③ 2AE.C₁₆

  1. 정수부 1010101110 (10자리)을 오른쪽부터 4비트씩 → 10|1010|1110, 왼쪽에 0을 채워 0010 1010 1110
  2. 각각 변환: 0010 = 2, 1010 = A, 1110 = E → 정수부 = 2AE
  3. 소수부 .11을 왼쪽부터 4비트씩 → 2개뿐이므로 오른쪽에 0을 채워 1100
  4. 1100 = C → 소수부 = .C
  5. 합치면 2AE.C

함정: ①번(.3)은 소수부를 0011로 만든 오답 — 왼쪽에 0을 채워버린 전형적 실수다. 소수부는 반드시 오른쪽에 0을 채운다. 또 ②④의 AB2는 정수부를 왼쪽부터 묶은 오답이다.

문제 42020 국가직 · 기출문제집 p.41

8진수 123.321을 16진수로 변환한 것은?

  1. 53.35
  2. 53.321
  3. 53.681
  4. 53.688
해설 보기

정답 ④ 53.688

8진 → 16진은 직접 못 간다. 반드시 2진수를 경유한다.

  1. 8진수를 3비트씩 펼친다: 1→001, 2→010, 3→011 / .3→011, 2→010, 1→001
    ⇒ 001010011 . 011010001
  2. 정수부 001010011을 오른쪽부터 4비트씩 → 0101 0011 → 5, 3
  3. 소수부 011010001을 왼쪽부터 4비트씩 → 0110 1000 1, 마지막 묶음이 1비트뿐이므로 오른쪽에 0을 채워 0110 1000 1000
  4. 각각 변환: 0110 = 6, 1000 = 8, 1000 = 8 → 소수부 = .688
  5. 합치면 53.688

함정: ③번(53.681)은 마지막 1비트를 0001로 처리한 오답이다. 소수부 마지막 묶음은 뒤에 0을 붙여 1000이 되어야 한다. ②번(53.321)은 소수부를 변환하지 않고 그대로 베낀 함정.

문제 52022 지방직 · 기출문제집 p.42

16진수 210을 8진수로 변환한 것은?

  1. 1020
  2. 2100
  3. 10210
  4. 20100
해설 보기

정답 ① 1020

  1. 16진수를 4비트씩 펼친다: 2→0010, 1→0001, 0→0000 ⇒ 001000010000
  2. 이제 같은 비트열을 3비트씩 다시 묶는다 (오른쪽부터): 001 000 010 000
  3. 각각 8진수로: 001 = 1, 000 = 0, 010 = 2, 000 = 0 → 1020

검산: 210₁₆ = 2×256 + 1×16 + 0 = 528. 1020₈ = 1×512 + 0 + 2×8 + 0 = 528 ✓

포인트: 16진 → 8진의 핵심은 "4비트로 펼쳤다가 3비트로 다시 묶기"다. 자릿수가 4자리로 늘어나는 게 정상이니 당황하지 말 것.

문제 62024 지방직 · 기출문제집 p.44

8진수 543₍₈₎과 10진수 124₍₁₀₎의 합을 8진수로 표현한 것은?

  1. 626₍₈₎
  2. 637₍₈₎
  3. 726₍₈₎
  4. 737₍₈₎
해설 보기

정답 ④ 737₍₈₎

진법이 다른 수끼리는 바로 더할 수 없다. 한쪽 진법으로 통일하는 게 원칙이고, 보통 10진수가 계산하기 쉽다.

  1. 543₈을 10진수로: 5×64 + 4×8 + 3×1 = 320 + 32 + 3 = 355
  2. 더하기: 355 + 124 = 479
  3. 479를 8진수로 되돌린다: 479 ÷ 8 = 59 … 7 / 59 ÷ 8 = 7 … 3 / 7 ÷ 8 = 0 … 7
  4. 나머지를 역순으로 읽어 737₈ (검산: 7×64 + 3×8 + 7 = 448+24+7 = 479 ✓)

함정: 8진수 543을 10진수 543으로 착각하면 543+124=667 → 1233₈ 같은 엉뚱한 값이 나온다. 아래 첨자를 먼저 확인하는 습관을 들일 것.

문제 72025 지방직 · 기출문제집 p.45

값이 (01100000)₂가 아닌 것은? (단, 아래 첨자는 진법, +는 덧셈, ×는 곱셈)

  1. (60)₁₆
  2. (60)₈ + (60)₈
  3. (00110000)₂ × (00000010)₂
  4. (46)₁₀에 대하여 왼쪽 산술 시프트 1회
해설 보기

정답 ④ (46)₁₀ 왼쪽 시프트 1회 = 92 (≠ 96)

  1. 기준값: (01100000)₂ = 64 + 32 = 96
  2. ① (60)₁₆ = 6×16 + 0 = 96 ✓
  3. ② (60)₈ = 6×8 = 48 → 48 + 48 = 96 ✓
  4. ③ (00110000)₂ = 48, (00000010)₂ = 2 → 48 × 2 = 96 ✓
  5. ④ 왼쪽 시프트 1회 = ×2 이므로 46 × 2 = 92 ✗ ← 정답

핵심 규칙: 왼쪽 시프트 1회 = ×2, 오른쪽 시프트 1회 = ÷2. 이것만 알면 ④를 바로 계산할 수 있다. 같은 이유로 ③의 "×(00000010)₂"도 사실 왼쪽 시프트 1회와 같은 연산이다.

문제 82011 지방직 · 기출문제집 p.37

한 페이지에 1,024개의 문자를 포함하고 512페이지로 구성된 책을 1GB의 저장장치에 저장할 경우, 최대 몇 권을 저장할 수 있는가? (단, 유니코드 방식으로 문자를 표현하고 부가 정보는 고려하지 않는다)

  1. 512
  2. 1,024
  3. 2,048
  4. 4,096
해설 보기

정답 ② 1,024권

유니코드는 문자 1개가 16비트 = 2바이트라는 게 출발점이다.

  1. 1페이지 용량 = 1,024문자 × 2바이트 = 2,048바이트 = 2¹¹ B
  2. 책 1권 = 512페이지 × 2¹¹ B = 2⁹ × 2¹¹ = 2²⁰ B = 1MB
  3. 저장장치 1GB = 2³⁰ B
  4. 2³⁰ ÷ 2²⁰ = 2¹⁰ = 1,024권

함정: ASCII(1바이트)로 착각하면 2,048권(③)이 나온다. 문제에 "유니코드"라고 명시돼 있으면 반드시 ×2바이트. 지수 계산(2¹⁰ = 1024)에 익숙해지면 암산으로도 풀린다.
