입출력 제어와 병렬처리

I/O 제어 방식, Flynn의 분류, 암달의 법칙, 클라우드 컴퓨팅 · PART 01. 전자계산기구조론

핵심 요약

I/O 제어는 프로그램 I/O → 인터럽트 구동 I/O → DMA → 채널 순으로 CPU 부담이 줄어든다.

병렬처리는 Flynn의 분류(SISD/SIMD/MISD/MIMD)로 나누고, 성능 향상의 한계는 암달의 법칙으로 계산한다.

💡주요 개념

I/O 제어 방식 4가지 (CPU 부담이 큰 순서 → 작은 순서)

방식동작CPU 개입
프로그램 I/OCPU가 입출력 명령을 직접 실행·대기가장 큼 (시간 낭비 심함)
인터럽트 구동 I/OI/O 모듈이 동작하는 동안 CPU는 다른 일 처리, 끝나면 인터럽트로 통지중간
DMADMA 제어기가 기억장치↔I/O 간 데이터 전송을 전담, CPU는 시작·종료에만 관여작음
채널자체 채널 프로그램으로 CPU 간섭 없이 여러 블록을 한 번에 입출력가장 작음 (최고성능)
비유: 프로그램 I/O = 사장이 직접 택배 포장, 인터럽트 = 포장 끝나면 알려달라 하고 다른 일, DMA = 아예 택배기사에게 통째로 맡김, 채널 = 전담 물류팀이 알아서 여러 건을 처리

DMA (Direct Memory Access)

  • 대용량 데이터 전송 시 CPU 레지스터를 거치지 않고 기억장치와 I/O 간 직접 전송
  • 기억장치 접근을 위해 CPU의 시스템 버스 사용권을 잠시 빼앗는 사이클 스틸링(cycle stealing) 수행
  • 전송이 완료되면 DMA 제어기가 CPU에 인터럽트를 요청
  • 한 시스템에 여러 개의 DMA 제어기가 존재할 수 있음
함정 주의: "대량 고속 전송에는 인터럽트 방식이 DMA보다 효율적" → ❌ 틀림. DMA가 CPU 상태정보 저장 없이 직접 접근하므로 더 효율적이다.

폴링(Polling) vs 인터럽트(Interrupt)

  • 폴링: 프로세서가 I/O 장치 상태를 반복적으로 검사(체크)하며 대기 → CPU 시간 낭비가 가장 심함
  • 인터럽트: 신호가 발생했을 때만 I/O에 관여 → 폴링보다 CPU 효율적

버퍼링(Buffering) vs 스풀링(Spooling)

구분버퍼링스풀링
목적느린 I/O와 빠른 CPU 간 속도차 보완동일
범위한 작업의 입출력과 계산을 동시 수행여러 작업의 입출력·계산을 함께 수행
사용 공간주기억장치디스크 (큰 버퍼처럼 사용)

Flynn의 분류 (명령어·데이터 스트림 기준)

분류명령어 스트림데이터 스트림예시
SISD1개1개단일 프로세서, 파이프라이닝
SIMD1개n개배열처리기(Array processor), GPU
MISDn개1개이론적 모델 (실제 사례 거의 없음)
MIMDn개n개다중처리기, 클러스터
함정 주의: "명령어가 순서대로 실행되지만 여러 단계로 나눠 중첩 실행" → 이건 파이프라이닝(SISD) 설명이다. MIMD와 헷갈리지 말 것.

GPU / GPGPU

  • GPU는 단순한 ALU를 매우 많이 가지고 있어 대량의 간단한 연산을 병렬로 빠르게 처리 (SIMD 방식)
  • 제어 부분이 약해 분기문(if) 처리에는 취약 → CPU가 GPU를 제어하는 구조
  • GPGPU: 그래픽 연산 외의 범용 계산에 GPU를 활용하는 기술 (OpenCL 등 사용)
  • 기계학습·인공신경망·블록체인 연산에 GPU가 널리 쓰이는 이유 = 대량의 단순 연산을 병렬 처리하는 데 최적화된 구조이기 때문

슈퍼스칼라 / VLIW / 슈퍼파이프라인

기법원리병렬화 결정 주체
슈퍼스칼라 (Superscalar)여러 개의 파이프라인(기능 유니트)을 두어 한 사이클에 2개 이상 명령어 동시 처리하드웨어
VLIW하나의 긴 명령어 안에 여러 연산을 미리 묶어 넣어 동시 실행컴파일러
슈퍼파이프라인파이프라인 한 단계를 더 잘게 쪼개 내부 클록 주파수를 높임하드웨어

암달의 법칙 (Amdahl's Law) ⭐ 계산 필수

시스템 일부를 개선했을 때 전체 성능 향상의 한계를 구하는 공식
전체 성능 향상 배수 = 1 / [ (1 − p) + p/s ]
(p = 개선 대상 부분이 차지하는 비율, s = 그 부분의 성능 향상 배수)

병렬처리 프로세서 수를 늘려도 순차 실행 부분 때문에 성능 향상에 한계가 있다는 것을 보여준다. (무어의 법칙과 다름 — 혼동 주의)

예시: 전체 작업의 75%를 4배 빠르게 해도, 나머지 25%는 그대로이므로 → 1 / [0.25 + 0.75/4] = 약 2.28배. "부분만 빨라져도 전체가 그만큼 빨라지진 않는다"가 핵심.

병렬 컴퓨터 시스템 구조

구분설명

NUMA (불균일 기억장치 액세스)로컬 메모리 접근이 원격 메모리 접근보다 빠름 (거리에 따라 접근시간 차이)
NORMA (무-원격 기억장치 액세스)프로세서가 원격(다른 노드) 기억장치에 직접 접근 불가

그리드 컴퓨팅원거리(WAN)로 연결된 서로 다른 종류의 컴퓨터들을 묶어 가상의 고성능 컴퓨터 구성

  • Public Cloud: 인터넷을 통해 비용 지불(또는 무료)로 사용 / Private Cloud: 회사 내부용

📌시험 빈출 포인트

  • I/O 제어 방식 중 CPU 부담이 가장 작은 것: 채널 > DMA > 인터럽트 > 프로그램 I/O 순 이해
  • DMA는 사이클 스틸링으로 시스템 버스 사용권을 일시적으로 가져간다
  • 버퍼링=주기억장치 사용, 스풀링=디스크 사용 — 자주 뒤바꿔 출제
  • Flynn 분류에서 "여러 단계로 나눠 중첩 실행"은 SISD(파이프라이닝)이지 MIMD가 아님
  • GPU/GPGPU가 유리한 이유 = 대량의 단순 병렬 연산 (분기문 처리는 오히려 취약)
  • 암달의 법칙 계산 문제: p(개선 비율)와 s(개선 배수)를 대입해 전체 향상 배수 구하기
  • 클라우드 서비스 모델 3단계(IaaS/PaaS/SaaS) 구분 — 매년 국가직/지방직 단골 출제
