입출력 제어와 병렬처리

I/O 제어 방식, Flynn의 분류, 암달의 법칙, 클라우드 컴퓨팅 · PART 01. 전자계산기구조론

핵심 요약

I/O 제어는 프로그램 I/O → 인터럽트 구동 I/O → DMA → 채널 순으로 CPU 부담이 줄어든다.

병렬처리는 Flynn의 분류(SISD/SIMD/MISD/MIMD)로 나누고, 성능 향상의 한계는 암달의 법칙으로 계산한다.

🎯이 단원을 왜 배우나

CPU는 너무 빠르고, 입출력 장치는 너무 느리다

CPU가 명령어 하나를 처리하는 데 나노초(10⁻⁹초)가 걸린다면, 하드디스크에서 데이터 하나를 읽는 데는 밀리초(10⁻³초)가 걸린다. 백만 배 차이다. 사람으로 치면 CPU가 1초 만에 할 일을 기다리느라 11일을 멍하니 서 있는 셈이다.

이 낭비를 어떻게 줄일 것인가 — 그 답의 발전사가 바로 I/O 제어 방식 4가지다. ①CPU가 직접 다 하다가(프로그램 I/O) → ②"끝나면 알려줘" 하고 다른 일 하다가(인터럽트) → ③"메모리에 직접 갖다 놔" 하고 아예 위임하고(DMA) → ④전용 프로세서에 통째로 맡기는(채널) 순서로 발전했다. 뒤로 갈수록 CPU가 편해진다는 흐름만 잡으면 이 단원 절반은 끝이다.

그리고 또 하나 — CPU를 여러 개 쓰면 그만큼 빨라질까?

안 빨라진다. 이것이 암달의 법칙이 말하는 바다. 아무리 코어를 늘려도 병렬화가 불가능한 순차 부분이 발목을 잡기 때문이다. 전체의 25%가 순차 실행이라면, 코어를 무한히 늘려도 최대 4배 이상 빨라질 수 없다.

이 단원의 계산 문제는 거의 전부 암달의 법칙 하나에서 나온다. 공식 하나에 변형이 3가지뿐이니 아래 연습문제 4~7번으로 그 3가지를 모두 익히면 된다.

DMA (Direct Memory Access) 📖 기출문제집 p.150

  • 대용량 데이터 전송 시 CPU 레지스터를 거치지 않고 기억장치와 I/O 간 직접 전송
  • 기억장치 접근을 위해 CPU의 시스템 버스 사용권을 잠시 빼앗는 사이클 스틸링(cycle stealing) 수행
  • 전송이 완료되면 DMA 제어기가 CPU에 인터럽트를 요청
  • 한 시스템에 여러 개의 DMA 제어기가 존재할 수 있음
함정 주의: "대량 고속 전송에는 인터럽트 방식이 DMA보다 효율적" → ❌ 틀림. DMA가 CPU 상태정보 저장 없이 직접 접근하므로 더 효율적이다.

폴링(Polling) vs 인터럽트(Interrupt)

  • 폴링: 프로세서가 I/O 장치 상태를 반복적으로 검사(체크)하며 대기 → CPU 시간 낭비가 가장 심함
  • 인터럽트: 신호가 발생했을 때만 I/O에 관여 → 폴링보다 CPU 효율적

GPU / GPGPU

  • GPU는 단순한 ALU를 매우 많이 가지고 있어 대량의 간단한 연산을 병렬로 빠르게 처리 (SIMD 방식)
  • 제어 부분이 약해 분기문(if) 처리에는 취약 → CPU가 GPU를 제어하는 구조
  • GPGPU: 그래픽 연산 외의 범용 계산에 GPU를 활용하는 기술 (OpenCL 등 사용)
  • 기계학습·인공신경망·블록체인 연산에 GPU가 널리 쓰이는 이유 = 대량의 단순 연산을 병렬 처리하는 데 최적화된 구조이기 때문

암달의 법칙 (Amdahl's Law) ⭐ 계산 필수 📖 기출문제집 p.163~165

시스템 일부를 개선했을 때 전체 성능 향상의 한계를 구하는 공식
전체 성능 향상 배수 = 1 / [ (1 − p) + p/s ]
(p = 개선 대상 부분이 차지하는 비율, s = 그 부분의 성능 향상 배수)

공식을 외우지 말고 "시간"으로 이해하라

공식이 복잡해 보이지만, 전체 작업 시간을 1이라고 두고 개선 후 시간을 계산한 것일 뿐이다.

  • 전체 시간 1 중에서 개선되는 부분이 p, 개선 안 되는 부분이 (1 − p)
  • 개선 안 되는 부분 (1 − p)는 그대로 걸린다
  • 개선되는 부분 p는 s배 빨라졌으니 p/s만 걸린다
  • → 개선 후 총 시간 = (1 − p) + p/s
  • 성능 향상 배수 = 원래 시간 ÷ 새 시간 = 1 / [(1 − p) + p/s]

즉 분모가 바로 "개선 후에 남은 시간 비율"이다. 이것만 이해하면 공식을 잊어버려도 그 자리에서 다시 만들 수 있다.

왜 한계가 있나

s를 무한대로 키워도(그 부분이 순식간에 끝나도) p/s는 0이 될 뿐, (1 − p)는 절대 사라지지 않는다. 따라서 최대 성능 향상은 1 / (1 − p)를 넘을 수 없다. 순차 부분이 25%면 아무리 코어를 늘려도 최대 4배가 천장이다. (무어의 법칙과는 전혀 다른 개념 — 혼동 주의)

문제 유형은 딱 3가지다. 공식 1 / [(1−p) + p/s]에서 무엇을 묻느냐만 다르다:

유형주어지는 것구하는 것연습문제
① 정방향p, s전체 성능 향상 배수4번
② 시간 계산p, s, 원래 소요시간개선 후 소요시간5번
③ 역산p, 목표 성능 향상필요한 s (또는 n)6·7번

  • 클라우드 서비스 모델 3단계(IaaS/PaaS/SaaS) 구분 — 매년 국가직/지방직 단골 출제

문제 12012 국회직 · 기출문제집 p.148~149

컴퓨터의 입출력 방식 중에서 CPU의 부담이 작은 방식부터 순서대로 나열한 것은?

  1. 인터럽트 구동 I/O — DMA — 프로그램된 I/O
  2. 인터럽트 구동 I/O — 프로그램된 I/O — DMA
  3. DMA — 프로그램된 I/O — 인터럽트 구동 I/O
  4. DMA — 인터럽트 구동 I/O — 프로그램된 I/O
해설 보기

정답 ④ DMA — 인터럽트 구동 I/O — 프로그램된 I/O

CPU 부담이 큰 순서로는 프로그램 I/O > 인터럽트 구동 I/O > DMA > 채널 순이다. 이 문제는 "작은 것부터"를 물었으므로 이 순서를 뒤집으면 된다.

  1. 프로그램된 I/O: CPU가 입출력 완료를 계속 확인(폴링)하며 기다림 → 부담 최대
  2. 인터럽트 구동 I/O: 맡겨두고 다른 일 하다가 "끝났다"는 신호를 받음 → 부담 중간 (단, 데이터 전송 자체는 여전히 CPU가 함)
  3. DMA: 데이터 전송까지 DMA 제어기가 전담, CPU는 시작과 끝에만 관여 → 부담 최소

함정: "작은 것부터"인지 "큰 것부터"인지를 놓치면 정반대 선택지를 고르게 된다. 문제에서 순서의 방향에 반드시 밑줄을 치고 시작할 것.

문제 2기출문제집 p.150

컴퓨터 입출력 방식에서 DMA(Direct Memory Access)에 대한 설명으로 옳지 않은 것은?

  1. DMA를 통한 데이터 전송 시 CPU의 레지스터를 거치지 않는다.
  2. DMA 제어기와 CPU가 시스템 버스를 공유한다.
  3. DMA 제어기에 의한 입출력이 수행되는 도중에 CPU는 다른 작업을 수행할 수 없다.
  4. DMA를 통한 메모리 접근을 위해서는 사이클 스틸링이 필요하다.
해설 보기

정답 ③ — DMA 동작 중에도 CPU는 다른 작업을 수행할 수 있다

DMA의 존재 이유가 바로 "CPU를 입출력에서 해방시키는 것"이다. CPU는 DMA에 명령만 내리고 곧바로 다른 프로그램을 처리하며, 전송이 다 끝나면 DMA가 인터럽트로 알려준다.

나머지 선택지가 모두 맞는 이유:

  • ① 데이터가 메모리 ↔ 입출력장치로 직접 이동하므로 CPU 레지스터를 경유하지 않는다 (이름 그대로 Direct)
  • ② 메모리에 접근하려면 시스템 버스를 써야 하므로 CPU와 공유한다
  • ④ 그래서 버스가 빌 때 CPU로부터 버스 사용권을 잠깐 뺏는데, 이것이 사이클 스틸링(cycle stealing)이다

핵심 정리: CPU는 입출력의 시작과 마지막(인터럽트 수신)에만 관여한다.

문제 3개념 확인 · 응용

DMA가 데이터를 전송하는 동안 CPU와 시스템 버스 사용권을 두고 충돌한다. 이때 DMA가 버스를 잠시 점유하는 기법의 이름은 무엇이며, CPU와 DMA 중 버스 우선순위가 높은 쪽은?

해설 보기

정답: 사이클 스틸링(cycle stealing), 우선순위는 DMA가 더 높다

  1. DMA도 메모리에 접근하려면 주소·데이터 버스가 필요한데, 이 버스는 CPU도 쓰는 공용 자원이다
  2. 그래서 DMA는 CPU가 버스를 쓰지 않는 사이클을 "훔쳐서(steal)" 전송한다 → 사이클 스틸링
  3. 버스 요청이 겹치면 DMA에 우선권을 준다. 입출력 장치는 타이밍을 놓치면 데이터가 유실될 수 있지만, CPU는 한 사이클 늦게 처리해도 문제가 없기 때문이다

주의: 사이클 스틸링 때문에 CPU가 아주 약간 느려지긴 하지만, 프로그램 I/O처럼 완전히 멈춰 기다리는 것과는 차원이 다르다.

문제 42016 서울시 · 기출문제집 p.163

암달(Amdahl)의 법칙에 따라, 특정 응용프로그램의 75%가 멀티코어를 이용한 병렬 수행이 가능하고 나머지 25%는 순차 실행만 가능하다는 전제 하에, 컴퓨팅 코어의 수를 4개로 늘릴 때 기대할 수 있는 최대 성능 향상은 약 몇 배인가?

  1. 약 1.28배
  2. 약 2.28배
  3. 약 3.28배
  4. 약 4.28배
해설 보기

정답 ② 약 2.28배

유형 ① 정방향 — p와 s를 공식에 그대로 대입하는 가장 기본 문제.

  1. 값 정리: p = 0.75(병렬화 가능 비율), s = 4(코어 4개)
  2. 분모 계산: (1 − p) + p/s = 0.25 + 0.75/4 = 0.25 + 0.1875 = 0.4375
  3. 성능 향상 = 1 ÷ 0.4375 = 약 2.29 (≈ 2.28배)

함정: ④번 약 4.28배는 "코어 4개니까 4배"라고 생각한 오답이다. 암달의 법칙의 요점은 정확히 그 직관이 틀렸다는 것 — 순차 부분 25%가 전혀 줄지 않기 때문이다.

참고: 코어를 무한히 늘려도 최대치는 1 ÷ 0.25 = 4배가 천장이다.

문제 52023 지방직 · 기출문제집 p.163

다음은 어떤 시스템의 성능 개선에 대한 내용이다. 성능 개선 후 프로그램 P의 실행에 걸리는 소요시간은?
• 개선 전, 특정 부분 A의 실행에 30초가 소요되었고, A를 포함한 전체 프로그램 P의 실행에 50초가 소요되었다.
• 시스템의 성능을 개선하여 A의 실행 속도를 2배 향상시켰다.
• 그 외 조건 변화는 없다.

  1. 25초
  2. 30초
  3. 35초
  4. 40초
해설 보기

정답 ③ 35초

유형 ② 시간 계산 — 사실 이 문제는 공식 없이 푸는 게 더 빠르다.

  1. 개선되는 부분 A: 30초 → 2배 빨라지므로 15초
  2. 개선 안 되는 나머지: 50 − 30 = 20초 (그대로)
  3. 합계: 15 + 20 = 35초

공식으로 검산: p = 30/50 = 0.6, s = 2 → 분모 = 0.4 + 0.6/2 = 0.7 → 성능향상 = 1/0.7 배 → 새 시간 = 50 × 0.7 = 35초 ✓

요령: "소요시간"을 묻는 문제는 부분별로 시간을 직접 계산해 더하는 방식이 공식 대입보다 빠르고 실수가 적다. 공식은 검산용으로만 쓰자.

문제 62015 국회직 · 기출문제집 p.164

어떤 프로그램에서 부동소수점 곱셈 연산이 전체 수행시간의 70%를 차지한다. 해당 프로그램의 성능을 2배 향상시키려면(전체 수행시간을 1/2로 단축) 부동소수점 곱셈 연산의 성능이 몇 배 향상되어야 하는가?

  1. 1.3배
  2. 2배
  3. 3배
  4. 3.5배
해설 보기

정답 ④ 3.5배

유형 ③ 역산 — 목표 성능 향상을 주고 필요한 s를 구하는 문제. 공식을 s에 대해 푼다.

  1. 식 세우기: 2 = 1 / [(1 − 0.7) + 0.7/s]
  2. 양변 정리: (1 − 0.7) + 0.7/s = 1/2 = 0.5
  3. 0.3 + 0.7/s = 0.5 → 0.7/s = 0.2
  4. s = 0.7 ÷ 0.2 = 3.5배

검산: s=3.5를 넣으면 분모 = 0.3 + 0.2 = 0.5 → 1/0.5 = 2배 ✓

함정: ②번 2배는 "전체를 2배 만들려면 그 부분도 2배"라고 생각한 오답이다. 순차 부분(30%)이 남아 있으므로 개선 대상은 2배보다 훨씬 더 빨라져야 한다.

문제 72017 하반기 지방직 · 기출문제집 p.164~165

어떤 컴퓨터에서 프로그램 P를 실행할 때 실행시간 중 60%의 시간이 연산 A에 소요된다. 연산 A만을 n배 빠르게 실행하도록 성능을 향상시킨 후 프로그램 P의 실행시간이 50% 감소했다면, n의 값은?

  1. 2
  2. 4
  3. 6
  4. 10
해설 보기

정답 ③ n = 6

유형 ③ 역산의 변형. 먼저 "실행시간 50% 감소 = 성능 2배 향상"이라는 말을 바꿔 읽는 것이 첫 관문이다.

  1. 조건 변환: 시간이 절반으로 줄었다 → 성능 향상 배수 = 2
  2. 식 세우기: 2 = 1 / [(1 − 0.6) + 0.6/n]
  3. 정리: 0.4 + 0.6/n = 0.5 → 0.6/n = 0.1
  4. n = 0.6 ÷ 0.1 = 6

검산: n=6 → 분모 = 0.4 + 0.1 = 0.5 → 1/0.5 = 2배 ✓ (시간 50% 감소)

표현 정리: "시간 50% 감소" = "성능 2배", "시간 1/3로 단축" = "성능 3배". 시간과 성능은 역수 관계라는 것만 기억하면 이 관문은 넘어간다.
