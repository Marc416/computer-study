명령어와 인터럽트

명령어 형식·주소지정 방식과 인터럽트 처리 · PART 01. 전자계산기구조론

핵심 요약

명령어 = OPCODE(연산코드) + OPERAND(주소부). OPCODE 비트 수로 명령어 종류 수를, OPERAND 비트 수로 주소 공간 크기를 계산한다.

인터럽트 = 실행 중 예기치 않은 상황이 생기면 현재 작업을 잠시 멈추고, 원인을 처리한 뒤, 원래 작업으로 복귀하는 기능.

🎯이 단원을 왜 배우나

명령어 = "무엇을" + "누구에게" 두 칸짜리 쪽지

CPU에게 일을 시키려면 무슨 일을 할지(더해라·옮겨라)와 무엇을 대상으로 할지(500번지 값을)를 알려줘야 한다. 그래서 명령어는 OP-Code 필드와 OPERAND 필드 두 칸으로 나뉜 고정 길이 쪽지다.

그런데 쪽지 전체 길이가 정해져 있으니(예: 32비트) 한쪽을 늘리면 다른 쪽이 줄어드는 트레이드오프가 생긴다. OP-Code를 늘리면 명령어 종류는 많아지지만 접근할 수 있는 메모리 범위가 좁아지고, 반대도 마찬가지다. 시험 문제는 100% 이 트레이드오프 계산이다 — "한쪽 비트 수를 주고 다른 쪽을 구하라."

인터럽트 = "부르면 갈게" 방식

프린터에 출력을 시켰다고 하자. 프린터는 CPU보다 수만 배 느리다. CPU가 "다 됐니? 다 됐니?"를 계속 물어보며 기다리면(폴링) 그동안 아무 일도 못 한다. 대신 "다 되면 네가 나를 불러라"라고 해두고 CPU는 딴 일을 하는 게 인터럽트다.

이 방식이 성립하려면 조건이 하나 있다 — 불려 갔다가 원래 하던 자리로 정확히 돌아올 수 있어야 한다. 그래서 인터럽트 처리의 절반은 "하던 일을 어디에 어떻게 적어두고 떠날 것인가(상태 저장)"에 관한 이야기이고, 시험도 그 순서를 집요하게 묻는다.

💡주요 개념

명령어 형식 계산 문제 📖 기출문제집 p.102~103

  • OPCODE 비트 수 n → 표현 가능한 명령어 종류 = 2ⁿ개
  • OPERAND(주소부) 비트 수 m → 표현 가능한 주소 공간 = 2ᵐ개

예제: 32비트 명령어, OPERAND가 256M(=2²⁸)워드 주소를 표현할 때 OPCODE로 표현 가능한 명령어 종류는?

  1. 256M = 256 × 2²⁰ = 2⁸ × 2²⁰ = 2²⁸ → OPERAND 필드는 28비트가 필요
  2. 전체 명령어 길이 32비트 중 OPERAND가 28비트를 차지
  3. 남는 OPCODE 비트 수 = 32 − 28 = 4비트
  4. OPCODE 4비트로 표현 가능한 명령어 종류 = 2⁴ = 16개
예제2: 12비트 명령어(연산코드 5비트 + 주소부 7비트), 직접 주소지정 방식, 주소 1개=1바이트 → 주소부 7비트로 표현 가능한 최대 메모리 = 2⁷ = 128바이트

단위 변환을 실수하지 않는 법

이 유형에서 틀리는 이유는 논리가 아니라 단위 환산이다. 아래 세 개만 외워두면 어떤 숫자가 나와도 지수로 바꿀 수 있다.

  • K = 2¹⁰, M = 2²⁰, G = 2³⁰
  • 앞에 붙은 숫자도 2의 거듭제곱으로: 256 = 2⁸, 64 = 2⁶, 4 = 2²
  • 곱셈은 지수의 덧셈: 256M = 2⁸ × 2²⁰ = 2²⁸ → 28비트

그리고 마지막에 "워드 단위인가 바이트 단위인가"를 반드시 확인하라. "1워드 = 32비트"라고 문제에 써 있으면 주소 1개가 4바이트를 가리킨다는 뜻이고, 메모리 용량을 물으면 주소 개수에 워드 크기를 곱해야 한다. 반면 "주소 1개 = 1바이트"면 주소 개수가 곧 바이트 수다(예제2).

주소지정 방식 (Addressing Mode) — 요약

방식설명
즉시 주소지정 (Immediate)오퍼랜드 자체가 데이터. 메모리 접근 없이 바로 사용 (가장 빠름)
직접 주소지정 (Direct)오퍼랜드가 데이터가 저장된 유효주소 그 자체
간접 주소지정 (Indirect)오퍼랜드가 가리키는 곳에 또 다른 주소가 있고, 그 주소에 데이터가 있음 (메모리 2번 접근)
상대 주소지정 (Relative)프로그램 카운터(PC) 기준으로 상대적 위치를 계산해 데이터 참조
비유: 즉시 = "지갑 속 현금 바로 사용", 직접 = "집 주소를 알려줌", 간접 = "이 쪽지가 가리키는 곳에 집 주소가 있음"
주소지정 방식 7종 전체 비교, 메모리 접근 횟수 다이어그램, 속도 순서는 CPU 레지스터와 명령어 처리 문서에 자세히 정리되어 있다. 이 문서에서는 명령어 형식 계산과 인터럽트에 집중한다.

인터럽트란?

컴퓨터 시스템에 예기치 않은 일이 발생했을 때 이를 CPU에 알리고, 현재 실행 중인 프로그램을 강제로 중단시킨 뒤 특정 위치(인터럽트 서비스 루틴)의 프로그램을 수행하게 하는 것.

구성 요소: 인터럽트 요청회로 + 인터럽트 처리 루틴 + 인터럽트 서비스 루틴

인터럽트가 없으면 어떻게 되나 — 폴링과의 비교

인터럽트가 없던 시절에는 CPU가 직접 물어보는 수밖에 없었다. 이를 폴링(polling) 또는 프로그램에 의한 I/O라 한다. CPU가 while(안 끝났으면) 계속 확인; 루프를 돌며 플래그를 검사하는 방식이라, 기다리는 내내 CPU가 통째로 낭비된다.

인터럽트 방식에서는 CPU가 입출력 명령만 던져놓고 다른 프로그램을 실행한다. 장치가 준비되면 신호를 보내오고, 그때서야 CPU가 하던 일을 잠시 멈추고 처리한다. 같은 시간에 훨씬 많은 일을 할 수 있으므로 시스템 전체 처리량이 올라간다.

세 방식의 차이 (자주 나오는 비교):

  • 프로그램에 의한 I/O(폴링): CPU가 플래그를 계속 검사 + 데이터 전송도 CPU가 직접 → 가장 비효율
  • 인터럽트 구동 I/O: 검사는 불필요(장치가 알려줌), 단 데이터 전송은 여전히 CPU가 직접
  • DMA: 장치가 주기억장치에 직접 접근해 블록 단위로 전송 → 데이터가 CPU 레지스터를 거치지 않음

즉 인터럽트는 "기다림"을 없앴고, DMA는 "전송 노동"까지 없앴다. 2015 서울시 기출이 정확히 이 세 가지를 구분시키는 문제였다.

인터럽트의 종류

구분종류예시
발생 위치외부 인터럽트 (하드웨어적)전원 이상, 기계 오작동, 입출력 완료, 외부 신호
내부 인터럽트 (소프트웨어적)오버플로, 0으로 나누기, 잘못된 명령어(프로그램 검사), 트랩·SVC(슈퍼바이저 호출)
발생 시점비동기 인터럽트CPU 동작과 무관하게 외부에서 발생 (키보드·마우스 입력, 타이머, 전원 이상)
동기 인터럽트명령어 실행 중 내부에서 발생 (0으로 나누기, 보호 메모리 접근)

인터럽트 처리 순서 📖 기출문제집 p.104~105

  1. 인터럽트 발생 장치로부터 요청 신호 수신
  2. 현재 프로그램의 상태(PC, 레지스터)를 스택에 저장
  3. 인터럽트 원인을 분석하고 해당 서비스 루틴을 호출·실행
  4. 서비스 루틴 종료 후 저장했던 PC·상태를 복구 → 인출(Fetch) 사이클부터 재개
함정 주의: 인터럽트 사이클을 마치면 실행 사이클이 아니라 반드시 인출(Fetch) 사이클부터 다시 시작한다. 또한 인터럽트가 끝난 뒤 항상 원래 프로세스로 복귀하는 것은 아니며, 스케줄링 정책에 따라 다른 프로세스가 실행될 수도 있다.

인터럽트 우선순위

하드웨어적 인터럽트 > 소프트웨어적 인터럽트 순서로 우선순위가 높다.

구분우선순위 순서 (높음 → 낮음)
하드웨어적전원 이상 → 기계 착오 → 외부 신호 → 입출력
소프트웨어적명령의 잘못 사용(프로그램 인터럽트) → 슈퍼바이저 호출(SVC)

우선순위 결정 방식

방식설명
폴링 (Polling)소프트웨어적으로 각 장치를 순서대로 검사해서 요청 장치를 찾음 — 느림
데이지 체인 (Daisy Chain)모든 장치가 인터럽트 요구선을 공유하며 직렬로 연결. CPU와 가까운 장치일수록 우선순위 높음. 하드웨어 간단하지만 뒤쪽 장치는 오래 기다릴 수 있음
다중 인터럽트 선장치마다 독립적인 인터럽트 선을 두어 병렬로 식별
인터럽트 벡터장치가 자신의 서비스 루틴 주소(벡터)를 직접 CPU에 전달

📌시험 빈출 포인트

  • OPCODE 비트 수 → 명령어 개수(2ⁿ), OPERAND 비트 수 → 주소공간 크기(2ᵐ) 계산 문제
  • 즉시 주소지정 방식은 메모리 접근이 필요 없음 (오퍼랜드=데이터 자체)
  • 인터럽트 서비스 루틴의 시작 주소는 프로그램 카운터(PC)에 적재됨
  • 인터럽트 사이클 후에는 반드시 인출 사이클을 수행 (실행 사이클 아님)
  • 데이지 체인 방식 — CPU에 가까운 장치일수록 우선순위 높음 (자주 나오는 함정: "병렬 연결"이 아니라 직렬 연결)
  • 인터럽트 우선순위: 하드웨어 > 소프트웨어, 그 중 전원 이상이 최우선
  • 인터럽트 처리 후 반드시 원래 프로세스로 복귀하는 것은 아님 (스케줄링에 따라 다름)
  • 오버플로·0으로 나누기는 내부(동기) 인터럽트 — 외부 인터럽트 요인을 고르는 문제의 단골 오답
  • 실행 중이던 기계어 명령 하나는 끝까지 마친 뒤 인터럽트를 처리한다 (명령어 중간에 끊지 않음)
  • CPU는 항상 인터럽트를 받아들이지 않는다 — 인터럽트 불가능 상태로 세트되어 있으면 인터럽트 사이클을 수행하지 않는다
  • 인터럽트 핸들러(ISR)는 커널 모드에서 실행되며, 기억장치에 적재되어 있어야 한다

✏️연습문제

먼저 스스로 풀어본 뒤 "해설 보기"를 눌러 확인하세요.

문제 12011 지방직 · 기출문제집 p.103

컴퓨터시스템의 명령어 형식이 [OPCODE | OPERAND]이고, OPERAND 필드가 256M 워드 크기의 메모리 주소를 나타낼 때 OPCODE 필드로 나타낼 수 있는 서로 다른 종류의 명령어는 모두 몇 개인가? (단, 1워드는 32비트이며 각 명령어 크기는 1워드)

  1. 16
  2. 64
  3. 256
  4. 512
해설 보기

정답 ① 16개

  1. 256M을 2의 거듭제곱으로: 256 = 2⁸, M = 2²⁰ → 256M = 2⁸ × 2²⁰ = 2²⁸
  2. 2²⁸개의 주소를 구분하려면 OPERAND 필드는 28비트 필요
  3. 명령어 전체가 1워드 = 32비트이므로 OPCODE = 32 − 28 = 4비트
  4. 4비트로 표현 가능한 명령어 종류 = 2⁴ = 16개

함정: ③번 256은 문제에 나온 "256M"의 숫자를 그대로 답으로 옮긴 것이다. 구하는 건 OPCODE의 가짓수이지 오퍼랜드 크기가 아니다. 또 흔한 실수는 M을 10⁶으로 계산하는 것 — 컴퓨터에서 M은 2²⁰이다.

문제 22025 지방직 · 기출문제집 p.103

다음 12비트 명령어 형식(연산코드 5비트 + 주소부 7비트)에 대하여 직접 주소 지정 방식으로 지정할 수 있는 메모리의 최대 크기는? (단, 하나의 주소공간 크기는 1바이트)

  1. 128바이트
  2. 256바이트
  3. 512바이트
  4. 1,024바이트
해설 보기

정답 ① 128바이트

  1. 직접 주소 지정 방식에서는 주소부(오퍼랜드)에 적힌 값이 곧 유효주소다
  2. 주소부가 7비트 → 표현 가능한 서로 다른 주소 개수 = 2⁷ = 128개
  3. 주소 1개가 1바이트를 가리키므로 → 최대 메모리 크기 = 128바이트

함정: ④번 1,024는 전체 12비트(2¹²=4096도 아닌 어중간한 값)나 연산코드까지 합쳐 계산하려다 나오는 오답이다. 메모리 크기를 결정하는 것은 오직 주소부 비트 수이며, 연산코드 5비트는 이 계산에 전혀 관여하지 않는다(그건 명령어 종류 2⁵=32개를 결정할 뿐).

문제 32016 계리직 · 기출문제집 p.105

컴퓨터 시스템의 인터럽트에 대한 설명으로 옳지 않은 것은?

  1. 인터럽트는 입출력 연산, 하드웨어 실패, 프로그램 오류 등에 의해서 발생한다.
  2. 인터럽트 처리 우선순위 결정 방식에는 폴링 방식과 데이지 체인 방식이 있다.
  3. 인터럽트가 추가된 명령어 사이클은 인출 사이클, 인터럽트 사이클, 실행 사이클의 순서로 수행된다.
  4. 인터럽트가 발생할 경우, 진행 중인 프로그램의 재개에 필요한 레지스터 문맥을 저장한다.
해설 보기

정답 ③ — 순서가 틀렸다

  1. 올바른 순서는 인출 → 실행 → 인터럽트(확인·처리)이고, 인터럽트 사이클이 끝나면 다시 인출 사이클로 돌아간다
  2. ③번은 인터럽트 사이클을 실행 사이클 앞에 놓았다 — 명령어를 실행하지도 않고 인터럽트부터 처리한다는 뜻이 되므로 틀렸다
  3. 인터럽트 사이클에서는 레지스터 정보와 복귀주소를 스택에 저장한 뒤, 서비스 루틴을 수행하기 위해 인출 사이클이 이어진다

핵심 암기: "인터럽트 사이클 다음은 언제나 인출(Fetch)" — 실행 사이클로 곧장 복귀하지 않는다. ①·②·④는 모두 올바른 설명이다.

문제 42012 지방직 · 기출문제집 p.106~107

인터럽트 발생 시 수행되는 작업순서로 옳은 것은?
ㄱ. 해당 인터럽트 서비스 루틴을 호출한다.
ㄴ. 현재 프로그램 카운터에 적재된 명령어 주소를 스택에 저장한다.
ㄷ. 해당 인터럽트 서비스를 수행한다.
ㄹ. 스택에 저장된 명령어 주소를 프로그램 카운터에 저장한다.

  1. ㄱ → ㄴ → ㄹ → ㄷ
  2. ㄱ → ㄷ → ㄴ → ㄹ
  3. ㄴ → ㄱ → ㄷ → ㄹ
  4. ㄴ → ㄱ → ㄹ → ㄷ
해설 보기

정답 ③ ㄴ → ㄱ → ㄷ → ㄹ

  1. ㄴ 저장: 떠나기 전에 돌아올 주소(PC)를 스택에 적어둔다 — 무조건 이게 첫 번째
  2. ㄱ 호출: 원인을 분석해 해당 서비스 루틴을 호출한다
  3. ㄷ 수행: 서비스 루틴을 실제로 실행한다
  4. ㄹ 복귀: 스택에 적어둔 주소를 PC로 되돌려 원래 자리로 복귀한다

요령: "저장 → 호출 → 수행 → 복귀" 네 글자로 외우면 어떤 변형이 나와도 풀린다. 선택지 중 ㄴ(저장)으로 시작하지 않는 것(①·②)은 즉시 제외, 남은 ③·④ 중에서는 호출했으면 수행부터 해야 하므로 ③.

  1. 입·출력
  2. 오버플로
  3. 전원 이상
  4. 기계 오작동
해설 보기

정답 ② 오버플로 (내부 인터럽트)

구분 기준은 "CPU 바깥에서 벌어진 사건이냐, 프로그램 실행 도중 생긴 문제냐"다.

외부 인터럽트 (하드웨어)내부 인터럽트 (소프트웨어·예외)
전원 이상, 기계 오작동오버플로, 0으로 나누기
입·출력 완료, 외부 신호, 타이머잘못된 명령어, 보호 메모리 접근

함정: 오버플로는 "계산이 잘못됐다"는 연산 결과의 문제이므로 CPU 내부 사건이다. 같은 논리로 0으로 나누기도 내부(동기) 인터럽트다. 반면 키보드·마우스 입력은 언제 올지 모르는 외부 사건이므로 비동기·외부 인터럽트(2017 서울시 출제).

문제 62024 계리직 · 기출문제집 p.108

인터럽트의 우선순위를 높은 것부터 바르게 나열하면? (전원 이상 / 외부 신호 / 기계 착오 / 입출력 / SVC / 명령의 잘못 사용)

해설 보기

정답: 전원 이상 → 기계 착오 → 외부 신호 → 입출력 → 명령의 잘못 사용 → SVC

  1. 먼저 하드웨어적 인터럽트가 소프트웨어적 인터럽트보다 항상 우선한다 (앞 4개가 하드웨어, 뒤 2개가 소프트웨어)
  2. 하드웨어 내부 순서: 전원 이상 → 기계 착오 → 외부 신호 → 입출력
  3. 소프트웨어 내부 순서: 명령의 잘못 사용(프로그램 인터럽트) → SVC(슈퍼바이저 호출)

이유로 기억하기: 전원이 나가면 모든 것이 끝장이므로 최우선이다. 그다음은 기계 자체의 고장, 그다음이 바깥에서 온 신호, 그다음이 일상적인 입출력이다. "급한 정도 = 시스템이 망가질 위험 순서"라고 생각하면 순서가 자연스럽다. 반대로 SVC는 프로그램이 스스로 "저기요, 커널님" 하고 부르는 것이라 전혀 급하지 않다.

문제 72014 계리직 · 기출문제집 p.109

데이지-체인(daisy-chain) 우선순위 인터럽트 방식에 대한 설명으로 옳은 것은?

  1. 인터럽트를 발생시키는 장치들이 병렬로 연결된다.
  2. 두 개 이상의 장치에서 동시에 인터럽트가 발생되면 CPU는 이들 인터럽트를 모두 무시한다.
  3. 인터럽트를 발생시킨 장치가 인터럽트 인식(ACK) 신호를 받으면 자신의 장치번호를 CPU로 보낸다.
  4. CPU에서 전송되는 인터럽트 인식 신호는 우선순위가 낮은 장치부터 높은 장치로 순차적으로 전달된다.
해설 보기

정답 ③

데이지 체인의 동작을 순서대로 보면 답이 보인다.

  1. 여러 입출력 모듈이 하나의 인터럽트 요구선을 공유하며 직렬로 줄줄이 연결된다 → ①번(병렬)은 틀림
  2. CPU가 확인(ACK) 신호를 보내면, 신호는 CPU와 가까운 장치부터 차례로 전달된다 → ④번(낮은 우선순위부터)은 틀림. 가까울수록 우선순위가 높다
  3. 인터럽트를 요구하지 않은 모듈은 신호를 다음 모듈로 그냥 넘긴다
  4. 요구한 모듈이 ACK를 받으면 데이터 버스로 인터럽트 벡터(자신의 장치번호)를 보내 CPU가 누구인지 알게 한다 → ③번이 정답

함정: ②번처럼 "동시 발생 시 모두 무시"하는 방식은 존재하지 않는다. 우선순위 방식은 애초에 동시 발생을 정리하기 위해 있는 것이다. 데이지 체인의 진짜 단점은 무시가 아니라 뒤쪽(먼) 장치가 계속 밀려 오래 기다릴 수 있다는 점이다.

문제 82025 법원직 · 기출문제집 p.110

인터럽트에 관한 설명 중 가장 옳지 않은 것은?

  1. 인터럽트가 발생함으로 인하여 문맥 교환(context switching)이 이루어질 수 있다.
  2. 인터럽트가 발생하더라도 CPU에서 실행 중이던 기계어 명령은 끝까지 실행된다.
  3. 인터럽트 핸들러의 실행은 커널 모드에서 진행된다.
  4. 인터럽트 처리가 종료되면 항상 인터럽트 발생 당시 실행 중이던 프로세스가 다시 실행된다.
해설 보기

정답 ④ — "항상" 원래 프로세스로 돌아가지는 않는다

  1. 인터럽트 처리가 끝나면 운영체제의 스케줄러가 다음에 실행할 프로세스를 다시 고른다
  2. 이때 더 우선순위가 높은 프로세스가 준비 상태로 올라와 있다면 그쪽이 먼저 실행될 수 있다 → ④번의 "항상"이 틀린 이유
  3. ①번은 이와 같은 맥락에서 맞는 말이다 — 인터럽트가 문맥 교환의 계기가 될 수 있다

②번을 눈여겨볼 것: 인터럽트는 명령어 중간을 끊지 않는다. 실행 중인 기계어 명령 하나를 끝낸 뒤, 다음 명령을 인출하기 직전에 확인한다. 명령어 중간에 멈추면 상태가 어중간해져 복구가 불가능하기 때문이다. 이 원리를 알면 "명령어 사이클 끝에서 인터럽트를 확인한다"는 구조가 왜 그런지도 함께 이해된다.

선택지에 '항상·반드시·모두'가 보이면 의심하라 — 이 유형에서 오답일 확률이 높다.
