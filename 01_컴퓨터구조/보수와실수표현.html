보수와 실수 표현 (IEEE 754)

1의 보수·2의 보수, 고정소수점, 부동소수점 표준 · PART 01. 전자계산기구조론

핵심 요약

컴퓨터는 음수를 2의 보수로 표현한다 — "0은 1로, 1은 0으로" 바꾼 뒤(1의 보수) +1을 더한다.

실수는 IEEE 754 표준으로 부호(1비트) + 지수(바이어스 적용) + 가수 3부분으로 저장한다.

🎯이 단원을 왜 배우나

"마이너스 기호"를 저장할 자리가 없다

컴퓨터 메모리에는 0과 1밖에 없다. 그러면 −5의 "−"는 어디에 저장하나? 가장 단순한 답은 "맨 앞 비트 하나를 부호 전용으로 쓰자"(부호-절대치 방식)인데, 이 방식엔 치명적 문제가 둘 있다. +0과 −0이 따로 생기고(0이 두 개!), 무엇보다 뺄셈 회로를 따로 만들어야 한다.

2의 보수는 이 두 문제를 한 번에 해결한다. 음수를 "보수"로 표현하면 A − B를 A + (B의 2의 보수)로, 즉 뺄셈을 덧셈으로 바꿀 수 있다. 그러면 CPU 안에 덧셈 회로 하나만 있으면 되고(앞 단원의 4비트 가산기/감산기가 정확히 이 원리다), 0도 하나뿐이다. 현대의 모든 컴퓨터가 2의 보수를 쓰는 이유다.

실수는 또 다른 문제다. 3.14 같은 수는 정수부·소수부 자릿수가 제각각이라 고정된 자리에 담기 어렵다. 그래서 과학적 표기법(1.xxx × 2ⁿ)으로 바꿔 "부호·지수·가수"를 따로 저장하기로 전 세계가 약속한 것이 IEEE 754다. 시험에서는 2진수 32비트 ↔ 10진 실수를 양방향으로 변환시키는 문제가 거의 매년 나온다.

왜 "반전하고 +1"이 음수가 되는가 — 시계 비유

4비트로 표현 가능한 수는 0~15까지 16개이고, 16이 되면 자리올림이 버려져 다시 0으로 돌아온다. 시계가 12를 지나면 1로 돌아오는 것과 같다. 이런 세계에서는 "−3"과 "+13"이 같은 동작을 한다. 3시간 되감는 것과 13시간 감는 것이 12시간 시계에서 같은 결과이듯이.

그래서 −N을 2ⁿ − N으로 표현하기로 한 것이 2의 보수다. 4비트에서 −3 = 16 − 3 = 13 = 1101. 그런데 2ⁿ − N을 매번 빼기로 계산하긴 번거로우니, (2ⁿ−1) − N을 먼저 하고(= 그냥 비트 반전) +1을 하는 요령을 쓰는 것이다. 반전이 곧 뺄셈인 이유는 1111 − 0011 = 1100처럼 전부 1인 수에서 빼면 각 자리가 그대로 뒤집히기 때문이다.

이 관점으로 보면 덧셈만으로 뺄셈이 되는 것도 당연하다. A − B = A + (2ⁿ − B)이고, 넘친 2ⁿ은 어차피 자리올림으로 버려지기 때문이다.

2의 보수를 쓰는 이유 — 뺄셈을 덧셈으로

  • A − B 연산을 A + (B의 2의 보수)로 바꿔서 덧셈 회로 하나로 가감산 모두 처리
  • 최상위 자리에서 발생한 캐리(carry)는 버린다 — 위 시계 비유의 "한 바퀴 돈 것"에 해당
  • 실제 회로 구현은 4비트 병렬 가산기/감산기에서 모드신호 M으로 처리한다
예: 7 − 3 을 2의 보수 덧셈으로 (4비트)
  1. 3 = 0011 → 1의 보수 1100 → +1 → 1101 (= −3)
  2. 7(0111) + (−3)(1101) = 1 0100 — 5비트가 되었다
  3. 넘친 최상위 캐리 1을 버린다 → 0100 = 4 ✓ (7−3=4)

함정 주의: 음수 쪽이 항상 하나 더 많다(−8은 되는데 +8은 안 됨). 2의 보수는 0을 한 가지로만 표현하므로 남는 자리 하나가 음수로 간다. 최댓값 + 최솟값 = −1이라는 것도 같은 이야기다.

오버플로(Overflow): 덧셈 결과가 표현 범위를 벗어날 때 발생한다. 판정법은 최상위 비트로 들어온 캐리와 나간 캐리를 XOR해서 1이면 오버플로다. 직관적으로는 "같은 부호끼리 더했는데 부호가 바뀌면 오버플로"로 기억하면 된다(양수+양수=음수, 음수+음수=양수는 불가능하니까).

컴퓨터가 "정확히" 표현하지 못하는 수도 있다

√2나 π처럼 끝나지 않고 반복도 하지 않는 무리수는 비트가 아무리 많아도 정확히 담을 수 없다. 심지어 10진수 0.1조차 2진수로는 무한소수(0.000110011001100…)라서 근사값으로 저장된다. 프로그래밍에서 0.1 + 0.2 != 0.3이 되는 유명한 현상의 원인이 이것이다.

반대로 0.5, 0.25, 2.5, −0.25×2⁻⁵처럼 분모가 2의 거듭제곱인 수는 2진 소수로 딱 떨어지므로 정확히 표현된다. 시험에서 "정확히 표현하기 어려운 것"을 고르라면 무리수(√2, π)를 고르면 된다.

IEEE 754 부동소수점 표준 📖 기출문제집 p.55

정규화된 형태 ±1.bbb…b × 2±E 로 표현하며, 아래 3부분으로 저장한다.

구분단일 정밀도 (32비트)이중 정밀도 (64비트)
부호부1비트1비트
지수부8비트 (바이어스 127)11비트 (바이어스 1023)
가수부23비트52비트
  • 부호 비트: 0=양수, 1=음수
  • 지수부에는 실제 지수 + 바이어스 값을 저장 (음수 지수를 양수로 표현하기 위함)
  • 가수부에는 정규화된 "1." 을 제외한 나머지 소수 부분만 저장 (어차피 항상 1이므로 저장하지 않고 1비트를 아낀다 — 숨은 비트)
  • 가수부 비트가 많을수록 정밀도가, 지수부 비트가 많을수록 표현 범위가 커진다
  • 0은 특별한 값으로 모든 비트를 0으로 표현

정규화(Normalization)를 하는 이유

같은 수라도 0.001011 × 2⁵, 1.011 × 2¹처럼 여러 방식으로 쓸 수 있다. 그중 소수점 왼쪽에 1 하나만 남는 형태로 통일하는 것이 정규화다. 이렇게 하면 표현이 딱 하나로 정해져 비교가 쉬워지고, 무엇보다 앞자리의 의미 없는 0들이 사라져 그만큼 가수부에 유효숫자를 더 담을 수 있다. 시험에서 "정규화의 목적"을 물으면 유효숫자를 늘리기 위해서가 정답이다.

반대 방향(비트열 → 10진수)도 같은 순서를 거꾸로
  1. 맨 앞 1비트로 부호 판정 (1이면 음수)
  2. 다음 8비트를 10진수로 읽고 −127 → 실제 지수 E
  3. 나머지 23비트 앞에 "1."을 붙여 가수 복원
  4. 가수 × 2E 계산 (소수점을 E칸 오른쪽으로 이동)
  5. 2진 소수를 10진수로 환산 (.101 = 0.5 + 0.125 = 0.625)

부동소수점의 사칙연산 규칙 📖 기출문제집 p.58

연산규칙
덧셈/뺄셈① 0인지 검사 → ② 지수가 큰 쪽에 맞춰 작은 쪽 가수 위치 조정 → ③ 가수 연산 → ④ 결과를 다시 정규화
곱셈지수를 더한다 (가수는 곱한다)

함정 주의: 지수를 맞출 때는 항상 지수가 작은 쪽의 가수를 오른쪽으로 밀어 큰 쪽에 맞춘다. 반대로 하면(큰 쪽을 작은 쪽에 맞추면) 큰 수의 유효숫자가 잘려나가 정보가 손실된다.

📌시험 빈출 포인트

  • 10진수를 2의 보수 n비트로 변환 (절대치 → 반전 → +1 순서)
  • 2의 보수 값을 다시 10진수로 해석 (최상위 비트=부호 먼저 확인, 음수면 다시 보수 취해 절대값)
  • 같은 비트열을 1의 보수로 해석 vs 2의 보수로 해석하면 값이 1 차이난다는 유형
  • 2의 보수 n비트 범위 = −2ⁿ⁻¹ ~ 2ⁿ⁻¹−1, 최댓값+최솟값 = −1, 음수가 하나 더 많다
  • 뺄셈을 2의 보수 덧셈으로 바꿔 계산 (최상위 캐리는 버림), 오버플로 판정
  • IEEE 754 단정도=32비트(1·8·23), 배정도=64비트(1·11·52), 바이어스=127/1023
  • 비트열 ↔ 10진 실수 양방향 변환 계산 (매년 출제)
  • 정규화의 목적 = 유효숫자를 늘리기 위해, 부동소수점 구성요소에 기수(base)는 포함되지 않음
  • 덧셈/뺄셈은 지수가 큰 쪽 기준 정렬, 곱셈=지수 덧셈, 나눗셈=지수 뺄셈

문제 12016 지방직 · 기출문제집 p.48

10진수 −20을 2의 보수 형식의 8비트 2진수로 나타낸 것은?

  1. 10010100
  2. 11101011
  3. 11101100
  4. 11110100
해설 보기

정답 ③ 11101100

  1. 절대값 20을 8비트 2진수로: 00010100 (16+4=20)
  2. 모든 비트 반전(1의 보수): 11101011
  3. +1 (2의 보수): 11101011 + 1 = 11101100

검산: 다시 반전 후 +1 하면 00010011+1 = 00010100 = 20 ✓

선택지가 곧 오답 유형표다: ①10010100은 부호-절대치 표현, ②11101011은 1의 보수(+1을 안 함)다. 문제가 어느 방식을 묻는지 반드시 확인할 것.

문제 22018 지방직 · 기출문제집 p.47

비트열 A를 2의 보수로 표현된 부호 있는 2진 정수로 해석한 값은 −5이다. 비트열 A를 1의 보수로 표현된 부호 있는 2진 정수로 해석한 값은?

  1. −4
  2. −5
  3. −6
  4. −7
해설 보기

정답 ① −4

"같은 비트열을 두 가지 방식으로 읽으면 얼마가 되나"를 묻는 유형이다. 비트열을 먼저 복원하는 것이 출발점.

  1. 2의 보수로 −5인 비트열 구하기(4비트): 5 = 0101 → 반전 1010 → +1 → A = 1011
  2. 이제 A를 1의 보수로 해석: 최상위 비트가 1이므로 음수
  3. 1의 보수에서 절대값은 반전만 하면 된다: 1011 → 0100 = 4
  4. 따라서 값은 −4

일반 규칙: 같은 음수 비트열이라면 1의 보수 해석값이 2의 보수 해석값보다 항상 1 크다(−5 → −4). 2의 보수가 +1을 더한 표현이기 때문이다. 이 규칙만 알면 계산 없이 ①을 고를 수 있다.

문제 32018 국가직 · 기출문제집 p.46

다음 수식에서 이진수 Y의 값은? (단, 모든 수는 8비트 이진수이고 1의 보수로 표현된다)
11110100₂ + Y = 11011111₂

  1. 11101001₂
  2. 11101010₂
  3. 11101011₂
  4. 11101100₂
해설 보기

정답 ② 11101010₂

비트 상태로 낑낑대지 말고 10진수로 번역 → 계산 → 다시 번역이 가장 안전하다.

  1. 11110100: MSB=1(음수) → 반전 00001011 = 11 → 값은 −11
  2. 11011111: MSB=1(음수) → 반전 00100000 = 32 → 값은 −32
  3. −11 + Y = −32 → Y = −21
  4. −21을 1의 보수로: 21 = 00010101 → 반전 → 11101010

함정: ④11101100은 −21의 2의 보수다(반전 후 +1까지 함). 문제에 "1의 보수"라 못박혀 있으므로 +1을 하면 안 된다. 1의 보수 문제에서 가장 흔한 실수다.

문제 42023 소방경채 · 기출문제집 p.46

다음 연산식에서 이진수 Y의 값으로 옳은 것은?
(10110101)₂ + Y = (11101111)₂

  1. (01110101)₂
  2. (11001001)₂
  3. (11001110)₂
  4. (00111010)₂
해설 보기

정답 ④ (00111010)₂

Y = 11101111 − 10110101 이다. 뺄셈은 2의 보수를 더하는 것으로 바꿔 푼다.

  1. 빼는 수 10110101의 2의 보수: 반전 01001010 → +1 → 01001011
  2. 더하기: 11101111 + 01001011 = 1 00111010 (9비트 발생)
  3. 최상위로 넘친 캐리 1은 버린다 → 00111010

10진수 검산: 11101111 = 239, 10110101 = 181 → 239 − 181 = 58, 그리고 00111010 = 32+16+8+2 = 58 ✓

포인트: 결과의 MSB가 0(양수)이라는 점도 맞는 답임을 뒷받침한다. 더 큰 수에서 작은 수를 뺐으니 양수가 나와야 정상이다.

문제 52009 국가직 · 기출문제집 p.53

4비트를 이용한 정수 자료 표현에서 2의 보수를 이용하여 음수로 표현했을 때 옳지 않은 것은?

  1. 십진수 −4는 이진수 1100으로 표현된다.
  2. 십진수 8은 이진수 1000으로 표현된다.
  3. 십진수 −1은 이진수 1111로 표현된다.
  4. 십진수 5는 이진수 0101로 표현된다.
해설 보기

정답 ② (4비트 2의 보수로 +8은 표현 불가)

  1. 4비트 2의 보수 범위는 −8 ~ +7. 따라서 +8은 애초에 표현할 수 없다 → ②가 틀림
  2. 참고로 1000은 이 체계에서 −8을 의미한다 (+8이 아니다)
  3. ① −4: 4=0100 → 반전 1011 → +1 → 1100 ✓
  4. ③ −1: 1=0001 → 반전 1110 → +1 → 1111 ✓ (−1은 항상 전부 1)
  5. ④ +5는 양수이므로 보수 없이 그대로 0101 ✓

외워두면 편한 두 가지: 2의 보수에서 −1은 항상 전부 1(1111…1), 최솟값은 1 뒤에 전부 0(1000…0)이다.

문제 62017 하반기 국가직 · 기출문제집 p.56

다음 2진 표현이 나타내는 IEEE 754 표준 단정도(single precision) 부동소수점 수의 값은?
1 10000011 10101010000000000000000

  1. +5.3125₍₁₀₎
  2. −26.625₍₁₀₎
  3. +21.25₍₁₀₎
  4. −13.3125₍₁₀₎
해설 보기

정답 ② −26.625

  1. 부호: 첫 비트가 1 → 음수 (①③ 즉시 탈락)
  2. 지수: 10000011₂ = 128+2+1 = 131 → 실제 지수 = 131 − 127 = 4
  3. 가수: 저장된 1010101… 앞에 "1."을 붙여 1.1010101
  4. 소수점을 지수만큼(4칸) 오른쪽으로: 1.1010101 × 2⁴ = 11010.101
  5. 10진 변환: 정수부 11010 = 16+8+2 = 26, 소수부 .101 = 0.5+0.125 = 0.625 → 26.625
  6. 부호 적용 → −26.625

시간 절약 팁: 부호비트만 봐도 선택지 절반이 날아간다. 그다음 지수로 대략의 크기(2⁴ ≈ 16~32 사이)를 가늠하면 ④(−13.3)도 걸러져 계산 전에 답이 보인다.

문제 72018 계리직 · 기출문제집 p.56

10진수 −2.75를 IEEE 754 표준 32비트 단정도 부동소수점 방식으로 표기했을 때 옳은 것은? (부호 1비트, 지수부 8비트, 가수부 23비트)

  1. 1000 0000 0000 0000 0000 0000 0000 1011
  2. 1000 0000 1011 0000 0000 0000 0000 0000
  3. 1010 0000 0110 0000 0000 0000 0000 0000
  4. 1100 0000 0011 0000 0000 0000 0000 0000
해설 보기

정답 ④ 1100 0000 0011 0000 0000 0000 0000 0000

  1. 2.75를 2진수로: 2 = 10, 0.75 = 0.11 → 10.11₂
  2. 정규화: 소수점을 왼쪽으로 1칸 → 1.011 × 2¹
  3. 부호 = 1 (음수)
  4. 지수 = 1 + 127 = 128 = 10000000₂
  5. 가수 = "1."을 뗀 011 + 0으로 채워 23비트 → 01100000…0
  6. 이어 붙이면 1|10000000|01100000… → 4비트씩 끊어 1100 0000 0011 0000 …

비트 경계 주의: 부호 1비트 때문에 지수부가 4비트 경계와 어긋난다. 그래서 지수 10000000이 화면상 "100 0000 0"처럼 쪼개져 보이는 것이다. 이 어긋남 때문에 ②(지수를 4비트 경계에 맞춰버린 오답)에 낚이기 쉽다.

문제 82021 국가직 · 기출문제집 p.57

−30.25 × 2⁻⁸의 값을 갖는 IEEE 754 단정도 부동소수점 수를 16진수로 변환하면?

  1. 5DF30000
  2. 9ED40000
  3. BDF20000
  4. C8F40000
해설 보기

정답 ③ BDF20000

  1. 30.25를 2진수로: 30 = 11110, 0.25 = 0.01 → 11110.01₂, 즉 −11110.01 × 2⁻⁸
  2. 정규화: 소수점을 왼쪽으로 4칸 옮기면 1.111001 × 2⁴ → 원래 지수와 합쳐 −1.111001 × 2⁻⁴ (4 − 8 = −4)
  3. 부호 = 1, 지수 = −4 + 127 = 123 = 01111011₂
  4. 가수 = 111001 + 0으로 채워 23비트
  5. 전체: 1 01111011 11100100000000000000000
  6. 4비트씩: 1011 1101 1111 0010 0000 0000 0000 0000 → B D F 2 0 0 0 0

부분 점수 전략: 지수가 음수(−4)이므로 저장값은 127보다 작은 123 → 지수부가 0111…로 시작한다. 부호 1과 합치면 첫 4비트가 1011 = B로 확정되어, 계산을 끝까지 안 해도 ③으로 좁혀진다.
